# V7代码区与重构边界

本文件作用于 `coauthoring-v7/`。通用授权、安全、工作模式和部署遵循 [根规则](../AGENTS.md)，实施遵循 [开发流程](../docs/DEVELOPMENT_WORKFLOW.md)，验证遵循 [验收标准](../docs/ACCEPTANCE.md)。本文件只补充当前代码区边界，不另设审批和测试门槛。

## 当前事实与新设计

- V7是当前唯一线上产品；代码、页面、数据和 [HANDOFF.md](HANDOFF.md) 用于运行查证、资产审计、迁移与回滚。
- 老板最新明确要求可改变现有页面、工作流、岗位、对象层级和技术实现。V7、V9等版本名称不使讨论稿自动变成规格。
- 已明确要求保留的功能和视觉偏好持续有效；重构前在当前合同列出保留、替换与兼容范围。
- 仅讨论整体重构不会自动启动编码。明确授权实现的任务按合同执行，不因历史“讨论期”标签重新请求开工。
- 新方案可以替换当前V7业务实现；根规则中的安全、内容可信和生产底线持续适用。

## 实施、复用与替换

- 当前产品代码位于本目录及明确的共享平台边界。新模块路径、技术方案和分批替换方式由已授权任务的合同确定，始终在项目内工作。
- 局部修复优先最小差异；整体重构可重新组织模块、重写不合适的业务核心。复用以目标、质量、依赖和维护成本判断，不强制逐代搜索旧版本，也不为保持旧代码而扭曲新架构。
- 已删除旧产品不恢复为当前运行依赖。确需参考Git历史时只取语义相符且验证合格的必要实现，历史页面与流程不成为新规格。
- 登录、会话、正文版本、计费和其他受保护的平台能力先审查再决定复用或替换；避免两套身份或账本互相冲突，替换需明确单一权威和兼容路径。
- 渐进切换期间允许有边界、可回滚的过渡实现，记录读写归属、版本和退出条件；同一任务不能被新旧执行器重复处理。
- 删除运行代码前确认新闭环可用、没有有效引用且满足兼容与回滚要求。已合并迁移、作者正文、结算和历史任务快照不按“旧实现”清理。

## 决定与记录

- 根规则保留长期底线；当前合同记录已授权任务的目标与验收；建议、比较、草图保持候选。
- 普通、可逆、授权范围内的产品细化与工程选择由Codex负责，说明理由即可，不强制每轮提问或每批等待老板确认。
- 重大产品目标、作者控制权、费用或安全授权缺失时提出最少的必要问题，其余工作继续。
- 当前结论写回相关源文档；任务状态与证据进入唯一清单，长期运行变化同步HANDOFF。不维护重复决定板，不复制通用规则。
