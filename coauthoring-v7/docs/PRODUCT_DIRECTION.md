# V7 当前产品方向

> 状态：讨论底稿。除“已确认边界”外均可修改、合并或删除，不能直接作为开发验收。

## 一、核心问题

当前产品把后台专业结构大量暴露给作者，形成“先把整本书设计完，才能开始写”的感觉。这样会产生三个问题：

1. 小白作者不知道应该填什么、选什么；
2. 作者的注意力被流程和术语消耗，而不是用于判断故事好不好；
3. Agent一次收到过多层级、未来计划和旧摘要，容易把计划当事实、忽略当前任务或前后漂移。

V7需要把复杂度留在后台，把作者体验改成轻量共创。

## 二、产品目标

V7希望形成一个可反复运行的最小循环：

```text
系统根据当前正式状态组装最小资料
→ AI给少量实质不同的下一步方向
→ 作者选择、补充想法、直接编辑或要求重做
→ AI把选定方向扩展成当前层级的可执行内容
→ 作者确认
→ 进入写作或下一层
→ 正文定稿后只结算实际发生
→ 更新正式状态、检索索引和故事雷达
→ 重新编译下一步资料
```

作者不需要理解RAG、ContextPack、模型、任务ID、内部模板或专业节奏术语。

## 三、目前倾向的创作旅程

### 1. 开始一本书

- 最简只选择题材，例如“玄幻修仙”。
- 一句话想法、已有片段、主角想法和完整方向均为可选。
- AI给少量明显不同的开书方向；作者选择、补充、编辑或换一批。
- 确认后形成版本化的开书简报，但不要求先填完大量设定表。

### 2. 当前卷

- AI根据开书简报、正式设定和上一卷实际结果给出本卷方向。
- 作者判断本卷主要变化、冲突、代价、卷末状态和阅读感受。
- 不在这一阶段强迫作者确认所有未来事件、角色和节奏模板。

### 3. 当前事件

- 后台可以维护本卷轻量事件骨架，保证因果和全卷方向。
- 前端默认只显示收缩时间线；作者可以查看调整，也可以直接处理当前事件。
- 当前事件详细完成后，根据实际结果再校准后续事件，不把早期预测当不可修改计划。

### 4. 当前章节

- 后台可以保留轻量完整章链，只记录每章责任和因果。
- 详细章纲只处理当前章，最多提示未来一至两章。
- 先让作者看到、编辑并确认章纲，再由主笔写正文。
- 事实、文学、体验检查是后台质量能力；前端不制造无限审查循环。
- 作者确认正文后产生不可变版本，并从正文结算实际发生。

### 5. 故事雷达

- 故事线、伏笔、关系和开放问题不作为开书门槛。
- 系统从正式正文和结算中持续识别正在形成的长期线路。
- 在事件或卷等自然节点轻量提醒作者；作者可确认、忽略、继续观察或手动添加。
- 它用于理解故事正在往哪里生长，不要求作者预先画完整全书地图。

## 四、AI编辑部方向

- Agent成员是后台岗位资源，不是24小时常驻并全部调用。
- 默认由系统分配一名合适成员；作者可以更换，或主动增加同岗位成员比较。
- 作者选择成员，不选择模型；模型绑定、可用性和供应商切换由后台管理。
- 每个AI节点都有“补充我的想法”输入，可留空，并作为版本化资料进入同一批次。
- 同岗位多人比较必须收到完全相同的资料包、作者输入、节点合同和模板版本。
- 单成员失败不清空其他成功结果；允许只重试失败成员或换成员，不能卡死流程。
- 岗位数量、名称和具体介入节点仍可重新讨论；现有七类25人只是可复用资源池，不是V7页面结构。

## 五、长篇稳定性方向

防漂移不依赖无限聊天记忆，而依赖正式状态：

- 规划、候选、作者想法、确认稿、正文实际严格分区；
- 正文完整版本不可变，修改产生新版本；
- 章节/事件/卷结算只读取正式正文；
- 人物状态、关系、时间线、资源、伏笔和故事线由证据投影；
- 每个任务读取最小充分资料，并记录来源、版本、采用与排除理由；
- 上游变化只使依赖的候选失效，不覆盖历史正文和真实结算。

## 六、前端UI方向

V7不沿用旧页面内部UI，也不拿旧设计图作为视觉验收基准。

已确认的视觉方向：

- 整体以白色和浅绿色为主，形成清爽、轻盈、安静的创作环境；
- 妙笔神书只作为视觉表现参考，借鉴简洁、充足留白、柔和圆角和清楚的按钮层级，不借鉴其功能模块、信息架构、导航、页面组织或营销内容；
- 浅绿色主要承载品牌氛围、轻背景和选中状态；正文、说明文字和关键操作必须使用对比度足够的深色中性色或绿色，不能为了“浅”牺牲可读性；
- 精确色值、用色比例和各状态色不在讨论阶段定死，后续通过桌面与手机原型一起验证。

已确认的导航排版：

- 保留当前产品“左侧书籍栏＋上方功能导航”的空间布局；
- 保留的是排版外壳，不是旧导航名称、页面数量、页面职责、对象层级或创作工作流；
- 移动端导航的具体排布仍需在主要页面和关键任务确认后通过原型验证。

目前倾向：

- 手机保留容易触达的顶部导航习惯，具体是否双排要结合新页面数验证；
- 首屏只突出一个当前任务和一个主要操作；
- 作者先看白话方案，再按需展开专业结构、来源和历史；
- 长内容默认折叠，选择、编辑、等待、失败和恢复状态必须清楚；
- 不做堆满成员卡、流程卡、数据卡的通用AI仪表盘。

导航名称、页面数量、故事雷达位置、共创深度入口、精确色值与用色比例、组件密度和移动端布局尚未确认，必须先做信息架构和低保真交互图。

## 七、明确不采用

- 不要求作者在写第一章前完成全书故事线、全部角色卡和所有事件链。
- 不把后台22种结构模板原样展示成专业考试。
- 不把每个后台对象都做成一个前端页面。
- 不让所有Agent默认同时介入。
- 不用摘要或AI推断覆盖作者确认内容与正文事实。
- 不为了复用旧代码把新工作流重新做回V6。
