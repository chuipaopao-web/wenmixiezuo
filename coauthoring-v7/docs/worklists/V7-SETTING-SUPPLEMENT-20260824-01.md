# V7 设定页资料展示与补充设计

任务编号：V7-SETTING-SUPPLEMENT-20260824-01
本次唯一清单：`coauthoring-v7/docs/worklists/V7-SETTING-SUPPLEMENT-20260824-01.md`
任务类型：已上线产品的局部 UI 与工作流调整
当前问题：设定页“开书资料”混入人物卡等非开书来源，摘要也包含无关推导；逐项设计一旦开始便锁定资料库，作者完成一部分后不能再加入新条目继续设计。
复现步骤：进入任一本书的“设定”页；查看开书资料摘要与展开内容；开始逐项设计并完成所选条目后，再打开完整设定库尝试勾选新条目。
期望结果：开书资料只展示当前有效开书信息中的作者可见字段；作者可在已有设定基础上发起补充设计，只把新增条目接入原逐项流程，完成后仍走原主编审查与确认。
允许修改：设定页开书资料展示、设定资料库的本地会话状态与补充设计交互、同区域样式、直接相关前端测试、本清单。
明确不改：开书数据结构与保存逻辑、设定条目目录、成员选择与出方案逻辑、自写/留白/现成内容、主编审查接口与标准、正式设定版本规则、数据库、权限、导航和其他页面。
必须保留：当前白色浅绿色视觉与排版；完整设定库；逐项设计；每项成员选择与独立方案；自己写一份；先留白；已有现成内容；失败恢复；主编审查、作者确认和历史版本。
新功能验收：开书资料不再读取人物卡或推导字段；空字段不占位；不显示内部来源、版本、模型、成员、ID等元信息；设计已开始或已完成时可进入补充设计，只能新增未进入本书设计范围的条目；新条目接入现有队列，旧条目及其内容不被重做；新一轮完成后原主编审查仍可用；刷新后本轮范围可恢复。
原功能回归：初次选择范围与开始设计不变；已选和已确认条目不可被补充操作取消；自定义条目仍可加入；现有设计、修改、留白、审查与确认入口不丢失。
测试范围：`setting-catalog`、`workspace-ui` 直接相关用例；Web 类型检查与构建；真实浏览器检查设定页桌面视口和窄屏关键操作。无数据库、权限、跨服务恢复或核心工作流结构性变化，不触发 `npm run verify:full`。
部署要求：与上一批已完成的开书 AI 设计改动合并发布；发布前完成差异审计；仍需可用的生产 SSH 授权，发布后验证首页、静态资源、登录和设定页关键链路。

## 范围与风险记录

- 只使用现有 `owner_id + book_id` 后端接口，不改变身份或书籍隔离。
- 补充设计不覆盖任何已确认设定；新增条目继续通过现有版本化保存与主编审查。
- “脱敏”在本批定义为作者界面不展示内部来源、版本、模型、成员、ID、推断和其他模块数据；不篡改作者填写的小说内容。
- 不新增迁移、不改 API/Worker，不构成全量验证触发条件。
