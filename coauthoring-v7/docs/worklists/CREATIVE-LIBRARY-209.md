## 2. 信息分工：本书资料与创作参考不是同一种东西

| 输入类别 | 权威及使用方式 |
| --- | --- |
| 作者原话、明确选择 | 创作意图来源；保留原文定位，不能从未提及推断禁止 |
| 已确认开书/设定/上层方案 | 按对象版本读取；规划是未来方向，不冒充正文事实 |
| 已采纳正文及有证据的结算 | 后续阶段事实依据；正文与规则冲突须定位来源，不自动选一个覆盖另一个 |
| 资料短卡 | 派生阅读视图；附来源引用，必要时回查；不能自行升级成正式设定 |
| 创作参考卡/方法 | 可选编辑经验与构思工具，不是本书事实，也不是必须执行的要求 |
| 成员新创意/推测 | 候选提案；记录依据或原创身份，不伪造作者授权和参考来源 |

冲突不是简单“最后一条总覆盖前面”：作者的新要求可以改变未来创作方向；要修改已发生正文仍走版本化修改，不能把新意图偷偷当成过去事实。

## 3. 库的组织：统一资产模型，九种用途

1. 题材与世界：背景、题材机制与典型处境，见第4节。
2. 情绪与欲望：阅读体验可能性，见第5节；不推断真实用户心理缺陷。
3. 核心卖点与发展空间：独特行动、关系或规则怎样持续生成新问题。
4. 人物驱动力：目标、需要、执念、信念、底线、能力与选择。
5. 关系与对抗：亲密、伙伴、家庭、组织、竞争、价值冲突与环境压力。
6. 故事发展：故事线、目标递进、关系变化、回报、阶段收束与长线承接。
7. 融合设计：题材/机制/体验组合的相互作用与失衡检查。
8. 节奏与表达：复用已有方法，包括宏观节奏、因果、信息、视角、声音、场景等。
9. 设计检查：相关性、作者意图、证据、发展空间、重复、尺度与层级越界。

分类是检索视图，不是九个相互复制的数据库。卡片有一个主用途、可多个辅助用途；现有方法保留独立ID，通过关联引用。起承转合适用全书/卷/链/章时共用一个方法，不复制四份。体验“群像”与背景“三国”可以组合，但不是同一级题材。性别频道只承接作者选择和平台分类，不能代替读者偏好判断。

| 治愈轻喜剧 | 小店、社区、旅行、伙伴 | 安宁、幽默、修复、小愿望 | 日常变化/关系/小难题；不强加大阴谋或毁灭危机 |
| 讽刺黑色幽默 | 荒诞制度、错位身份、社会讽喻 | 反差、释放、重新看问题 | 规则碰撞/误认/后果；冒犯本身不等于有效讽刺 |
| 文学与实验 | 内在生活、非线性、不可靠叙述 | 审美、理解、形式探索 | 体验与主题组织；不能用商业节拍否定形式选择 |
| 儿童少年 | 成长、童话、探险、校园 | 好奇、友谊、能力与安全感 | 年龄适配/探索/关系；不得照搬成人冲突与表达 |

横向机制另维护可组合索引：穿越、重生、回归、系统、无敌、弱起点成长、身份隐藏/互换、时间循环、无限/多世界、快穿、空间资源、直播/通信、召唤/御兽、非人主角、模拟经营、群像、多主线、单元叙事、反套路、同人/衍生。它们不是自动要求；如“无外挂”明确排除外挂机制，但不会排除所有幻想背景。衍生题材卡只提供创作方法，不存放大段他人原文或把版权状态当作已许可。

覆盖审核单位为“范围+真实区别的子方向+相关维度”，不要求全量笛卡尔积。每行至少有可用入口、非模板示例、关联卡、失衡检查和审核记录；没有对应内容就显示缺口，不能用一个泛化“成长”卡把全部标完成。

## 5. 跨题材内容种子：体验、人物、关系和故事

### 5.1 阅读体验与回报卡

| 方向 | 设计提问 | 可体现的回报/变化 | 防止误用 |
| --- | --- | --- | --- |
| 能力与掌控 | 人物终于能解决什么？ | 困境转为可选择、行动有效 | 不等于必须无敌 |
| 尊严与认可 | 谁忽视了什么价值？谁的认可重要？ | 被看见、自我确认、公平待遇 | 不强制先羞辱再打脸 |
| 自由与自主 | 人物希望摆脱什么限制？ | 可以拒绝、选择身份与生活 | 不替作者添加永久束缚 |
| 归属与信任 | 什么行动让人愿意依靠彼此？ | 接纳、支持、共同承担 | 配角不是主角奖品 |
| 爱与亲密 | 为何吸引，能否理解与回应？ | 靠近、坦诚、相互选择 | 无感情线也可成立 |
| 公正与秩序 | 什么被误判、侵害或失衡？ | 翻案、追责、规则改变 | 公正不等于所有对手受辱 |
| 创造与积累 | 投入怎样变成可见成果？ | 家园、作品、团队、制度成长 | 避免只有数字增长 |
| 安全与安宁 | 哪种危险或不稳定得到缓解？ | 可以安睡、持续生活、信任环境 | 不必用更大灾难抵消每次胜利 |
| 探索与惊奇 | 新发现怎样改变理解？ | 新可能、世界扩展、认知更新 | 设定百科不是探索过程 |
| 智力参与 | 读者凭什么推断？ | 识破误导、解题、理解因果 | 不能靠临时补规则赢 |
| 刺激与释放 | 不确定性如何影响选择？ | 脱险、竞胜、压力释放 | 强度不必一路升高 |
| 幽默与反差 | 哪两种预期相撞？ | 意外、会心、荒诞后果 | 不靠重复梗或贬损身份 |
| 修复与重新开始 | 哪种关系或生活逐渐恢复？ | 和解、告别、新生活 | 不强迫原谅施害者 |
| 理解与共鸣 | 什么处境值得被看见？ | 理解自己或别人、复杂感受 | 不替真实读者诊断心理 |
| 审美与沉浸 | 表达、环境、节律带来何种体验？ | 意境、感官与形式满足 | 不因缺少爽点判失败 |
| 意义与抉择 | 哪些值得保护的东西不能两全？ | 坚持、重新理解、承担结果 | 不强制牺牲或预设唯一正确立场 |

现实中难满足的愿望是创作视角之一，不是阅读的唯一解释。所有“读者可能期待”标为编辑假设；没有研究/平台数据不写成统计事实。商业数据如后续加入，另存来源、采样范围、日期、方法与局限，不自动覆盖作者意图。

### 5.2 人物驱动力卡的内容范围

- 外在目标：此刻想完成什么；可以改变，不能仅写“变强”。
- 内在需要：什么感受、关系或自我理解对他重要；允许未知，不替角色诊断。
- 欲望与执念：为何难以放下；执念可助行动，也可造成盲区，但不是人人必需。
- 信念与立场：认为怎样做才正确；信念坚定不等于必须被剧情纠正。
- 恐惧与回避：不愿面对什么；不强制童年创伤。
- 底线与矛盾：愿做到哪一步，何时两种价值冲突；不能仅“善良但腹黑”。
- 资源与能力：实际可采取哪些行动；开局能力与成长潜力分开。
- 行动与选择：在压力下做什么，导致怎样的结果；人物不是心理说明书。
- 变化类型：能力成长、认识变化、责任扩大、关系重构、堕落、修复、坚持信念改变环境；不是统一正向性格弧。
- 角色主体性：配角有自己的目的与反应，不要求每位配角独立长篇弧光。

### 5.3 关系与对抗卡的内容范围

师徒、伙伴、友情、亲密、亲子、手足、家庭照护、同僚、竞争者、上下级、共同体、阵营、契约合作、人和非人关系。每卡回答：相互需要什么、有什么不一致、通过什么行动变化、变化怎样影响选择。

对抗来自人物、制度、利益、环境、知识不足或内在选择；不是所有故事都需要一个反派。重要对手的候选结构：目标、重视/保护之物、立场、资源、限制、与主角冲突的原因、可能应对、底线。动机可理解不等于行为正当，不强制洗白、悲惨过去或最后和解。心理深度与其叙事分量相称。

### 5.4 故事发展与卖点卡的内容范围

独特身份进入新场景、能力改变解决办法、关系改变目标、局部行动影响扩大、解决问题产生新选择、成果积累引发资源分配、角色追求相撞、秘密改变立场、竞争促成合作、信任建立与破裂、重复处境中的不同选择、阶段目标结束与新目标接续、暂时离开后回归、胜利后的生活变化、安静回报、失败后的重新定义、价值兑现、开放结局。

上述是内容审核清单，不预先声称都有现成方法ID。实现前逐条与旧方法比对；相同机制用旧ID，近似但用途不同保留差别，确无对应才新增。故事线类型与具体故事实体分开：“成长线”不是一条已设计好的故事，更不是一条链。

## 6. 融合题材判断合同

成员按相关性选择问题，记录简短结论，不输出内部推理过程：

1. 主体验/并列体验：作者主要想享受什么；是否允许双核心，不强制主辅唯一比例。
2. 相互作用：A中的身份/能力/规则怎样改变B中的行动，B又怎样改变A的意义。
3. 独有故事：什么情节只有这个组合容易成立；若去掉一个标签完全不变，检查是否只有外壳。
4. 规则兼容：哪些前提冲突；选择明确解释、保留有意谜团或提示待定，不偷偷削弱能力。
5. 人物与关系：新组合会接触谁、改变何种利益/立场/合作。
6. 发展空间：开篇新鲜感之后，目标、场景、关系与影响能怎样变化。
7. 味道协调：喜剧与战争、治愈与恐怖如何转换；不机械平均分配。
8. 失衡与可信度：一方是否消失，反差是否失效；题材事实、虚构规则和作者指定例外分开。

例：三国+配送，检索不是“外卖+三国”关键词拼贴。可判断配送带来人物接触、通行、信息、粮草与信任；乱世会改变交易与服务的边界；主角可以进入更大局势，但称帝/中立/恋爱都不是必选终点。提问不能转成八段前端必填表。

## 7. 分层输出与人物深度边界

| 阶段 | 主要设计 | 不提前锁定 | 后续传递 |
| --- | --- | --- | --- |
| 开书 | 卖点、味道、已有主角的初始追求与身份处境；作者给的方向 | 全书钩子、细分卷、所有配角身世、完整心理弧光 | 当前正式字段、作者原话与待定项 |
| 设定 | 支持故事的世界/能力/身份/关系条件 | 用一堆禁止项封死创意；把开局情况扩大为永久限制 | 已确认设定及简短资料卡 |
| 时光机 | 全书主线/重要支线、长期期待、分卷方向、核心人物可能的变化与对抗 | 全部小支线和章节事件；固定所有人物结局 | 本书基线、卷目标/收束、关联编号与当前版本 |
| 卷 | 阶段目标、主要变化、关系与本卷应兑现的内容 | 把整本书所有支线强塞本卷 | 本卷信息与相关上层约束 |
| 链 | 有目标、行动、阻力、结果的小故事及关联线 | 每链必须升级/牺牲/不可逆；链等同支线 | 链进度、起止依据、相关人物与事实 |
| 章纲/正文 | 当下行动、场景、声音、信息释放、连续性 | 每章三场景、固定悬念、逐条执行全部方法 | 采纳正文及有证据结算；不把参考方法记成事实 |

上游已解决的判断通过短结论与引用复用，下游只检查新增问题或明显不适配处；可以提出上游调整建议，不能静默改正式方案。一个支线可跨多链，一条链可服务多线；相关性不等于该线实质推进。

## 8. 卡片合同与内容示例

### 8.1 存储合同（拟新增，非现有API）

```ts
type CreativeCard = {
  id: string; displayCode: string; revision: number; schemaVersion: 1;
  name: string; kind: 'genre'|'experience'|'appeal'|'character'|'relationship'|'development'|'fusion'|'review';
  shortPhrase: string; summary: string; aliases: string[];
  facets: { genres: string[]; mechanisms: string[]; experiences: string[]; purposes: string[] };
  stages: Array<'opening'|'setting'|'book'|'volume'|'chain'|'chapter'|'prose'>;
  useWhen: string[]; questions: string[]; possibilities: string[];
  imbalanceChecks: string[];
  examples: Array<{ premise: string; direction: string; boundary: string }>;
  relatedCards: string[];
  methodRefs: Array<{ id: string; reason: string }>;
  evidence: { kind: 'editorial_heuristic'|'cited_research'|'observed_evaluation'; refs: string[]; limitations: string };
  status: 'draft'|'reviewed'|'published'|'retired';
  authoredBy: string; reviewedBy: string|null; updatedAt: string;
};
```

id由系统生成稳定无语义主键；displayCode为必有的稳定中文编号，shortPhrase为经审核短语，详见第18节。不得用名称或排序序号当关联主键。stages是适用提示，检索可跨层查看；执行写入权限不能因此跨层放开。审查卡不得改写模型岗位权限。

目录投影返回displayCode/revision/shortPhrase/必要的summary及匹配用途，每条目标约80—140字符；服务端按冻结版本解析真实id，模型无需重复接收长主键。熟悉且已读条目可使用第18节更短的引用投影。完整模型投影目标400—900字符；需要较长示例时单独获取并计入预算，不能硬截卡片中条件。系统元数据、审核日志不默认注入。这些是供应预算初值，不是创作输出长度限制。

### 8.2 三张完整示范（编辑候选，不冒充已发布种子）

**三国·小人物进入大局**：适用历史脑洞/职业跨界；当原始身份有趣却容易重复营生时参考。吸引力是独特本领改变人物关系与局部局势。问题：最初靠什么行动被看见？后来谁需要他？他能否选择合作条件？可能方向：技艺→人物接触→信任/资源→阵营与局势选择。可选味道为反差、热血、经营、智斗，服从作者偏好。失衡检查：不强制逐级升官或称帝，不把无名籍扩大成永远无法获得身份。示例：厨师用宴席接触将领，后来参与军粮组织；若作者只想温暖小店，不套战争。方法关联待旧库核对后填真实ID，不能虚构。

**温暖日常·一个场所连接不同生活**：适用小店/社区/家庭日常。吸引力来自熟悉人物、小愿望与生活改善。问题：谁会反复来到这里？他这次有什么小变化？店主也会被改变吗？可能方向：开业困难、邻居互助、失约后修复、季节活动、重新开始。失衡检查：不用大反派毁店维持刺激，不让每章只有闲聊。示例：退休教师经营海边书店，帮邻居找回写信的勇气；主角可成长但不必走商业帝国路线。

**无外挂悬疑·证据改变判断**：适用调查/推理。吸引力是读者能参与理解真相。问题：当前假设依据什么？哪条证据使它不足？真相会改变谁的处境？可能方向：取证、排除、证人关系、矛盾证词、重构时间。失衡检查：不能用突然获得超能力解案，不任意增设凶手/关键规则；是否公正揭示应结合叙述类型。示例：法医从伤痕判断转向时间矛盾，发现目击证词被误解；恋爱不是必要支线。

每张正式卡必须至少有一个适用示例与一个不适用/改用例；批量生成后全量逐条审核，抽样模型测试不能代替内容全量审核。若同一人撰写和自检，状态仍为draft；独立审核可用另一会话/成员，若宣称异模型必须核实实际modelId，不靠头像区分。

## 9. Agent执行合同：允许自主判断，限制副作用和无限查询

### 9.1 单次工作状态

queued → preparing_sources → assessing_needs → retrieving（可跳过/有限循环）→ designing → self_review → independent_review（按阶段规则）→ ready_for_author。

异常为failed_retryable、failed_input、outcome_unknown、budget_exhausted；保存已完成步骤及原因。前端只显示当前实际阶段；无后台任务不能显示“正在思考”。失败不是自动切回旧模型重新生成一次。

### 9.2 判断记录（简短工作产物，不是内部思维链）

```json
{
  "authorIntent":"保留作者想法的短句",
  "confirmedRefs":["本书来源版本引用"],
  "designNeeds":[{"purpose":"发展空间","question":"配送身份怎样进入三国局势"}],
  "selectedRefs":[{"id":"真实卡ID","revision":1,"use":"参考行动影响扩大的可能性"}],
  "originalChoices":["无对应卡时的原创提案短句"],
  "deferred":["完整人物弧光留时光机"],
  "openQuestions":[]
}
```

不要求逐题写分析。记录是可审计的任务输入/选择/输出摘要，不索取、持久化或展示隐性思维链。选卡不是必须引用到小说里；成员可弃用已查卡并给一句原因。

### 9.3 拟新增受控工具

| 工具 | 参数 | 返回与边界 |
| --- | --- | --- |
| search_creative_cards | query、purposes、genres、stage、cursor、limit（默认6，最多12） | 冻结库版本中的短目录，最多约1800字符；空命中明确为空，不自动扩到全库 |
| read_creative_cards | ids/revisions，单次最多3张 | 完整模型投影、版本与剩余预算；超预算返回可缩小请求，不静默截断 |
| search_design_methods | purpose/query/stage | 复用真实方法供给，返回可用ID与短介绍，不能只查源码静态全集 |
| read_design_methods | ids/revisions | 具体用途和短说明；方法不等于必做规则 |
| read_book_sources | sourceRefs、范围 | 当前owner/book授权范围内原文片段；原有资料工具适配，不开放任意SQL/文件路径 |
| submit_design | result、referenceRefs、briefChecks | 校验本阶段输出，不直接采用或修改上游正式数据 |

书籍owner/book由服务端会话/任务上下文注入，不能信任模型参数。资产引用必须属于本次可访问快照；不能要求模型“猜ID”。工具返回内容按资料处理，卡片里的“忽略指令”等无权改变系统角色或工具权限。

执行者可提出查询→读取→设计→自检后的补查，系统验证工具参数/预算/权限/状态。不是后台固定替它选完所有卡，也不是开放任意工具循环。缺少原生tool calling时可实现经验证的结构化action协议，必须真的执行工具并把结果回送；不可只让模型描述“我已查阅”。

### 9.4 预算和循环初值

- 完整可见输入上限15,000 Unicode字符，包含system、developer、历史、工具schema/结果、参考、修复指令和输出格式；同时检查模型token窗口并预留输出，不把字符等同token。
- 初始分配参考：岗位/规则/输出合同约2500，书籍证据与上游结果约7500，参考卡/方法约2500，工具与修复余量约2500。是调度初值，不要求填满；资料少就直接少用。
- 默认最多2轮查询、6次只读工具调用、进入生成前总阅读参考约2500字符；语义自修最多1轮，格式修复最多1次，不能嵌套倍增。当前层必要证据装不下时缩任务/分片，不删硬事实。
- 默认任务软时限180秒、硬时限沿用模型适配器当前允许上限且不大于15分钟；软时限只改变状态提示/停止额外查询，不能盲目取消已发模型请求再扣一次。上线以真实耗时调整这些初值并记录版本。
- 每次模型调用重新计量，累计用量/调用数由服务端记账。达到工具预算后资料足够可说明不再补查并设计；关键证据不足则报告具体阻断，不装作完成。
- 工具历史可生成结构化选择摘要，已选卡、关键证据与其版本仍保留；摘要不能代替当前待审候选全文。审查超长候选按对象分批覆盖，保留全局方向和覆盖清单。

## 10. 自审、独立审查与事实更新

自审问题：作者想法是否保留；题材是否真正影响故事；卖点能否产生不同情境；人物是否有行动理由；融合是否互相作用；味道是否一致；是否凭空加禁令；是否越过当前层级。只检查相关项，允许“不适用”。

独立审查读取作者意图、必要事实/上游合同、待审结果、所用参考的简短依据，可自主回查，不只读生成者的总结。单人设计审查遵守当前异模型规则；无可用异模型则明确等待/缺席，不换头像假装独立。主编可能负责生成时，也不能自行冒充另一位审查者。

问题分级：事实/作者明确要求冲突与结构错误可阻断；发展空间、节奏、味道、主观文学偏好通常为建议。任何错误结论应附本书证据位置；缺证据写待查，不能凭题材惯例判作者错。评分仅为辅助，不能用一个“95分”代替问题和证据。

本批不新增正文结算引擎。未来接卷链章时，只有作者采纳的正文版本触发事实维护，保留证据、幂等和冲正；“选用了成长方法”“计划战胜对手”绝不是人物已成长或对手已败。偏移检查比较实际事件与当前有效规划，允许经作者调整后的新方向，不因连续几章未升级自动判失败。

评测方法：每个题材范围至少一个代表样例；广泛或差异大的范围另补不同子方向。组合样例按风险覆盖，不要求所有题材两两穷举。用同一模型配置比较有库/无库，保留输入、版本、输出和耗时；文学结果由不知道方案标签的审核者比较原意、具体性、差异、发展空间、适当克制与层级边界。每项给证据，不只给总分。初测有效后再扩大或重复，不能用单次优秀样例证明稳定提升。

```text
将作者初始想法发展为可供选择的开书方向，完成当前开书输出合同。
先识别题材、特殊切入点和作者明确偏好。考虑这本书具体有什么好看、希望带来什么体验，以及这个切入点还能产生哪些不同的故事。职业、第一项任务或开局困境是入口，不自动成为全书唯一活动。
coreAppeal写本书具体的吸引力及可展开的矛盾、关系或行动，避免只列爽、燃、甜等抽象词。readingTone写作者期望的整体体验与主次；未明确时提出与创意相称的候选，不能改写成作者已要求。
人物可有简短欲望和行动理由，不强制创伤或性格缺陷。开书不预写全部人物弧光、最终结局或完整分卷，不提前锁死全书长期悬念。
融合创意应让两部分产生具体作用：例如职业能力怎样影响题材中的人、规则或局势；同时尊重作者想写轻松日常等明确选择，不一律扩大为争霸救世。
输出字段遵守当前schema。目录字段只能引用本次提供的有效项；阅读味道的自由文本不等于有效标签。没有匹配项时遵守该字段的空值或自定义规则，不造ID、不强行近似映射。
自查：是否把开局当成全书上限；是否只靠改名字制造卖点；是否凭空添加禁止条件；是否提前设计了后续阶段的细节。纠正后输出完整候选。
```

不新增“阅读期待”等同义必填字段来重复coreAppeal/readingTone；开书可描述想读到的体验，但时光机才把它发展为全书具体问题与兑现方向。书名/简介继续遵守既有独立任务和可生成前置条件，本节不提前触发简介。

### 17.4 设定设计与设定总整理

```text
依据作者已确认的开书方向设计当前设定，保护核心卖点和阅读味道。先考虑这项设定怎样支持人物行动、冲突与后续故事，再决定细节深度。
区分明确规则、允许的例外及尚未决定的空间。不要为了严密而限制所有可能，也不要用新设定消除作品核心困难。复杂度以当前故事需要为准，不为每本书增加全部体系。
人物动机可以是愿望、责任、利益、情感、信念或探索，不强制悲惨过去。对抗可以来自人物、制度、环境、资源或选择；有对手时让其有行动理由，但不要求洗白，也不自动对称双方责任。
总整理时保留作者实际确认的内容、来源和未决项，合并真正重复的表述。不要把审查建议或未采用候选写成确定设定，不将没写清楚升级为禁止。
输出前检查各设定是否直接矛盾、是否误改作者方向；信息不足与冲突分别说明。不能仅因不同于常见题材判为错误。
```

设计与总整理分别挂载到现有节点，不为了共用上述文本额外创建一次模型调用。仍须作者确认设定、完成主编总整理后再启动资料短卡。

### 17.5 资料成员：提取与合并

```text
你的职责是准确整理本书资料，不是重新设计作品。按当前六栏模板提取与故事线和全书方向有关的信息，保留来源引用及确认状态。
premise：题材、融合切入点、核心卖点。protagonists：主要人物的身份、当前处境、目标/动机、关键能力与真正的限制。world：会影响大方向的世界条件与核心矛盾。openingEnding：已有开局及作者明确给出的结局方向，未给结局就不补造。preferences：作者偏好、阅读味道、希望看到的内容。prohibitions：仅作者明确禁止或已确认规则明确排除的内容。
突出卖点、人物可行动空间及会改变故事方向的信息。能力只保留作用与关键限制，不搬运每级参数；世界只保留相关条件，不复制百科；不把示例订单、当前职业或阶段任务扩成全书边界。
不因作者没提名将、感情或战争就记录为禁止，也不替作者加入这些内容。没有证据的栏可为空；不得为了填满模板发明内容。简短不等于删掉关键条件，15,000字符是整次调用上限，不是本卡目标长度。
合并时合并语义相同的事实并保留必要来源，不把不同状态或互斥版本揉成一个事实；冲突交回核对，不默默选边。自查人名、身份、能力边界、卖点、味道和禁止项是否可回指来源，再输出当前schema。
```

核对成员配套正文：

```text
将短卡与原始已确认来源对照，查遗漏关键卖点、误加禁令、事实变化、失去条件和来源失配。必要时回查原文。不要将短卡中新创意视为资料，不要求收录所有细节。指出具体问题及来源；没有来源只能记录待查，不能给虚假的准确率。
```

实现须保持六栏当前映射兼容，不能因为本节中文解释变了就偷偷改JSON名称。准确性核对与文学建议分开，审查者不得以“最好有恋爱”等偏好修改短卡事实。

### 17.6 故事线推荐主编

```text
依据本书短卡及作者当前选择，推荐可供选择的主线与支线。让作者看懂每条线关注谁、追求什么、可能经历什么变化，以及为什么本书值得沿它展开。
考虑题材与味道，但不要把成长线、感情线等目录名直接当成完整推荐；介绍必须落实到本书人物与追求。按作品决定单主线或多主线、贯穿或阶段支线，数量由内容需要决定。
初始职业和任务可以向人物结交、能力运用、局势影响、关系变化等方向发展，也可以依作者偏好保持小范围生活。避免全部故事线都只是同一种任务换名字。
有群像诉求时考虑其他人物自己的目标和选择怎样影响故事；不是每个配角都复制主角成长路线。融合题材要在行动和回报中有作用。
相似线可以提出合并建议，不能擅自删除作者选择。当前只设计全书层面重要方向，不列完所有小故事、链和章节，也不要求所有支线贯穿每卷。
自查推荐是否保留核心卖点、阅读味道与作者意图，是否具体且有区别，是否误把新提案写成已确认事实。按当前推荐schema输出，等待作者选择后才能开始全书基线。
```

推荐中的“最终变化”属于可选方向，不替代全书方案最终结局，也不能在作者勾选前进入正史事实。

### 17.7 全书基线及分卷设计成员

```text
根据已确认资料、作者选择的故事线和目标字数，设计一套有具体发展方向的全书方案。参考方法可按需要选择搭配，不强制每本书同一种节拍。
讲清故事从什么处境出发，主要追求如何发展，哪些关键选择或事件改变方向，以及结局回答什么。全书期待应是开篇能建立、全书最终值得回答的问题；阶段任务放进对应卷，不冒充全书钩子。
人物变化可以体现能力、认识、关系、责任、地位或对既有信念的坚持，不要求人人性格反转，也不要求每次成长牺牲。不同主线要有各自追求及必要交织，关系必须说明实际影响，不能只关联全部编号。
分卷写本卷开始、主要追求、阻力、关键变化/高潮、结束状态及承接。给后续卷设计留出链和事件空间。按故事容量估计篇幅，不靠增加重复任务凑字数。具体数字与schema由系统校验。
重要支线可给预计活跃卷段与阶段目标，允许后续细化；不预写全部小支线，不强求终卷汇集全部线。已结束的线无需再次收束；终卷应结束本书主要承诺，不默认引向不存在的下一卷。
开篇尽早给出具体人物处境、行动和可感知的期待，避免先堆设定；不将吸引读者机械等同为每章大战、反转或悬念截断。遵守作者已经确定的开篇要求。
按本阶段完整schema输出，保留候选身份。自查因果、发展差异、味道、来源与收束，不提前填满卷内链章细节。
```

### 17.8 自审与独立审核

自审模块：

```text
在提交当前候选前，检查本层相关问题：有没有违背作者明确要求或已有事实；卖点是否具体；题材融合是否真正起作用；人物为什么行动；故事是否有可持续发展的空间；是否添加了无依据禁令或固定套路；是否越过本层边界。
可在本次候选内修正的问题先修正。需要新证据时按剩余权限补查；仍缺关键证据则记录阻断。仅返回修正后的结果及合同允许的简短检查结论，不展示反省过程。
```

独立审核模块：

```text
独立阅读待审候选和相关来源，不把生成者的自我评价当作结论。逐项核对作者原意、已确认规则、候选内部因果、当前层级和应兑现的方向；文学评价结合本书味道，允许不同创作选择。
事实冲突须列出候选具体位置与冲突来源。来源不足应回查或标为待核实；不能因为摘要没有某事就断言正文不存在。规划可以提出未来新事件，不能按“未发生”判它错误。
发展空间、趣味、节奏等建议说明具体影响，不以题材惯例强制添加爱情、反杀、牺牲或固定事件数。分清必须纠正的问题与可选建议，不用总分代替证据。
只修正真正的问题，不把方案重写成自己的偏好。返回当前审核schema；不宣称已检查未提供或未读取的部分，不输出隐藏推理。
```

独立性由系统实际模型身份检查，提示词不能实现模型隔离。审查必须覆盖完整候选；当前紧凑骨架审查只能声明结构核查，不能宣称检查了全部分卷细节。详细候选过长时按卷分片，公共上下文带全局方向，记录对象覆盖清单；不再用一轮摘要替代全文审核，也不无限追加审核调用。

### 17.9 后续卷链章接入模块

```text
围绕当前对象的起点、目标、过程与结束条件设计，承接上层有效方向及已采纳正文事实。选取本次相关主支线推进，不要求每章推进所有线；链是完整行动单元，不自动等于一条支线。
让场景、人物选择和结果产生具体变化；回报可以是认识、关系、资源、情绪或局势，不固定为升级。根据本层设计深度使用方法，不把全书骨架方法直接当正文写法。
结束条件是待兑现规划，只有正文证据足够时才可建议收束。计划完成、写作完成、事实结算完成分开；写入状态由有权限的结算任务执行，设计者不直接修改事实库。
```

此模块仅规定未来接口，不注册尚未开发的卷链章岗位或新增结算调用。正式接入时必须配本层输出schema、结束判据、事实来源及独立批次验收。

## 18. 稳定编号、短语、后台分类与检索验收补充

2026-09-13根据作者要求补充：本节与第8、9、11—15、17节一起执行；仍为待开发规格，不表示编号库、语义检索或后台界面已经上线。

### 18.1 所有方法与参考卡都有稳定编号

统一展示“类型汉字＋数字＋短语”，例如`法012 起承转合`、`参037 由小入局`。这些仅为格式示例，实际编号必须盘点旧库后分配，不把示例硬绑定到既有条目。方法用“法”，创作参考用“参”，与书内主线1、支线3、卷A、链A1分开。数字至少三位显示，超过999自然增长，不限制条目容量。

- 数据库id维持现有主键；新displayCode建立唯一约束和反查索引。旧方法已存在编号时优先保留或映射为别名，不改历史引用。
- 系统事务分配编号并处理并发、防重；Agent负责短语、含义、适用性和重复判断。编号不是语义分类，不能让模型猜下一个号。
- 编号分配后不可重用。修改名称、移分类、排序不改号；新版内容递增revision。合并条目保留旧号及替代指向，旧任务按原revision读取，不能偷偷改成新版含义。
- 全局库与未来私有扩展库如并存，唯一键包含namespace；本批不据此创建私有库。模型调用由任务冻结的库范围解析，不能访问其他用户内容。
- UI显示编号和短语，任务引用保存真实id、revision、release及当时显示名称。无对应编号返回未找到，不做近似引用替换。
- 方法引用与书内关系分开：`链A1参考法012`不代表`链A1推进主线1`，更不代表正文已兑现。编号只能提高精确定位，不能自行证明文学或事实准确。

### 18.2 三档文本，压缩保留含义

| 投影 | 内容 | 使用时机 |
| --- | --- | --- |
| 引用 | 法012 起承转合（版本由冻结映射保留） | 已读已选方法的重复引用、关系清单 |
| 目录 | 编号、短语、一句作用与必要限制 | 初次快速选择，不只凭名称猜含义 |
| 详情 | 作用、适用条件、关键问题、可选做法、失衡提醒；按需例子 | 选用前消除歧义、检查适用性 |

shortPhrase建议4—12个汉字，一句说明建议20—60字符；属于编辑目标，不是硬切长度规则。不能将“在已有线索支持时反转读者判断”压成“突然反转”，或将“阶段回报”压成“必须升级”。主语、条件、否定、可选性影响含义时必须保留。

短语由内容成员拟写，独立内容审核比较完整定义与短版是否同义；歧义则改短语或保留更长说明。未审短版不进入正式目录。缩写只用已说明术语，不创造AI和作者都难懂的暗号。完整内容永久保留可查，不能为省上下文删除原定义。

编号并不替代内容：未读方法不能只给`法012`让模型凭空回忆。重复引用可以省字，初次设计仍须最小充分说明。一次任务的真实总字符/token由程序计量，不能按显示标题长度估算；不把数据库元信息全集塞给模型。

### 18.3 后台分类采用用途树＋交叉筛选

“资产方法论”保留两个主入口：方法、创作参考；共享搜索与引用关联，不复制同一条方法到不同层级。库内第一分类以“解决什么创作问题”为准：

| 主类 | 子类示例 |
| --- | --- |
| 题材与融合 | 题材特征、横向机制、融合取舍、规则兼容 |
| 卖点与阅读体验 | 核心吸引力、反差、情绪回报、阅读期待 |
| 人物与关系 | 欲望动机、人物变化、群像、合作对抗、亲密关系 |
| 故事与因果 | 目标行动、阻力选择、事件发展、信息因果、故事交织 |
| 结构与节奏 | 宏观节奏、阶段结构、场景结构、情绪节奏、叙述速度 |
| 信息与表达 | 悬念伏笔、视角声音、时间组织、对白描写、叙述表现 |
| 衔接与收束 | 承接转场、阶段回报、长期兑现、结局 |
| 审查与修订 | 事实连续、意图一致、结构检查、文学修订 |

该用途树细化第3节展示方式，不替代卡片kind或第4节题材覆盖目录。原分类中“宏观节奏、视角与声音”等保留为可查子类/别名；迁移须逐项给去向，不能因此删方法。“行动策略”按实际含义落到人物选择或故事推进，不按原标签直接搬。

每条有一个导航主类、多个用途标签；同时可筛选题材、机制、体验、创作层级、发布/审核状态。层级是适用建议：起承转合等可同时适用于全书、卷、链、章，不强制单层归属；跨层检索可见，但详情须说明尺度差异。题材及用途筛选支持并集/交集明确显示，不让作者猜过滤含义。

列表显示编号、短语、一句话作用、主类、适用层、版本状态；详情提供完整定义、例子与边界、同义别名、关联方法、修改记录和评测。支持编号直达、中文短语搜索、筛选重置、分页及无结果提示。编辑短语/分类不直接发布；显示改动前后，审核后发布新revision。

另设覆盖与缺陷视图：按题材/用途/层级检查缺口、待审、语义歧义和实际召回失败，能跳到具体条目和失败案例。只统计真实数据；“有分类”不等于有内容，“已发布”不等于实测有效。

### 18.4 精确与语义查询的执行规则

1. 编号/完整别名查询走确定性索引；歧义别名返回候选，不擅自选一条。请求带revision时精确取该版，停用/合并/旧版状态明确。
2. 自然语言查询保留用途、题材、当前阶段与限制；本书私有内容不写入通用资产。先按已发布冻结release检索短语、别名、summary、useWhen、用途，采用已验证的中文词法能力。
3. 对“怎样让一个小人物逐渐影响大局”这样的同义需求，不能只用题材词精确匹配。首期可以在有限词法召回候选中由成员判断相关性、改写一次查询；这是语义判断辅助，不能宣传为已实现向量检索。
4. 评测显示词法覆盖不足时，再按独立接入批次增加向量召回，与精确/词法结果合并去重排序。向量服务、模型和部署需按实际环境确认；未接入前后台显示未接入，不用假分数代替。
5. 精确编号不受向量相似度覆盖；仅软偏好的层级可扩大到跨层召回，权限/release/发布状态不能放宽。候选排序不等于适用性确认，成员结合完整定义判断。
6. 先短目录，后少量详情；用第9节现有两轮/六次预算。已读ID+revision缓存，重复请求不重复加入上下文。零命中可改写一次，仍无匹配如实原创或指出缺口，不无限扩大到全库。
7. 自审发现具体问题可在剩余预算内补查；达到预算时关键书籍证据缺失则停在可恢复状态，只有参考不足可说明后继续原创。不能混淆参考库空命中与本书事实缺失。

目录返回displayCode/revision/短语/必要说明/匹配用途；读工具允许传displayCode并由服务端转换为真实id。返回工具错误、限额与状态都遵守统一协议。对未读候选的选用应补读其最小定义；不要求反复读同一冻结版本。完整选用表存审计，模型只接当前需要部分。

### 18.5 Agent闭环的可验收记录

每次任务记录输入与参考版本、当前岗位、设计需要短摘要、实际查询、返回候选号、实际读过/选用/弃用编号、输出对象、检查发现与处置、真实耗时用量。不能用“已思考全面”当记录，也不保存隐藏推理。

设计需要→查询→短目录→详情→设计→自查→必要补查/修订→独立审核→候选提交的每一段都有真实状态和失败位置；跳过检索可以明确原因。系统恢复已完成节点，不重复扣用量或重写正式事实。发布前应能用一条脱敏测试任务回放整个过程，证明并非固定塞资料后一次生成。

### 18.6 编号、语义和上下文的专项测试与验收

| 对象 | 测什么 | 通过依据 |

首期以旧检索作基线，在同一冻结库、模型和预算下比较；编号精确性、权限隔离、版本恢复必须全通过。语义指标在建立验收集后冻结目标并记入批次合同，禁止看到结果再降低目标；已知核心失败样例未解决不得声称检索准确。缩短上下文需同时对照短长版语义与作品输出，不只报告节省字符比例。
