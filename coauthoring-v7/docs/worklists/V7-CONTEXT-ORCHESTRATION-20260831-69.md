# V7 资料策划、方法检索与分层上下文编排

任务编号：V7-CONTEXT-ORCHESTRATION-20260831-69

本次唯一清单：`coauthoring-v7/docs/worklists/V7-CONTEXT-ORCHESTRATION-20260831-69.md`

任务类型：核心创作工作流重构、Agent 语义检索、ContextCompiler 权威来源、作者端与后台最小纵向闭环

当前问题：V7 已有方法资产、题材融合档案、任务合同、ContextPack 与审计表，但不同创作层级仍存在固定方法包、全量设定注入、字符/Token 估算不一致和默认路径绕过语义资料策划的问题。模型可能收到过多无关资料，也可能拿不到准确方法、任务期题材人设和当前活动版本；作者看不到本环节为何这样设计，后台也不能统一追踪最终资料包的来源、预算与采用理由。

复现步骤：

1. 追踪全书、卷、链、章纲、正文和审查调用，比较最终模型请求与 `v7_context_pack_traces`、方法检索记录、题材档案。
2. 检查默认全书规划是否经过语义资料策划，检查下层任务是否使用固定通用方法包或把全部设定无差别注入。
3. 比较各模型网关和 ContextPack 的字符、Token、超时与输出上限算法。
4. 在作者端查看当前方案说明、加入想法和重新设计入口；在后台查看资料包、方法、人设、来源版本和最终长度。

期望结果：每个创作任务先由资料策划 Agent 基于当前书、当前层级、活动版本和作者补充意见，从结构化候选中语义选择最小充分资料与方法，并生成只属于“本书＋本任务”的题材融合执行人设；系统负责权限、候选召回、版本、预算、裁剪、校验、存储和审计。模型既可采用或组合后台资产，也可基于任务自行设计，不被固定模板锁死。作者只看到大白话设计逻辑并可原位补充想法后重新设计，后台可追踪最终输入但不展示思维链。

允许修改：V7 共享任务合同、上下文编译和追踪；规划、创作、人物或设定中直接装配资料包的方法；现有方法候选召回与模型选择接口；任务期题材融合人设；相关 API；作者端现有规划/创作页面的最小说明和原位重新设计交互；独立后台现有上下文/提示治理页面；直接相关测试和当前交接文档。

明确不改：会员开通、用户管理、模型套餐编辑、通用任务详情中心、全局导航与视觉重设计、三席审查并行、生产作者数据、已合并迁移、历史任务状态、模型供应商密钥与套餐采购。若现有 102 个迁移和 JSON 审计字段足以承载本批，不新增迁移；不得改写任何已合并迁移。

必须保留：作者确认内容、作者原话、不可变正文和实际结算的权威性；`owner_id + book_id` 隔离；146 项方法、156 项情节模式、36 项配方及其版本；书级题材融合档案；V7 通用成员身份和异模型治理；TaskContract、PromptManifest、用量记账、幂等与失败证据；现有 V7 页面主结构和无弹窗原则。

新功能验收：

- 全书、卷、链、章纲、正文和审查任务都使用同一资料策划输出合同；每层只接收当前任务所需的活动来源，不全量继承上层原文。
- 方法资产先按确定性范围和结构字段召回候选，再由 Agent 判断相关性、组合、改写或放弃；关键词、固定标签或分数不能直接决定最终采用方法。
- 通用方法可在全书、卷、链或章节任务重复成为候选，但 Agent 必须根据当前任务给出不同的白话责任和使用方式；不得随机抽取。
- 资料策划 Agent 可以输出 `采用资产 / 组合改写 / 自主设计`，并保留开放创作区；后台资产不是强制模板。
- 执行人设由当前书籍题材融合档案、作者意图和当前任务动态生成，不绑定成员、岗位或个人专业人设，不持久化为成员偏好。
- 硬事实、作者必须项、当前任务与上一实际结果不得被静默截断；软参考按预算降级，超限时保存排除理由或停止并报告必要资料放不下。
- 作者端用大白话说明当前环节如何设计、采用了哪些方向和保留了哪些创意空间；作者可原位加入想法并重新设计，不弹窗、不暴露模型、哈希、内部字段或提示词。
- 后台能查看任务种类、资料包最终字符/估算 Token、来源类型与版本、方法采用方式、任务人设摘要、排除/裁剪原因、模型调用结果和失败摘要；不保存或展示思维链。

原功能回归：V7 开书、设定、全书规划、卷、链、章纲、正文、审查、定稿、人物与故事状态仍能读取当前活动版本；作者确认内容和不可变正文不被候选或摘要覆盖；模型治理、用量记账、失败记录、账号/书籍隔离和后台权限保持有效。

测试范围：受影响后端单元/集成测试，方法召回与 Agent 选择的有答案/无答案/通用方法跨层级样本，ContextPack 预算和权威来源测试，作者端与后台相关组件测试，六个 workspace 类型检查与构建，一次受控真实模型探针。因本批改变 ContextCompiler 权威来源和核心创作工作流结构，完成纵向闭环后运行 `npm run verify:full`；浏览器验证覆盖当前相关页面的手机优先与桌面视口。

部署要求：本批通过全部合同门禁、真实浏览器验证和差异审计后形成独立提交；默认按 API/Worker/静态同源发布，部署前所有当前 V7 可执行任务连续 30 秒为零并立即复核，不取消或改写作者任务；保留旧发布和数据库回滚点，线上验证健康、登录保护、核心页面和本批真实链路。

## 成员能力合同（待真实代码审计后冻结参数）

- 岗位目标：资料策划 Agent 为当前任务选择最小充分可信资料、方法策略和任务期题材融合执行人设；主编基于该结果协调任务并对作者结果负责。
- 可信输入：当前 owner/book、任务合同、活动正式版本、作者原话/本次补充、实际结算、题材融合档案、带版本的方法/情节模式/配方候选；禁止其他书、旧候选、失败草稿和无来源推断。
- 工具与权限：只读结构化来源注册、当前书活动版本、方法候选召回和预算统计；不能写正文或正式事实，不能读取密钥、其他 owner/book 或思维链。
- 模型与参数：复用 V7 当前模型治理；语义策划使用结构化规划能力，温度、最大输入/输出和时限按真实探针冻结，不采用全岗位统一值。
- 输出结构：选择来源、排除来源、方法策略、白话任务责任、任务人设摘要、开放创作区、缺失/冲突、预算分配和来源版本；输出必须通过 JSON/长度/版本校验。
- 作者可见反馈：一句大白话状态＋设计说明；失败时先说“抱歉，这次没有完成”，再说明保留结果和可执行恢复动作。
- 幂等恢复：同一任务、来源版本和作者补充复用成功结果；来源或作者补充变化使旧候选失效后重编译；结果未知先核对调用记录，不盲目重发。
- 后台审计：记录成员、模型快照、任务参数、来源版本、最终长度、采用/排除摘要、调用状态和错误摘要；不记录思维链。

## 设计审查 DR-V7-CONTEXT-ORCHESTRATION-69

### 第一轮：权威来源、数据与兼容

- 结论：通过。系统继续决定 `owner_id/book_id`、活动版本、required 正式来源、哈希、幂等、预算与落库；Agent 只决定相关性、任务责任、任务期题材身份和方法检索意图，不可写正式事实。
- 旧数据：保留 `v7-creation-context-v1` 外层兼容标识和全部旧 JSON；只提升 `CONTEXT_PROJECTION_VERSION`，使新任务不会误用缺少新字段的旧活动资料包。历史资料包仍可只读审计，不回填、不覆盖、不删除。
- 数据结构：102 个已合并迁移零修改，不新增迁移；新增字段只进入现有 `selection_json/content_json` 与 PromptManifest 内容快照。作者确认内容、正文和结算不变。
- 跨书与密钥：候选仍由当前 owner/book 仓储召回，解析器校验设定 sourceId 属于当前候选；PromptManifest 既有秘密扫描、范围校验和来源追踪继续生效。
- 回滚：本批为代码与 JSON 新写入语义，可回滚到上一个发布；旧程序忽略 JSON 多余字段。不存在数据库降级或作者数据恢复动作。

### 第二轮：调用、费用、失败恢复与预算

- 结论：通过，采用“一次资料策划 + 一次候选召回 + 原执行成员最终取舍”。同一 `taskKind/taskId/sourceFingerprint` 成功结果复用，三套方案共享同一资料包，不按席位重复调用资料策划。
- 调用变化：正常新任务固定增加一次已有套餐内的 `context_editor` 结构化调用；删除“只有超限才调用”的旁路。结果未知沿用原阻断与核对记录，确定失败按不同底模交接；不盲目重发。
- 输出限制：资料策划只输出结构化选择、2—6 条责任、任务身份和检索意图，最大输出从 4000 收紧为 3000；不输出故事方案或正文。方法候选由系统在 Agent 给出的范围/维度/查询内召回，不发全库。
- 输入限制：卷/链/章纲/正文/审校/结算的模型可见资料硬上限分别为 12000/8000/6000/6000/6000/6000 字符；required 正式源放不下时明确失败，不静默裁掉。正文、当前章纲等节点精确载荷仍按原调用合同单独传入，不在 ContextPack 重复。结算不注入叙事方法，6000 字符用于容纳确认链责任、当前章纲和必要实际状态。
- 费用边界：不新增供应商、密钥、套餐或批量探针；真实验收只做一个受控样本。最终以 PromptManifest 实际 input/output token 与现有用量记账核对。

### 受影响回归证据计划

- 新合同单元测试：资料策划 JSON 的有效/越层/跨书 sourceId/资产、组合、原创、无需方法四种模式；通用方法在卷/链/章节可重复召回但不随机。
