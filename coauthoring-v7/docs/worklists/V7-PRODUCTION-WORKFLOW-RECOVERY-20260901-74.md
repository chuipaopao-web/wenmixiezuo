# V7 生产开书与设定恢复稳定性（第74批）

任务编号：V7-PRODUCTION-WORKFLOW-RECOVERY-20260901-74

本次唯一清单：`coauthoring-v7/docs/worklists/V7-PRODUCTION-WORKFLOW-RECOVERY-20260901-74.md`

任务类型：生产故障复现、开书/设定任务恢复修复、受影响作者页面操作区统一、回归与生产部署

当前问题：生产作者反馈团队设计在保存或找回旧工作记录后卡死；返回首页仍无法重新开书，点击“新建书籍”出现白屏。进入设定后部分条目失败，重新设计会卡死。受影响页面的主操作分散在页面上方和下方，作者无法稳定判断下一步。

复现步骤：使用只读生产日志与任务审计确认真实失败状态；在隔离数据库注册测试作者，依次覆盖首次开书、保存后返回、废弃任务、重新开书、刷新、重复点击、开书完成进入设定、设定部分失败、失败条目重试、重新设计与再次刷新；同时检查受影响页面桌面和手机操作区。

期望结果：任何旧开书任务都不能永久阻塞新书入口；作者返回后可重新开书，页面不会白屏或无限停在“找回工作记录”。设定成功条目保留，失败条目明确结束且可定向重试，重复操作不重复下单。受影响页面的当前主操作位于内容末尾或稳定底部操作区。

允许修改：V7作者端开书、信息/设定、时光机、卷、链、章、资料库、任务和团队中与操作区及失败恢复直接相关的组件和样式；当前API/Worker中的开书与设定任务状态、恢复、幂等、模型调用、会员可用算力投影和作者投影；后台问题中心改读V7任务审计；本批审计证明零有效V7引用的旧Canon、旧合同工作流、旧岗位模型重绑运行闭包及其纯旧测试；受影响测试、运行闭包证据、发布号、当前交接和本清单。

明确不改：不重做产品信息架构，不改变会员套餐、计费、账号或权限语义；可用算力只修正为“配额减去已消耗和执行中预占”，不改变扣量规则；不修改或删除已合并迁移，不清库、不删除历史表行或作者生产数据，不覆盖作者输入、成功方案、正式设定、正文或历史版本，不恢复V6页面、旧团队初始化、旧岗位人设或旧模型通道。

必须保留：`owner_id + book_id`隔离；作者已保存的开书输入和历史任务证据；设定已经成功的条目及其来源版本；未知模型结果不盲目重发；当前V7资料策划Agent、题材任务人设、最小ContextPack、任务审计、失败道歉与原位恢复；第73批生产版本和上一版V7回滚点。

新功能验收：

- 旧任务处于working、failed、abandoned、completed或损坏绑定时，新建书籍入口都能在有限时间内得出真实状态，不白屏、不无限加载。
- 作者返回首页后可再次进入开书；废弃历史资料只读保留，不重新占用新任务或当前路由。
- 开书创建请求具有明确幂等与冲突恢复；重复点击不重复扣量，冲突响应能在页面原位恢复。
- 设定批次部分失败时成功条目继续展示，失败条目进入真实失败状态并可定向重试；重新设计不会重发仍在working/unknown的调用。
- 受影响页面的主要操作位于内容阅读流末端或稳定底部，桌面与当前手机视口均可达；空、加载、完成、失败和恢复状态不出现按钮跳位或遮挡。
- 作者端只显示业务状态和恢复办法，不展示内部任务ID、模型协议、堆栈或旧版本词。

原功能回归：登录、2000字开书输入、作者资料保存、题材分类、开书资料确认、设定正式版本、时光机、卷/链/章、资料库、任务、团队、会员与反馈入口继续可用；作者正式数据与历史版本不变；模型调用仍使用当前冻结成员、岗位、供应商、模型和套餐。

测试范围：74A、74B、74C分别运行受影响组件/集成测试、对应TypeScript检查和作者端构建，并以隔离浏览器完成真实纵向场景。老板明确要求模拟作者检查整个工作流，本批同时修改核心开书/设定恢复状态和共享操作区，属于核心工作流结构性变化，因此部署前运行一次 `npm run verify:full`，并记录具体通过项。生产发布执行数据库备份、连续30秒零在途任务、逐服务切换和公网复核。

部署要求：各批验收完成后冻结同源提交并直接部署。生产不取消、暂停或改写作者任务；API/Worker切换前所有在途任务连续30秒为零，异常自动回滚第73批；部署后用真实浏览器检查开书入口、2000字上限、返回/重进、受影响操作区，并核对任务、服务与错误日志。

## 用户端三句话

1. 作者此刻要从一个想法稳定创建新书，再完成设定并进入后续创作。
2. 当前最妨碍完成的是历史开书任务把新入口锁死，以及设定失败没有可靠结束和恢复。
3. 页面现在只需要展示当前内容、真实状态、保留结果和位于底部的下一步操作；内部任务与模型细节留在后台。

## 最小交互合同

- 开书页唯一主任务是提交当前开书想法；“开始设计/继续/重新开始”按真实状态只出现一个主按钮，返回入口保留。
- 找回历史任务必须有限时完成；无法恢复时显示道歉、已保留内容和明确的“重新开始”，不能无限加载。
- 设定页保留已成功条目，失败条目就地显示“重新设计”；整页主操作在内容末尾，不在顶部复制同义按钮。
- 时光机、卷、链、章、资料库、任务和团队只调整合同内操作区位置，不借机改变页面职责或导航。
- 不新增弹窗；桌面与手机均采用自然阅读流末端或安全底部操作区，键盘和长错误不能遮挡按钮。

## 复用审计

已检查当前 `NewNovelPage`、`AuthorApp`、`TaskLogPage`、开书 API/服务/仓储和对应测试，并追溯 `3d37f2d`、`42c5ce1`、`25d9d38`、`3e18702` 的相关差异。继续复用现有服务端任务、候选、幂等键、只读历史和任务页显式恢复，不新增依赖或第二套恢复状态机。

74A 已定位的当前 V7 根因：

- `NewNovelPage` 会在没有显式任务编号时扫描最近 50 条服务端任务，导致“新建”被另一项历史待确认任务劫持；扫描完成前整页只显示找回文案。
- 本地草稿仍指向 `archived_by_author` 任务时，已放弃页面只返回首页、不清除本地引用；再次点击团队设计会恢复同一任务，形成永久循环。
- 恢复任务的 GET 失败后继续隐藏在纯加载页中，没有原位错误、手动重试或直接开始新书出口。
- 生产近 24 小时 37 项开书任务中有 25 项 `archived_by_author`，API/Caddy 无对应崩溃日志，且这些任务都是当前 V7 完整成员快照；故障属于当前作者端恢复闭环，不是 V6 服务或模型通道重新运行。

最小修正方向：只恢复显式任务链接或当前浏览器确实保存的任务；“新建书籍”清除当前本地任务指针但不删除服务端历史；已放弃任务自动释放新建入口；恢复请求失败必须结束加载并提供重试、重新填写和返回动作。

设定服务、操作区矩阵和零引用旧代码仍按后续批次继续审计。V6只用于确认零引用残留，不作为运行依赖或产品规格；本批不引入新第三方依赖。

74B 已定位的当前 V7 根因：

- 生产一个 14 项设定批次实际完成 7 项、失败 7 项；失败前 3 次分组模型调用均成功，失败条目没有模型调用记录。青铜会员当时已用 180,888/200,000 算力，下一组需预占约 34,000 算力，会员门禁在发送模型前正确拒绝。
- 设定服务把 `MEMBERSHIP_REQUIRED`、`MEMBERSHIP_EXPIRED`、`MEMBERSHIP_QUOTA_EXHAUSTED` 误当成成员能力失败，在不同成员之间反复离岗和交接，生产因此生成 39 条不真实成员事件。
- 会员门禁发生在模型调用记录建立前；旧重试只允许存在 `failed model_call` 的条目，所以这种明确未发送的安全失败永远无法恢复。
- 单项重新设计同步等待 1 至 3 个最长 15 分钟的模型调用；全部失败时直接抛错，没有关闭 synthetic batch，留下永久 `working` 状态。

最小修正方向：持久化批次级 `failure_code + failure_stage + retry_safety`，只有明确 `pre_dispatch + safe_after_precondition` 的前置条件失败可以在条件恢复后继续；unknown 仍禁止盲目重发。会员门禁不得产生成员离岗/交接，批次失败时原子保留已完成条目并只把未完成条目置为失败。重新设计无论成功、已知失败或结果未知都写入明确终态，并向作者投影真实、可执行的恢复文案。
