# 第123批：团队开书用量核心

状态：内部核心本地验收通过，生产仅同步后台路线；真实开书与完整计费尚未接通。用户要求继续推进，普通工程细化沿用自主授权与GPT-5.5编码、主代理审查分工。

## 目标与范围

为保留的团队开书接入独立PG后端补齐用量预留、结算、释放及未知结果保护。旧公开收费与算力口径（真实token×2）保持；当前页面、开书步骤、模型配置和会员价格不变。只增加rebuild内部业务服务与加法迁移，不公开发放权益/扣量HTTP接口，不导入生产账号/作品，不调用付费模型，不让模拟任务或成员目录冒充真实AI开书。

旧实现依据：apps/api/src/infrastructure/security/membership-service.ts、account-usage-service.ts及infrastructure/models/v7-opening-agent-model-gateway.ts。旧算力口径可复用；SQLite的查询后插入及未关联账号豁免不直接复制为PG并发/身份策略。新后端无真实会员迁移，内部权益快照必须有明确来源且不能由普通作者输入，更不能自动给测试权益冒充生产余额。

## 实施与数据边界

GPT-5.5先核对旧代码和依赖，确认最小内部合同后实现。用量同owner范围串行事务；预留/结算与后续开书任务事务可组合，不能各自提交导致一边成功一边失败。金额与token使用安全整数，预留不能重复、不同参数复用同键拒绝；账本保留追加证据。未知远端结果保留预留，不因超时推定未调用或自动补扣；明确未执行才释放，已确认结算不能重复或改成不同数额。

本批只实现确定性核心，未实现真实供应商成本与会员发放/续费、开书执行和生产兼容的部分必须明示，不变更商业权益政策。旧作者服务持续运行。
