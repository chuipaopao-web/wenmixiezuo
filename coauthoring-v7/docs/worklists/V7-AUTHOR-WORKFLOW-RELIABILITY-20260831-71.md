# V7 作者全流程可靠性与旧运行残留清理（第 71 批）

任务编号：V7-AUTHOR-WORKFLOW-RELIABILITY-20260831-71

本次唯一清单：`coauthoring-v7/docs/worklists/V7-AUTHOR-WORKFLOW-RELIABILITY-20260831-71.md`

任务类型：V7 作者主流程 BUG 修复、失败恢复、逐页回归与 V6 零引用运行残留清理

当前问题：生产截图证明开书页面标注“4至2000字”，但旧表单仍把原始想法限制为800字；提交开书资料时可能返回409“页面内容已经修改，请先提交主编复审”，作者无法继续；设定页面存在任务完成后仍无法进入下一步或恢复的问题；时光机失败页只有“重新开始”，返回设定或从可靠检查点恢复不稳定。老板要求以当前 V7 工作流为唯一产品，模拟作者创建书籍逐页检查，修复 BUG，并在新闭环通过后删除零有效引用的 V6 运行代码。

复现步骤：使用新测试作者从作者端创建书籍，输入超过800且不超过2000字的开书想法，完成开书资料生成、编辑、确认建书；随后完成设定生成/复审/保存、进入时光机、触发成功与失败恢复，再依次访问卷、链、章、资料、任务、团队、会员和反馈页面。交叉核对浏览器、API、任务状态与测试，不使用生产作者数据做破坏性验证。

期望结果：作者输入、前端提示和 API 对“开书原始想法”的限制统一为2000字；开书资料脏状态和主编复审状态可理解、可提交、可重复安全恢复，不再形成无解409；设定与时光机的完成、失败、刷新、返回和重新开始均从真实后端状态恢复；当前 V7 每个页面都能到达并完成主要操作；确认零有效引用的 V6 运行入口、分支、限制、文案和测试从当前树删除。

允许修改：`coauthoring-v7/author-app`、`coauthoring-v7/backend`、`apps/api`、`apps/worker`、当前 V7 共享合同与直接相关测试；确认零有效引用后删除对应旧运行文件；同步本清单、必要的 `docs/API.md`、`docs/DATA_MODEL.md`、`docs/DEPLOY.md`、`HANDOFF.md` 和 `RELEASE_ID`。

明确不改：不删除、覆盖、回填或伪造作者生产数据；不改写或删除已合并迁移；不恢复 V6 页面、旧岗位专业人设、旧团队/提示运行闭包或旧模型通道；不泄露密钥、提示词或思维链；不购买新服务，不用清库冒充流程通过。

必须保留：V7 唯一作者端和独立后台；账号、会话、会员、反馈、安全、用量、备份与恢复底座；`owner_id + book_id` 隔离；作者原话、确认规划、正文实际和不可变正文版本；任务幂等、成功检查点、失败证据、已完成结果保留和生产回滚点。

- 时光机失败时可重新开始，也能返回设定修正；刷新、路由返回、版本变化和重复请求绑定真实任务状态，成功检查点不丢失。
- 新测试书可走通当前 V7 作者主流程和全部导航页面；页面不显示内部ID、JSON、堆栈或旧V6术语，桌面与390px手机主操作可达。
- 只删除已证明新闭环覆盖且启动、路由、动态注册、服务、测试、迁移与恢复均零有效引用的V6运行残留；共享平台、历史迁移和数据兼容边界保留。

原功能回归：登录、书籍隔离、手动开书、开书 Agent、多成员已完成结果保留、设定正式版本、时光机活动规划、卷/链/章、正文不可变版本、任务恢复、资料库、团队、会员、反馈与后台权限保持可用；被当前 V7 明确替代的 V6 行为不作为门禁。

## 用户界面三句话

1. 作者此刻要完成的是把自己的开书想法可靠地变成一本可继续设定和规划的新书。
2. 最妨碍完成的是前后端限制不一致、脏状态/复审状态没有可执行出口，以及失败后路由和任务检查点没有正确恢复。
3. 当前页只应显示作者输入、真实任务状态、保留结果和唯一下一步；内部版本、请求键、模型协议和技术错误只留在后台审计。

## 最小交互合同

- 开书页唯一主任务是完成当前开书资料并创建书籍；主按钮根据真实状态显示“开始设计”“提交复审”或“确认并创建”，不会让作者猜测409含义。
- 设定页唯一主任务是完成并保存本书正式设定；待决定、失败和已保存状态原位处理，不使用普通弹窗。
- 时光机唯一主任务是确认全书方向；失败先道歉，显示保留成果，并同时提供有效的重新开始和返回设定入口。
- 草稿、AI候选、作者编辑、待复审和已确认内容必须视觉可区分；刷新与返回不丢输入、不重复发任务。
- 手机首要视口390px，无横向溢出，输入字号不小于16px，主要触控目标约44px，长错误和键盘弹起时主操作可达。

## 阶段证据与发现

- 2026-08-31：生产截图显示开书页标注4至2000字；审计确认 `ManualOpeningForm.tsx` 的 `LONG_LIMIT = 800` 属于具体资料单项，不是原始想法限制，因此继续保留。真正冲突在任务表旧CHECK；截图中的整份资料补充意见则与原始作者要求统一到2000字，具体决定卡和资料单项仍保持各自800字合同。
