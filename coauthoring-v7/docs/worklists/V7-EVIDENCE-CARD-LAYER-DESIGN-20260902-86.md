# 第86批设计稿：证据卡层（分层资料卡 + 引用合同 + 节奏锚定）

- 日期：2026-09-02
- 状态：**设计稿，待老板审批，未实施**
- 关联：第82批（libraryRefs 确定性归一 + 遗留设计项"证据卡层"）、第85批（GLM-5.3 思考余量修复）
- 目标（老板原话归纳）：全书/卷/链/章每一层都有资产介入、固定节奏框架；同时解决资料包过大、后台资产引用失败；**不限制死成员创意**。

## 二、卡模型（统一四种卡，全部带来源和责任边界）

```ts
interface V7EvidenceCard {
  cardType: 'fact' | 'rhythm' | 'method' | 'responsibility';
  // fact=硬事实（人物/世界观/已发生剧情/伏笔状态）
  // rhythm=节奏锚（上层对本层的节奏/预算/转折位置要求）
  // method=方法提名（只传名字，不传解释——方法论是模型内建知识，见下）
  // responsibility=责任卡（本层必须完成什么，如"本卷中段升级冲突，不提前解决核心矛盾"）
  key: string;                 // 复合键：cardType + 资产 key（沿用第82批复合键归一）
  title: string;
  sourceKey: string;           // 来源：快照 sourceKey / 方法库 assetKey + 版本（可追溯，来源永不丢）
  conclusion: string;          // 可用结论（白话，≤120字）——成员拿到的是"任务责任"，不是教材原文
  misreadGuard: string;        // 禁止误读（如"这是节奏建议，不是固定章节模板"）
  scope: Array<'book' | 'volume' | 'chain' | 'chapter'>;  // 允许出现在哪些层
  hardness: 'hard' | 'soft';   // hard=不可裁、不可违背；soft=可裁、可忽略
}
```

**精简方法卡原则（2026-09-02 老板两轮定稿）**：五幕式、故事圈等叙事方法论是 AI 成员的内建知识，长篇解释原文不应进任务输入；但**零解释会造成误读**（如把转折点死板等分）。因此 method 卡采用**固定小结构**：名字 + 分阶段/分段节奏一句话 + 一句防误读，总量 ≤100 字，任何层（全书/卷/链/章）通用。示例：

- 五幕式：「阶段：①建置 ②发酵 ③转折 ④高潮 ⑤收束。注意：转折点位置按本层预算放，不是死板等分。」
- 扮猪吃虎：「节奏：藏拙 → 受压 → 反转亮底。注意：反转前必须让读者先看到主角真实实力的一角。」

成员看到这个既掌握骨架又不会被教材淹没；方法库的详版解释（publicExplanation/cautionSignals 等）只留在后台供资料策划选型参考，不再进入任何任务输入。**方法库资产需要一次性精简重构**：为每个资产新增"提名卡"字段（名字+分段节奏+一句注意），由模型辅助从现有详版一次性凝缩、管理员审核后生效；此后新资产入库时按提名卡格式维护。任务输入的预算全部让给模型不可能知道的东西：本书事实、节奏决定、本层责任。

**方法库分层标注 + 按层召回（2026-09-02 老板第四轮定稿）**：节奏框架是**自相似的**——起承转合管全书，也管一卷、一条链、一个小事件；五幕式在全书、卷、链总节奏上同样成立。宏观节奏保证的是"这一层的事件弧完整"，所以方法资产**不是按层隔离分库，而是每个资产标注适用层（可多层）**：如五幕式/起承转合标注[全书,卷,链,章]，扮猪吃虎标注[链,章]，钩子开头标注[章]。设计某一层任务时，**只召回标注了当前层的候选**；同一框架在不同层复用时，骨架相同、颗粒度按本层预算伸缩（全书五幕跨百万字，链内起承转合跨几章，小事件起承转合跨一段）。召回后由资料策划挑 3~5 条候选，以提名卡形式交给成员；**用哪条、怎么组合、或完全不用，由成员自己判断**（延续 candidateOnly + originalStrategyRequired 原则：候选不是指令，原创永远合法）。上层已选定的节奏框架（如全书五幕式）作为节奏卡下传，下层召回的候选默认先看与上层框架兼容的方法——但成员仍可自判替换。

## 三、分层装配与递降（解决"资料包过大"的核心）

每一层的任务包 = **继承卡（递降为结论行）+ 本层精选卡（全文）**，总量受卡预算约束：

| 层 | 继承卡形态 | 本层精选卡上限 | 卡预算（约Token） |
|---|---|---|---:|
| 全书 recipe | 无 | ≤8 张（核心事实卡+主线节奏卡+责任卡） | 4k |
| 卷 volume | 全书卡各压成一行"[来源] 结论" | ≤6 张 | 3k |
| 链 chain | 卷级继承链继续压缩 | ≤6 张 | 2.5k |
| 章 chapter | 链级继承链继续压缩 | ≤6 张（场景卡+连续性事实卡） | 2k |

**裁剪顺序（超预算时）**：软卡的 explanation 尾部 → 次要软卡整卡 → 软卡 conclusion 压半行。**hard 卡永不裁剪**，只允许"全文 → 一行结论+来源指针"降级（结论行仍可回溯来源，审计不丢）。

**谁选卡**：
- fact/rhythm 卡：确定性投影（按 scope 和树结构判定相关性），不消耗模型调用、不引入资料策划的自由摘要漂移；
- method 卡：资料策划**只召回标注了当前层的资产**（同一资产可多层复用），挑 3~5 条候选**只下发提名卡**（名字+分段节奏+一句注意，≤100字），方法库详版解释不下发；用不用由成员自判。召回仍不做第二次泛召回（`buildPlanningLayerReferencePack` 原则不变）；
- responsibility 卡：从上层确认树的节点责任确定性提取。

与现有预算体系的关系：卡预算**取代**自由文本包成为任务输入的主形态；快照 sources 机制**保留**，降级为追溯与审计来源（sourceFingerprint、sourceTraces 不动）——卡引用 sourceKey，排查时能一路查回原文。

## 四、引用合同（解决"后台资产引用"问题的闭环）

1. **引用只认卡包内**：成员输出中的 `libraryRefs`（扩展为可引用全部四种卡）逐条按第82批同款确定性规则归一：卡包外丢弃、复合键归一、去重、缺 applicationNote 丢弃、超 `libraryUseLimit` 保留前 N。**不硬失败**（第82批原则）。
2. **缺卡上报通道（新增）**：成员可以在输出里声明 `neededCards: [{title, why}]`（本层需要但卡包里没有的资料）。校验器不丢弃、不失败，落档为结构化"缺卡请求"；资料策划下一轮按需补卡。把今天生产上"引用了本轮未提供的后台资产"这类失败，从**硬失败/静默丢弃**变成**可闭环的补给流程**。后台按缺卡请求频次做聚合视图，高频缺卡=卡库缺口信号。
3. **禁止照抄模板**：现有提示词原则保留并推广到全部卡型（`planning-tree-agent-runtime.ts:44`："后台资产只是少量候选，不是剧情答案……不得把模板替换人名后直接使用"）。

## 五、不限制死创意的四道保险

1. **卡只给"下限与边界"，不给剧情答案**：fact 卡是"不可违背的事实"，rhythm 卡是"节奏锚点"，两者都不含走向方案；剧情方案仍由 `originalStrategies` 承载，**原创策略必备要求保留**（`originalStrategyRequired: true`，允许完全不引用任何卡、只走原创——现有测试已锁定此行为，继续有效）。
2. **misreadGuard 强制字段**：每张卡必须声明"这不是什么"（如责任卡："本卷中段升级冲突"≠"每章都必须冲突升级"）。
3. **数量上限**：每层精选卡 ≤6~8 张、方法引用 ≤5（现状），杜绝"卡片刷屏"反向稀释注意力。
4. **回校只查事实不查文风**：回校（下述）只针对 hard 卡的显式矛盾，不评价创意质量、不强制贴合软卡。

## 六、回校（生成后验证，v1 从简）

- 范围：仅 hard 事实卡 + 节奏预算数字。可确定性检查的项目：出场人物是否与事实卡冲突（名字/关系字段级）、章节落点是否越出节奏卡给出的预算区间、引用是否与卡结论方向相反。
- 手段：确定性字符串/数字比对优先；确需语义判断时才用模型（复用现有审校工位，kimi-k3 有停止条件证据合同）。
- 矛盾处理：定向 revise（把具体卡作为证据注入修订指令），不整树报废。
- v1 明确不做：全量语义审校、软卡回校。

## 八、验收指标

1. 任务输入体积：规划层编译后提示词 estimatedTokens 下降 ≥50%（卡预算 2.5k~4k 对比现状 10k~18k 字自由文本）。
2. GLM-5.3 规划调用思考字符从 4.4万~5.1万 降到 ≤2万（大输入驱动思考的效应随之减弱）。
3. "引用未提供/过多后台资产"类校验失败保持 0；缺卡请求有落档、有聚合视图。
4. 质量不回退：原创策略数量仍为 5（现有合同）、作者采纳率与当前基线持平或更好。
