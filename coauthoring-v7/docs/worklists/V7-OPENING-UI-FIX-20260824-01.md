任务类型：已上线功能的局部 UI、交互与长度合同修正
当前问题：新建书籍示例过短、第一步底栏提前显示书名；开书资料仍有人物卡独立编辑入口且视觉偏旧、字号偏小；开书与设定自由长文本长度不统一。
复现步骤：打开“新建书籍”查看第一步示例、底栏与两种设计入口；打开任一本书的设定页，展开开书资料并点击人物卡编辑；进入开书资料修改和设定逐项设计查看自由长文本框。
期望结果：短想法也能提交 AI；“自己设计”立即进第2步，AI路线只在真实完成后进第2步；新书第一步不显示尚未创建的书名；开书资料只从“修改开书资料”修改，展示与设定页统一为白色浅绿且清晰易读；相关自由长文本默认最多800字。
允许修改：开书向导及直接长度合同、设定页开书资料展示、设定逐项设计自由长文本、局部样式、直接相关测试、本清单；若接口必须同步，只修改开书思路与开局/方向/结局的受影响校验。
明确不改：故事、分卷、事件、章节页面；设定资料库条目结构、逐项设计、补充设计、主编审查；人物数据与人物卡后端；会员、身份、书籍隔离、正文、结算、数据库迁移；全局视觉令牌和共享外壳。
必须保留：开书草稿恢复与失败重试；AI真实任务与刷新恢复；现有分类、标签、角色、开局、结局、故事方向的提交链路；修改开书资料产生新版本；设定候选、确认、历史版本与补充设计；旧数据可读取。
新功能验收：见 `ACC-01` 至 `ACC-07`。
原功能回归：见 `ACC-R01` 至 `ACC-R05`。
测试范围：开书向导、设定目录/协作、工作台 UI 相关测试；Web类型检查与构建；若API合同修改则追加开书接口/合同测试与API类型检查/构建；真实浏览器桌面和390×844手机走查。无数据库、权限、恢复或全工作流结构变化，不运行 `verify:full`。
部署要求：全部清单通过后部署生产；前端使用静态资源原子切换，若API合同同步则按零在途任务门禁发布API；保留回滚版本并做线上健康、资源、交互和日志验证。

## UI 三句话

1. 作者此刻要把一个可能很短、也可能较具体的故事想法交给团队，或自己进入现有表单继续设计。
2. 最妨碍完成的是示例不够清楚、底栏出现尚未创建的书名，以及开书资料展示过小、过密并存在重复编辑入口。
3. 当前只需出现开书思路、两种路线、真实工作状态和可读开书资料；人物卡独立编辑与其他后续创作信息不应出现在这里。

## 页面状态

- 初始：显示开书思路、长示例、800字口径和两种入口。
- 选择：自己设计立即进入第2步。
- 工作中：AI真实等待，后续步骤禁用。
- 失败：保留思路，可重试或改自己设计，不越级。
- 完成：AI回填后进入第2步，作者继续修改。
- 修改：设定页只从“修改开书资料”进入现表单。
- 恢复：刷新/关闭后沿用现有草稿和AI设计编号恢复。
