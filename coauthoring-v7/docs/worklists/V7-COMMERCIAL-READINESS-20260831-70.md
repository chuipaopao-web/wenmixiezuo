# V7 商用全链路验收与修复清单（第 70 批）

任务编号：V7-COMMERCIAL-READINESS-20260831-70

本次唯一清单：`coauthoring-v7/docs/worklists/V7-COMMERCIAL-READINESS-20260831-70.md`

任务类型：核心创作工作流、上下文与检索、作者端、独立后台、模型运营、用户会员的商用验收与修复

当前问题：第 69 批已把每个新创作任务固定接入一次资料策划 Agent，但仍需从真实运行结果确认全书、卷、链、章纲、正文、审查与结算是否逐层得到准确而不机械复制的方法责任；作者任务页是否准确、快速、可恢复；独立后台是否真正支持上下文、资料包、任务人设、模型、用户和会员运营。老板已指出当前后台不能给用户开通会员，并要求对全部 V7 前后端闭环主动找 BUG、修复、测试和部署。

复现步骤：从当前 V7 作者端建立或读取一部测试书，依次检查全书规划、卷、链、章纲、正文、审查、结算、任务详情、刷新/失败/重试；从独立后台检查同一任务的上下文、资料包、任务人设、模型调用、用户和会员开通。每一步以 API、数据库审计、真实页面和模型调用结果交叉验证，不只看文档或字段存在。

期望结果：作者能在现有 V7 UI 中清楚看到每个环节的设计结果、当前成员、进度、耗时、失败原因和恢复动作；资料策划 Agent 为每次新创作任务选择最小充分资料、题材融合任务人设和适合当前层级的专业方法责任。通用方法可以在全书、卷、链等层级重复采用，但每层必须依据范围、目标、上下游接口和阅读体验重新语义化，形成因果、钩子、伏笔和回收的连续结构，不把方法教材或上一层全文塞入下层。管理员能安全管理模型 API 配置状态、用户和会员，并追溯上下文、资料包、人设、调用和失败。

允许修改：`coauthoring-v7/backend`、`coauthoring-v7/author-app`、`coauthoring-v7/admin-console`、`apps/api`、`apps/worker`、共享合同与直接相关测试；必要时新增向后兼容的 V7 增量表或索引、更新 `docs/DATA_MODEL.md`、`docs/API.md`、`docs/DEPLOY.md`、`RELEASE_ID` 和本清单。

明确不改：不恢复 V6 页面、旧岗位专业人设、旧团队/提示运行闭包或已删除模型通道；不把关键词、正则、固定标签、分数阈值当成最终语义判断；不安装与需求无关的新平台；不改写或删除 102 个历史迁移；不回填、删除、覆盖作者生产数据；不保存/展示模型思维链、密钥或原始提示词；不承诺任何第三方模型永不超时或永不空返回。

必须保留：V7 唯一作者端与独立后台；账号、会话、管理员权限和会员流水；`owner_id + book_id` 隔离；作者原话、确认规划、正文实际和不可变正文版本的权威边界；任务幂等、用量预留/结算、结果未知冻结、失败证据、旧版本回滚；上一生产发布和正式数据库回滚点。

新功能验收：

- 全书、卷、链、章纲、正文、审查和结算的新任务均可追溯一次资料策划结果，包含任务期题材融合人设、资料选择、方法候选、采用/排除理由、层级化责任、创意空间和预算。
- 同一通用方法可跨层召回，但 Agent 输出必须针对当前层级重解释；下层只接收活动上游合同、相关正文实际和当前任务所需材料，不接收方法论全文、无关上层全文或其他书资料。
- 作者任务页真实展示成员、阶段、已用时/合理等待提示、完成结果、失败道歉、保留结果和原位恢复；刷新、返回、重复点击不重复发任务或重复扣量。
- 独立后台可按权限查看安全的任务人设、上下文/资料包摘要、来源、预算、方法、调用、失败与恢复；能管理当前模型可用性/路由/套餐边界，不能暴露 API Key。
- 管理员可搜索用户、查看会员状态并成功开通/续期/撤销会员；流水不可变、状态更新正确、重复提交幂等、越权为 403、作者数据不受影响。

原功能回归：登录、书籍隔离、开书、设定、规划树、人物资料、正文不可变版本、审查独立性、结算正式化、用量记账、反馈、后台管理员权限、作者会员页和静态深链接保持可用；被本合同明确替代的旧展示不作为门禁。

测试范围：因老板明确要求全链路并涉及核心创作工作流结构、ContextCompiler 权威来源、模型用量和会员权限，记录全量门禁触发事实；每个纵向阶段先运行受影响测试、对应类型检查/构建和真实浏览器，最终运行 `npm run verify:full` 等价门禁、迁移清单/空库/重复执行（仅在新增迁移时）、一次相称真实模型探针、桌面与 390px 手机端，并执行生产部署前在途任务门禁与上线后只读验证。

部署要求：各阶段形成可独立回滚提交；全部通过后冻结同一源码发布 API、Worker 和静态资源。重启前当前 V7 可执行任务连续 30 秒为 0 并立即复核，不取消、暂停或改写作者任务；保留旧发布和数据库回滚副本，逐服务切换并验证健康、登录保护、作者端、后台、会员接口、Worker 心跳与警告日志。

## 用户界面三句话

1. 作者此刻要完成的是理解当前创作环节的设计、给出自己的想法，并可靠地得到下一层或正文结果。
2. 最妨碍完成的是资料与方法是否准确不可见、任务等待和失败状态不够可判断，以及后台无法闭环处理会员与运行问题。
3. 当前页必须立即显示业务结果、真实阶段、成员、等待/失败与恢复；详细来源、预算、模型和审计只在有权限的独立后台按需展开。

## 最小交互合同

- 作者创作页唯一主任务：完成当前层级设计或写作；主按钮随真实状态显示开始、提交想法、确认或重试，不堆叠同级操作。
- 任务详情原位展开，不使用普通弹窗；作者可见文案只用大白话，不出现模型名、内部 ID、JSON、提示词、哈希、堆栈或思维链。
- 工作中显示当前成员、正在完成的业务阶段、已用时与可离开说明；失败先道歉，再说明已保留结果和唯一可执行恢复动作。
- 后台以运营任务为主：查任务、查用户、开会员、检查模型；技术审计按需展开，不重复页面标题和说明。
- 手机首要视口为 390px；无横向溢出，触控目标约 44px，输入字号不小于 16px，长错误、长书名和键盘弹起时主操作可达。

## 成员能力合同

- 资料策划 Agent：接收 owner/book、任务类型与活动版本、作者原话、正式源候选、正文实际、方法候选和字符预算；可做语义检索选择、题材融合任务人设、方法重解释和缺失/冲突报告；输出严格结构化资料计划，不可读取其他书、密钥、思维链或全库正文。
- 规划/写作/审查成员：只接收已冻结资料包、当前任务合同、必要上游活动合同和开放区；规划成员输出当前层结构与下层接口，写作成员保留场景自由，审查成员绑定精确正文版本并独立反馈。
- 模型和参数：资料策划延续已验证的 DeepSeek → Kimi → GLM 兜底，并以可见结构化输出为成功条件；各业务节点按任务预算设置超时、输出上限和温度，不采用全岗位统一值。模型不可用、空输出、合同无效或结果未知均保存真实调用状态并走幂等恢复。
- 作者反馈：工作中和失败状态来自真实任务/调用；完整技术证据只供管理员。失败必须先说“抱歉/对不起，这次没有完成”，再说明保留结果和恢复办法。

## 复用审计

- 继续复用 `V7CreationContextCompiler`、一次资料策划 Agent、`planning-method-retrieval`、叙事方法资产画像、规划树严格合同和现有模型兜底，不新建第二套 ContextPack 或“资料翻译”旁路。
- 继续复用现有叙事方法多范围画像：同一个方法资产可登记 `book/volume/event` 等适用范围，由资料策划 Agent 语义检索、由执行成员结合当前层重新解释；禁止把五幕式或任一方法硬编码为唯一选择。
- 继续复用作者端 `TimeMachinePage` 的真实耗时与失败恢复表达、`TaskLogPage` 的成员执行记录以及 `CreationWorkspacePage` 的创作闭环，只补齐状态与详情缺口，不重排主导航或恢复旧团队页面。
- 继续复用 `MembershipService`、管理员会员接口、不可变 `membership_transactions` 流水和现有内联办理表单；不另建会员系统。现有接口尚无办理幂等键，真实浏览器链路也未被测试覆盖，列入 70C 修复。
- 继续复用 `CreationOperationsPage`、`PromptContextCenter`、统一成员治理、模型绑定和用户运营页；后台只展示安全摘要和配置状态，不展示密钥、完整提示词或思维链。
- V6 只用于识别仍被当前 V7 引用的平台底座，不恢复旧开书、旧团队、岗位专业人设或已删除模型通道。

## 设计审查

- 修改前审查：已完成第一轮。当前一次资料策划调用、同书活动来源校验、字符硬预算和任务期题材融合人设方向正确；发现下层规划树的紧凑投影遗漏上层 `designStrategy`、伏笔和开放问题，导致方法责任与钩子可能在卷/链交接处丢失。会员流水不可变但办理缺少请求幂等键；后台部分文案仍只描述“三名主编读取同一资料范围”，没有准确反映一次资料策划、任务人设与分层资料包。以上均可在现有闭环内增量修复，无需恢复旧系统或引入新服务。
- 修改后审查：已完成第二轮。统一父层交接投影只传递作者确认的结构化决策，当前子节点保留方法应用、因果、伏笔和开放问题，相邻节点只保留位置/结果/接口；来源仍绑定 owner、book、活动版本和指纹，未放宽跨书查询或正式数据写入。会员迁移仅新增可空字段和部分唯一索引，不回填历史流水；开通、续期、撤销的状态与流水在 `BEGIN IMMEDIATE` 单事务内完成，同一管理员和幂等键只生效一次，冲突复用返回 409。作者批量清理只归档失败/中断的开书任务，不再误删等待作者确认或决定的任务。后台只展示资料、人设、预算、方法和调用安全摘要，不展示密钥、提示词、正文或思维链。差异未触及不可变正文、作者生产数据、102 个历史迁移和已删除旧运行闭包。
