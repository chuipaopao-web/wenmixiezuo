# 文秘写作开发闭环

本Skill负责路由；授权与安全读根AGENTS，实施读 [开发流程](../../../docs/DEVELOPMENT_WORKFLOW.md)，测试读 [验收标准](../../../docs/ACCEPTANCE.md)。不另设固定报告、审批或全量门禁。

## 执行

1. 根据当前请求区分讨论、文档、小修、新功能或已授权重构。明确要求实现即可在相应范围执行，不要求固定口令；讨论和规则维护不自动授权产品重构。
2. 新任务读一次HANDOFF并检查工作区；再读受影响文件和必要参考，不反复通读历史文档。
3. 修改前说明目标、范围、保留项、验证与部署要求，按开发流程建立相称合同。长任务告知唯一编号与清单路径；开工说明不等于等待批准。
4. 小修优先最小差异；重构按目标重新设计边界，并记录复用或重写理由。不强制逐代搜索旧代码或保留不适合的新架构依赖。
5. 分批实现和验收，尽早获得可运行结果；已授权普通批次通过后继续，不每批申请确认。真正缺少产品目标、费用或安全授权才暂停相关部分。
6. 按验收标准检查实际风险和证据，保护用户数据与其他任务修改，审查完整差异后提交并报备。

## 按需配合

- 产品目标与取舍未清楚：使用产品决策Skill，给专业推荐，必要时询问关键问题。
- 涉及页面和交互：使用UI/UX Skill，保留用户已明确的视觉偏好并核对真实状态。
- 涉及上下文、正文事实或文学质量：使用长篇质量Skill，不把它当成所有任务必经流程。
- 涉及发布：按已授权合同与根规则执行，不因使用本Skill扩大部署范围。

## 恢复与报告

按已知清单路径核对最新要求、已完成证据与Git状态，继续未完成项。报告“通过、未通过、未验证、不适用”及实际限制；不把格式合格、模拟模型或HTTP成功当作文学质量或真实交互通过。
