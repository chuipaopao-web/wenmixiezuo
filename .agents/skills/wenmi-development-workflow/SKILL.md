# 文秘写作开发闭环

把老板最新任务变成一批可核对、可测试、可报备的改动，不用旧规格否决新功能。

## 先区分讨论与开发

- “讨论、商议、评估、先给方案、先看看”属于设计讨论：不建立开发清单、不修改产品代码、不把讨论稿当定稿。可以按需只读查证现状。
- 明确要求修改代码、规则、Skill或正式文档才属于开发；修改范围只到用户授权的文件和直接依赖。
- `HANDOFF.md` 标记为 V7 讨论期时，旧流程、页面、对象层级、UI和历史验收只用于了解现状，不得进入变更合同的“必须保留”，除非老板在本次任务重新明确确认。
- 老板明确说“开始开发”才激活 V7 功能开发；规则解绑、讨论记录维护等文档任务不等于功能开发授权。

## 开始开发前

1. 新任务只读一次项目 `HANDOFF.md`；同一任务后续不重复读取。
2. 读取 `docs/DEVELOPMENT_WORKFLOW.md`，按受影响范围再选择 UI、长篇质量、数据、API 或部署资料，不全量通读。
3. 用户可以只说大白话；第一条用户可见的开发回复必须按 `docs/DEVELOPMENT_WORKFLOW.md` 的“开工回复”要求给出确认消息和工单信息。发出回复前不得编辑文件，不在 Skill 复制工单格式。
4. 可以先做只读定位；修改前必须按该文档的唯一模板建立变更合同与开发验收清单，并在回复中给出任务编号和唯一清单路径。
5. 先判断请求能否作为一个独立验收和回滚单元；包含多个独立用户结果、未确认产品语义或无法中途验证的长任务，按该文档拆批后再开发。
6. 代码或运行问题先查真实页面、当前实现、相关本地 Git 历史及已配置远程仓库；V7 按本地规则依次检查现有 V7、V6 真实实现、现有依赖/官方实现和合适的公开源码。纯规则/Skill任务只查生效规则、直接引用和相关评测，不为了流程完整读取无关产品代码。
7. 检查同一工作区的其他任务和未提交改动；存在另一项未完成开发时不得覆盖、回退或混合提交对方文件，无法隔离就停止并等待。
8. 把老板每一条要求映射到清单中的需求、实现、验收和证据编号。任务恢复或对话压缩后先重读唯一清单，不依赖模糊搜索或聊天记忆续做。

## 控制长任务

- 一个开发批次只能交付一个主要用户结果和一个可独立回滚单元；跨前后端没有问题，但不能把多个互不依赖的功能塞进同一清单连续开发。
- 产品可见的工作流或 UI 先做一条最小真实纵向闭环，完成运行或浏览器证据和阶段差异审计后，再扩展相邻能力；需要老板判断的结果必须先确认。
- 每批完成立即结算清单和证据。相同实现路径连续失败两次时停止重复尝试，重新检查根因、复用判断和合同范围；需要新产品决定或扩大权限时暂停说明。
- 详细拆批、唯一清单和阶段结算规则只在 `docs/DEVELOPMENT_WORKFLOW.md` 维护，本 Skill 不复制第二套模板。

## 复用优先

- 写代码前必须留下复用审计：检查过什么、选择直接使用、复制、微调、依赖复用还是最小新写，以及为什么。
- 优先级是修改现有合格实现，其次复用已验证的项目/历史代码，再次采用维护良好且商业许可兼容的官方依赖或公开源码，最后才写最少的新代码。
- 公开源码必须核对许可证、来源版本、安全、维护性和必要声明；减少 Token 不能成为跳过语义理解、权限隔离、测试或供应链检查的理由。

## 逐项开发

- 优先最小修改，能复用、删除冲突规则或调整现有实现就不整文件重写、不新增无关抽象或重构。
- 发现实现必须超出变更合同的允许范围时停止并说明，不得自行扩大范围。
- 一项只有同时具备“实现完成、新功能验收通过、原功能回归通过、差异审计通过”才能标为通过；相关代码可以同批编辑，验收仍逐条对应。
- 每完成一个纵向批次就更新唯一清单、验收证据和阶段差异，不连续积累多个未验收批次后再统一检查。
- 状态、任务进度、模型结果和失败恢复必须来自真实后端事实，不用前端猜测伪造成功。
- 新流程替代旧流程后，只清理变更合同明确替代且已证明零有效引用的旧入口、旧分支、旧文案、旧测试和当前冲突文档；过渡期保留的生产回滚入口不算失败。历史作者数据和已合并迁移不删除、不改写。
- 测试按风险执行：默认只跑受影响测试、对应包类型检查和构建。单页 UI、文案、局部接口、模型适配器和明确 BUG 修复不得以“更保险”为由擅自跑全量；模型调用变化优先跑适配器测试、受影响业务集成测试和必要的真实探针。
- 只有迁移改变既有受保护数据语义/形状、回填历史数据、权限或账号隔离、跨服务恢复、不可逆迁移、核心创作工作流结构变化，或者老板明确要求时才运行全量 `npm run verify:full`。独立新功能的加法表/索引只做迁移清单、空库与重复执行、受影响仓储/接口及类型检查/构建。全量测试前必须在验收清单记录具体触发事实；“有数据库迁移”本身不是理由，没有具体事实就不运行。
- 浏览器或外部环境不可用时如实标为“未验证”，继续完成可确定的代码和自动测试，不用截图或字段存在冒充真实交互。
- 完工前检查最终修改文件列表、`git diff --stat` 和完整 `git diff`；合同外改动、合同明确保留的入口丢失或失败恢复退化时不得结算。

## 完工报备

结束时逐项回看最初清单，只能使用“通过、未通过、未验证、不适用”，并按 `docs/DEVELOPMENT_WORKFLOW.md` 的唯一完工报告模板报备。没有真实浏览器或运行证据不得写交互通过；没有真实部署记录和线上验证不得写“已上线”。

先服从变更合同的部署要求；合同明确不部署时不得部署。合同未禁止部署的小型 BUG 修复通过相称门禁后默认直接部署，不再逐次请求上线。部署遇到付费、新凭证、作者数据永久删除、生产恢复、不可逆迁移或在途任务无法安全等待时，才暂停并说明。

清单未全部结算、关键测试失败、合同要求删除的旧入口仍可用，或作者数据安全无法证明时，不宣布完成。
