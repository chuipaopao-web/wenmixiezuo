# 生成、审校、结算与恢复

仅在任务管线、方案/融合、正文生成、独立审校、作者确认、结算、幂等、预算或恢复变化时读取。

## 对象闭环

每个正式层遵循：作者补充 → 独立候选 → 差异/质疑 → 作者选择 → 主编只融合所选内容 → 作者编辑/确认 → 活动版本。作者确认前是候选，不能自动进入下一层。

正文使用一个活动主笔；事实、文学、体验按当前产品配置独立审查，互不读取报告。审查意见绑定精确正文版本，旧稿报告不能放行新稿。作者接受后创建不可变正文版本并结算。

## 任务合同

任务至少保存 owner/book、对象与活动版本、输入来源、预算、幂等键、阶段检查点、输出对象和恢复状态。重复请求或断点恢复复用已成功检查点，不重复扣量；结果未知时先调和供应商结果，不盲目重发。

状态来自真实队列、心跳、调用和工具事件。普通作者只看“准备资料/成员设计/等待选择/融合/审查/失败可恢复”等业务状态；内部模型、阶段键、任务ID、堆栈和原始协议留在管理员审计。

## 结算

章节结算记录实际人物状态、关系、资源、地点、时间、承诺/伏笔、线程推进、代价和下一章接口；事件结算汇总小故事实际结果；卷结算汇总本卷兑现、损耗、不可逆变化、未回收问题和下一卷起点。

结算引用正文证据，不复制计划。计划未发生就保持未发生；正文偏离计划但作者确认后，以正文实际为准并触发后续回校。

## 停止与恢复

以下情况就地停止并给恢复动作：缺活动上游、设定硬矛盾待作者决定、必要资料放不下、候选同质、模型/预算不可用、结果合同无效、审查阻断、版本已变或写入只读。停止不能覆盖作者输入、正文、结算或调用证据。

恢复从最后可靠检查点开始，绑定相同对象和版本；如果上游版本已变，旧候选作废并重新编译。取消只终止当前未完成工作，不把已确认对象改成取消状态。

## 验收

- 从当前对象可以追到输入、候选、作者选择、确认版本和下游绑定。
- 并行席位独立，缺席可定向补发，成功席位不陪跑。
- 失败、取消、超时、结果未知和重试都有幂等/预算测试。
- 旧正文、结算和作者原话在回滚前后不变。
- 普通作者错误可读、可恢复且无技术泄漏。
- 真实长篇验收按用户指定规模逐阶段进行，失败立即停止扩大，不用确定性夹具冒充文学质量。
