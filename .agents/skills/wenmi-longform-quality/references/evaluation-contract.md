# 长篇质量评测合同

## 目录

1. 证据等级与独立性
2. 系统、检索与上下文
3. 工作流与精简
4. 创造性非劣效
5. 纵向创作与作者治理
6. 通过门槛与审计字段

## 1. 证据等级与独立性

| 等级 | 最低证据 | 允许表述 | 禁止外推 |
|---|---|---|---|
| E0 | 想法、提示词、文档或界面 | 已定义目标和候选方案 | 不得称已实现 |
| E1 | Schema、接口、代码或配置存在 | 已实现某机制 | 不得称机制有效 |
| E2 | 单元、集成和构造场景测试通过 | 在构造场景通过 | 不得称真实长篇有效 |
| E3 | 独立金标、对抗、消融、故障注入和长规模回放通过 | 系统性风险在评测范围内降低 | 不得称文学质量已解决 |
| E4 | 真实模型连续创作、跨章盲评和作者验收通过 | 在指定题材、模型和规模内改善 | 不得保证其他作品或模型 |

“解决长篇问题”至少需要E3与E4，并说明题材、章节规模、模型配置、基线、改进幅度和剩余风险。E4同时要求治理机制相对基线满足创造性与输出质量非劣效。

评测遵守：

- 金标、查询和失败样本不得由被测实现规则自动生成。
- 维护隐藏对抗集并报告失败，不用平均分掩盖blocker。
- 同一模型生成和自评只作观察；关键结论需要确定性证据、异模型或人工盲评。
- 在看结果前冻结评测方法、样本、顺序随机化和核心门槛。
- 确定性模型只能证明流程、状态、版本、隔离和恢复，不能证明文学质量。

## 2. 系统、检索与上下文

系统正确性至少使用200章或100万字符隔离测试书，分散人物、关系、地点、规则、故事时间、知情状态、谎言、失效事实和开放线索。硬状态正确率要求100%，跨书污染为0；正式事实变化后，旧上下文、摘要、向量和Wiki必须失效或重建。

混合检索覆盖精确词、别名、语义改写、多跳关系、当前/过去/计划/失效/有限视角、否定、冲突、反事实、无答案和高相似错误实体。分别报告Recall@K、Precision@K、MRR、nDCG、无答案准确率、延迟和Token，完成通道消融并与单一FTS、单一向量和整书上下文比较。

上下文质量按当前产品合同中实际激活的能力评测，不写死成员或模型名单：

- 比较全量上下文、最小充分上下文和只有硬事实三种输入。
- 测试证据位于输入开头、中部和末尾，覆盖重复、冲突和超预算。
- 硬来源不得静默截断，压缩结果必须能回查原文。
- 独立创意能力与提前共享答案做对照，报告创意覆盖、结构差异、因果质量和少数高潜方案保留。
- 正式稿的事实、文学和体验审校读取同一不可变稿，模型来源均与活动写手不同，提交前互不可见；验证缺席、重复、版本错位、Token和延迟。
- 来源与原创性风险评测覆盖授权、受保护原文隔离、类型惯例误报、相似风险漏报和无独立页面时的门禁可达性；不把结果冒充法律或平台保证。

## 3. 工作流与精简

工作流重构至少验证：

- 上下文协作、创意推演、暂存试写和正式生产的状态与写入边界不同。
- 协作发生在资料、设定、阶段、事件、章纲或正文旁边时，作者原话只保存一次并能按对象追溯。
- 切页、刷新、重启、取消、超时和结果不明后不重复调用、不丢候选、不猜测完成。
- 可选事件层启用与跳过均可完成当前阶段；跨度变化不破坏章号、正文或正史。
- 当前卷纲和事件大纲支持白话节奏方案、自定义结构和无模板路径；正式方法名不作为前端标题，节拍可跳过、合并、拆分和重排，且不会从卷纲自动套入每个事件。
- 作者原始想法在开书信息、设定、卷纲、事件、章纲和正文旁只保存一次，能追溯意图强度、采用位置、调整和未采用理由。
- 卷内高潮阶梯能表达蓄势、事件后果、卷级升级、卷末余波和下一卷触发；系统不把每章反转、恒定强度或固定爽点密度当通过条件。
- 正式正文仍逐章版本化、审校、作者确认和结算；批量入口不能越过门禁。
- 旧书、旧URL、旧任务、旧角色修订和旧Artifact保持兼容读取。

代码精简分别报告：

- 作者步骤和页面切换变化；
- 重复入口与不可达代码；
- 页面到数据/任务/恢复的可达图；
- 依赖边数、循环依赖和巨型装配文件规模；
- 全量回归、迁移、运行和恢复结果；
- 删除前后模型调用、Token、延迟和缺陷变化。

文件数、行数或测试数下降不能单独证明更简单。删除页面成功也不能证明背后能力已安全替代。

## 4. 创造性与输出质量非劣效

任何改变检索、上下文、规划粒度、题材模板、团队、生成、审校或经验的机制，都设置旧流程或弱治理基线。使用相同任务、相近模型与预算、多次采样和匿名随机呈现。

评测强度与影响范围匹配：

- 不影响模型输出的机械修改只做目标回归。
- 局部可逆软规则做相关场景多样本对照。
- 岗位默认、检索或审校策略做跨任务盲评。
- 全书、跨岗位或流水线改变做20/50/100—200章纵向评测。

独立报告而不互相抵消：

- 正式事实与任务目标遵循；
- 原创性与非套路化；
- 合理惊喜与因果成立；
- 人物声音和行为生命力；
- 情绪力度、张力和读者投入；
- 语言、画面、节奏和整体阅读质量；
- 作者意图符合度；
- 旧文模仿、检索锚定和重复。

核心创作维度门槛在评测前定义。样本不足或分歧过大时结论为不确定，不启用强制默认。原创性、惊喜、爽点和岗位差异只用于诊断，不作为每章生成配额。

## 5. 纵向创作与作者治理

真实模型连续创作分层：20章观察早期趋势，50章验证中期人物/节奏/开放线索，100—200章或约100万字符进入长篇范围判断。连续5章只证明短流程可运行。

记录每万字正式事实矛盾、无依据重大新增、人物声音漂移、重复情节/表达、承诺债务、规划偏离和重写率。分别报告局部章节、跨章连续性、阶段/事件闭环、全书叙事和作者满意度。

作者治理至少测试：

1. 作者提出与正式事实冲突的方案。
2. 作者用确定语气提出证据不足的判断。
3. 作者连续偏爱同一套路。
4. 作者改变长期方向。
5. 作者在不同创作台页签对同一对象提出相反意见。

系统区分事实、偏好和决定，给出有证据的反例，同时保留作者最终创作裁决。建议采纳率只能观察，不能作为正确性奖励。

经验进化测试单次成功、跨题材失败、过期偏好和相反要求。经验必须带适用范围、反例、版本、到期和撤销条件。

## 6. 通过门槛与审计字段

- 任一blocker未解决：不通过。
- E0—E2：只宣布计划、机制或构造测试状态。
- E3无E4：可宣布系统可靠性在评测范围改善，不能宣布创作质量改善。
- E4：只在评测题材、模型、规模和时间范围内表述改善。
- 指标与人工盲评相反：暂停结论并调查指标失真。
- 可靠性或代码量提高但任一核心创作维度低于非劣效门槛：不通过并回滚对应机制。
- 活动写手自由创作区为空、软模板累积、模式误路由、历史不可恢复或删除目标仍可达：不通过。

审计最低字段：明确结论与置信度、当前事实基线、能力追踪矩阵、替代方案、预先验尸与反例、修正设计、创造性与输出质量保护、测试与E0—E4证据等级、剩余风险与未知项、停止/回滚/升级条件。
