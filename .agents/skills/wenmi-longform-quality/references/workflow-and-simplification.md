## 1. 外部方案审查

把外部建议视为候选，不视为当前事实或老板决定。逐项标记：

- **采用**：直接解决已确认根因，且与权威、安全、恢复和创造性边界兼容。
- **调整后采用**：方向有价值，但固定数量、角色、阈值、模板或页面需要参数化或改为可选。
- **暂缓**：需要真实数据、作者原型或模型评测才能决定。
- **拒绝**：与权威数据、不可变版本、费用、独立性、恢复或创造性保护冲突。

禁止用文档完整度、术语专业度或方案篇幅证明可行。核对真实调用图、数据生命周期、旧书兼容和运行证据。

## 2. 工作流分层

把作者看到的入口、业务状态和数据权威分开：

```text
作者入口（页签、按钮、协作框）
→ 用例命令（讨论、选择、编辑、确认、生成）
→ 持久任务/状态机
→ 版本化产物
→ 作者确认
→ 正式正文与正史
```

页面可以删除或合并，业务状态不能只存在页面或聊天中。刷新、切页、重启和模型结果不明后，必须从持久状态恢复，不得重复调用或猜测完成。

使用“当前最有价值的一步”推进作者，不把完整流水线一次展示为表单墙。允许作者直接编辑、补充、选择、拒绝或暂存；只有正式层使用完整生产门禁。

## 3. 上下文协作

将交流放在当前资料、设定、阶段、事件、章纲或正文旁边，不要求独立聊天页面。所有入口复用统一协作底座，并携带：

- `owner_id`、`book_id`；
- 当前模式；
- 当前表面入口 `surface`；
- 当前对象类型与ID；
- 作者原话和附件；
- 实际参与能力/成员；
- 任务、候选、确认和失败状态。

不要为每个页签建立互不相通的消息事实源。作者原话保存一次，页面只建立对象引用和作者可读投影。历史记录可按当前对象折叠查看；不得因取消独立聊天页而删除历史消息、讨论、附件、任务或调用证据。

点名、创意推演、资料整理、候选确认和控制命令使用不同用例，但共享幂等、权限、恢复和审计边界。受理层只做确定性路由和最小资料准备，不代替创作能力形成结论。

## 4. 规划粒度

长篇小说标准流程使用以下逐层展开结构：

```text
开书信息与作品主脉
→ 设定大纲
→ 当前卷纲与卷内节奏
→ 事件大纲与事件节奏
→ 当前事件的章纲
→ 单章正文
→ 卷结算
→ 下一卷卷纲
```

当前卷纲是本卷创作的长程方向约束，至少说明卷首状态、卷目标、主要冲突、人物变化、事件链、高潮阶梯、卷末状态、保留线索和下一卷接口。它是版本化活动规划，不是已经发生的正史，也不按固定章数或字数要求凑满。

用语义闭环定义事件，不用固定字数或章数定义：事件必须说明起始状态、触发、目标、阻力/代价、结束条件、结果状态、在本卷节奏中的职责和下一接口。事件大纲必须引用当前卷纲；章纲必须引用当前卷纲与当前事件；正文任务再引用当前章纲和上一章结算。上层内容只注入本次必要部分，但引用链、版本和来源必须可回查。

“在卷纲约束下”表示禁止无提示的主线漂移，不表示正文只能机械执行。若事件或正文产生更好的重大偏离，系统先说明偏离点、原因、受影响事件/章纲/人物弧和卷末目标，由作者选择保留原卷纲、局部改纲或创建新卷纲版本；不得静默放行，也不得静默改写已结算正文。

一卷结束后先按正式正文结算实际人物状态、已兑现承诺、未闭合线索、局势变化和卷末余波，再以这些事实加开书信息与作品主脉作为下一卷设计输入。下一卷应承接前卷后果自然启动，而不是清空状态、重复开局或提前批量生成所有卷纲。

## 5. 白话叙事模板、作者想法与高潮阶梯

三幕式、五幕式、救猫咪、起承转合、英雄之旅和题材专用结构可以作为内部模板来源，但作者前端不得要求理解这些术语。界面只显示大白话任务卡，例如：

- “先让人物和问题站稳，再不断加压，最后集中解决”；
- “逐步升级到最低谷，再做关键选择并承担结果”；
- “从熟悉生活出发，经历考验后带着变化回来”；
- “先铺垫和推进，再发生方向变化，最后留下回响”；
- “由我自己安排这一卷/这个事件”。

每张卡直接说明适合什么故事、作者接下来要填写什么、可能带来什么节奏、常见套路风险和能否自由修改。正式方法名只保存为内部 `source_method` 元数据，用于版本、评测和维护，不作为作者选择题标题。

系统区分：

- **模板定义**：版本化的节拍职责、白话引导问题、适用范围、常见风险和内部来源方法，不包含待创作故事内容。
- **模板实例**：作者为当前卷纲或事件选择并改写后的节奏方案；允许混合、自定义、跳过、合并、拆分和重排。
- **活动卷纲/事件大纲**：作者确认的当前结构版本；只约束已明确的目标、因果、重大节点和边界，不锁死具体场景和表达。

同一内部模板不得默认递归套入卷纲和每个事件。AI推荐时至少给出两个节奏明显不同的白话方案和一个“自己安排”入口，说明适合理由与套路风险。题材和预计篇幅只能影响推荐，不能自动确认方案或生成固定反转次数。

作者可以在开书信息、设定、卷纲、事件、章纲和正文旁输入想法。每条想法至少保留作者原话、附件、目标层级/对象、意图强度（必须遵守、强偏好、灵感、问题）、适用范围和当前处理状态。AI必须显示它被采用到哪里、怎样调整、为何暂存或为何未采用；未确认想法不进入正史，也不因模型总结丢失原话。

高潮使用卷内递进阶梯而非恒定高压：

```text
章节中的发现、选择或局部转折
→ 事件级代价与状态改变
→ 卷级不可逆局势重构与核心高潮
→ 卷末余波和下一卷触发
```

每一层可以包含蓄势、受挫、安静、余波和重新选择。系统关注前一高潮留下的后果是否成为下一事件或下一卷的压力来源，不要求每章反转、每个事件同样激烈或按数值曲线写作。若所谓“持续高潮”导致读者麻木、人物没有消化后果或事件只是重复升级，必须降低模板约束并回到因果、人物目标与卷末变化。

推荐协作顺序是：作者填开书信息→与AI讨论并确认设定→为第一卷选择白话节奏方案并补充想法→AI独立形成卷纲候选→作者选择/混合/编辑→逐个设计事件及其白话节奏→只为当前事件滚动设计章纲→逐章创作和结算→卷结算→用前卷后果自然设计下一卷。任何修订都显示影响范围，不静默改写已结算正文。

## 6. 团队与工具能力

先定义能力，再决定可见成员数量：

- 方向统筹与作者协作；
- 两条真实独立的创意路径；
- 设定/连续性与来源核对；
- 单一活动写手；
- 事实、文学、体验三个独立审校维度；
- 任务接管与失败恢复；
- 按需研究、来源授权与原创性风险保护；
- 确定性上下文编译、检索、权限和状态机。

把确定性数据准备、检索、权限和队列交给服务，不用一个拟人Agent垄断数据库访问。成员可以请求岗位专用上下文，但不能直接修改权威数据。

同一正式稿只允许一个活动写手。候任写手用于故障接管、明确A/B或定点重写，不默认对每章串行整稿润色。事实、文学和体验复核使用真实独立来源；岗位名称和人数不能冒充独立性。

研究和来源风险可以是按需能力、工具或非默认成员，但不能因删除可见岗位而删除正式生产所需的来源、授权、相似风险和事实边界。

## 7. 功能和代码精简

删除前建立可达图：

```text
页面/按钮
→ 客户端函数
→ HTTP接口
→ 应用服务
→ Repository
→ 数据表/文件
→ Worker任务/恢复
→ 测试与文档
```

按以下五类处理：

1. **保留**：单一权威、正文/正史、任务恢复、来源原件、安全或仍被核心链使用。
2. **合并**：多个页面或服务表达同一作者用例，但底层数据仍只有一个权威。
3. **停用**：先从新流程移除入口，保留兼容读取和运行观察。
4. **兼容**：旧书、旧URL、旧任务、旧Artifact和旧角色修订仍需读取，禁止新写入。
5. **删除**：静态与运行证据都证明不可达、无数据所有权、无恢复职责且目标回归通过。

不要修改已合并迁移来“清理历史”。不要按目录名删除聊天、版权、研究或旧角色代码；先确认其中是否还承担协作、附件、规划确认、来源隔离、写作准备、恢复或历史显示。

精简指标同时报告：作者步骤和页面切换、重复入口、依赖边数、循环依赖、巨型文件规模、不可达代码、运行任务数、模型调用/Token、恢复时间和缺陷率。文件数或行数下降不能单独证明架构更简单。

先拆分装配层和建立边界测试，再删除逻辑。一次提交只处理一个可回滚能力簇，避免导航、数据模型、团队、检索和审校同时大爆炸切换。

## 8. 验收与回滚

至少覆盖：

- 新流程从开书、第一卷规划到单章结算、卷结算和下一卷启动的公开入口；
- 作者原话、附件、候选、确认和成员回复的对象定位；
- 刷新、切页、取消、超时、结果不明和重启恢复；
- 旧书、旧URL、旧任务、旧角色和旧Artifact兼容；
- 正式正文、正史、来源、审计和删除墓碑零丢失；
- 跨书隔离和权限；
- 当前卷纲→事件大纲→当前事件章纲的引用链与版本防偏移；
- 卷纲和事件节奏可以选择白话方案、自定义或不用模板，节拍可跳过/合并/拆分/重排；
- 作者想法在所有规划层级保留原话、强度、采用位置和未采用理由；
- 高潮阶梯包含后果、张弛和递进，不退化为每章强制反转；
- 单一活动写手与独立审校；
- 来源与原创性风险保护在无独立页面时仍有效；
- 新旧流程的创造性与输出质量非劣效。

出现隐藏能力不可达、重复任务、历史数据丢失、来源保护失效、作者原始想法丢失、自由创作区被模板挤空、层层模板套娃、恒定高强度或盲评退化时，停止删除并回滚对应入口、策略或默认配置。回滚不得删除新产生的作者资料、正文版本、正史、任务和失败证据。
