# 上下文与混合RAG合同

## 权威层次

| 层 | 内容 | 默认检索 | 是否权威 | 生命周期 |
|---|---|---|---|---|
| 正式源 | 已确认正文、设定、规划、决定、正史事实 | 是 | 是 | 不可变版本；可失效但不覆盖历史 |
| 临时源 | 聊天、讨论、初稿、重写稿、中间推演 | 仅当前任务 | 否 | 有界保留、归档或清理 |
| 候选源 | 待确认事实、研究结论、规划提案 | 按任务显式 | 否 | 确认后进入对应正式层，否则失效 |
| 派生Wiki | 人物、地点、组织、规则、事件、伏笔页面 | 是 | 否 | 从正式源重建，带版本与来源 |
| 检索索引 | FTS/BM25、向量、关系邻接、时间投影 | 是 | 否 | 可删除、可重建、不能决定正史 |
| 上下文包 | 某次岗位调用实际采用的资料 | 仅追溯 | 冻结快照 | 依赖变更后失效，不静默改写 |

聊天不是长期权威。聊天中形成的决定、设定或偏好必须经过识别、结构化和相应确认，才能进入正式层。

## 检索流水线

```text
任务与岗位识别
→ 查询解析（实体、别名、关系、故事时间、意图）
→ 硬范围过滤（owner/book/版本/状态/权限）
→ 多路召回
   ├─ 结构化事实与时间状态
   ├─ FTS/BM25精确文本
   ├─ 向量语义相似
   └─ Wiki/关系链接多跳扩展
→ 证据去重与冲突检测
→ 融合与岗位重排
→ 原文/正式事实回查
→ 上下文预算与排序
→ 不可变上下文包
```

## 各检索通道职责

- 结构化查询：生死、位置、数量、知情、关系、物品归属、故事时间和规则状态。
- FTS/BM25：姓名、专名、原句、口头禅、明确关键词和正文定位。
- 向量：无关键词重合的语义改写、主题、情绪、行为相似和风格片段候选。
- 关系链接：人物—地点—组织—事件—规则—伏笔之间的多跳扩展。
- 时间过滤：返回创作章节当时有效的信息，区分现在、过去、计划、谎言和认知。
- 融合重排：结合硬约束、岗位意图、来源权威、时间有效性和相似度，而非只看向量分数。
- 原文回查：任何重要结论都能定位正式事实或正文片段；Wiki和向量不得成为唯一证据。

## 岗位上下文合同

| 岗位 | 必需来源 | 可选来源 | 默认禁止 | 二次回查条件 |
|---|---|---|---|---|
| 主编 | 老板最新要求、活动决定、任务状态、相关岗位意见 | 关键正史、预算与历史决策 | 全部正文、无关岗位私人记忆 | 意见冲突、重大方向、证据不足 |
| 编剧 | 活动规划、人物欲望、已结算事件、开放伏笔、阶段目标 | 历史相似因果链、读者趋势 | 全部聊天、语言精修记录 | 新路线与正史冲突、转折依赖未知规则 |
| 设定师 | 类型化事实、时间线、人物状态、规则和来源 | 相关原文、候选冲突 | 无来源摘要、失效投影 | 同名实体、时间不可能、规则版本冲突 |
| 主笔 | 写作工单、场景契约、前章状态、相关人物声音、允许伏笔 | 少量风格原文、必要地点和规则 | 整本书、全部讨论、废稿、原始拆书资料 | 人物动机/声音缺证据、伏笔含义不明 |
| 审校 | 完整正文、写作契约、硬规则、相关正史、主笔来源 | 跨章趋势、重复和体验摘要 | 主笔内部解释、无证据偏好 | 软问题可能是合理成长或叙事误导 |

Token预算必须为每个岗位单独设定。硬来源超预算时暂停，不得静默截断；可选来源按作用和证据价值逐级淘汰。

## 上下文排序

1. 任务目标、输出合同和硬禁止项。
2. 当前章节/场景状态与必须遵循的正史。
3. 与查询直接相关的证据。
4. 必要原文和人物声音片段。
5. 低优先级候选、经验和备选。

去除重复表达，但保留不同来源的真实冲突。压缩必须带原文指针、压缩方法和丢弃说明。

## 失败处理

- 检索为空：明确资料缺口；允许创造性新增时标为候选，否则停止。
- 证据冲突：同时返回来源、版本和时间，不由相似度静默裁决。
- 旧版本命中：排除或标记历史用途，不能驱动当前任务。
- 低置信度：扩大一轮关系/原文回查；仍不足时升级。
- 上下文超限：先删重复、低权威、远期和无关岗位资料；硬约束仍超限则暂停。
- 无答案查询：允许回答“不足以判断”，不得用最相似片段填空。

## 示例：张三向天安城宣战

查询不得只搜索完整句子。应拆解为：

1. 解析张三的实体ID、别名、当前状态、阵营、位置、能力和知情边界。
2. 解析天安城的实体ID、控制者、防御、盟友、地理和当前状态。
3. 检索宣战规则、战争规则、触发条件和当前有效版本。
4. 沿人物—组织—地点—事件关系检索双方历史冲突与承诺。
5. 按当前故事时间对比双方实力，排除失效状态和人物未知情报。
6. 回到正式事实和原文证据，区分客观判断与人物主观判断。
7. 向对应岗位提供不同上下文：编剧关注因果与后果，设定师关注规则，主编关注选择与影响。

## 验证要求

- 查询集与实现代码独立，不得用内置同义词生成金标。
- 分通道报告召回、精度、MRR/nDCG、延迟和Token。
- 做消融：结构化、BM25、向量、关系、融合、重排分别移除。
- 与单一FTS、单一向量和整书长上下文比较。
- 验证索引损坏后从正式源重建，且跨书污染为零。
