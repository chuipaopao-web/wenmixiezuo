# 卷—事件工作流的上下文与混合检索

## 1. 原则

上下文由确定性的 `ContextCompiler` 按任务编译，不由某个拟人岗位垄断数据库，也不依赖聊天记忆。

每个ContextPack都要记录：`owner_id`、`book_id`、任务类型、目标对象、活动版本、作者原话、直接权威源、检索查询、纳入/排除理由、裁剪结果、预算、来源指纹和编译版本。每条资料还必须携带约束强度（`hard_fact/current_task/soft_reference/open_space`）、真实性（`planned/actual`）、适用范围、来源版本和依赖。

直接活动版本是规划任务的首要输入；检索用于补充相关事实、历史因果、人物状态、开放线索和声音证据，不能覆盖直接权威源。

## 2. 数据权威

按用途区分：

1. 作者确认的开书信息、设定和正史事实；
2. 已确认正文不可变版本；
3. 全书故事总线、卷方向、事件链、事件设计、章链和详细章纲的活动规划版本；
4. 章节、事件与卷结算；
5. 带来源的作者原话与附件；
6. 可重建摘要、Wiki、向量、关系和分析投影；
7. AI候选、审查报告和失败任务记录。

规划描述未来，不是已经发生的事实。摘要、Wiki、向量和图谱都是导航或派生层，不得反向成为正史。

正式生产不建立聊天历史、会话摘要或对话记忆源。独立灵感保存在隔离域，默认不是生产上下文或事实源；只有作者主动摘录并绑定具体业务对象的片段，才转为带讨论来源的作者原话。任务过程保存为候选、决定、调用与检查点，而不是可无限累积的对话。

## 3. 完整输入与无损压缩

“压缩”不是只保留几句摘要，而是把上游全部有效字段编译成更短的结构化约束包。信息可以换成紧凑表达，覆盖范围不能缩水。

开书信息较短，开书与设定任务直接接收完整活动版本。卷纲及后续任务使用 `BookCorePack`，它必须覆盖开书活动版本中的全部作者字段：书名、定位/卖点、题材与标签、目标读者、预计规模、节奏/风格选择、主角及其他初始角色、身份、性格、目标、核心机制/金手指、开篇场景、作者自定义内容、必须项、强偏好、灵感、问题和附件引用。没有填写的字段保留为空，不由AI猜测补齐。

其他上游信息分别编译为：

- `SettingConstraintPack`：全部活动硬设定的紧凑账本，以及当前任务相关设定原文；四项核心以外的已确认设定只有与当前任务相关时进入，不因数量整体硬注入；
- `BookStorySpinePack`：第一卷建立的长期承诺、主角长期变化、中心问题、升级阶梯、可选结局方向和受保护留白，始终作为软方向；
- `VolumeResponsibilityPack`：活动卷方向的本卷责任、重点表达、人物变化、高潮、卷末状态与作者原话，不携带内部结构方法名；
- `EventResponsibilityPack`：当前事件责任、进入/结果状态、前后因果接口、线索责任和对卷责任的覆盖；
- `ChapterTaskPack`：当前章骨架、完整详细章纲、必须实现、禁止违反、结束状态、下一接口和自由区；
- `RecentActualStatePack`：由最新正文结算形成的人物、关系、资源和局面真实状态；
- `StoryThreadPack`：当前任务相关的承诺、伏笔、问题、关系、冲突和回收软窗口，计划项与实际项分开；
- `BookCorePack`：完整覆盖活动开书字段；它与前述七包共同构成八类稳定组合包。

当前目标对象仍以完整任务对象进入：当前事件完整设计、当前事件完整章链、`CurrentChapterOutlineFull` 和 `CurrentManuscriptFull` 不用摘要替代。三级结算包只记录已发生结果并携带正文/正史来源。

无损压缩必须满足：

1. 所有作者已填字段都有对应字段或显式引用，不能因“看起来不重要”而删除；
2. 作者原话、`must`、强偏好和问题保留原文，不能只保留AI改写摘要；
3. 活动上游目标、硬设定、关键人物、核心机制和因果接口不得省略；
4. 每个压缩项携带来源对象、版本、字段或片段引用，遇到歧义可回查完整原文；
5. 强度和真实性正交分栏：硬事实不等于已发生的剧情，当前任务不自动成为永久事实，软参考不能阻止确认，开放区不能被补造成事实；
6. 上游版本改变后重新编译，旧压缩包随冻结任务失效；
7. 超预算固定按“规范化去重→删除重复摘要→缩短或丢弃软参考→丢弃无关证据”处理；硬事实、当前任务和直接父级合同不得做原始字符串头尾截断，仍超预算时阻止调用并返回可操作原因。

去重先比较规范化内容，再判断来源覆盖关系。若完整活动章纲、完整前章正文或其他完整权威对象已经进入硬来源，同一对象、同一版本的摘要、尾段和检索切片不再重复注入；只有切片包含完整源没有覆盖的独立证据，或完整源未进入资料包时才保留。每个被排除来源都要记录原来源、版本和`duplicate_of_hard_source`或`duplicate_of_included_source`等原因，不能用去重掩盖裁剪。

## 4. 任务上下文矩阵

权威任务矩阵只有一份：`docs/LONGFORM_QUALITY.md` 第 8.3 节（按任务列出直接接收、按需检索、明确排除）；分层创作的八类稳定包与验收状态以 `docs/LAYERED_CREATION_IMPLEMENTATION_AND_ACCEPTANCE.md` 第9节和F01—F15为准。本节不复制整张矩阵，避免多份拷贝漂移。

审查时按该矩阵逐项核对当前任务的 ContextPack：

- 直接接收列中的活动版本与作者已填字段是否完整进入硬来源；
- 排除列内容（其他书、聊天、无关候选、过期版本、未确认猜测）是否确实缺席；
- 每项纳入、排除、去重和裁剪是否记录来源、版本与理由；
- 硬约束是否被预算裁剪静默删除。

## 5. 混合检索路由

按照任务选择通道，不设一个全局相似度阈值：

- 精确通道：ID、名称、别名、规则、版本和活动指针；
- 全文通道：专有名词、原句、约定和场景关键词；
- 语义通道：同义表达、主题与声音相似片段；
- 关系通道：人物、势力、地点、道具、规则和线索邻域；
- 时间/因果通道：前因、后果、最近状态和阶段结算；
- 原文回查：已确认正文、设定与来源附件。

融合前依次执行书籍隔离、版本有效性、权威层级、时间一致性、冲突标注、去重和预算裁剪。相似结果若缺少来源或与活动版本冲突，只能作为待核候选。

## 6. 检索不足与冲突

- 找不到依据：标注未知或需确认，不补造。
- 事实冲突：把冲突双方和来源交给事实审查或作者裁决。
- 规划与正文冲突：正文结算代表实际发生；是否修订后续规划由作者决定。
- 召回过多：按任务关系、来源权威、时间邻近和因果必要性裁剪。
- 召回过少：扩大别名、关系、时间和原文邻域，不先降低全局阈值。

### 类型化资料直达

配角、势力、地点、地图和道具资源公开视图只从本书权威实体、事实、状态和来源重建。结构化查询可命中实际存在的年龄、性格、所属、规模、实力、驻地、地点层级、道具属性、归属和流转；空字段不形成事实。世界路线只证明故事到达先后，不能自动证明地理距离或方向。公开字段不构成永久岗位包，仍按当前任务、版本和预算动态选择。

## 7. 必测项

- 跨书隔离与越权；
- 错活动版本和过期候选；
- 直接权威源不会被语义召回覆盖；
- 摘要误导时能回查原文；
- 作者灵感不会被升级为硬事实；
- `BookCorePack`对全部开书字段的覆盖率为100%，空字段不会被AI补造；
- 八类稳定组合包均保存编译版本、来源版本、纳入/排除理由和预算；
- 卷方向、事件链、事件完整设计、章链、详细章纲和正文均能回查直接父级完整合同；
- 当前任务适用硬事实进入率100%，无关设定不会因“已确认”而整包进入；
- 设定很多时上下文不会随设定总数线性膨胀，也不使用固定前N条；
- 故事线程只按当前任务相关性和事件/卷软窗口进入，不固定精确章号；
- 计划与已发生的真实性标记不会互相冒充；
- 压缩前后作者必须项、强偏好、核心机制、活动设定和上层因果不丢失；
- 三类审查绑定同一正文与完整当前章纲，但事实/文学/体验附加资料和结果相互隔离；
- 章节、事件和卷结算均只能从已确认正文、下级结算和既有正史提取实际结果；
- 下一卷使用上一卷完整真实结算，未实现计划不会冒充历史事实；
- 规划未实现内容不会进入结算；
- 中间、开头和末尾位置证据召回；
- 同义、否定、时间、因果、关系和对抗查询；
- 检索增益与创造性非劣效对照。
