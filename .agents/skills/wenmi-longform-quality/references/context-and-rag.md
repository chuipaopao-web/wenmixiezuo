## 权威层次

| 层 | 内容 | 默认检索 | 是否权威 | 生命周期 |
|---|---|---|---|---|
| 正式源 | 已确认正文、设定、规划、决定、正史事实 | 是 | 是 | 不可变版本；可失效但不覆盖历史 |
| 临时源 | 聊天、讨论、初稿、重写稿、中间推演 | 仅当前任务 | 否 | 有界保留、归档或清理 |
| 候选源 | 待确认事实、研究结论、规划提案 | 按任务显式 | 否 | 确认后进入对应正式层，否则失效 |
| 派生Wiki | 人物、地点、组织、规则、事件、伏笔页面 | 是 | 否 | 从正式源重建，带版本与来源 |
| 检索索引 | FTS/BM25、向量、关系邻接、时间投影 | 是 | 否 | 可删除、可重建、不能决定正史 |
| 上下文包 | 某次岗位调用实际采用的资料 | 仅追溯 | 冻结快照 | 依赖变更后失效，不静默改写 |

聊天不是长期权威。聊天中形成的决定、设定或偏好必须经过识别、结构化和相应确认，才能进入正式层。

检索遵守“最小充分”而不是“越多越完整”。进入模型的资料会改变生成分布，也可能锚定旧剧情和旧表达；任何候选只有对当前岗位、当前任务有可说明的作用才进入上下文。

## 检索流水线

```text
任务与岗位识别
→ 查询解析（实体、别名、关系、故事时间、意图）
→ 硬范围过滤（owner/book/版本/状态/权限）
→ 多路召回
   ├─ 结构化事实与时间状态
   ├─ FTS/BM25精确文本
   ├─ 向量语义相似
   └─ Wiki/关系链接多跳扩展
→ 证据去重与冲突检测
→ 融合与岗位重排
→ 原文/正式事实回查
→ 约束胶囊与灵感调色板分离
→ 上下文预算与最小充分排序
→ 不可变上下文包
```

## 各检索通道职责

- 结构化查询：生死、位置、数量、知情、关系、物品归属、故事时间和规则状态。
- FTS/BM25：姓名、专名、原句、口头禅、明确关键词和正文定位。
- 向量：无关键词重合的语义改写、主题、情绪、行为相似和风格片段候选。
- 关系链接：人物—地点—组织—事件—规则—伏笔之间的多跳扩展。
- 时间过滤：返回创作章节当时有效的信息，区分现在、过去、计划、谎言和认知。
- 融合重排：结合硬约束、岗位意图、来源权威、时间有效性和相似度，而非只看向量分数。
- 原文回查：任何重要结论都能定位正式事实或正文片段；Wiki和向量不得成为唯一证据。
- 创意去锚：风格和相似场景只作少量候选，不因召回命中就强制采用；必要时先形成场景方案，再做第二轮定向回查。

## 五级输入合同

每个上下文包都要区分：

1. 硬事实：正史、当前状态、故事时间、版权和安全边界。
2. 任务目标：本次必须产生的叙事功能和结果，允许不同实现。
3. 软倾向：风格、节奏、气质和建议节拍，可以有理由偏离。
4. 自由创作区：未指定的对白、动作、细节、意象、局部调度和过渡。
5. 重大候选：允许探索但正式结算前需要确认的新规则、命运和主线变化。

硬事实与任务目标组成约束胶囊；少量人物声音、主题、意象和开放伏笔组成灵感调色板。软倾向和灵感不能伪装成硬规则。若自由创作区为空，退回任务书或上下文包。

## 岗位上下文合同

| 岗位 | 必需来源 | 可选来源/创作自由 | 默认禁止 | 二次回查条件 |
|---|---|---|---|---|
| 主编 | 老板最新要求、活动决定、任务状态、各岗位独立意见 | 关键正史、预算、历史决策；可保留少数高潜方案 | 全部正文、无关岗位私人记忆、把人数当共识 | 意见冲突、重大方向、证据不足、少数方案被压缩 |
| 编剧 | 活动规划、人物欲望、已结算事件、开放伏笔、阶段目标 | 历史因果链、读者趋势；自由提出结构不同的备选 | 全部聊天、语言精修记录、旧成功套路全集 | 新路线与正史冲突、转折依赖未知规则、方案过度相似 |
| 设定师 | 类型化事实、时间线、人物状态、规则和来源 | 相关原文、候选冲突；为未知区域说明可创造边界 | 无来源摘要、失效投影、把空白自动当错误 | 同名实体、时间不可能、规则版本冲突 |
| 主笔 | 写作工单、约束胶囊、前章状态、人物声音、自由创作区 | 灵感调色板、少量风格原文、允许伏笔；实现方式自主 | 整本书、全部讨论、废稿、原始拆书资料、唯一句式答案 | 硬动机/声音缺证据、伏笔含义不明、自由区为空 |
| 审校 | 完整正文、写作契约、硬规则、相关正史、主笔来源 | 跨章趋势、重复和体验摘要；软问题允许保留原稿 | 主笔内部解释、无证据偏好、边写边审记录 | 软问题可能是合理成长、叙事误导或有意不规则 |
| 体验官 | 完整章节、目标读者、阶段节奏、承诺—兑现和情绪趋势 | 类型预期、跨章样本；允许有意反预期和留白 | 固定爽点模板、所有历史反馈、单一综合分 | 体验下降可能来自必要铺垫、题材或读者分群 |
| 文编 | 完整正文、作者/角色声音证据、明确语言问题 | 少量对照片段；允许不规则句式和角色差异 | 通用标准文风、全文统一改写、拆书原文 | 修改可能抹平角色、作者声音或整体文气 |
| 研究员 | 研究问题、时间/地区、可信来源和事实边界 | 多种可能解释、现实变体；资料只提供可能性 | 无关资料堆积、把现实常见做法当唯一剧情 | 来源冲突、当前性不足、资料将决定重大剧情 |
| 版权顾问 | 参考来源、授权、隔离资料、待审稿件和风险维度 | 抽象类型惯例、独立表达证据；允许题材共有元素 | 原文进入主笔包、以最保守方案消灭题材特征 | 实质性相似不明、授权范围冲突、误把惯例当专有 |

Token预算必须为九个岗位分别定义，但只为本次被激活岗位实际组包。硬来源超预算时暂停，不得静默截断；可选来源按作用和证据价值逐级淘汰。不能为了岗位“公平”提供相同资料，也不能让九个岗位默认全部参与。

## 上下文排序

1. 模式、任务目标、输出合同和硬禁止项。
2. 当前章节/场景状态与必须遵循的正史。
3. 明确的自由创作区和需要确认的重大候选。
4. 与查询直接相关的证据。
5. 少量必要原文和人物声音片段。
6. 标为可选的灵感、低优先级候选、可撤销经验和备选。

去除重复表达，但保留不同来源的真实冲突。压缩必须带原文指针、压缩方法和丢弃说明。不得通过重复硬规则提高其表面权重，也不得把灵感调色板写成必须逐项消费的检查单。

## 失败处理

- 检索为空：明确资料缺口；允许创造性新增时标为候选，否则停止。
- 证据冲突：同时返回来源、版本和时间，不由相似度静默裁决。
- 旧版本命中：排除或标记历史用途，不能驱动当前任务。
- 低置信度：扩大一轮关系/原文回查；仍不足时升级。
- 上下文超限：先删重复、低权威、远期和无关岗位资料；硬约束仍超限则暂停。
- 无答案查询：允许回答“不足以判断”，不得用最相似片段填空。
- 检索过多：按任务作用裁剪；保留未采用记录，不因“已经召回”要求正文使用。
- 输出锚定旧文：减少相似场景和风格原文，保留硬事实后重新生成，并与原上下文做盲评。
- 自由创作区为空：退回工单或上下文组装，不启动正式主笔。

## 示例：张三向天安城宣战

查询不得只搜索完整句子。应拆解为：

1. 解析张三的实体ID、别名、当前状态、阵营、位置、能力和知情边界。
2. 解析天安城的实体ID、控制者、防御、盟友、地理和当前状态。
3. 检索宣战规则、战争规则、触发条件和当前有效版本。
4. 沿人物—组织—地点—事件关系检索双方历史冲突与承诺。
5. 按当前故事时间对比双方实力，排除失效状态和人物未知情报。
6. 回到正式事实和原文证据，区分客观判断与人物主观判断。
7. 向对应岗位提供不同上下文：编剧关注因果与后果，设定师关注规则，主编关注选择与影响。

## 验证要求

- 查询集与实现代码独立，不得用内置同义词生成金标。
- 分通道报告召回、精度、MRR/nDCG、延迟和Token。
- 做消融：结构化、BM25、向量、关系、融合、重排分别移除。
- 与单一FTS、单一向量和整书长上下文比较。
- 比较最小充分包、全量包和无软资料基线的约束遵循、原创性、人物可辨识度、情绪力度和整体输出质量。
- 验证索引损坏后从正式源重建，且跨书污染为零。
