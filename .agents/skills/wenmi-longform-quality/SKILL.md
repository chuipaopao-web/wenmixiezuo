# 文秘写作长篇质量审查

## 核心原则

把“写不好长篇”或“流程太重”拆成可观察失败、根因、产品机制和验证证据。不要从向量库、多Agent、长上下文、更多页面或更强模型等名词开始。

坚持双底线：减少正史、连续性、恢复、检索和流程失控，同时不得把创造性、人物声音、审美张力和整体输出压平。治理是脚手架，不是文学内容的替代生成器；精简是减少重复责任，不是删除追溯与恢复能力。

只把权威事实、安全、来源与原创性风险、费用、权限、数据隔离和不可逆操作作为硬门禁。规划层级、章数、节奏、风格、偏好、题材模板和经验默认属于软机制；除非老板明确升级且非劣效验证通过，不得在首稿中逐项硬控。

不要声称治理对创造性“零影响”。任何改变模型输入、生成、审校或团队拓扑的机制，都按影响范围相对旧流程或弱治理基线做创造性与输出质量非劣效验证。证据不足时保持候选或可选，不升级为强制默认。

把稳定质量原则与当前产品配置分开。Skill不得写死当前页面、团队人数、成员姓名、模型名称、Token套餐或决定编号；每次从当前权威规格读取这些配置。Skill只约束设计与验收，不能替代业务实现、真实模型评测或作者判断。

## 开始前

1. 完整读取项目 `AGENTS.md` 和与任务直接相关的当前规格。
2. 检查真实代码、测试、数据或运行证据，不以完成声明、建议文档或文件名称代替事实。
3. 先形成独立专业判断，再单独考虑老板偏好和外部建议；建议不是当前决定，偏好不是事实。
4. 将材料标记为：已确认事实、可验证推断、老板偏好、外部建议、未知项。
5. 为重要方案建立唯一 `design_review_id`，记录Skill版本或哈希、引用、替代方案、两轮审查、证据等级和回滚条件。
6. 按任务完整读取适用参考：
   - 影响讨论、规划、生成、审校或经验时读取 `references/creativity-and-output-quality.md`。
   - 诊断创作或流程失败时读取 `references/longform-failure-model.md`。
   - 设计协作到结算的运行流程时读取 `references/runtime-quality-loops.md`。
   - 设计记忆、检索、Wiki或上下文时读取 `references/context-and-rag.md`。
   - 重构页面、合并功能、调整规划粒度或删除代码时读取 `references/workflow-and-simplification.md`。
   - 判断是否可以声称有效或完成时读取 `references/evaluation-contract.md`。

## 先选择创作模式

按用户意图选择最轻且足够的模式，不把模式绑定到某个页面：

1. **上下文协作**：围绕当前资料、设定、事件、章纲或正文交流、质疑和补充；不自动进入正式层。
2. **创意推演**：生成相互独立的剧情、人物或世界候选；保留冲突可能，不提前压成共识。
3. **暂存试写**：试写对白、场景、开头或文风；只进入临时区，不强制全套审校和结算。
4. **正式生产**：生成准备进入正式正文的章节；满足准备、版本、硬检查、独立审校和结算门禁。

不确定时使用限制更少且不写正式层的模式。前三种模式不得因缺少完整规划而被阻断；正式生产不得绕过完整链路。任何模式仍遵守安全、来源与原创性风险、费用、权限、隔离和永久操作边界。

## 建立能力追踪

为每个重要问题建立以下链条：

```text
用户痛点
→ 可观察症状
→ 根因假设
→ 已知事实与未知项
→ 候选机制
→ 最强反例
→ 对创造性与输出质量的潜在代价
→ 可测指标
→ 证据等级
→ 停止或升级条件
```

缺少任一项时，不得声称问题已解决。只说明“使用某技术、增加某岗位、加入事件层或删除某页面”而不能映射失败时，退回方案。

## 执行两轮审查

### 第一轮：建立独立候选结论

1. 明确目标、非目标、成功标准和权威来源。
2. 区分能力“存在”“可运行”“构造测试通过”“独立对抗通过”“真实创作有效”。
3. 至少比较推荐方案、一个可行替代方案和维持现状。
4. 检查方案解决根因还是只改善界面、提示词、角色名称或局部症状。
5. 建立受影响的数据生命周期、能力/工具边界、Token/算力/延迟、恢复和可逆性。
6. 明确硬约束、软倾向、自由创作区和允许新增的候选事实。
7. 涉及精简时建立页面→动作→API→应用服务→Repository→表/文件→任务/恢复→测试的可达图，再分类为保留、合并、停用、兼容或删除。

### 第二轮：攻击第一轮结论

1. 假设方案已经失败，定位最可能的传播路径并据此修正方案。
2. 测试十倍规模、无关键词重合、多跳关系、时间冲突、旧版本命中和无答案查询。
3. 测试关键证据位于长上下文中部、重复资料过多、上下文超限和二次回查失败。
4. 测试作者强烈表达错误观点、历史偏好形成迎合、同模型岗位形成确认偏误。
5. 测试中断、模型离线、结果不明、索引损坏、派生知识过期和跨书隔离。
6. 检查测试数据是否由实现规则生成；自证式测试不得作为独立质量证据。
7. 测试全量资料锚定、规划绝对化、叙事模板层层套娃、恒定高强度、边写边审、过早共识、偏好固化和经验永久化是否让输出更安全却更平庸。
8. 测试受理层、路由器或本地模型是否截断作者原话、越权创作、按消息长度判断风险或冒充独立意见。
9. 测试功能合并或代码删除是否让隐藏入口、历史追溯、附件、确认、恢复、旧书读取或安全能力失效。
10. 将新机制与旧流程或弱治理基线做多样本成对盲评；一致性或代码量改善不能掩盖创造性、整体质量或可恢复性下降。

## 审查十个质量回路

只审查与任务相关的回路，不机械注入全部内容：

1. 权威：事实来源、生效、冲突、失效和裁决。
2. 检索：实体、别名、时间、关系、多跳因果和原文证据。
3. 注意力：能力所需、排除、排序、预算和回查。
4. 规划：作品主脉、当前卷纲、事件大纲、可选节拍模板、近期章纲、场景目标、卷结算和受控修订；不写死固定卷章规模，不把任何叙事模板变成强制正文公式。
5. 人物：状态、知情、欲望、关系、声音和成长。
6. 生成：任务到完整场景，区分硬缺口与自由创作区。
7. 审校：硬检查、独立软检查、证据、定点重写和上游返工。
8. 结算：正文确认、事实候选、投影更新和旧上下文失效。
9. 作者治理：就地协作、异议、反迎合和最终裁决。
10. 纵向质量：重复、节奏、承诺债务、人物/文风漂移和长期回归。

创造性保护横跨全部回路：使用最小充分约束，分离约束胶囊与灵感材料，先完整生成再做软审校，保留少数意见和合理偏离，让经验可质疑、可到期、可撤销。

叙事模板只提供可解释的规划问题、结构候选和节拍职责。作者可以在卷纲或事件层选择、混合、拆分、合并、重排或放弃模板；作者界面使用大白话说明“接下来要设计什么、为什么”，不要求作者理解方法术语。作者原始想法必须保留并标明采用、调整、暂存或未采用理由。高潮设计采用卷内递进阶梯和张弛波形，允许蓄势、回落与余波，不要求每章反转或维持同一强度。

## 读取当前产品合同

每次从当前 `DECISIONS.md`、`PRODUCT.md`、`AGENT_SYSTEM.md`、`MEMORY.md`、`API.md`、`ACCEPTANCE.md` 和活动开发文档读取实际工作流、团队、模型和页面。旧聊天、外部建议、Skill示例和历史release只能提供追溯或候选，不能覆盖老板最新决定。

用能力而不是人数审查团队：创意方案是否真实独立、活动写手是否单一、事实/文学/体验复核是否覆盖且与写手来源独立、上下文是否由可审计服务准备、研究与来源风险是否按需触发、任务状态是否由真实事件驱动。不要把同模型不同头像、同一输出二次改写或工具角色计作独立意见。

删除作者可见页面或岗位时，先辨别其背后的能力是否仍为正式生产所需。可以删除独立入口、重复展示和空转岗位；不得因此删除正文版本、正史、任务/调用证据、来源原件、恢复信息或仍被核心链调用的服务。

## 使用证据门禁

使用 `references/evaluation-contract.md` 的 E0—E4 等级：

- 文档或提示词只能证明计划存在。
- 代码和接口只能证明机制存在。
- 由实现自身规则生成的测试只能证明构造场景。
- 确定性模型只能证明流程、状态、版本和恢复，不能证明文学质量。
- 真实连续创作、跨章盲评和作者验收只能证明评测范围内改善，不能保证所有作品。
- 正史、检索、流程完成率或代码量改善时，创造性、输出质量和恢复能力仍分别通过非劣效门禁；禁止用综合平均分抵消退化。

## 输出审查结果

完整审查至少包含：

1. 明确结论与置信度；
2. 当前事实基线；
3. 能力追踪矩阵；
4. 最强替代方案与取舍；
5. 预先验尸与反例；
6. 修正后的最终设计；
7. 创造性与输出质量保护；
8. 测试与证据等级；
9. 剩余风险与未知项；
10. 停止、回滚和升级条件。

普通单一决策可压缩输出，但仍保留结论、反例、证据和剩余风险。不要向老板机械复制全部检查清单。

完成审计文档后运行：

```powershell
node .agents/skills/wenmi-longform-quality/scripts/validate-audit.mjs <审计文件.md>
```

结构校验通过不等于方案正确，只表示没有遗漏最低可审计字段。

## 停止条件

- 方案需要现金付费、新密钥、永久删除、生产恢复或尚未授权的重大架构改变。
- 关键事实无法从权威代码、数据或来源核实，且不同假设会改变方案。
- 检索、模型或工具结果不明，继续会污染正式层或重复生成。
- 删除目标的可达性、数据所有权、历史兼容或回滚方式没有查清。
- 证据只达到E0—E2却要求宣称已经解决长篇质量。
- 新机制只改善一致性、流程或代码量，却降低原创性、惊喜、人物可辨识度、情绪力度、整体阅读质量或可恢复性。
- 软规则、模板和经验不断累积，已经无法说明主笔仍拥有哪些真实自由创作区。

停止时说明缺口、已完成检查、可安全继续的部分和需要的最小决定。
