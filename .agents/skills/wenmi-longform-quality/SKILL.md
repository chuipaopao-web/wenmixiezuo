# 文秘写作长篇质量审查

## 核心原则

把“写不好长篇”拆成可观察失败、根因、产品机制和验证证据。不要从向量库、多Agent、长上下文或更强模型等技术名词开始。

坚持双底线：减少正史、连续性、恢复和检索等系统性失败，同时不得把创造性、人物声音、审美张力和整体输出压平。治理是脚手架，不是文学内容的替代生成器。

只把事实、安全、版权、费用、隔离和不可逆操作作为硬门禁。章纲、节奏、风格、偏好和经验默认属于软约束；除非老板明确升级，不得在首稿中逐句控制。

“不影响创造性”不能伪装成数学上的零影响保证。任何会改变模型输入、生成或审校的机制都必须按影响范围，相对旧流程或弱治理基线做创造性与输出质量非劣效验证；局部可逆修改做针对性多样本对照，岗位默认或全链路改变做跨任务/纵向评测。证据不足时不得升级为强制软规则。

Skill只约束设计与验收，不能提升基础模型智力，也不能替代业务实现、真实模型评测或作者的文学判断。

## 开始前

1. 完整读取项目 `AGENTS.md` 和与任务直接相关的当前规格。
2. 检查真实代码、测试、数据或运行证据，不以完成声明代替事实。
3. 先形成独立专业判断，再单独考虑老板偏好；偏好不是事实。
4. 将材料标记为：已确认事实、可验证推断、老板偏好、未知项。
5. 根据任务读取参考文件：
   - 任何会影响讨论、规划、生成、审校或成员进化的方案先完整读取 `references/creativity-and-output-quality.md`。
   - 诊断创作失败时读取 `references/longform-failure-model.md`。
   - 设计讨论到结算的工作流时读取 `references/runtime-quality-loops.md`。
   - 设计记忆、检索、Wiki或上下文时完整读取 `references/context-and-rag.md`。
   - 判断是否可以声称有效或完成时完整读取 `references/evaluation-contract.md`。

## 先选择创作模式

先判断当前工作属于哪一种模式；不确定时使用限制更少且不写正史的模式：

1. **开放讨论**：自由交流、发散和质疑；不进入正史，不要求完整规划链。
2. **创意推演**：生成多条剧情、人物或世界方案；只形成候选，保留相互冲突的可能性。
3. **暂存试写**：试写对白、场景、开头或不同文风；只进入临时区，不强制结算和全套审校。
4. **正式生产**：生成准备进入正式正文的章节；必须满足准备、版本、硬检查、审校和结算门禁。

不得把前三种模式误路由为正式生产。只有正式生产不能绕过完整链路；任何模式都不能绕过版权、安全、费用、数据隔离和永久操作边界。

## 能力追踪

为每个重要问题建立以下链条：

```text
用户痛点
→ 可观察症状
→ 根因假设
→ 已知事实与未知项
→ 候选机制
→ 最强反例
→ 对创造性与输出质量的潜在代价
→ 可测指标
→ 证据等级
→ 停止或升级条件
```

缺少任一项时，不得声称问题已解决。只说明“采用某技术”而不能映射失败时，退回方案。

## 两轮审查

### 第一轮：建立独立候选结论

1. 明确目标、非目标、成功标准和权威来源。
2. 区分能力“存在”“可运行”“构造测试通过”“独立对抗通过”“真实创作有效”。
3. 至少比较推荐方案、一个可行替代方案和维持现状。
4. 检查方案解决根因还是只改善界面、提示词或局部症状。
5. 建立受影响的数据生命周期、Agent边界、Token/延迟、恢复和可逆性。
6. 明确硬约束、软倾向、自由创作区和允许新增的候选事实，说明方案为创作者保留了什么选择。

### 第二轮：攻击第一轮结论

1. 假设方案已经失败，定位最可能的传播路径。
2. 测试十倍规模、无关键词重合、多跳关系、时间冲突、旧版本命中和无答案查询。
3. 测试关键证据位于长上下文中部、重复资料过多、上下文超限和二次回查失败。
4. 测试老板强烈表达错误观点、历史偏好形成迎合、同模型岗位形成确认偏误。
5. 测试中断、模型离线、结果不明、索引损坏、派生知识过期和跨书隔离。
6. 检查测试数据是否由实现规则生成；自证式测试不得作为独立质量证据。
7. 测试全量资料锚定、章纲绝对化、边写边审、过早共识、偏好固化和经验永久化是否让输出更安全却更平庸。
8. 将新机制与旧流程或弱治理基线做多样本成对盲评；一致性提升不能掩盖创造性或整体质量下降。
9. 根据攻击结果修改推荐方案，不得只罗列风险后原样通过。

## 十个质量回路

审查与任务相关的回路，不要机械注入无关内容：

1. 正史：事实来源、生效、冲突、失效和裁决。
2. 检索：实体、别名、时间、关系、多跳因果和原文证据。
3. 注意力：岗位所需、排除、排序、预算和回查。
4. 规划：总纲、卷纲、章纲、场景契约和受控修订。
5. 人物：状态、知情、欲望、关系、声音和成长。
6. 生成：工单到场景，禁止自由补齐重大缺口。
7. 审校：硬检查、异模型软检查、证据、定点重写和上游返工。
8. 结算：正文确认、事实提取、投影更新和旧上下文失效。
9. 作者治理：讨论、异议、反迎合和最终裁决。
10. 纵向质量：重复、节奏、伏笔债务、文风漂移和长期回归。

创造性保护横跨十个回路：使用最小充分约束，分离约束胶囊与灵感调色板，先允许完整生成再做软审校，保留少数意见和合理偏离，并让经验可质疑、可到期、可撤销。完整规则见 `references/creativity-and-output-quality.md`。

## 证据门禁

使用 `references/evaluation-contract.md` 的 E0—E4等级。遵守以下最低规则：

- 文档或提示词只能证明计划存在。
- 代码和接口只能证明机制存在。
- 由实现自身规则生成的测试只能证明构造场景。
- 确定性模型只能证明流程、状态、版本和恢复，不能证明文学质量。
- 真实连续创作、跨章盲评和作者验收只能证明评测范围内改善，不能保证所有长篇作品质量。
- 正史正确率、检索分数或规则遵循率提高时，创造性和输出质量仍必须单独通过非劣效门禁；禁止用综合平均分抵消退化。

## 输出合同

完整审查输出：

1. 明确结论与置信度；
2. 当前事实基线；
3. 能力追踪矩阵；
4. 最强替代方案与取舍；
5. 预先验尸与反例；
6. 修正后的最终设计；
7. 创造性与输出质量保护；
8. 测试与证据等级；
9. 剩余风险与未知项；
10. 停止、回滚和升级条件。

普通单一决策可压缩输出，但仍保留结论、反例、证据和剩余风险。不要向老板机械复制全部检查清单。

完成审计文档后运行：

```powershell
node .agents/skills/wenmi-longform-quality/scripts/validate-audit.mjs <审计文件.md>
```

结构校验通过不等于方案正确，只表示没有遗漏最低可审计字段。

## 停止条件

- 方案需要现金付费、密钥、永久删除、生产恢复或尚未授权的重大架构改变。
- 关键事实无法从权威代码、数据或来源核实，且不同假设会改变方案。
- 检索、模型或工具结果不明，继续会污染正史或重复生成。
- 证据只达到E0—E2却要求对外宣称已经解决长篇质量。
- 新机制只改善一致性指标，却在成对盲评中降低原创性、惊喜、人物可辨识度、情绪力度或整体阅读质量。
- 软规则、历史偏好或经验不断累积，已经无法说明主笔仍拥有哪些真实创作自由。

停止时说明缺口、已完成检查、可安全继续的部分和需要的最小决定。
