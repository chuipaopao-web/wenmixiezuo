# 文秘写作 UI/UX

这是可用性与交互质量 Skill，不是产品蓝图。它帮助理解作者要完成什么、减少操作负担并验证真实界面，不能替老板决定页面数量、导航、工作流、对象层级、卡片数量、视觉风格或AI介入节点。

## 先判断模式

- **从零设计或 V7 探索**：以老板当前目标、用户负担和本轮讨论为输入。V6 页面、截图、规格和组件只证明当前状态或痛点，不是新设计必须继承的模板。可以提出、比较、推翻或合并多种方案；老板确认前不写产品代码、不把建议变成验收门禁。
- **已批准设计的实现**：以批准的原型、状态流和变更合同为基准。被新设计替代的旧入口、样式和行为不作为回归门禁；合同明确保留的能力、失败恢复和数据读取必须回归。
- **局部 UI 修复**：只保护变更合同明确列出的相邻区域、共享外壳和设备行为，不假定整站当前视觉都不可动。

外壳、导航、设备习惯或品牌元素只有在老板本轮明确确认后才视为设计输入；后续新决定仍可修改。整体探索不默认读取旧视觉图、旧页面清单、旧创作层级或历史验收，也不用“保持一致”否决新信息架构。

## 先理解任务

设计讨论先理解当前目标和负担；实现或修复时再读取当前页面代码、直接共享组件、相关状态/API合同，以及可用的当前截图或浏览器状态。旧页面证据用于定位问题，不用于预设答案。需要从零制作视觉概念时可按需使用 `frontend-app-builder`；普通讨论和局部调整不触发它。

先写三句话：

1. 用户此刻要完成什么；
2. 当前最妨碍完成的是什么；
3. 哪些信息和操作必须现在出现，哪些可以稍后或按需出现。

## 局部修改保护

修改前在本次变更合同登记老板明确要求保护的区域和行为。没有被列为保护对象的旧视觉不是永久规范，但仍不得在局部任务中顺手改动无关区域。

- 局部 UI 问题不得修改全局 CSS、全局 token 或共享外壳，除非证据证明根因确实位于共享层。
- 必须修改共享层时，先列出所有受影响页面，并为这些页面补齐对应视觉和交互回归。
- 修改前后对相关区域保留同视口截图对照；没有截图或真实浏览器证据时只能标记“未验证”。
- 同时检查当前状态以及空、工作中、完成、失败和恢复状态；不适用的状态要说明原因。
- 新 UI 通过不能替代合同明确保留能力的回归；被新设计明确替代或删除的旧入口和旧交互不作为门禁。

## 结构与状态

不强制使用三层工作台、卡片矩阵、抽屉、时间线或单一主按钮。根据当前任务选择最少且最清楚的结构：用户应容易理解当前位置、当前状态、主要内容和可执行动作；内容层级来自任务关系，不靠重复边框、标题和说明堆叠。

## 状态驱动

只设计本功能真实存在的状态。不要为了满足通用清单凭空增加“选择、融合、主编、审查、过期”等步骤。AI候选、作者输入、正式内容和历史版本不能混淆；AI工作状态来自真实任务；存在的阻断必须说明影响并提供恢复动作。

## 逐层显露

优先减少当前不需要的决定，何时显示未来信息、专业字段或更多选项由本轮产品设计决定，不由旧创作层级决定。AI何时介入、由谁触发以及是否展示比较方案，也必须来自当前工作流而不是 Skill 默认值。

长说明改成一句范围说明 + 就近帮助；专业结构术语转换为本书的具体故事路线。作者原话、AI方案、活动定稿和历史版本视觉上必须可区分。

## 响应式与可访问性

目标设备和视口由当前设计合同决定，不能由 Skill 固定产品形态。无论采用何种视觉方案，都应保证：

- 主操作位于自然阅读流末端或稳定底部操作区，不能被浏览器栏/键盘遮挡；
- 触控目标约44px，输入字号至少16px，尊重安全区和动态 `visualViewport`；
- 桌面结构在小屏采用适合当前设计的重排方式，不把多栏硬压成一栏小字；
- 页面本身不产生非预期横向溢出，主要内容与操作始终可达；
- 键盘弹起、旋转、长书名、长错误和高倍字体都要可达。

## 视觉语言

视觉方向从老板批准的概念与内容任务中产生。安静、浓烈、文学感、工具感、卡片式或无边框都不是 Skill 的默认答案；只要求层级清楚、可读、对齐稳定、焦点明显、对比合格和交互反馈一致。动效解释状态或空间关系，并尊重减少动画设置。

## 实施节奏

整体重设计先形成信息架构、关键状态流和必要的桌面/手机原型，再由老板确认是否开发。实现顺序根据依赖、风险和纵向闭环决定，不固定为任何旧页面顺序。每批应可回滚，不用半套新旧交互强迫作者猜规则。

## 验收

实现后读取 `references/interface-review.md`，只检查本次实际页面和状态。通常验证相关组件测试（若有）、Web类型检查/构建以及可用环境中的真实浏览器场景；测试范围服从变更合同，不因使用本 Skill 自动触发全量测试或长篇质量验收。

只有老板明确要求研究其他写作产品或需要比较交互模式时，才读取 `references/writing-workspace-patterns.md`。其中内容是可质疑的研究样本，不是文秘写作的默认信息架构。
