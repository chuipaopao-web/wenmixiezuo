# 界面短验收

只检查本次受影响页面，不生成大报告。本清单验证可用性，不规定信息架构、页面数量、视觉风格或工作流；不适用项直接略过并说明。

## 任务与层级

- 只看标题、状态和按钮，能否知道“在哪、正在做什么、下一步是什么”？
- 当前最重要的操作是否容易识别？多个并列操作是否有真实业务理由？
- 是否重复解释同一件事，或用卡片边框代替层级？
- 当前对象、作者输入、AI候选、确认稿和历史版本是否容易区分？

## 状态与恢复

- 本功能真实存在的空、加载/工作中、待决定、完成、失败、只读/过期状态是否有设计？
- 工作中是否说明阶段、可否离开、结果保存在哪里？
- 阻断是否给直接恢复动作，而不是只说“条件不满足”？
- 刷新、返回、重复点击和任务完成后，选择/输入是否保留且不重复发任务？

## 表单与AI协作

- 用户最少要提供什么？非必填是否明确且可跳过？
- 选项数量、搜索、自定义和默认值是否符合当前任务，而非沿用旧页面习惯？
- AI介入时机是否来自当前工作流，状态和消耗是否真实？
- 需要比较时是否突出真实差异和代价，而不是让作者阅读长同义文？
- 确认后是否收起过程并突出结果/下一步？

## 手机

- 当前合同的目标手机宽度无非预期横向滚动；长书名和长错误可换行。
- 主要触控目标约44px；输入16px以上；焦点、键盘和安全区处理正确。
- 抽屉打开可见、可点、可关闭；遮罩层级不盖住抽屉。
- 固定顶部/底部不遮正文，主按钮在键盘弹起时仍可达。
- 方案比较、长表单和正文编辑没有把桌面多栏硬压缩。

## 可访问性与视觉

- 语义按钮/标签、键盘操作、可见焦点、对比度和非颜色状态提示成立。
- 动效使用 transform/opacity 为主，尊重 `prefers-reduced-motion`。
- 视觉风格符合批准的概念；层级、对齐、可读性和交互反馈不依赖某种固定配色、边框或装饰密度。
- 文案是业务语言，不含设计评论、内部ID、模型名、JSON、路径或堆栈。

## 工程

- 按当前设计选择复用或升级共享token/原语；局部实现不散落不可维护的一次性CSS。
- 成功、失败、禁用、重复点击和旧数据兼容有相关测试或手工证据。
- 运行相关组件测试（若有）、Web类型检查和Web构建。
- 可用浏览器时截取手机和桌面关键状态；环境不可用时诚实说明，不伪造视觉验收。
