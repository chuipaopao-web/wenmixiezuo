## 明确结论与置信度

结论：采用老板明确的卷驱动主流程——“开书信息→设定大纲→当前卷纲与节奏→事件大纲与节奏→当前事件章纲→正文→卷结算→下一卷”，置信度高。内部可以参考成熟叙事方法，但前端必须改写成大白话任务卡；作者想法在每层保留原话并作为AI输入；事件、章纲和正文通过活动规划版本链防止静默偏移。

卷纲应重新成为正式、版本化规划对象，但不恢复固定卷长或一次规划全书全部卷。所谓“约束”只阻止无提示漂移；有价值的偏离通过影响预览和作者确认修订上层规划。所谓“持续高潮”通过事件后果递进、卷级高潮和卷末余波实现，不要求每章反转或恒定高压。

该结论已达到E0：方向和合同清楚。Skill文件与参考更新属于E1机制文件存在；只有代码、迁移和接口存在后才能称工程实现，真实长篇有效仍需E3/E4证据。

## 当前事实基线

### 已确认事实

- 当前书内流程仍分散在对话、创作台、图谱、资料库、版权和取名等入口；设定与剧情讨论仍会跳转独立对话页。
- 当前创作台主要显示本书资料、设定大纲、剧情总纲、章纲和正文，尚没有老板要求的正式卷纲→事件→章纲版本链。
- 当前Web主装配和样式文件体积很大；对话、讨论和章节流水线也承担任务、恢复、路由和确认，不能按页面名称整包删除。
- 当前数据库历史曾退役独立卷纲Artifact，`artifacts` 类型受既有CHECK约束；重新启用正式卷纲必须使用新决定和向前迁移，不能修改旧迁移或假装旧阶段等于新卷纲。
- 当前正文已经使用不可变版本、作者确认和正史结算，这些能力可以保留并接入卷驱动流程。
- 当前消息、讨论、附件、任务、上下文包、来源和调用记录具有历史或恢复价值；退役独立页面不等于删除底层能力。

### 可验证推断

- 正式卷纲能在阶段过大、近期章纲过小之间提供作者易理解的长程约束，但如果细化到全卷逐章不可修改，会放大前期猜测错误。
- 事件完成前先形成完整章节序列、再只冻结近期1—3章，可以兼顾“先设计好再写”和正文反馈后的滚动调整。
- 把成熟结构方法改成白话卡能降低学习门槛；如果只改标题、不改问题与预览，作者仍会感到抽象。
- 让每个下层任务引用活动上层版本可以发现漂移；如果把全部卷纲和全部资料原文注入模型，又会产生Token过载和检索锚定。

### 老板已明确方向

- 作者开书并填写信息后，先与AI设计和讨论设定大纲。
- 设定后设计第一卷节奏，选择模板并加入作者自定义想法。
- 再设计事件及事件节奏，作者继续加入想法。
- 根据第一个事件设计章纲，章纲设计完成后再开始正文。
- 编剧必须结合卷纲、事件大纲、开书信息和章纲信息，保证小事件服从大卷纲方向。
- 一卷结束后自然引入下一卷。
- 前端不能直接显示“救猫咪、五幕式”等术语，必须用大白话告诉作者怎么设计、当前步骤是什么。

### 未知项

- 第一版白话卷纲卡和事件卡各保留多少种，需用作者原型测试选择负担。
- 卷纲编辑界面更适合时间线、卡片链还是上下分层，需要视觉原型验证。
- 旧书中旧剧情总纲、阶段和物理卷如何生成新卷纲迁移候选，需要只读统计和样本核对。
- 九名可见团队候选尚未得到老板确认，不能与本次卷驱动流程一起自动激活。

## 最强替代方案与取舍

### 方案A：逐项照搬外部建议

优点是流程完整、卷—事件—章层级直观。缺点是固定卷章范围、专业模板名、固定摘要和阈值、双写手串行、批量正文等会增加模板化、费用和恢复风险。采用其卷驱动骨架与作者参与方式，拒绝固定数量和机械参数。

### 方案B：全书蓝图—当前阶段—可选事件

优点是理论上灵活、适合不同体量。缺点是“当前阶段”对作者不如“第一卷/第二卷”直观，也不能满足老板已明确的卷纲约束与卷末接续。该方案被老板最新方向替代，只保留“不要一次细化全书”的保护原则。

### 方案C：卷驱动、白话模板、版本防偏移（推荐）

开书信息和设定形成作品主脉；一次只详细设计当前卷；卷内逐个设计事件；当前事件先形成完整章节序列，再滚动冻结近期章纲；正文逐章结算；卷末按实际正文结算并自然启动下一卷。模板内部专业、前端白话；作者想法跨层可追溯；重大偏移由作者裁决。

代价是需要重新建立正式卷纲数据对象、旧规划兼容和更多版本引用测试，但它最符合作者心智与老板最新要求，回滚也可以按卷纲、事件、前端卡片分别进行。

## 预先验尸与反例

假设推荐方案失败，最可能的路径：

1. 卷纲被做成全卷逐章硬表，正文有新发现时无法调整，写手开始机械填空。
2. 前端虽然隐藏方法名，但卡片说明仍充满“激励事件、第二幕”等术语，作者仍不知道要填什么。
3. 同一个内部模板自动继承到每个事件，所有事件形成同构的受挫—反转—胜利。
4. “保证不偏移”被实现成任何局部变化都阻断，人物行为不再自然。
5. 为了保证上下文完整，把开书、设定、卷纲、事件、章纲和资料全文全部注入，关键约束反而淹没。
6. 事件设计引用旧卷纲版本，章纲又引用旧事件版本，系统表面有层级但实际错版。
7. 当前事件几十章的详细章纲一次冻结，早期正文反馈无法改变后续，维护成本陡增。
8. 卷末只显示“完成”，没有从正式正文结算人物状态和开放线索，下一卷重新开局或继承错误。
9. 删除独立对话页时连同附件、点名、失败恢复和历史记录一起切断。
10. 为了少写代码把旧剧情总纲直接视为新卷纲，旧书出现语义和版本错配。

第二轮修正：卷纲只锁重大方向并保留自由区；前端卡片使用白话问题、预览和风险；卷与事件不自动继承同一模板；偏移分为硬冲突、规划偏移、合理偏离和有价值重大偏离；上下文使用最小相关摘取加完整版本引用；每个任务冻结上层版本；事件全章序列先形成但只冻结近期1—3章；卷末从正式正文结算；旧页面先停用后删除；旧规划只生成待确认迁移候选。

## 修正后的最终设计

```text
开书信息与作者想法
→ AI协作形成活动设定
→ 第一卷选择白话节奏方案
→ 两条独立卷纲候选
→ 作者选择/混合/编辑并确认活动卷纲
→ 当前事件选择白话节奏并形成事件候选
→ 作者确认活动事件
→ 设计当前事件完整章节序列
→ 冻结近期1—3章任务
→ 单一活动写手逐章创作、三维审校、作者确认与结算
→ 事件结算并承接下一事件
→ 卷结算
→ 用卷末后果和开放线索设计下一卷
```

活动依赖链：

```text
开书信息版本
+ 活动设定版本
+ 上一卷结算（后续卷）
→ 活动卷纲版本
→ 活动事件版本
→ 活动章纲版本
→ 正文上下文包与正文版本
```

每次上层规划变化都产生新版本并使未执行的下层候选失效或要求重算；已结算正文与正史不被改写。作者想法独立保存原话，通过引用进入卷纲、事件和章纲版本。

前端主流程固定为“开书信息、设定大纲、卷纲设计、事件设计、章纲设计、正文创作”，辅助工具为图谱、资料库和取名。左栏只显示书籍。

## 创造性与输出质量保护

- 卷纲约束目标、因果、重大节点与卷末接口，同时明确保留对白、场景、动作、意象和局部调度的自由创作区。
- 所有新机制都与旧流程基线比较，按影响范围执行创造性与输出质量非劣效测试和匿名盲评。
- 白话节奏卡是作者可改写的规划起点，不是评分清单；始终提供自定义和不用模板路径。
- 同一内部模板不自动从卷纲继承到事件，避免结构套娃。
- 当前事件先形成完整章节序列，但只冻结近期1—3章，正文反馈可以受控修订后续章纲。
- 高潮通过后果递进；允许安静、恢复、关系深化和卷末余波，避免恒定高压。
- 作者的“必须、强偏好、灵感、问题”分开处理，模型不得把灵感升级成硬规则。
- 新卷纲、模板、上下文和防偏移机制分别相对旧流程做消融与盲评，一致性提升不能抵消原创性、人物、情绪和整体阅读质量下降。

## 测试与证据等级

- E0：本审计、Skill和卷驱动开发设计相互一致。
- E1：卷纲/事件不可变版本、白话模板注册与实例、作者想法映射、上下文版本链和兼容适配器存在。
- E2：Repository、API、迁移、旧书升级、任务恢复、跨书隔离、前端步骤、版本失效、卷结算和下一卷启动测试通过。
- E3：错版注入、静默偏移、模板套娃、上下文超限、故障恢复、旧书迁移和至少200章规模回放通过。
- E4：真实模型按20/50/100—200章连续创作，与旧流程匿名盲评，在限定题材与模型范围内达到方向一致性和核心创作维度非劣效。

必须单独测试：第一卷路径、后续卷路径、作者不用模板、自定义模板、卷与事件选择不同节奏、事件完整章纲加近期冻结、上层修订失效、卷结算、卷末余波引出下一卷，以及专业术语不出现在前端卡片标题和主要引导中。

## 剩余风险与未知项

- 白话模板卡片数量、顺序和默认推荐需要作者原型验证，不能只由开发者决定。
- 当前物理分卷、旧剧情总纲和新正式卷纲之间的映射需通过真实旧书样本确认。
- 卷纲防偏移提醒过多可能打断创作，需要区分硬冲突、重大规划影响和自由区。
- 卷内事件与章节数量变化会影响进度展示，但不得要求凑齐原预计数量。
- 下一卷“自然引入”最终是文学质量目标，工程只能保证结算输入、承接字段和流程可运行；效果需要E4验证。
- 九名团队候选未确认，不能与本次流程一起默认切换。

## 停止、回滚和升级条件

- 若正式卷纲的语义、旧规划映射或物理卷关系尚未冻结，不开始迁移和业务写入。
- 若事件、章纲或正文无法可靠引用活动上层版本，不启用卷纲防偏移声明。
- 若白话模板仍要求作者理解专业术语，或不同卡片产生同构输出，停止设为默认并保留自定义路径。
- 若卷纲约束造成创作阻断、人物工具化、恒定高压或核心创作维度低于基线，关闭对应硬门禁并回到软提示与作者确认。
- 若卷结算不能从正式正文和正史原子派生，不自动启动下一卷。
- 若新入口不能覆盖设定讨论、想法输入、附件、点名、候选选择、失败恢复和历史追溯，不退役独立对话入口。
- 若旧书、历史任务、正文、正史、来源或恢复证据无法读取，停止删除并恢复兼容适配器。
- 回滚只撤销新导航、白话模板默认、卷纲/事件编排和上下文策略；不回退已合并迁移，不删除作者想法、规划版本、正文、正史和审计证据。
- 任何真实付费、新密钥、生产恢复、永久删除或超出当前授权的架构变化必须单独升级老板。

## 外部建议完整覆盖补充审查

### 新增事实基线

- 当前前端仍有“对话、创作台、图谱、资料库、来源风险、取名”等书内入口，创作台仍是“本书资料、设定大纲、剧情总纲、章纲、正文”五页。
- 当前开书合同已支持从零/续写、多主角、分类标签、故事方向、背景、地图、必须遵守和高级风格意图，不能退回只支持单主角的简化表。
- 当前白话剧情模式库已经包含适用范围、推进结构、收益与风险，可复用并拆成卷级和事件级注册，不需要重造一套重复内容。
- 当前章纲V2、不可变正文、单活动写手、候任写手接管、三职责异模型审查、任务租约/心跳/取消/恢复、混合检索、阶段结算和续写反向章纲均已有实现基础。
- 旧volume_outline规划曾被向前迁移停用；新卷纲不能修改旧迁移或直接复活旧Artifact写法，应使用独立规划卷领域并让旧总纲生成待确认候选。

### 完整裁决结论

采用：卷—事件—章、事件后果承接、渐进开书、设定模块讨论、卷节奏轨道、事件链、两条独立编剧方案、事件章纲、三维审查、作者全程裁决、真实任务状态和卷末承接下一卷。

修改采用：固定体量改为估计范围；题材/风格改为软推荐；爽点选择改为读者收益意图；融合改为重组连贯候选；全事件章纲只冻结近期一至三章；副编改为资料质量复核；摘要改为版本化导航；固定状态面板改为响应式任务投影；并发、超时和Token改为版本化策略。

不采用：全局0.8向量阈值、副编独占数据库、固定节拍频率、默认双写手串行整稿、批量正式正文、摘要压缩时删除权威信息、在正式正文内留下“需确认”占位、结果不明自动重试。

暂缓：团队人数与成员重分配、首批模板数量与排序、固定并发和生产预算。这些不阻塞卷驱动工作流。

### 两轮审查补充

第一轮反例：照搬外部建议会把现有多主角/续写能力降级，把旧剧情总纲误当卷纲，把摘要当事实，把单阈值当检索正确性，把每章双写手整稿变成声音同质化与成本倍增，并使批量正文绕过章结算。

第二轮修正：保留现有成熟底座，新增专用volume_plans与story_events版本链；卷级和事件级模板分开；作者原话独立保存；ContextCompiler负责确定性资料准备；正文只接收相关卷约束而非整份卷纲；卷末以正式正文与正史结算；页面退役前先完成对象旁协作和来源门禁替代。

### 证据与停止条件

本轮仍是E0设计与代码事实核对，不能证明文学质量改善。实施后必须分别取得E1机制、E2构造/故障、E3独立回放和E4真实连续创作证据。

以下任一发生即停止默认升级：旧书或续写路线退化；规划卷与物理卷混淆；错版上下文进入任务；卷纲约束使自由区为空；模板导致卷与事件同构；作者原话失真；独立页面退役造成附件、来源、安全或恢复缺口；一致性提升但原创性、人物、情绪或整体阅读质量下降。
