# 产品规格

## 1. 产品定位

小说平台是一个“对话式小说创作工作台”。老板可以同时创建多本小说，每本书拥有完全隔离的团队、记忆、任务、正文、正史和预算。老板主要通过说话完成建书、讨论、规划、写作、暂停、继续、选稿、修订和查看成果。

## 2. 核心用户体验

老板输入想法后，活动主编应主动完成以下工作：

1. 识别这是闲聊、咨询、创作讨论、重大会审、建书、写作任务还是明确控制命令。
2. 读取当前书籍、有效决定、故事圣经、相关正文和任务状态。
3. 对信息不足但可安全补全的内容给出默认建议；只有方向性差异、重大正史、高费用、版权风险或不可逆操作才请求老板决定。
4. 选择相关岗位参与，而不是召唤全部成员。
5. 汇总不同意见，明确推荐方案、理由、分歧和影响。
6. 老板确认后推进后续流程，并将长期有效信息写入相应数据层。

平台不得要求老板理解数据库、分支、迁移、API或测试命令。

## 3. 页面和交互

### 3.1 桌面端

采用可折叠三栏：

- 左侧：书籍、当前任务、卷章目录、创作阶段、故事圣经和资料入口；“当前任务”标题可打开任务中心二级页面，任务行可查看章节、阶段、检查点和任务书，并可执行真实取消。
- 中间：对话、Agent发言、任务回报和老板输入；任务中心二级页面集中显示进行中的任务、最近任务、预算和待确认事项。
- 右侧：只显示带原型头像的女性成员身份、短岗位和真实状态。

两侧栏保持紧凑，桌面默认约为176像素和190像素，把主要横向空间留给中间创作区。默认使用低饱和浅绿色底色，设置中可切换米白、雾蓝和夜间底色，并调整四档字体大小。正文、故事圣经、章纲和图谱拥有独立成果页。正文阅读模式可以完全收起两侧区域，并使用适合长文的宽度、字号和行距。

### 3.2 手机和平板

- 对话和正文阅读是主界面。
- 书籍、任务与目录进入左侧抽屉；点击任务入口后在主内容区打开任务中心。
- 右侧抽屉只显示团队成员和真实状态；资料继续使用中间独立成果页。
- 输入框固定在安全区域，不被软键盘遮挡。
- 正文、故事圣经和图谱使用全屏页面。
- 不把桌面三栏机械压缩到手机屏幕。

### 3.3 PWA与离线

- 支持安装到桌面。
- 只缓存已经加载过的正文、故事圣经和知识快照。
- 输入草稿保存在IndexedDB，刷新和短暂断网后不丢失。
- 不缓存或伪造离线模型结果。
- 正史版本变化后，相关旧缓存必须失效并重新校验。

### 3.4 命令和确认

- “暂停”“继续”“取消”“回到上一版”等明确命令使用确定性规则识别，零模型调用。
- 模糊的创作意图才交给模型理解。
- 普通确认可以使用明确按钮或包含对象的自然语言。
- 重大正史和高费用操作必须显示对象、范围、影响和费用，再由明确按钮或严格确认词确认。
- “好”“可以”“嗯”等模糊回复不能确认重大操作。
- 永久删除不提供绕过门禁的按钮，必须输入包含 `YES`、对象名称和短ID的完整确认词。

## 4. 每本书的9个岗位

每本书创建5个核心岗位和4个按需专家岗位。岗位详情、激活规则和模型独立性见 `AGENT_SYSTEM.md`。

成员栏直接显示九名稳定女性身份和短岗位：貂蝉（主编）、婉儿（编剧）、文姬（设定师）、秋香（主笔）、妲己（审校）、昭君（体验官）、清照（文编）、道韫（研究员）、弄玉（版权顾问）。完整职责只在岗位详情中展示。状态位于姓名下方，采用空闲、排队中、后台工作中、需要处理和离线五种真实语义。

核心岗位负责持续闭环；按需专家仅在任务相关时参与，避免所有成员同时发言和重复消耗Token。

## 5. 建书流程

### 5.1 输入方式

老板可以：

- 用自然语言描述题材、剧情、标签和风格；
- 从分类、主题、情节、感情线、爽虐倾向、文笔风格和热门标签中选择；
- 同时使用自然语言和标签，并继续补充。

### 5.2 定位卡

系统将输入整理为可编辑定位卡，字段必须区分：

- 老板明确提供；
- 系统推断；
- 尚未指定；
- 存在冲突。

老板确认定位卡后，系统原子创建书籍、9个岗位Agent实例、配置快照、预算、故事圣经骨架和基础资料。任何一步失败都不能留下半本书。

### 5.3 多书隔离

切换书籍时同时切换：消息、目录、滚动位置、面板、输入草稿、当前任务、阅读版本、Agent记忆和预算。页面状态以 `book_id` 为顶层隔离键。

## 6. 题材自适应

题材、标签和老板偏好共同形成版本化适配快照。适配内容包括：

- 岗位提示与专业关注点；
- 写作质量维度和权重；
- 情绪、爽虐、节奏和钩子标准；
- 题材专属Schema，例如游戏属性、历史时间线、技能装备或感情线；
- 推荐的专家岗位和研究来源；
- 不适用或需要抑制的通用规则。

定位变化不会静默改写旧成果。受影响的计划、上下文包和任务必须失效或进入复核。

## 7. 规划成果

规划按以下层级生成并版本化：

```text
创作方案
→ 故事圣经
→ 总纲
→ 卷纲
→ 章纲
→ 写作契约
```

- 固定骨架保证信息完整。
- 题材模块和书籍扩展负责适配。
- 越远章节越粗，近期章节逐步细化。
- 计划、候选设定和已经发生的正史事实必须分开。
- 老板可以从对话直接打开、比较、确认或返回历史版本。

## 8. 主笔选择

支持三种模式：

- 标准：Codex和GLM在同资料、同章纲、同修改机会下进行匿名样章盲测。
- 快速：根据题材适配、健康状态和历史表现直接推荐。
- 老板指定：老板明确指定主笔。

完整盲评至少由两个非参赛、真实不同模型进行独立评审。先过硬门禁，再按剧情、人物、画面、语言、情绪、钩子、正史符合度和修改能力评分。总分差达到5分时形成推荐；不足5分或分歧较大时交由老板盲读决定。

临时代笔与正式换笔分开。连续代笔3章进入换笔评估；正式换笔后的第一章是加强审校的试笔章。

## 9. 单章与多章创作

一次可以安排3至5章，但必须逐章串行：

```text
预检
→ 上下文包与写作契约
→ 完整初稿写入暂存区
→ 硬规则检查
→ 异模型审校
→ 最多两次定点重写
→ 最终复核
→ 事实提取
→ 正史结算
→ 保存章末状态
→ 更新后续章纲
→ 下一章
```

- 前章未结算，后章不得开始生成。
- 半章只能保存在暂存区，不能拼接进入正式正文。
- 中断恢复从下一项能够证明尚未完成的阶段继续。
- 已完成章节不得重复生成或重复计费。

## 10. 写作与审校

写作采用积极标准：具体场景、动作、人物声音、心理、张力、信息差和读者期待。系统不使用永久禁词表，也不通过机械同义词替换“去AI味”。

审校意见必须包含位置、问题类型、严重程度、引用依据和可执行修改要求。严重度为：

- `blocker`：不能进入下一步；
- `major`：必须修复或由主编明确处理；
- `minor`：建议修复，可进入定点重写；
- `observation`：观察项，不直接阻断。

每次修改产生新的完整不可变版本。同类重大文风问题连续两章且定点重写无效时，停止机械润色，调整主笔、模型、章纲或写作契约。

## 11. 讨论与决策

### 11.1 讨论类型

- 快速讨论：主编加1至2个相关岗位。
- 协同讨论：主编加3至5个相关岗位。
- 正式会审：用于重大方向、选稿、主笔选择或高风险冲突。

### 11.2 流程

```text
建立讨论范围
→ 独立意见
→ 交叉复核
→ 主编形成候选方案
→ 相关成员补充或提出有理由的异议
→ 主编修订
→ 老板决定或系统按授权收口
```

未回复或离线成员不阻塞收口；系统不伪造其意见。讨论结论只有在满足相应门禁后才进入项目决定或小说正史。

## 12. 拆书、借鉴与版权

支持四条路径：研究分析、快速参考、干净室借鉴、已授权改编。

- 原文、详细逐章摘要、人物映射和拆书FTS不能进入主笔上下文。
- 抽象结构卡必须去除专有名词、独特场景、人物映射和原事件顺序。
- 新方案重新设计人物、关系、因果、世界规则、转折、高潮、结局、主题和表达。
- 生成前检查结构，生成后分别检查文本、设定、关系、事件链、章节结构、标志性场景和表达。
- 换名仿写、近似改写、翻译规避和多来源拼接不能通过普通确认放行。

## 13. 联网研究与推荐

只有需要当前市场、热点、历史核验或版权核实时才联网。网络资料进入独立研究区，保存来源、发布时间、检索时间、地区、语言、哈希、可信度和主张—证据关系。

联网结果只能形成候选建议，不自动修改书籍定位、标签、章纲、正文或正史。离线时不得声称“当前热门”或“本周大火”。

## 14. 预算与自动运行

标准模式默认；省钱模式约为标准预算60%；精细模式最高180%，必须老板明确选择。

| 场景 | 标准模型调用 | 标准Token上限 | 标准耗时 |
|---|---:|---:|---:|
| 快速讨论 | 2次 | 4万 | 8分钟 |
| 协同讨论 | 7次 | 16万 | 25分钟 |
| 正式会审 | 12次 | 32万 | 45分钟 |
| 单章创作 | 6次 | 24万 | 45分钟 |
| 联网研究 | 3轮搜索、8页、2次整理 | 10万 | 20分钟 |
| 人物/深度一致性 | 3次 | 10万 | 20分钟 |

9个岗位不会全部默认参与。使用70%预算时重新预测并缩减非必要专家和扩展检索；达到100%后不能启动新模型或付费工具。结果不明的调用保持 `interrupted`，不得自动重试。

## 15. 书籍生命周期

支持：创建、活动、暂停、归档、恢复、导出、导入和永久删除。

- 普通删除为归档。
- 恢复和导入先进入隔离区，验证后才进入正式书籍。
- 永久删除必须生成删除墓碑，防止旧备份恢复已删除书籍。
- 删除一本书不得影响其他书籍、全局模板或模型配置。
