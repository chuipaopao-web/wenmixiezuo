# 系统架构

## 1. 总体形态

统一账号的模块化单体加独立 Worker：

```text
React/Vite Web → Fastify REST/SSE → Application Services → Repositories → SQLite/Files
                                      ↓ outbox/tasks
                                  Independent Worker → Model adapters / projections
```

Fastify API 与 Worker 协调端口继续只监听 `127.0.0.1`。本机由浏览器直接访问；公网部署由同机 HTTPS 反向代理接收域名流量并转发到回环端口，数据库和 Worker 不直接暴露。不使用微服务、WebSocket或需要独立运维的向量/图数据库。

## 2. 模块边界

- Web：统一创作台、书籍切换、对象编辑、团队/任务状态、隔离灵感、报告和辅助工具。
- API：认证、校验、领域命令、查询投影、任务排队、SSE。
- Worker：领取长任务、编译上下文、调用模型、保存候选和重建投影。
- Contracts：跨端共享的请求、响应和事件类型。
- Repositories：业务代码访问SQLite的唯一入口；新增应用服务不得直接写SQL。
- Files：不可变正文、导入原件、附件、备份和可重建投影文件。

## 3. 当前工作流编排

开书、设定、卷纲、事件、章纲、正文和结算分别使用明确领域对象与版本链。任务冻结上游版本、作者输入、模型绑定、预算和上下文包。上游改变时下游候选失效或重新确认，不静默沿用。

对象页面直接启动正式AI任务并展示结果；正式生产不依赖聊天入口、消息回复流水线或会话记忆。灵感是隔离的辅助域，只保存讨论轮次和引用，不能调用正式对象写入；只有作者主动摘录并绑定业务对象后才转成 `author_planning_inputs`。

## 4. 写入模型

SQLite使用单写者事务、外键、WAL和向前迁移。每项核心写入携带 `owner_id`、`book_id`。跨书访问在Repository入口校验。并发投影短暂占用写锁时，只允许上下文包落库与同任务附件绑定做有限、可观测的锁冲突重试；非锁错误立即失败，达到次数后保持原任务可恢复，不能无限重试或掩盖数据错误。

正文使用不可变完整版本。Worker只能保存任务结果、候选、调用记录和投影，不得直接覆盖正式正文或正史。作者确认由API事务提交。

## 5. 任务与恢复

任务状态：pending → queued → working → succeeded/failed/cancelled/paused/blocked。领取使用租约、attempt编号和lease token；模型结果提交还校验主编epoch。结果未知时冻结并等待调和，不盲目重试远程调用。

每次模型调用保存：任务、Agent、模型快照、输入哈希、上下文包、预算预留、耗时、Token、结果哈希和最终状态。不保存思维链。

长篇规划、审校等慢推理调用的HTTP响应头与响应体等待上限必须与模型业务超时一致，当前最高15分钟；连接建立仍最多30秒。任何一层先中断且无法确认供应商结果时继续记为结果未知，不能因放宽传输等待而自动重放。

## 6. 上下文与检索

确定性 ContextCompiler 按任务编译资料：先取活动版本与结构化直达，再按实体、时间、因果、伏笔、声音和来源触发混合检索。SQLite是正式源；FTS、LanceDB、Wiki、图谱和摘要都是可重建投影。

检索永远携带书籍隔离键；其他书、未摘录灵感、过期版本、无关候选和模型猜测不能进入生产上下文。灵感自己的检索只读取当前书已确认正式源，不能读取其他讨论会话作为事实。

## 7. 模型与Agent

岗位、Agent实例和模型绑定分离。卷纲与事件规划可并行调用两位互不可见的异模型编剧，随后由主编融合；正文只有一个活动写手；事实、文学、体验三席使用三异模型独立审查。

## 8. 文件与附件

作者附件绑定具体开书、设定、卷、事件、章纲或正文对象。原件不可变，解析文本和预览可重建；公开API和运行时统一使用作者附件语义。

## 9. 前端布局

桌面端为左侧纯书籍栏、顶部完整功能栏和中心创作台。书籍栏只切换书；功能栏统一切换信息、设定、分卷、规划、章纲、正文、资料库、取名、团队、任务、灵感和设置。不设第二套对象导航或常驻成员右栏。默认使用iOS式浅色玻璃视觉。窄屏时书籍栏变抽屉、功能进入紧凑菜单。创作台内部按对象加载，正文和长列表虚拟化或分页。任务通过SSE更新，不伪造进度。

顶部导航承担功能定位，内容区避免重复功能标题、宣传副标题和固定使用说明。同义状态只显示一次；动态对象名、真实进度、错误与影响不能因去重被隐藏。任务仍由持久状态和SSE驱动，但Web展示层只输出自然语言进度，不渲染任务ID、内部枚举、检查点、ContextPack、哈希、JSON、SQL、Worker或SSE等技术细节。

移动端高度以`visualViewport.height`同步CSS变量，不依赖固定`100vh/100dvh`猜测软键盘高度；输入、文本域、选择框或可编辑区域获得焦点及可视视口变化时，将当前控件滚入可视中心。清理监听器后恢复默认高度，桌面无`visualViewport`时安全降级。

## 10. 构建与可达性

启动入口为API、Worker、Web和共享Contracts。`scripts/audit-runtime-reachability.mjs` 必须报告四端零孤儿源码。生产构建、类型检查、全量测试、迁移和启动验证均为发布门禁。

## 11. 作者展示门禁

Web 的 `AuthorPresentationGate` 是作者可见动态内容的统一边界：结构化内容递归过滤技术字段，状态与错误映射为自然语言，未知机器值使用安全兜底；业务对象、API响应和数据库原件不在展示层被改写。门禁区分界面、进度、错误和故事文本，故事文本与作者原话只剥离机器协议，禁止全局术语替换改变叙事语义。

API在展示层之前再设置网络洁净投影边界：当前Web对普通作者请求和SSE发送`clean-v1`能力头，Fastify统一删除任务/讨论/模型/方法/错误内部字段并只保留业务恢复动作；旧缓存前端不发能力头时走兼容结构。兼容别名只在新Web内存中恢复给既有组件，不能重新写入网络缓存。完整任务、阶段、模型、工具和方法证据只由独立管理员审计路由返回。

## 12. 账号、会话与管理后台

认证属于基础设施边界，但账号状态和管理员权限由应用服务判定。`user_accounts` 一对一关联 `owners`；首次注册在事务内优先复用尚未认领且含本机书籍的历史老板所有者，后续注册创建新所有者。升级库只重新绑定唯一空管理员的所有者关系，不批量改写任何创作表。`auth_sessions` 只保存随机令牌的 SHA-256 摘要；密码使用每账号独立盐值的 scrypt 摘要。浏览器通过 HttpOnly、SameSite=Lax Cookie 维持会话，HTTPS 部署额外启用 Secure。所有业务路由在进入应用服务前从会话解析 `user_id + owner_id + role`，领域路由不再读取固定配置所有者。

首个注册使用 `BEGIN IMMEDIATE` 原子判断并授予管理员角色。管理员路由只提供统计、用户检索、暂停和恢复；暂停用户时撤销其所有活动会话。不能暂停当前管理员自己或最后一个活动管理员。测试注入身份只存在于受控测试配置，不进入生产路由。

公网保持单域部署：`https://wenmixiezuo.com` 同时承载 Web 与 `/api`，反向代理负责 TLS、请求大小、访问日志脱敏与外围限流。API、SQLite、文件、LanceDB 和 Worker 仍位于服务器本机回环/本地文件边界。完整部署步骤见 [DEPLOY.md](DEPLOY.md)。手机号、微信以后作为登录身份绑定到现有 `user_id`，不能建立第二套书籍所有权。

## 分层规划与上下文编译

设定工作区固定四个核心模块，并保留可扩展的可选模块。卷版本可携带具体路线、故事脊柱和第一卷开篇计划；旧卷版本缺少这些可选字段时仍可读取和编辑。内部叙事方法注册表只服务方案编排、版本快照和审计，作者API投影不返回专业来源。

ContextPack来源清单新增约束强度、真值状态、业务范围和依赖。硬事实与当前任务进入不可裁剪区；相关可选设定以全文进入，其他可选设定只进入延后目录。编译器先做同源去重和低相关软资料淘汰，不能用头尾截断伪装成功。

卷路线由卷规划服务生成，事件与章纲只读取已确认路线并逐层落实。第一卷开篇职责从卷版本向事件章链、单章章纲和正文任务传递；任何下层都不能重新发明另一条卷路线。
