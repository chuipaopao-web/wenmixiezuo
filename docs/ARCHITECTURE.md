# V7 当前系统架构

## 1. 运行形态

文秘写作 V7 是同一仓库内的模块化单体：

- `coauthoring-v7/author-app`：作者端 React 应用。
- `coauthoring-v7/admin-console`：独立后台 React 应用。
- `coauthoring-v7/backend`：V7 领域合同、Agent 治理、规划、创作和提示词资产。
- `apps/api`：Fastify API、会话、安全、持久化和 V7 服务装配。
- `apps/worker`：V7 正式化 outbox 追赶与心跳。
- `apps/contracts`：仍由当前入口复用的跨包合同。
- SQLite：正式业务源、版本链、任务、用量、审计和 outbox。
- 文件目录：封面、不可变正文和备份等受登记文件。

生产作者端为 `https://wenmixiezuo.com/`，独立后台为 `https://admin.wenmixiezuo.com/v7/`。Caddy 负责 HTTPS、静态资源和同源 `/api` 反向代理；API 与 Worker 只使用服务器回环和本地数据目录。

当前系统不依赖 LanceDB、本地嵌入模型、旧 SSE、旧通用任务领取器或旧创作路由。

## 2. 唯一入口

API 生产入口是 `apps/api/src/main.ts`，只创建 `createV7Server`。它装配：

- 账号、会话、会员、反馈与请求安全；
- V7 开书、书名封面、设定、全书规划、人物记忆和创作；
- V7 Agent 与提示词/Context 资产治理；
- 独立后台经营、会员、用量、问题和审计；
- Worker 心跳、readiness 和 V7 内部正式化接口。

Worker 生产入口是 `apps/worker/src/main.ts`，只负责心跳和可选的 V7 正式化循环。旧章节任务领取、向量投影和正典索引循环已退出当前入口。

## 3. 权威数据

确定性事务由系统负责：

- 已验证会话与管理员权限；
- `owner_id + book_id` 隔离；
- 版本、幂等、哈希、队列、租约、用量与文件路径；
- 正文不可变版本和正式化 outbox；
- 数据库迁移、备份、校验与恢复。

语义工作由具备任务合同的 V7 Agent 负责：

- 理解作者输入；
- 开书、设定、规划、人物与正文候选；
- 语义冲突、相关性、创作和文学审查；
- 写后人物、规划与故事状态维护建议。

Agent 输出先保存为可追溯候选或派生记录。只有作者确认或正式化合同允许的内容才进入当前正式状态；任何摘要、索引、候选或模型推断都不能覆盖作者原文和不可变正文。

## 4. V7 创作闭环

1. 作者通过开书任务或手动资料确认创建 V7 书籍。
2. 设定编辑部按作者选择生成、复核和版本化设定。
3. 全书规划以树、路线、来源快照和版本决定持续维护。
4. 人物记忆从正式来源生成带证据的状态或问题候选。
5. 创作工作流生成方案、章纲和正文候选，作者明确采用与定稿。
6. 正文定稿在同一事务写入不可变正文和正式化事件。
7. Worker 从 outbox 幂等追赶结算与维护；失败保留证据并可恢复。

规划和候选描述的是“可能发生”；正文与结算记录的是“实际发生”。两者在存储、接口和前端表达上保持分离。

## 5. 安全边界

- 作者身份只来自会话，客户端不能指定有效 owner。
- 管理员接口与作者接口物理分组并再次校验角色。
- 内部 Worker 接口要求 Worker 身份和令牌。
- API Key 只来自环境变量，不进入数据库、日志、导出或 Git。
- 作者响应不暴露模型协议、内部键、提示词、哈希、堆栈和路径。
- 普通删除使用归档；永久删除作者数据必须经过影响预览、`YES` 和二次确认。
- 已合并迁移只追加不改写；历史表名仅承担升级与审计兼容，不代表旧产品仍在运行。

## 6. 发布与恢复

静态 Web 通过版本目录构建并原子切换入口，保留旧哈希资源用于回滚。API/Worker 发布使用同一冻结源码，等待在途任务安全窗口后逐服务切换。SQLite 和登记文件通过 `BackupService` 建立一致性备份，并在隔离目录执行哈希、完整性、外键和删除墓碑验证。

详细接口、数据和部署规则分别见 [API.md](API.md)、[DATA_MODEL.md](DATA_MODEL.md) 和 [DEPLOY.md](DEPLOY.md)。
