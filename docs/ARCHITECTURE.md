# 系统架构

## 1. 架构选择

首版采用“本地优先的模块化单体＋独立Worker”。这保证本机部署简单，同时让模型调用和长任务不阻塞API。

```text
React / PWA
     │ REST命令与查询 + SSE事件
Fastify API
     │
应用服务与领域模块
├─ 书籍与章节
├─ Agent与岗位
├─ 对话与讨论
├─ 创作流水线
├─ 正史与知识
├─ 上下文组装与检索
├─ 预算、调用与审计
└─ 备份、导出与恢复
     │
Repository与基础设施
├─ SQLite + WAL
├─ 本地不可变文件
├─ SQLite FTS/BM25
├─ LanceDB OSS本地可重建向量投影
├─ SQLite时间关系与Wiki投影
├─ 模型/工具/联网适配器
└─ 持久任务与恢复账本
     ↑
独立Worker
```

## 2. 目录契约

正式开发时建立：

```text
apps/
  web/       React、PWA、IndexedDB草稿、SSE客户端
  api/       Fastify、领域规则、应用服务、Repository与基础设施
  worker/    任务领取、模型调用、检索、写作、审校与工具
docs/        版本化开发文档
data/        运行数据；必须被Git忽略
```

后端内部按 `domain`、`application`、`infrastructure` 和 `contracts` 分层。首版不拆大量独立Package；只有边界稳定且完全无产品语义时才评估第三方通用包。

## 3. 运行边界

- Web、API和Worker属于同一产品发布版本，但运行进程独立。
- API负责指令、查询、确认和核心领域写入。
- Worker负责模型调用、检索、写作、审校和工具执行。
- Worker不开放额外HTTP端口，通过数据库健康记录上报启动时间、进程标识、能力和心跳。
- API提供 `/health`。
- Web和API只监听 `127.0.0.1`。
- AI智囊团与小说平台使用不同端口、数据库、数据目录、配置、日志和启动器。

## 4. SQLite写入模型

- 开启 WAL、外键、`synchronous=FULL`、统一 `busy_timeout` 和有限写重试。
- 所有核心领域写入经过应用服务和Repository。
- Worker只能通过受限Repository更新任务领取、阶段、心跳、事件、调用、健康和暂存结果记录。
- 模型调用、文件复制和长工具操作不得放在数据库事务中。
- 事务保持短小；章节结算需要原子性，但正文文件必须先完成受控提升并具备恢复日志。
- 数据库迁移只向前新增；已合并迁移不可修改。

## 5. 文件存储

```text
data/
  database/
  books/<book_id>/
  staging/<task_id>/
  archives/
  imports/
  exports/
  backups/
  quarantine/
  logs/
  cache/
  indexes/
```

`indexes/lance/<book_id>/canon` 保存每书正式向量投影，`indexes/lance/<book_id>/tasks/<task_id>` 保存任务级临时向量投影。两者物理隔离；正式检索默认没有访问临时表的路径。`cache/models` 保存本地嵌入和重排模型，模型快照与向量索引绑定。

### 5.1 正文三层结构

1. 不可变正文文件：按书、章节和版本组织，使用内容哈希命名。
2. 数据库版本指针：记录路径、哈希、作者、模型、来源任务、状态和当前正史指针。
3. FTS索引：只负责检索，损坏后可以重建，不决定正史。

Worker只能写 `staging/<task_id>/`。完整结果通过哈希、格式和任务校验后，由应用服务使用稳定 `operation_id` 提升到正式目录并登记。失败或取消的暂存结果不能被视为正式正文。

### 5.2 归档

当前和近期版本保留在热目录。单章历史版本超过20个时，从最早版本开始归档超出部分；清单、状态和哈希永久保留。归档不是删除，也不是备份。

## 6. 任务与恢复

任务使用SQLite持久状态机，支持：依赖、幂等键、租约、心跳、阶段、检查点、事件、暂停、继续、取消、有限重试、受阻、失败、接管和重启恢复。

Worker首版全局并发为1，同一本书严格串行。调度依据数据库状态和依赖，不依赖内存队列。

崩溃恢复顺序：

1. 扫描待处理和心跳过期任务；
2. 检查关联模型与工具调用；
3. 结果不明的调用标记 `interrupted`，等待主编判断；
4. 调用未开始时从阶段检查点恢复；
5. 调用已成功时复用结果继续校验；
6. 只有能够证明不会重复计费或生成时才自动恢复；
7. 恢复失败后如实标记并升级。

## 7. 模型和工具适配层

统一适配器处理：能力声明、文本与文件请求、工具调用、流式输出、超时、真实取消、限流、错误分类、Token、费用、耗时、暂停、降级和接管信号。领域层不得出现供应商专属字段。

每次调用先生成唯一 `request_id` 并写 `model_calls`：

```text
pending → working → succeeded
                  ↘ failed
                  ↘ interrupted
```

`interrupted` 不自动重试。相同任务、阶段、模型和输入版本使用幂等约束，防止重复调用。

当前真实模型层采用两类零现金通道：

- GPT-5.6 Sol 通过本机 Codex 的 ChatGPT 登录态启动临时、只读、无工具子进程；子进程只继承运行所需的安全环境变量，不继承方舟或OpenAI API Key。
- DeepSeek V4 Pro 只调用方舟 `/api/coding`，GLM 5.2、Kimi K2.6 和 Doubao 2.0 Pro 只调用 `/api/plan`；URL白名单拒绝 `/api/v3` 和其他按量端点。

运行时模式只有 `deterministic` 与 `subscription-plan`。真实模式缺少任一套餐凭证时明确退回测试模式，不把测试结果冒充真实调用；一旦真实任务开始，则不允许按量付费回退。岗位换模创建新 `model_config_snapshots`，旧调用、选择和正文继续引用旧快照。九岗位详细提示词见 `docs/ROLE_PROMPTS.md`。

## 8. REST与SSE

- REST用于查询、命令、确认、暂停、继续、取消、导入导出和恢复请求。
- SSE用于真实状态、任务进度、确认单、冲突、正文版本和结果事件。
- 重要事件携带持久递增 `eventSeq`。
- 客户端保存最后序号，重连时先回放再进入实时流。
- 事件至少保留最近7天或10000条，取范围较大者。
- 首版不使用WebSocket。

## 9. 跨产品交换

AI智囊团与小说平台只通过显式、版本化、可审计的导入导出契约交换岗位模板、模型配置模板、题材标签和系统规则。禁止跨库读取、共享任务或自动同步私有记忆。

## 10. 可替换边界

首版使用SQLite、本地文件、FTS和单Worker，但必须通过接口隔离：

- Repository；
- FileStorage；
- RetrievalProvider；
- ModelAdapter；
- ToolAdapter；
- WebResearchAdapter；
- TaskScheduler；
- UsageLedger。

未来替换PostgreSQL、对象存储、向量索引或多Worker时，不重写书籍、章节、正史和记忆核心领域。

### 10.1 混合RAG边界

- 正史事实、正式规划和不可变正文是权威源；向量、Wiki、关系和摘要只是可重建投影。
- `RetrievalProvider` 负责查询理解、结构化查询、BM25、向量、关系扩展、时间过滤、融合重排和原文回查，领域层不依赖具体索引引擎。
- 向量引擎固定采用LanceDB OSS TypeScript本地嵌入模式，只由Worker访问，不开放端口、不调用云服务；SQLite FTS5继续承担关键词和原文定位。
- 关系、故事时间和Wiki使用SQLite结构化表、索引和有限深度递归，不引入Neo4j或其他图数据库。GBrain/LLMWiki等只作设计参考，不成为运行时依赖或第二权威源。
- 正式源与临时源保留在同一权威SQLite的不同表与Repository权限域，提升时创建新的不可变正式版本；正式与临时LanceDB索引按书和任务物理隔离。
- 本地嵌入和可选重排通过Node适配器运行，模型、版本、维度、归一化和查询指令形成不可变快照；任何模型变化都触发相应投影全量重建。
- 索引构建和重建由Worker执行，正式源写入仍只经过应用服务和Repository。
- 权威事务通过投影任务/outbox触发构建；每个投影保存正史版本、切片策略和完成水位。正式生产禁止静默使用落后或版本不明的向量、Wiki和关系投影。
- 任何索引命中都携带 `owner_id`、`book_id`、正史版本、故事时间、来源ID、块ID和原文指针。

## 11. 备份与恢复

备份采用“冻结—一致性快照—复制文件—哈希清单—临时恢复验证—解冻”。不完整或校验失败的备份不能用于恢复。

有数据变化时，每个滚动24小时至少完成一次真实恢复演练。恢复在隔离目录验证数据库完整性、外键、正文哈希、正史指针、跨书关系和版本兼容性后，才允许替换正式数据。

LanceDB、Wiki和关系投影不承担数据恢复权威。备份可以携带投影以缩短恢复时间，但恢复后必须校验模型、切片版本和正史水位；不一致时删除并从SQLite与正式文件按书重建。
