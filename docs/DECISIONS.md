# 老板决定登记册

本文件记录专题讨论结束后的老板最新决定。这里的生效决定优先于旧共识中的冲突部分。

## DEC-001：每本书采用9个岗位

- 状态：生效
- 决定时间：2026-07-16
- 决定人：老板
- 影响共识：第5条“岗位、Agent实例与模型配置”，以及涉及岗位数量的产品、架构、数据、成本和验收规则。

### 原规则

每本书原子创建5个常驻岗位：总编与编排、剧情架构、设定与一致性统筹、主笔、审校。

### 新规则

每本书原子创建9个岗位，分为：

5个核心岗位：

1. 总编与编排；
2. 剧情架构师；
3. 设定与连续性统筹；
4. 主笔；
5. 审校。

4个按需专家岗位：

6. 读者体验与情绪专家；
7. 文风编辑与去AI味专家；
8. 资料研究与考据专家；
9. 版权与原创安全专家。

### 执行约束

- 9个岗位都建立稳定Agent实例和书籍级配置，但按需专家默认待命，不在每轮讨论中全部激活。
- 调度器根据任务类型激活2至5个相关岗位；正式会审可以扩大，但受预算和独立性门禁约束。
- 同一模型可以承担多个岗位，但界面必须显示真实模型来源。
- 同模型分身不算异模型独立意见，不能成为唯一独立复核。
- 新书创建时，9个岗位及配置快照必须原子创建；部分创建失败则整次建书回滚。

### 修改原因

5个岗位足以跑通基础流水线，但不足以长期覆盖读者情绪、语言去AI味、联网考据和版权安全。采用“5个核心＋4个按需专家”可以提升专业覆盖，同时避免9个成员在每轮对话中同时发言造成Token浪费。

- 决定时间：2026-07-16
- 决定人：老板

### 新规则

- 正式授权在 `D:\wenmixiezuo` 内连续完成首版八个阶段；普通阶段通过后自动进入下一阶段。
- 产品显示名称为“文脉写作”。
- Web监听 `127.0.0.1:43110`，API监听 `127.0.0.1:43111`；如未来端口发生冲突，只能改为其他空闲本机端口并同步记录。

- 未获得单次明确付费授权前，现金费用保护线上限为0；缺少真实模型凭证时使用确定性假模型开发和验收。
- API Key只从环境变量读取，不写入代码、数据库、日志、聊天、上下文、备份、导出或Git。
- 第二物理位置备份暂未配置，不得声称能够防止本机硬盘损坏。
- 远程Git暂未配置，首版只创建本地发布提交，不推送。
- 业务代码由当前Codex单独完成，不调用其他开发Agent，也不触碰 `D:\AI智囊团`。

### 执行约束

- 开始时初始化本地Git，建立唯一 `release_id`、SQLite任务账本和阶段验收记录。
- 每阶段必须完成类型检查、自动测试、构建、空库与升级迁移、本地运行、Repository契约及相关恢复/隔离验证，并保存与提交一致的证据。
- 只有需要实际付费、需要真实密钥、永久删除、重大架构变更、生产数据恢复或无法自行消除的外部阻塞时暂停询问老板。

### 修改原因

老板已确认正式开工，并要求以安全、可逆、零现金默认策略连续开发到完整首版交付。

## DEC-004：工作台采用内容优先的智囊团式界面

- 状态：生效
- 决定时间：2026-07-17
- 决定人：老板
- 生效版本：首版 `release_id` `wm-v1-20260716-220959-d5dd704d` 的界面增量
- 影响文件：`docs/PRODUCT.md`、`docs/ACCEPTANCE.md`、Web工作台、任务工作区接口、界面测试和使用说明。

### 原规则

桌面采用可折叠三栏，但左右栏分别为272像素和320像素；当前任务位于右侧检查器，成员只有状态点，没有人物头像；底色和字号仅跟随固定CSS与系统偏好，用户不能自行调整。

### 新规则

- 默认采用低饱和浅绿色工作台，并提供米白、雾蓝和夜间底色。
- 用户可在设置中调整小、标准、大、特大四档字体；底色和字体只保存在本机并即时生效。
- 桌面左右侧栏压窄至内容够用的宽度，中间创作、对话和正文区域占据主要横向空间。
- 当前任务放在左栏，必须显示章节、任务类型、真实阶段和状态；点击后可查看任务书、检查点、执行岗位和任务ID，并可通过真实任务接口取消。
- 右栏以紧凑成员列表为主，每个小说岗位显示原型人物头像、真实模型来源和事件驱动状态。
- 手机不压缩三栏，书籍/任务与成员分别进入左右抽屉；设置入口在窄屏仍可使用。

### 执行约束

- 头像资产允许从 `D:\AI智囊团` 只读复制，但文秘写作必须保存自己的副本，不能形成运行时依赖，也不得修改、停止或重启智囊团。
- 九个岗位的头像是视觉身份，不得用头像或文案伪造Agent在线、工作或独立模型状态。
- 任务章节信息必须来自数据库任务记录和章节记录，取消必须调用持久任务状态机。
- 主题必须保持键盘焦点、对比度和减少动画支持。

### 修改原因

老板认为原界面左右栏过宽、创作区受挤压、成员缺少原型头像、任务位置和信息不直观，要求界面更接近AI智囊团的浅绿、紧凑、内容优先风格。

## DEC-005：九岗位使用女性成员身份和短岗位名

- 状态：生效
- 决定时间：2026-07-17
- 决定人：老板
- 生效版本：首版 `release_id` `wm-v1-20260716-220959-d5dd704d` 的界面增量
- 影响文件：`docs/AGENT_SYSTEM.md`、`docs/PRODUCT.md`、`docs/ACCEPTANCE.md`、Agent领域定义、Schema迁移、Web工作台、测试和使用说明。

### 原规则

成员栏把“设定与连续性统筹”“文风编辑与去AI味专家”等完整职责当作岗位名称，并在第二行显示模型字符串，成员缺少独立姓名，状态只显示“工作中/待命”。桌面左右栏宽度约为208像素和224像素。

### 新规则

- 九名成员固定显示为：貂蝉（主编）、婉儿（编剧）、文姬（设定师）、秋香（主笔）、妲己（审校）、昭君（体验官）、清照（文编）、道韫（研究员）、弄玉（版权顾问）。
- `displayName` 保存成员姓名，`roleName` 保存简短职业名称；完整职责继续保存在岗位模板职责字段和规格文档中，不再冒充名称。
- 九名成员在团队栏直接显示，不把按需专家默认折叠。
- 状态位于成员身份下方，采用智囊团语义和配色：空闲、排队中、后台工作中、需要处理、离线。
- 后台工作中必须同时有真实工作任务、匹配的执行成员、就绪Worker和相同任务心跳；否则不得显示工作中。
- 模型来源保留在成员悬停说明和详细记录中，不占用紧凑成员栏第二行。
- 桌面左右栏进一步收窄到约176像素和190像素；1180像素以下收窄到约168像素和180像素，中间创作区优先获得剩余宽度。

### 执行约束

- `role_key`、岗位职责、权限、调度规则和任务引用保持不变。
- 通过新增向前迁移升级现有书籍，不修改已合并迁移，不删除任务、记忆、正文或模型配置。
- 姓名和头像只提供稳定视觉身份，不能用于伪造模型差异或运行状态。

### 修改原因

老板指出职责长称不是岗位名称，要求成员身份全部女性化，状态展示与AI智囊团一致，并继续缩窄两侧栏，把更多空间留给创作区。

## DEC-006：预算与待确认归入任务中心二级页面

- 状态：生效
- 决定时间：2026-07-17
- 决定人：老板
- 生效版本：首版 `release_id` `wm-v1-20260716-220959-d5dd704d` 的界面增量
- 影响文件：`docs/PRODUCT.md`、`docs/ACCEPTANCE.md`、Web工作台、体验测试、使用说明和任务账本。

### 原规则

右侧检查器同时显示团队、预算和待确认事项；左侧当前任务区域只能打开单条任务详情，没有承载任务全局信息的二级页面。

### 新规则

- 右侧栏只显示团队成员、头像、短岗位和真实状态，不再显示预算或待确认事项。
- 左侧“当前任务”标题成为任务中心入口，点击后在中间内容区打开任务二级页面。
- 任务中心统一显示进行中的任务、最近任务、预算和待确认事项。
- 单条任务仍可从左栏或任务中心打开详情；取消继续调用真实任务状态机。
- 重大确认只在任务中心显示，接受或拒绝继续调用真实确认接口。

### 执行约束

- 不修改任务、预算或确认的数据结构与业务规则，不新增数据库迁移。
- 任务中心只展示当前书籍工作区聚合API返回的真实数据，不构造示例预算或待确认事项。
- 手机端从左抽屉进入任务中心，右抽屉仍只显示团队成员。

### 修改原因

老板要求把预算和待确认移到任务按钮内的二级页面，并让右侧只保留团队成员。
