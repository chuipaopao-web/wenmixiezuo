# 卷驱动工作流 V2 可达图与改造基线

- `design_review_id`：`DR-20260808-workflow-skill-v2`
- `release_id`：`wm-longform-r1-20260719-003435-e4d7b8b7`
- 基线时间：2026-08-08
- 基线原则：只读生产库，只统计数量和状态，不读取或输出书名、正文、附件、密钥或模型私密内容。

## 1. 基线结论

当前系统已经具备可靠的书籍隔离、不可变正文、三职责点评、任务租约、上下文包、混合检索、投影、结算和恢复基础；这些能力应保留并接入新工作流。主要结构问题不是“什么都没有”，而是规划层和入口层错位：前端集中在单个超大组件中，后端仍以旧剧情总纲、自由对话和通用Artifact入口串联流程，卷和事件没有独立正式源，三个主要模型管线各自拼装上下文。

新开发必须优先新增卷、事件和作者意见的正式领域，再迁移现有章纲与正文管线。任何旧入口只有在替代入口、旧书读取、恢复路径和测试同时通过后才可删除。

## 2. 规模与正式库只读样本

|---|---:|---:|---|

## 3. 页面到数据与任务的可达图

| 能力 | 当前可达链 | V2归属 | 处置 |
|---|---|---|---|
| 开书 | `App.tsx` → `client.ts` → `/book-drafts`、`/book-drafts/:id/confirm` → `PositioningService` / `BookOnboardingService` → 开书与书籍表 | 开书 | 保留并改造；增加大白话风格选择、作者想法来源和新流程初态 |

| 旧剧情总纲 | 创作台“剧情总纲” → 通用Artifact与Discussion → `PlanningArtifactService` / `DiscussionPipelineService` → `master_outline` | 旧书兼容 | 停止新建；只读适配到首卷/事件候选，不能继续作为V2权威源 |
| 卷 | 物理卷目录 → `/volumes` → `ChapterCatalogService` → `volumes` | 卷目录；另增卷蓝图 | 物理卷保留；新增不可变卷蓝图正式源，不能复活已退役Artifact做法 |

| 正文 | 正文页 → `/writing-runs`、章节、重写、定稿 → `ChapterBatchService` / `ChapterPipelineService` / `ChapterApprovalService` → 正文、写作单、点评与正史表 | 逐章正文 | 保留核心生产链；以新章纲门禁替代旧总纲门禁 |

| 事件/卷结算 | 当前 `StageSettlementService` 和章节结算只表达旧阶段 | 事件结算、卷结算、下一卷交接 | 复用结算、正史和索引机制，新增明确事件与卷来源 |
| 上下文 | 三条模型管线分别调用 `ContextPackService`，并自行拼接来源 | 全流程 `ContextCompiler` | 合并；建立岗位×阶段唯一策略和不可变资料包 |
| 检索 | `/retrievals` / preview → `HybridRetrievalService` → 四路检索、证据闭环、Lance投影 | 上下文编译内部能力与诊断 | 保留；按事实/因果/声音/灵感意图路由，禁止统一阈值 |
| 团队与状态 | 团队栏 → Agent、任务、租约、调用与心跳 | 当前任务相关成员 | 保留数据源；前端只突出当前介入成员和真实状态 |
| 图谱 | `/projections` → `NarrativeProjectionService` → 投影表与Worker | 创作台工具 | 合并到创作台；保持派生层，不成为正史 |
| 资料库 | `/library`、实体、事实、标签、主角状态 | 创作台工具 | 保留并合并入口；继续显示来源与权威层 |
| 取名 | 前端本地 `NamingAssistantPanel` | 创作台工具 | 保留并嵌入当前书；不得自动修改正式设定 |
| 独立对话页 | 消息页 → `/conversation-entry`、`/messages` → `ConversationService` / `ConversationReplyPipelineService` → 对话、消息、会话表 | 不再是独立主流程 | 新UI停用；历史消息只读兼容。设定/卷/事件的作者意见改走明确阶段入口 |
| 对话附件 | `/chat-attachments` → `ChatAttachmentService` → 附件表和书内文件 | 作者意见附件 | 合并到阶段意见来源；完成迁移前保留旧接口 |

| 批量写作 | `/chapter-batches` → `ChapterBatchService` | 旧兼容 | 新UI不显示；旧任务恢复与重写仍调用，待逐章新入口接管后再删兼容路由 |
| 续写 | 导入页 → `/continuation-imports` → 续写服务/分析管线 → 导入、反向章纲、正文与索引 | 开书分支 | 保留；交接结果改为进入当前卷和当前事件 |
| 任务/恢复 | `/tasks`、Worker领取、租约、Attempt、恢复日志 | 全流程基础设施 | 保留并扩展新任务类型；禁止UI伪造状态 |

## 4. 后端清理边界

### 4.1 直接复用

- 书籍、物理卷、章节和正文不可变版本；
- Repository隔离、乐观并发、确认和正史修订；
- 任务租约、Attempt、心跳、取消、恢复与幂等键；
- 三职责点评、写手租约和主编综合；
- 设定资料、事实、人物状态、开放线程、投影和结算基础；
- 混合检索四通道、检索计划、证据聚类与来源核验；
- 本地SQLite权威源、LanceDB可重建投影和Worker边界。

### 4.2 必须改造

- `book_planning_states` 从旧阶段枚举迁移到卷—事件—章状态；
- `PlanningArtifactService` 和 `PlanningStageArtifactService` 的新建职责由专用卷/事件领域接管；
- `WritingReadinessService` 改为校验活动卷、活动事件和已冻结章纲；
- 三条模型管线的上下文拼装收敛到确定性 `ContextCompiler`；
- Discussion任务按“设定讨论、卷规划、事件双方案、章纲设计”明确编排；
- 续写交接从旧剧情总纲转入卷和事件。

### 4.3 暂时只读兼容

- `master_outline` / `stage_master_v2`；
- 历史对话、消息、对话附件；
- 旧 `chapter_batches`、`writing-runs` 和旧任务恢复；
- 旧阶段结算和历史 `volume_outline` 审计记录。

### 4.4 删除候选及前置条件

| 候选 | 删除前必须成立 |
|---|---|
| 独立对话页面、右侧对话导航和相关CSS | 六步创作台每一步均有作者意见入口；旧消息有只读查看/导出路径 |
| 独立版权/研究页面及前端聚合客户端 | 安全服务仍被正文生成和导入链调用；资料库能查看必要来源证据 |
| `chapter-batches` 公共路由和客户端 | 新逐章入口支持新写、重写、取消、恢复和幂等；旧任务迁移完成 |
| 旧剧情总纲编辑器、提示词和新建路由 | 旧书适配器通过；首卷/事件候选可审阅；无生产调用 |
| 重复的上下文拼装函数 | 所有模型调用均生成同一编译器的可追溯资料包；消融和回归通过 |

数据库迁移只能向前新增。历史正文、Artifact版本、消息、来源、任务和审计记录不得以“精简”为由物理删除。

## 5. 基线测试证据

| 检查 | 结果 |
|---|---|
| 类型检查 | 通过 |
| API/Web/Worker构建 | 通过；前端主包603KB并有拆包警告 |
| 空库与历史升级迁移测试 | 4个文件、8项测试通过 |

| 现有验收旅程 | 3/3通过 |
| 发布审计 | 除“工作树不干净”外全部通过；工作树变化正是本轮已授权规格修改 |
| 正式库迁移 | 未执行，避免P1改变生产数据 |

## 6. P1停止条件核对

- 正式库没有被写入；
- 没有删除、停用或迁移任何业务能力；
- 对话、附件、来源、卷、旧阶段、章纲、正文、团队、任务和恢复均已找到实际归属；
- 正式样本缺口已明确交由隔离测试夹具补齐；
- 所有删除候选仍被标记为“有前置条件”，当前不具备直接删除资格。

因此P1可以结束，P2从前端壳层拆分开始，P3随后建立共享工作流类型；后端正式迁移从P7开始。
