# 作者界面与AI回复大白话改造计划

> release_id：`wm-longform-r1-20260719-003435-e4d7b8b7`  
> design_review_id：`DR-20260806-author-plain-language-v1`

## 目标

让作者在软件里看到的剧情说明、成员回复、状态提示和常见错误都使用具体、自然、容易理解的中文；优先说明人物做了什么、为什么这样做、心里怎么想、会造成什么结果。内部结构化字段、版本、来源、审计和安全门禁保持不变。

## 架构

采用三层保护：模型调用前统一加入作者语言合同；模型结构化回复在服务端投影为简单标题；Web端对历史回复、结构化资料和常见技术错误继续做兼容展示。机器使用的 `workflowArtifact`、审校JSON与数据库内容不做语义降级，也不改写历史记录。

## 技术栈

TypeScript、Fastify应用层、React作者界面、Vitest。

## 全局约束

- [ ] 保护当前脏工作区，不重置、不覆盖、不删除任何现有修改。
- [ ] 不调用其他开发Agent，不修改迁移、生产数据、密钥或AI智囊团。
- [ ] “大白话”不等于删掉动机、因果、代价、分歧和未知项，也不把小说表达改成幼稚说明书。
- [ ] 只改变作者可见投影和新模型回复要求；内部正式源、审计原文和机器合同继续保留。

## 任务

### 1. 建立失败基线与作者语言合同

- [ ] 用截图中的抽象表达建立回归样例。
- [ ] 定义统一规则：姓名/对象＋动作或情绪＋原因＋结果；概念词必须落到具体表现。
- [ ] 明确禁止在作者回复里出现的内部流程腔，如“结构边界、可验证目标、有界收敛、落库、资料包”。
- [ ] 保留事实不确定性，不允许为了通俗而补造剧情。

### 2. 修改所有成员的新回复

- [ ] 在讨论岗位系统提示中加入统一大白话规则。
- [ ] 在剧情抽卡、阶段总纲、设定讨论、主编汇总和恢复重试提示中复用同一规则。
- [ ] 更新确定性模型样例，避免测试环境继续生成概念句。
- [ ] 保持正文生成、机器审校JSON和内部工作流结构不受影响。

### 3. 修改作者可见的回复排版

- [ ] 将“关键依据”改为“为什么这样安排”。
- [ ] 将“可选方向”改为“还可以这样写”。
- [ ] 将“风险与未知”改为“要留意”。
- [ ] 将“需要确认”改为“想请你定一下”。
- [ ] 将“补充/完整依据”改为“展开说说”。
- [ ] 服务端和Web历史兼容投影使用同一套标题，避免新旧消息显示不一致。

### 4. 精简软件里的技术提示

- [ ] 把小文秘书路由回执改成作者能直接看懂的句子。
- [ ] 对常见服务端技术错误提供作者版说明，内部原错误仍留在服务端记录。
- [ ] 定向清理创作台、对话、资料页里直接暴露的“正史修订、投影、落库、候选语义”等产品术语。
- [ ] 保留确实需要作者作决定的“正式/待确认/历史版本”等状态含义。

### 5. 验证与交付

- [ ] 专项测试覆盖提示词、结构化回复、历史回复、路由回执和常见错误。
- [ ] 运行类型检查、全量测试、构建和设计审计校验。
- [ ] 用旧表达与新表达做多样本人工对照，确认信息没有减少、可读性提高。
- [ ] 记录剩余无法仅靠确定性测试证明的真实模型表现风险。

### 6. 让当前已保存总纲使用新展示类型

- [x] 旧阶段没有剧情分段时，用已有章节范围、概述和预估字数组成只读展示区间。
- [x] 将人物拆成“新增出场人物”和“人物成长”两个固定栏目。
- [x] 将章节起止、预估字数、主线、支线、起承转合、情绪、阅读体验、爽点、虐点、事件收获和长线伏笔固定显示。
- [x] 把内部规划字段收进默认折叠的“章纲参考”，主页面不再显示“阶段约束契约”。
- [x] 保留原始数据和历史版本，不执行迁移或语义改写。
