# 创作流程端到端修复实施计划

## 任务合同

- 目标：修复“设定大纲跳转讨论后成员不回复”的真实运行故障，并以当前书籍 `65206058-e8c2-4429-982c-916925cc1084` 连续验证设定大纲、剧情总纲、卷纲、章纲、10章正式正文及保存/审校/正史链路。
- 不做：不伪造模型回复，不直接向业务表写入假大纲或假正文，不修改或依赖 `D:\AI智囊团`，不使用现金兜底，不删除现有书籍数据。
- 唯一负责人：当前 Codex。
- 允许文件：讨论/对话/接管/规划/正文流水线及对应测试、当前规格与本计划、测试证据。
- 禁止文件：密钥文件、AI智囊团目录、与本故障无关的用户改动。
- 依赖：现有本地 API、Worker、SQLite、已配置的套餐模型；缺少新密钥或需要现金调用时停止。
- 实现约束：保留双异模型编剧、主编汇总、三异模型审校、不可变正文版本、老板确认与正史门禁；失败必须可见、可恢复且不得重复消耗已成功意见。
- 验收标准：
  1. `provider_result_unknown` 能进入安全接管/恢复路径；
  2. 已完成的双编剧意见在恢复时被复用；
  3. 作者界面收到真实主编/副编结果或明确可行动故障说明；
  4. 各规划层级内容职责不混淆并与开书资料一致；
  5. 10章正文均有正文版本、三席审校、确认/结算记录且可读取；
  6. 无重复前端消息、无代码字段泄漏、无跨书数据。
- 测试命令：相关 Vitest 定向测试；全量类型检查、自动测试、构建、迁移空库/升级、运行健康、Repository/隔离/恢复测试；最后执行数据一致性审计。
- 停止条件：需要新密钥、现金付费、永久删除、生产数据恢复或重大架构变更；真实模型反复失败时保留检查点并如实报告。
- 回滚：应用代码和测试用非破坏性 Git revert；数据库迁移只向前；当前书籍的模型产物和审计记录不覆盖、不删除。
- 复核人：当前 Codex 先做自动化与逐项内容复核，最终由老板验收。

## 施工顺序

1. 固化无回复故障的回归测试并修复讨论接管。
2. 增加最终失败的作者可见说明和幂等保护。
3. 从当前失败任务恢复，验证副编真实可用并完成该设定项。
4. 按设定清单逐项讨论、确认并检查展示结果。
5. 依次完成剧情总纲、卷纲和未来10章章纲，检查层级职责。
6. 逐章正式生产10章，逐章检查正文、审校、修订、定稿与正史。
7. 执行全量质量门禁并保存证据。
