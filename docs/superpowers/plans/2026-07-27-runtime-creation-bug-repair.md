# 运行时创作链缺陷修复计划

## 目标

修复真实模型讨论完成后前端没有设定大纲、总纲、卷纲、章纲和正文入口的问题，并消除任务假终态、自动接管反复切换、成员身份显示错误及有效回复被错误过滤。

## 不做什么

- 不改十一名创作成员合同和模型绑定架构。
- 不绕过老板确认把讨论自动写入正史。
- 不用确定性假内容冒充真实模型产物。
- 不释放结果未知的模型预算预留，除非取得供应商终态证据。
- 不触碰 `D:\AI智囊团`。

## 根因与修复

1. DeepSeek/GLM可能在结构化JSON前添加Markdown标题或代码围栏，旧解析器只接受单行裸JSON。
   - 改为从契约标记后提取首个字符串安全、括号配平的完整JSON对象。
   - 同时覆盖章节跨度和规划落库两类契约。
2. 主编有效输出清洗会丢弃规划落库原始结构。
   - 作者界面继续显示清洗结果；规划证据保留原始结构化回复。
3. 规划的故事弧跨度被未来1—3章滚动章纲数量错误覆盖。
   - 故事弧使用结构化建议跨度；章纲仍只细化未来1—3章。
4. 任务完成或失败时，阶段表可能残留“进行中”。
   - 完成、失败、取消均同步终结工作阶段和尝试记录。
5. 副编接管后再次故障会自动切回主编，形成乒乓切换。
   - 自动接管只允许epoch 1单向切换一次；安全回切走独立检查入口。
6. 主编接管后通知仍硬编码“貂蝉”，自然锁定语句识别过严，重复秘书通知堆积。
   - 通知读取当前租约成员；扩展明确锁定句式；相邻同内容秘书通知去重。
7. 有效输出字段为字符串而非数组时，被误判为空并用机械兜底覆盖。
   - 安全接受非空字符串并标准化为单元素列表。

## 验收

- 解析单元测试覆盖裸JSON、Markdown标题、代码围栏和多行JSON。
- 讨论集成测试真实生成双编剧跨度、主编规划，并在确认后形成设定/总纲/卷纲/1—3章章纲。
- 任务完成和失败后不存在工作中的阶段。
- 副编接管后再次自动故障不回切。
- 类型检查、全量测试、构建、空库迁移、升级迁移、本地运行和API健康检查通过。
- 用现有测试书执行一次可追溯的规划恢复；未取得真实模型成功证据时不得伪造前端内容。

## 回滚

代码回滚到本修复提交的父提交；数据库不新增破坏性迁移，已有书籍数据不做删除或覆盖。
