# 动态主角资料与团队栏实现计划

> 唯一负责人：当前Codex。项目规则禁止调用其他开发Agent。

**目标：** 让主角页按每本书的实际资料动态生长，支持正史自动建档、待归类询问和无损重分类；同时移除右栏重复小文秘书卡并提高默认字号。

**不做什么：** 不删除小文秘书运行能力，不改变11名创作成员，不建立题材固定模板，不让草稿/聊天进入正史，不新增数据库迁移，不调用付费模型，不修改生产数据，不触碰 `D:\AI智囊团`。

**架构：** 复用SQLite `protagonist_profiles`、追加式 `protagonist_state_entries` 和 `knowledge_gap_findings`。分类继续是可扩展字符串；`unclassified` 是待归类保留键。Web只按实际记录分组，重分类通过应用服务新增修订并关闭对应缺口。

**技术栈：** TypeScript、Fastify、SQLite、React、Vitest。

### 任务2：实现动态主角资料服务

**允许文件：** 主角应用服务/Repository、分类缺口Repository复用、HTTP路由、Web API client、章节事实抽取提示。

**步骤：**
1. 正史投影只在主角专用结构化事实上自动建档；精确同书角色名与实体绑定，不做模糊匹配。
2. 解析自由分类；`unclassified` 投影后创建按 `profileId + logicalKey` 去重的开放资料缺口。
3. 新增重分类方法和API：只允许当前最新项，新增修订，保留值、单位、权威层和来源，关闭对应分类缺口。
4. 更新事实席提示：按本书语义分类，不确定用 `unclassified`，禁止从短暂动作/情绪/模糊描述猜当前状态。
5. 运行知识与API目标测试。

### 任务3：实现前端去模板、团队栏去重和字号调整

**允许文件：** `apps/web/src/app/App.tsx`、`app.css`、`workspace-preferences.ts`、API client和UI测试。

**步骤：**
1. 删除 `PROTAGONIST_CATEGORIES` 固定空卡，按当前/候选记录的实际分类分组；旧英文键只做显示兼容。
2. 无资料时显示自动整理说明；手工补充改为自由分类输入，本书已有分类只作建议。
3. `unclassified` 卡显示分类问题、自由输入和确认按钮，成功后刷新面板。
4. `TeamInspector` 只渲染11名创作成员，删除专用秘书卡样式；聊天秘书身份保持不变。
5. 四档字号改为 `1.00/1.10/1.20/1.32`，团队职责/状态元数据基线各提高1px；侧栏宽度不变。
