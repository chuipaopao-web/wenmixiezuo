## 一、冻结后的产品流程

```text
创建书籍
  ↓
开书资料确认
  ↓
主编/副编主动接待
  ↓
作品风格基线确认
  ↓
设定大纲逐项讨论
  ↓ 作者确认“设定基线”
剧情总纲讨论
  ↓ 作者确认“全书方向”
当前卷卷纲讨论
  ↓ 作者确认“本卷目标”
未来1—3章滚动章纲
  ↓ 作者确认“下一章”
主笔写作→三席点评→作者定稿→正史结算
```

### 1. 开书资料

作者必须能够填写并检查：

- 书名；
- 男频/女频；
- 一个主分类、多个辅助题材；
- 主要标签、辅助题材、自定义标签；
- 作品风格意向：语言气质、情绪基调、节奏与爽感、整体氛围；
- 至少一位主角：身份类型、姓名、年龄或生命阶段、人物背景、性格；
- 必须遵守。

本书资料页面只显示这些作者开书信息、来源和修订版本。不得显示：

- `confirmedRecommendation`、内部 Schema、JSON、模型提示词；
- 讨论摘要、候选方案、确认命令；
- 后续模型擅自补造的人名或设定；
- 总纲、卷纲和章纲内容。

作品风格必须从普通标签中拆开显示和保存，不能再混入一个无层级的 `dynamic` 标签数组。

### 2. 作品风格基线

作品风格分两步完成：

1. **开书选择风格意向**：作者选择或自定义主要方向；
2. **主编协助确认风格基线**：主编根据题材、作者样稿和目标效果提出可编辑建议，作者确认后形成不可变版本。

开书页至少提供以下分组：

| 分组 | 示例 | 作用 |
|---|---|---|
| 语言气质 | 幽默、严谨、克制、毒舌、轻松、冷峻 | 决定叙述和对白的整体温度 |
| 情绪基调 | 热血、温馨、压抑、治愈、高燃、悲壮 | 决定长期情绪底色 |
| 节奏与爽感 | 爽点密集、快节奏、稳步升级、慢热蓄力、强情节 | 决定兑现频率和阅读推进感 |
| 叙事氛围 | 史诗、日常、悬疑、黑色幽默、群像、沉浸 | 决定整体阅读质感 |

开书最低要求：

- 至少选择或填写 1 个语言气质；
- 至少选择或填写 1 个情绪基调；
- 至少选择或填写 1 个节奏/爽感方向；
- UI明确提示“这是全书主要方向，具体场景会动态调整”；
- 可以选择“请主编推荐”，但进入剧情总纲前仍必须由作者确认最终基线。

风格基线最终保存：

- 主风格与辅助风格；
- 强度：弱、中、强，而不是只有布尔标签；
- 适用范围和允许变化；
- 需要避免的反面表现；
- 作者提供的可选样稿来源；
- 叙事人称、视角距离和文字密度；
- 版本、来源和生效范围。

示例：

```text
主风格：热血、爽点密集
辅助风格：幽默
长期基线：叙事推进快，关键胜负必须有因果铺垫；幽默来自人物关系和处境，不使用网络段子硬插笑点。
动态适配：战斗场景提高压迫感和动作清晰度；情感场景放慢节奏并增强细腻度；悬疑场景减少解释。
禁止退化：连续无代价碾压、每章机械打脸、所有角色同一种搞笑口吻。
```

作品风格与“写作手法”必须分开：

- 作品风格是全书稳定方向，前期确认；
- 写作手法由主笔根据战斗、感情、悬疑、经营等当前场景动态选择；
- 不预先限制一本书只能使用 1—3 种写作手法。

### 3. 主编接待

- 正常由活动主编接待；活动主编不可用时，经真实可用性检测后由副编接管。
- 接待资料包只含当前开书快照、风格意向、缺失的风格/设定必备项和作者原话。
- 首次回复先准确复述已确认内容，再提出 1—3 个最高价值问题。
- 不启动双编剧，不估算章数，不生成剧情总纲、卷纲、章纲或正文。

### 4. 设定大纲

由“通用骨架＋分类扩展＋题材扩展＋标签触发模块＋作者自定义项”组成。

每项状态只能是：

- 待讨论；
- 讨论中；
- 候选待确认；
- 已确认；
- 稍后补充；
- 刻意留白；
- 不适用。

进入剧情总纲前：

1. 所有可见项目都必须被明确处置；
2. 题材必备项目必须为“已确认”；
3. 不得存在“讨论中”或“候选待确认”；
4. 老板必须点击一次“确认设定基线”。
5. 活动作品风格基线已经由老板确认。

游戏/历史融合题材至少检查：

- 游戏世界接入方式及现实/游戏边界；
- 主角初始身份与核心优势；
- 属性面板字段、显示边界和数值含义；
- 等级、技能、装备、成长和死亡规则；
- 奖励来源、货币、资源产出与消耗闭环；
- 历史背景、时代差异、势力结构和技术边界；
- 游戏机制与历史世界如何发生因果作用；
- “上线就给钱”类书名承诺对应的核心奖励机制。

“排行榜、副本、公会”等只在作品确实需要时启用，不能因为属于游戏文就全部强制填写。

### 5. 剧情总纲

剧情总纲回答“整本书讲什么”，只包含：

- 一句话核心故事；
- 主角起点、核心欲望与最终变化；
- 全书核心冲突及主要对手力量；
- 主线因果链；
- 3—8 个故事阶段及每阶段不可替代的作用；
- 主题承诺与读者核心体验；
- 结局方向和必须兑现的全书承诺；
- 已知风险、刻意未知和允许调整的区域。

剧情总纲不得包含逐章场景、连续几十章章纲或把第一卷内容复制为全书。

### 6. 卷纲

卷纲回答“这一卷完成什么”，必须绑定一个已确认剧情总纲版本，并包含：

- 本卷在总纲中的阶段职责；
- 开卷状态和卷末状态；
- 本卷核心矛盾、升级链和不可逆变化；
- 关键人物关系变化；
- 中段转折、卷高潮和卷末兑现；
- 本卷打开、推进、关闭和移交的承诺/伏笔；
- 大致章节范围，只用于容量评估；
- 与上一卷、下一卷的接口；
- 本卷自由调整区。

卷纲不得复制总纲全文，也不得直接生成全部章纲。

### 7. 章纲

章纲只滚动细化未来 1—3 章，回答“这一章完成什么”，包括：

- 本章叙事目标；
- 承接的卷目标；
- 起始状态与必须结果；
- 视角人物、参与人物、地点和时间；
- 冲突、阻力、信息变化和关键转折；
- 必须遵守的硬事实；
- 可选节拍、伏笔/回收和章末钩子；
- 禁止新增的重大事实；
- 主笔可自由决定的对白、动作、意象、局部调度和实现方式。

章纲不得被系统自动升级为已发生正史。实际正文可以合理偏离软节拍，但改变重大结果时须返回规划确认。

## 二、状态机与门禁

新增书籍规划阶段：

```text
opening_confirmed
style_in_progress
style_ready
setting_in_progress
setting_ready
master_outline_in_progress
master_outline_ready
volume_outline_in_progress
volume_outline_ready
chapter_outline_ready
writing_enabled
```

门禁规则：

| 当前操作 | 必须满足 | 禁止行为 |
|---|---|---|
| 讨论作品风格 | 开书资料已确认 | 把风格标签直接升级为逐句硬规则 |
| 确认作品风格 | 三个最低风格维度已处置、作者确认 | 用模型猜测代替作者确认 |
| 讨论设定 | 开书资料已确认 | 生成剧情跨度/章纲 |
| 确认设定 | 风格基线已确认、设定必备项已确认、其余项已处置 | 用模型自动代替老板确认 |
| 讨论总纲 | 设定基线已确认 | 同时生成卷纲/章纲 |
| 确认总纲 | 总纲契约完整且引用活动设定版本 | 自动创建章节 |
| 讨论卷纲 | 总纲已确认 | 复制总纲充当卷纲 |
| 确认卷纲 | 起止状态、矛盾、高潮、兑现均存在 | 一次生成整卷章纲 |
| 讨论章纲 | 当前卷纲已确认 | 生成未来3章以外的详细章纲 |
| 启动正文 | 下一章章纲已确认 | 用标签或聊天摘要代替章纲 |

所有非法越级返回可理解的领域错误和缺项列表，不显示“内部错误”。

- 正常场景适配不算漂移；
- 修改活动风格只影响未来任务，不自动重写历史正文；
- 重大风格改变生成影响预览，使未来未执行章纲/工单陈旧；
- 每20/50章观察兑现密度、语言同质化、人物声音和情绪单调，但不自动改写正文。

### Task 11：旧数据兼容与污染书恢复预演

**Files:**
- Create: 只读影响分析服务和恢复预演测试
- Modify: 文档与运维说明

**Rules:**
- 不删除旧规划、正文和正史；
- 标记旧层级产物为 `legacy/unverified`；
- 输出“保留、归档、失效、需要重建”的影响清单；
- 《这游戏上线就给钱》的实际恢复必须在修复完成后另行获得老板确认。

### Task 12：验收、证据与提交

每个子任务执行：

- 类型检查；
- 自动测试；
- 构建；
- 空库迁移和旧库升级；
- 本地运行；
- Repository 合同；
- 中断恢复与跨书隔离；
- 前端无英文代码、无重复内容、无错误原始堆栈；
- 独立语义夹具验证游戏、历史、融合题材；
- 对“幽默＋热血＋爽点密集”做多场景成对盲评，分别覆盖战斗、情感、悬疑和日常，验证风格稳定但不机械重复；
- 分别报告风格符合度、原创性、人物可辨识度、情绪力度和整体阅读质量，禁止压成一个总分互相抵消；
- 真实模型仅在工程门禁通过后做小规模对照，不能再用十章生成代替语义验收。

## 四、上下文控制

讨论不会把整套设定全部发送给每名 Agent。

每轮资料包分为：

1. 当前议题与作者原话；
2. 活动作品风格短胶囊；
3. 上游已确认摘要；
4. 与当前设定项直接相关的 3—8 条事实；
5. 当前缺口和冲突；
6. 允许自由提出的候选范围；
7. 来源ID和版本。

总纲讨论读取设定基线摘要及必要详情；卷纲只读取总纲、本卷相关设定和上一卷接口；章纲只读取当前卷目标、近期状态和相关正史。需要细节时允许一次定向回查，不预先塞入全部资料。

## 五、最强反例与修正

1. **反例：设定门禁让作者永远填不完。**
   修正：所有项目必须处置，但非必备项允许稍后补充、刻意留白和不适用。

2. **反例：标签越多，模型上下文越准确。**
   修正：标签只用于路由设定模块和检索，不整库注入；重复和低相关标签不进入当前资料包。

3. **反例：严格章纲可以避免写偏。**
   修正：章纲锁定目标、结果和硬事实，表达与局部实现保留自由区；合理偏离不自动判错。

4. **反例：总纲、卷纲、章纲都由一次模型调用生成更省钱。**
   修正：这会制造伪分层和错误锚定。按阶段确认虽然多轮，但只有当前需要的成员和资料被调用。

5. **反例：确认了“幽默、热血、爽点密集”，每章就必须同时出现三者。**
   修正：风格基线约束全书长期分布与主要方向；场景按自身功能动态适配，不能按章机械打卡。

6. **反例：风格标签越多，正文质量越高。**
   修正：标签先编译成短而明确的风格基线；冲突近义词必须在确认时合并、排序或说明适用范围。

## 六、停止与回滚条件

- 新流程仍能越级生成总纲、章纲或正文；
- 本书资料继续混入模型内部字段或后续虚构内容；
- 游戏题材必备设定为空仍可解锁总纲；
- 总纲、卷纲和章纲在结构或内容上高度重复；
- 主角姓名无来源改变；
- 风格基线没有进入实际主笔上下文，或因重复注入造成注意力稀释；
- 正文更符合标签但变得套路、同质、人物声音下降或整体阅读质量退化；
- 新上下文策略使原创性、人物可辨识度、情绪力度或整体阅读质量低于旧基线；
- 旧书迁移改变已有正文、正史或文件哈希。

发生以上任一项，停止启用新默认流程，保留旧数据并回滚活动策略指针。

## 七、推荐实施顺序

1. 冻结规格、决定和状态机；
2. 修复开书快照、主角信息、本书资料和风格选择；
3. 完成作品风格基线、版本和确认门禁；
4. 完成动态设定基线和门禁；
5. 拆分四层规划服务；
6. 修复讨论路由、风格胶囊和岗位上下文包；
7. 重做规划前端；
8. 接入正式写作门禁和风格漂移审校；
9. 完成迁移、恢复预演和全量验收；
10. 老板确认后，单独处理当前污染书籍。
