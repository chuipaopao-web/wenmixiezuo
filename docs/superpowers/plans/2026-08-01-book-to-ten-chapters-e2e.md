# 新书至十章真实流程验收计划

**release_id：** `wm-longform-r1-20260719-003435-e4d7b8b7`
**test_run_id：** `E2E-20260801-BOOK-TO-10-V1`
**负责人/复核人：** 当前 Codex / 当前 Codex 独立证据复核（不调用其他开发 Agent）

## 目标

只通过文秘写作公开业务接口和正常 Worker 流程，创建一本隔离的合成测试书，依次完成开书、类型自适应设定大纲、作者逐项确认、第一阶段剧情总纲、十份详细章纲、十章正式正文、三席审校、作者确认、正史结算及前端可读投影。发现故障时保留失败现场，先修复再从持久化检查点继续。

## 不做什么

- 不直接改数据库伪造讨论、正文、正史、Agent 状态或模型调用。
- 不把十章短流程当作 500 万字长期质量证据，也不宣称 E3/E4。
- 不生成全书所有阶段；本次只完成一个有起承转合且连续覆盖第 1—10 章的阶段。
- 不写入、输出或提交 API Key；不产生套餐外现金费用。
- 不修改、停止、重启或依赖 `D:\AI智囊团`。
- 不永久删除作者数据，不覆盖现有书籍或正式正文。

## 允许与禁止文件

- 允许：本次测试脚本、相关应用服务/API/Worker/Web、目标测试、当前规格、`TASKS.md`、本 release 证据。
- 禁止：来源快照、既有迁移、API Key、其他项目和非本次故障涉及的数据。

## 依赖与约束

- 沿用 DEC-038/040/044/045/049/069/074/078/080/083/084/085。
- 新书设定必须逐项讨论并由模拟作者明确确认；设定未就绪不得创建剧情总纲、章纲或正文任务。
- 第一阶段总纲必须包含连续章节范围、阶段主线、起承转合、阶段结果、待回收信息/伏笔和后续方向。
- 每章章纲按 `chapter_outline_v2` 约束，正文目标为 2500—3500 个规范化中文字符，硬边界 2350—3650。
- 正式正文必须经硬检查、三异模型职责点评、最多两次修订、模拟作者确认后结算。
- 所有调用显式携带 owner/book 隔离键；失败可恢复且不重复计费或重复写入。

## 验收标准

1. 新书开书资料在“本书资料”中与输入一致，故事方向只作参考，不替代设定讨论。
2. 设定大纲显示本题材所需项目，逐项经历待讨论→候选→作者确认，最终基线就绪。
3. 第一阶段总纲覆盖第 1—10 章且不是十份章纲的拼接；设定未就绪时越级请求被前置阻断。
4. 第 1—10 章各有可读章纲、正式正文、真实审校记录、确认记录和结算证据；正文互相衔接且符合开书资料。
5. 规划、正文、图谱、资料库、任务中心不展示内部 JSON、字段名、技术 ID 或重复脏数据。
6. 失败任务可从检查点继续；重复提交不产生重复 Agent 调用、重复正文或重复正史事实。
7. 类型检查、目标与全量自动测试、构建、空库/升级迁移、运行、恢复、Repository 和跨书隔离门禁通过并保存证据。

## 停止条件

出现套餐外付费、新密钥需求、生产数据恢复、跨书写入、正史越权、无法判定的重大架构缺口或永久删除需求时停止并升级老板。普通代码/数据故障不停止整项任务，先修复并回归。

## 回滚

代码按本次差异逐项非破坏性回滚；合成测试书保留给老板检查并明确标注为测试资料。新增迁移若存在只允许停用新读写路径，不逆向删除数据。
