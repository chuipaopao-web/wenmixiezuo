# 文秘写作长篇创作质量 Skill 实施计划

> **执行约束：** 由当前 Codex 在 `D:\wenmixiezuo` 内逐项执行，不调用其他开发 Agent。Skill 先约束设计和验收，再用于审计现有实现；它不能代替业务代码、真实模型评测或老板的文学判断。

**目标：** 创建项目专用 `wenmi-longform-quality` Skill，把“长篇小说为什么会写坏”转换成可追溯的产品能力、失败模式、测试数据和停止条件，并用它重新审计文秘写作当前的记忆、RAG、上下文、规划、Agent、创作与审校闭环。

**架构：** Skill 使用“痛点 → 可观察症状 → 根因 → 产品机制 → 反例 → 指标 → 证据”的能力追踪链。`SKILL.md` 只保留触发、核心工作流和输出契约；长篇失败模型、运行闭环、上下文/RAG规则和评测方法放入按需读取的 `references/`。项目规则强制重要创作系统决策使用该 Skill，但普通文案和低风险小修改不触发。

**技术栈：** Codex Agent Skills、Markdown、YAML、Skill Creator 官方脚本、Node.js 确定性校验脚本、Vitest/现有项目门禁、Git。

## 一、Skill 要解决的真实问题

Skill 不以“检查得全面”为目标，而以阻止以下长篇创作失败进入产品为目标：

| 痛点 | 可观察症状 | 必须存在的产品机制 | 不能接受的伪解决 |
|---|---|---|---|
| 长上下文注意力分散 | 忘记中间章节、被无关资料带偏 | 岗位专用检索、去重、排序、Token预算、来源回查 | 把整本书或全部检索结果一次塞入提示词 |
| 人物与世界状态漂移 | 生死、位置、知情、关系、能力前后矛盾 | 带故事时间和来源的类型化正史、确定性约束检查 | 只存人物摘要或让模型凭印象检查 |
| 隐含关系检索失败 | 能找到同名句子，找不到因果、别名、多跳关系 | 结构化查询＋FTS/BM25＋向量＋关系链接＋重排＋原文证据 | 手写同义词表冒充语义检索；只做向量相似度 |
| 计划长期漂移 | 后文偏离主题、卷目标、伏笔和人物弧 | 动态分层规划、近期细化、版本影响传播、偏离门禁 | 一份静态总纲从头执行到底；完全即兴生成 |
| 主笔上下文过载 | 工单虽全但正文机械、遗漏重点 | 场景级写作契约、角色专用最小上下文、分轮回查 | 所有岗位共享同一个巨大资料包 |
| 幻觉污染正史 | 推测和废稿被后续成员当事实 | 临时区/候选区/正史区隔离，证据门禁和老板确认 | 模型回复后自动写入长期记忆 |
| 人物声音和文风趋同 | 所有人说话一样、长期出现套话 | 人物声音证据、原文风格片段检索、跨章漂移与重复检测 | 只写“模仿某种风格”的提示词 |
| 节奏和叙事功能失控 | 连续高潮、长期无兑现、重复钩子 | 跨章窗口的承诺—兑现、情绪、信息释放和场景功能投影 | 只审当前一章是否流畅 |
| 自审与多Agent同质化 | 多岗位都同意、同一盲点反复出现 | 独立任务边界、差异化证据、异模型审校、确定性检查 | 同模型换名字后冒充独立复核 |
| 迎合作者 | 只肯定作者、偏好越记越窄 | 偏好分级、事实/意见分离、强制反方、异议保留、作者最终裁决 | 把全部历史选择当作长期偏好继续强化 |
| 中断后创作重复或失真 | 重写已完成章节、丢决定、重复计费 | 持久检查点、幂等、不可变版本、结果不明停止 | 依赖聊天上下文恢复任务 |
| 质量评测失真 | 字数合格就称好，测试只验证实现自己的假设 | 对抗语料、独立金标、盲评、纵向指标、缺陷密度 | 固定同义词夹具证明“语义Recall”；5章证明长篇稳定 |

## 三、Skill 核心工作流

### 1. 先定义要改善的失败，而不是先选技术

每个重要方案先填写能力追踪链：

```text
用户痛点
→ 可观察症状
→ 根因假设
→ 已知事实/老板偏好/未知项
→ 候选机制
→ 最强反例
→ 可测指标
→ 所需证据
→ 停止或升级条件
```

如果方案只说明“使用向量库、Agent、Wiki、长上下文或更强模型”，却不能指出它具体降低哪种失败，Skill 必须退回方案。

### 2. 建立独立基线判断

在考虑老板倾向和现有实现之前：

1. 从权威代码、数据、测试和当前规格建立事实基线。
2. 将材料分为事实、推断、偏好和未知项。
3. 至少比较推荐方案、可行替代方案和维持现状。
4. 判断现有能力是“存在”“可运行”“在构造测试中通过”还是“在真实长篇场景中有效”。
5. 发现验收与实现不匹配时，以真实代码和可重复测试为准，登记文档缺口。

### 3. 按十个质量回路审查

每次跨模块方案至少覆盖与任务相关的回路：

1. **正史回路：** 什么能成为事实、何时生效、如何失效、冲突如何裁决。
2. **检索回路：** 如何识别实体、别名、时间、关系、多跳因果和原文证据。
3. **注意力回路：** 每个岗位需要什么、排除什么、超预算时删什么、何时二次回查。
4. **规划回路：** 总纲、卷纲、章纲、场景契约如何联动且允许受控修订。
5. **人物回路：** 状态、知情、欲望、关系、声音和成长如何跨章验证。
6. **生成回路：** 主笔如何把工单转成场景，而不是自由补全缺失设定。
7. **审校回路：** 硬检查、异模型软检查、证据、定点重写和上游返工如何闭环。
8. **结算回路：** 正文通过后如何提取事实、更新投影、使旧上下文失效。
9. **作者治理回路：** 如何讨论、保留异议、避免迎合并让老板做真正需要的决定。
10. **纵向质量回路：** 如何发现跨章重复、节奏塌陷、伏笔债务、文风漂移和长期回归。

### 4. 对第一版结论执行预先验尸

至少攻击以下情况：

- 资料规模扩大十倍或达到百万字；
- 查询与证据没有相同关键词；
- 同名实体、别名、谎言、误认和人物有限视角；
- 旧事实被新章节改变，但旧摘要和向量仍存在；
- 关键证据位于长上下文中间；
- 检索返回高相似但时间错误的片段；
- 任务中断、模型离线、结果不明、上下文包失效；
- 老板用肯定语气提出错误方案；
- 多岗位底层模型相同或读取相同资料；
- 生成局部精彩但破坏十章后的计划；
- 测试夹具与实现共享同一规则，形成自证；
- 指标改善但盲评质量下降。

攻击后必须修改方案；不能把风险原样列出后仍宣布方案通过。

### 5. 输出可执行结论

完整审计固定输出：

1. 明确结论与置信度；
2. 当前事实基线；
3. 能力追踪矩阵；
4. 最强替代方案与取舍；
5. 预先验尸发现；
6. 修正后的最终设计；
7. 系统测试、真实模型评测和人工盲评；
8. 不能解决的剩余问题；
9. 停止、回滚和升级条件。

不把内部检查清单机械复制给老板，只呈现影响结论的发现。

## 四、证据等级与“解决”用词门禁

Skill 使用五级证据：

| 等级 | 证据 | 允许表述 |
|---|---|---|
| E0 | 只有想法、提示词或文档 | “计划解决” |
| E1 | 接口、Schema或代码存在 | “已实现机制” |
| E2 | 确定性单元/集成测试通过 | “系统行为在构造场景通过” |
| E3 | 独立对抗数据、故障注入、消融和长规模回放通过 | “系统性风险显著降低” |
| E4 | 真实模型连续创作、跨章盲评和作者验收通过 | “在评测范围内改善长篇质量” |

任何情况下都禁止表述“保证写好长篇”。“解决长篇问题”至少需要 E3＋E4，并明确作品类型、章节规模、模型配置和仍未覆盖的文学判断。

## 五、长篇质量评测最低合同

### 1. 系统正确性评测

- 使用至少200章或100万字符的隔离测试书，不把全部硬锚点集中放在同一段。
- 构造人物、关系、地点、物品、时间、知情状态、谎言、失效事实和伏笔的独立金标。
- 硬状态查询要求100%正确；跨书污染必须为0。
- 正史变化后，旧上下文、旧摘要、旧向量和旧Wiki投影必须失效或标记待重建。
- 临时讨论、废稿和未确认推测不得进入正式检索默认域。

### 2. 混合检索评测

- 查询集与实现代码独立维护，不得用检索器内置同义词生成金标。
- 覆盖精确词、别名、语义改写、多跳关系、时间切片、反事实、否定和无答案查询。
- 分别报告 BM25、向量、结构化、关系遍历、融合和重排的召回、精度、MRR/nDCG与延迟。
- 必须做消融实验，证明混合方案确实优于单一FTS、单一向量和整书长上下文。
- 检索命中必须回到原文或正式事实证据，向量和Wiki投影不作为唯一事实源。

### 3. 上下文质量评测

- 为主编、编剧、设定师、主笔和审校分别定义输入合同，不共享默认大包。
- 比较“全量上下文”和“岗位最小上下文”的约束遵循、遗漏、幻觉、重复、Token与延迟。
- 测试关键证据位于输入中部、检索结果冲突和预算不足时的表现。
- 预算不足时必须暂停或回查，不能静默删掉硬约束。

### 4. 纵向创作评测

- 确定性模型用于验证流程、版本、结算和恢复，不用于证明文学质量。
- 真实订阅模型至少连续创作20章；第1、5、10、20章和随机跨章对进行盲评。
- 统计每万字正史矛盾、人物声音漂移、无依据新增事实、重复情节/表达、伏笔债务、章纲偏离和重写率。
- 人工盲评至少覆盖剧情因果、人物、语言、情绪、节奏、信息控制、钩子、原创性和整体现实感。
- 同时保留局部章节质量和全书纵向质量，禁止用平均分掩盖 blocker。

### 5. 作者协作评测

- 测试“作者提出明显破坏正史的建议”“作者连续偏爱同一套路”“作者改变长期方向”等场景。
- Agent必须区分偏好、事实和决定，给出有证据的反对意见，同时保留老板最终裁决权。
- 以建议采纳率作为观察项，不作为正确性奖励；不得训练成只提高采纳率。
