# 文秘写作统一取名助手实施计划

> **执行方式：** 按项目协作规则，由当前 Codex 单独实现、测试、复核和提交；不调用其他开发 Agent。

**目标：** 在开书角色姓名输入处和书籍工作台左侧增加同一套离线取名能力，按题材语境提供人物、地点、势力、物品、生灵、能力等完整类别的可选候选名。

**不做什么：** 不调用付费模型，不新增 API Key，不自动写入正史、设定或正文，不把候选名冒充已确认事实，不改变现有 11 岗位或模型绑定。

**架构：** 采用纯 TypeScript 本地候选生成器与一个可复用 React 面板。生成器以书籍频道、分类、题材、标签和故事方向作为轻量偏好，按目标类别选择词库与构词模板；UI 只消费结构化候选。开书弹窗使用“选中并填入”，书内工作台使用“复制”和“换一批”。

**技术栈：** React、TypeScript、Vitest、Testing Library、现有 Phosphor 图标和 `app.css`。

**负责人：** 当前 Codex
**复核人：** 当前 Codex 自检；项目规则禁止调用其他开发 Agent。
**依赖：** 现有开书分类/题材/标签状态、书籍资料接口、工作台导航。
**允许文件：** `apps/web/src/app/**`、`tests/**`、`docs/**`、`TASKS.md`。
**禁止文件：** `D:\AI智囊团/**`、密钥文件、已合并数据库迁移、产品运行数据。

## 任务 6：验证、运行与提交

**测试命令：**
- `npm.cmd test -- --run tests/foundation/naming-assistant.test.ts tests/integration/experience/workspace-ui.test.tsx`
- `npm.cmd run typecheck`
- `npm.cmd test`
- `npm.cmd run build`
- `npm.cmd run migrate`
- 项目现有空库/升级、Repository、运行和恢复验证命令（以 `package.json` 与 `docs/ACCEPTANCE.md` 为准）

**验收标准：**
1. 开书每个角色姓名旁都有取名入口，选中候选能准确填入对应角色且不覆盖其他角色。
2. 书内左侧“取名”能覆盖人物、山川湖泊、村庄城镇、势力、道具药品、法宝武器、坐骑灵兽、魔法技能等目标。
3. 分类、题材与标签会改变推荐语境；候选不重复，可换批次，可复制。
4. 任何候选都不会自动进入正史、设定、正文或数据库。
5. 类型检查、自动测试、构建、迁移和本地运行验证通过。

**停止条件：** 发现需要付费、新密钥、永久删除、生产数据恢复或重大架构变更时停止；普通 UI、类型和测试问题由 Codex 修复后继续。

**回滚方法：** 回退本功能提交即可；本功能不含数据库迁移和数据写入，不影响已有书籍与正史。
