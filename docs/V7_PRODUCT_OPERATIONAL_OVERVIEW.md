## 先看结论

V7 不是一个“只有开书页”的产品。当前代码已经有一条完整的长篇创作主线：

```text
注册/登录
  → 书架
  → AI 团队开书 或 作者自己填写开书资料
  → 设定编辑部
  → 时光机（全书方向与实际正文进度）
  → 卷 → 链 → 章纲 → 正文 → 定稿
  → 自动结算、故事状态维护、资料库沉淀
```

同时有独立后台，能够查看资产、成员、提示词与上下文审计、创作运行、用户、会员、用量、收入和问题记录。

但下面三件事**不能因为页面已经存在就被误认为已经完全商业可用**：

1. 近期确实发生过开书确认、设定、时光机、资料包解析等生产故障；相应热修已经有代码与发布记录，但所有作者路径尚未完成一次新的真实浏览器全量回归。
2. 目前后台是“多个专业管理页”，不是一个面向非技术运营者的一站式“配置中心”。功能台账已存在，但仍需要把运营动作、风险和下一步建议再收拢。
3. 单机运行与真实模型调用可以支撑当前试运营；**没有一万人同时使用的压测、扩容和容量证据**，因此不能宣传为已验证的一万人并发能力。

## 1. 谁在做什么：作者、系统、AI 成员

| 角色 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 作者 | 提供想法、补充偏好、选择/修改方案、确认正式资料与正文、决定是否托管写作 | 不需要理解上下文包、模型、方法论或任务队列。 |
| 系统程序 | 登录、权限隔离、版本、书籍归属、幂等防重、队列、计费、进度读取、保存与恢复 | 不应靠关键词或死规则替作者判断“这个故事好不好”。 |
| 资料策划 Agent | 每个新创作任务先整理本轮真正需要的资料，形成短任务包；结合题材给出本轮工作身份、任务责任、方法菜单与创意空间 | 不把方法论全文、整本旧方案或其他书资料直接塞给下游模型。 |
| 规划/创作/审校成员 | 理解题材、选择或组合方法、设计方案、写章纲和正文、审校、提出调整建议 | 不可改写作者已确认资料、不可变正文或真实结算。 |
| 主编 | 在需要比较或审核时做方案点评、指出需作者决定事项；不是每一步都抢走作者选择 | 不能把未发生的规划写成正文实际。 |

### 资料策划 Agent 当前是否还在运行？

**在运行。** 它没有被取消；被取消的是“把后台方法论原文和上游全文一次性塞入每个模型”的旧做法。

当前目标是：每项新创作任务先产生一次短、可追溯的资料策划结果。成员拿到的是当前任务所需的事实、已确认上游、作者新要求、题材工作身份、少量可用方法菜单和允许创新的边界。成员可以采用、组合、变形，或提出临时原创方法；资产不是强制模板，更不是随机抽奖。

## 2. 作者从登录到写完一章的全流程

### 2.1 总流程图

```text
账号会话
 ├─ 未登录：登录 / 注册
 └─ 已登录：书架
      ├─ 新建书籍
      │    ├─ 团队设计：想法 → 编剧设计 → 主编审查 → 作者确认 → 建书
      │    └─ 自己设计：填写两步开书资料 → 作者确认 → 建书
      └─ 已有书籍
           ├─ 信息：开书资料 / 设定 / 取名 / 封面
           ├─ 时光机：全书方向、已确认框架、正文实际进度、后续调整
           ├─ 卷：卷方案 → 作者采用
           ├─ 链：单元链方案 → 作者采用
           ├─ 章：章纲 → 正文 → 审校 → 作者定稿
           ├─ 库：已确认章纲与正文目录
           ├─ 任务：进行中、失败、待确认、历史任务
           └─ 团队：本书此刻可接单成员
```

### 2.2 登录、注册与个人中心

| 项目 | 当前功能 | 失败或异常时怎样兜底 | 状态 |
| --- | --- | --- | --- |
| 登录 | 邮箱 + 密码登录，进入自己的书架。 | 密码/账号错误显示安全提示；会话失效回登录页。 | 已上线，有代码与发布证据 |
| 注册 | 昵称、邮箱、密码、确认密码；密码至少 10 位。 | 前端先拦截空值、短密码和两次不一致；服务端再校验。 | 已上线，有代码与发布证据 |
| 创作空间初始化 | 打开站点时先核验会话，再读取会员状态。 | 会话读取失败显示“暂时没有打开”与“重新连接”，不白屏。 | 已实现，需真实回归 |
| 个人中心 | 显示账号状态、会员档位、算力使用、客服入口与问题反馈表单。 | 会员读取失败可单独“重新读取”；反馈提交失败显示可读提示，不暴露技术堆栈。 | 已上线，有代码与发布证据 |
| 退出 | 退出会撤销当前会话。 | 退出接口异常时提示稍后重试；身份失效仍会回登录。 | 已上线，有代码与发布证据 |

**会员对创作的影响**：管理员不限额；普通作者无有效会员、会员到期或本轮剩余算力不足时，不能继续发起受限模型任务。页面会带着原开书任务回到个人中心，刷新会员状态后再回原任务继续，而不是让作者重新填写想法。

### 2.3 书架与书籍生命周期

| 作者能做什么 | 具体逻辑 | 失败兜底 |
| --- | --- | --- |
| 看自己的书 | 左侧书架读取当前账号的活跃书籍；可切换当前书。 | 加载失败显示“重新加载”；URL 指向无权访问或不存在书籍时回首页，不继续卡在坏链接。 |
| 新建书籍 | 首页可选“团队设计”或“自己设计”。剧本入口显示“即将开放”，当前不可点。 | 见下一节开书恢复。 |
| 归档书 | 对当前书作可恢复归档，正文和资料保留。 | 先在页内二次确认；失败显示提示并保持原书不变。 |
| 恢复归档书 | 在“已归档”折叠列表恢复。 | 失败不删除归档资料，可重试。 |

**明确边界**：归档不是永久删除；当前作者端没有“删除整本书”按钮。永久清理作者生产数据仍是高风险后台操作，不能作为普通故障处理手段。

## 3. 开书：两种入口、一个正式建书门槛

### 3.1 团队设计开书

| 阶段 | 作者看到什么 | 后台实际做什么 | 失败恢复 |
| --- | --- | --- | --- |
| 1. 填想法 | 4–2000 字输入框；可选指定开书设计成员，也可让编辑部安排。 | 保存任务壳与幂等键，再由设计成员处理。当前上限已是 **2000 字**，不再是旧 800 字。 | 草稿保存在当前账号本机；提交失败不会重复创建相同请求。 |
| 2. 设计中 | 成员、真实阶段、进度和“可以离开，回来继续”的提示。 | 设计成员生成开书资料，主编独立审查。 | 页面轮询任务；刷新/离开不会抹掉任务。 |
| 3. 审查与选择 | 作者查看资料、主编意见和需要决定的项目；可接受、修改意见或换成员重新设计。 | 主编输出审查与作者决策点；原候选版本保留。 | 未完成/中断任务会显示“对不起，这次没有完成”，并给出重连、重填或返回首页。 |
| 4. 确认建书 | 作者确认资料后创建真正书籍。 | 服务端比较授权时的候选与当前提交；创建书籍及正式开书版本。 | 近期修复了“空可选字段被误判页面已修改”的确认死锁；若资料确有变化，会要求先交主编更新，而不会静默覆盖。 |

### 3.2 自己设计开书

作者不使用 AI 也能填写开书资料。页面分两步校验：书名、频道、分类、预计总字数、1–2 位主要角色等。确认后同样进入正式书籍，不绕过版本与归属校验。

作者可随时：返回上一步、暂存并离开、只清空未提交草稿、重新填写。已保存历史资料不会因“清空重填”而删除。

### 3.3 开书失败时，作者应该看到的正确体验

| 状态 | 作者可做的恢复动作 | 系统不得做的事 |
| --- | --- | --- |
| 任务记录正在读取 | 等待，或稍后回到同一任务。 | 不能因为刷新就重新扣费发起设计。 |
| 任务失败/中断 | 重新连接原任务；按失败原因继续或重新填写；必要时回首页。 | 不能把一个失败任务永久绑死在新建书入口。 |
| 会员阻断 | 去个人中心办理/刷新会员，再返回同一任务。 | 不要求作者复制想法到新页面。 |
| 确认资料冲突 | 让作者提交给主编更新，或回原资料修改。 | 不能覆盖另一次已保存更新。 |
| 用户主动放弃 | 在任务页清理“尚未建成书籍”的开书任务。 | 不删除已建书、历史候选或作者正式内容。 |

**当前风险提示**：开书是近期故障最密集的区域。第 89 批已修复一次确认死锁，但仍应以新隔离账号做一次“注册 → 团队设计 → 修改一项可选字段 → 确认建书”的浏览器验收，才可标记为稳定闭环。

## 4. 每本书的作者页面

顶部固定导航为：**信息、时光机、卷、链、章、库、任务、团队**。同一书的 URL 始终带书籍标识，接口按当前登录账号和该书同时校验归属。

### 4.1 信息页：开书资料、设定、取名助手

#### A. 开书资料

作者可查看已确认的书名、频道、题材标签、最初想法、世界与时代、主要角色、故事方向和硬性要求。

可在页面下方完成：

- 修改开书资料；
- 请求主编设计书名并采用一个候选；
- 请求主编和视觉成员设计封面，预览、下载和采用一张封面；
- 进入设定。

资料读取失败不会出现空白内容，会显示读取失败；书名、封面设计都保留任务和失败历史，离开后可以从任务页回来查看。

#### B. 设定编辑部

| 作者操作 | 系统与成员行为 | 失败恢复 |
| --- | --- | --- |
| 请主编建议“本书真正需要的设定” | 主编依据确认开书资料提出可选设定目录。 | 推荐任务可以刷新或重试，不必从头再开书。 |
| 打开完整设定库 | 选择系统建议项或新增自定义条目；已设计项目不会被重复设计。 | 页面加载失败提供“重新连接”。 |
| 批量设计 | 默认每个设定由一名成员设计，进度可见。 | 批次可继续、重试或重新开始；已成功结果保留。 |
| 修改/重设计一项 | 作者可直接改，或选成员重新设计、融合多个结果、请求复审。 | 失败任务有单条重试；不会让其他设定消失。 |
| 主编终审 | 在准备进入全书规划前，主编检查设定清单。 | 终审失败可继续、刷新或回设定修改；时光机会定位回该终审。 |

设定结果只有在作者确认后才成为正式上游；推荐、候选与正在讨论的文字不应被当成正文事实。

#### C. 取名助手与封面助手

取名助手依据当前开书资料提出候选，作者采用后才写回书名。封面助手可选择平台风格、画面风格、构图、色彩、氛围、出现/避免元素和作者补充；成功候选可以下载或采用。封面图制作中、失败或采用失败均会保留可恢复状态。

**已知体验问题**：这两项当前采用抽屉/对话层展示，不完全符合“尽量不弹窗”的长期原则；功能存在，但交互是否保留为现状，需要后续产品验收决定。

### 4.2 时光机：规划与正文实际的总入口

时光机不是“历史资料页”，而是全书级的下一步工作台：

- 读取已确认的全书规划树；
- 显示全书路线候选、主编建议和作者选择；
- 从已定稿正文读取真实章数、最近已确认链、故事状态；
- 展示从正文实际偏离中产生的未来调整建议；
- 继续生成全书框架、重做缺失方案、取消运行、选择/调整/融合路线，并继续到正式全书树。

它会把“未来计划”和“已发生正文”分开显示。正文进度读取失败时，页面保留上次成功读取的实际内容并明确提示“可能不是最新”；规划成员名单或建议项临时失败不应阻断已确认框架读取。

| 常见情况 | 当前恢复机制 |
| --- | --- |
| 没有全书框架 | 给出生成全书路线/框架的入口，而不是报错。 |
| 规划生成失败 | 重新读取、仅补缺失方案、取消当前运行或重新生成。 |
| 读取正式正文进度失败 | 单独“重新读取”，不会把规划树一起清空。 |
| 上次读到的实际正文还在 | 保留旧结果并标注可能已过期。 |
| 已确认树与新候选冲突 | 已确认树优先；旧候选失效不覆盖已确认内容。 |

**已知风险/待确认**：时光机是用户近期集中反馈的页面。代码已增加“实际正文进度独立读取、保留上次结果、不能用候选冒充实际”的处理，但必须用含有多章定稿正文的真实测试书重新验收路线、链、章的继续动作。

### 4.3 卷、链、章：创作工作台

这三页共用一个工作台，只是打开的层级不同，避免同一件事在多个页面重复配置。

| 页面 | 作者真正做的事 | 前置条件 | 主要结果 |
| --- | --- | --- |
| 卷 | 在全书树下选择先创作哪一卷；可填写本卷目标，选择 1–3 套方案与成员偏好。 | 已确认全书框架。 | 通过审查的卷方案，作者采用后进入该卷。 |
| 链 | 在已确认卷下选择单元链，设计事件推进与阅读节奏。 | 已确认卷方案。 | 通过审查的单元链方案。 |
| 章 | 将已确认链拆为 4、6、8、10 或 12 章章纲；确认章纲后写正文。 | 已确认单元链。 | 正式章纲、正文草稿、审校、定稿与结算。 |

#### 方案比较与创意空间

每次卷、链、章纲默认只出 **1 套**，节省时间和用量。作者可主动选择 2–3 套独立方案比较；多方案时可指定成员偏好，并由主编比较。每个候选独立保存，某一套失败不会删除其他成功方案。

#### 资料整理与恢复

卷设计前的完整资料包上限为15000字符，资料编辑先分批读取、去重并核对完整包大小，通过后才交给创作成员。预算或格式不符会有限自动修正；先前Agent误标的硬约束必须通过覆盖核对才能移除，不能丢掉真实作者要求。旧资料整理任务明确失败时，作者可以在原页“继续整理资料”，沿用已保存步骤；结果未知时先核对，不重复下单。此处是故障恢复能力，不保证任意复杂资料或供应商故障都能自动成功。

#### 正文两种模式

| 模式 | 作者体验 | 安全边界 |
| --- | --- | --- |
| 每章确认 | 成员写一章 → 审校 → 作者确认定稿 → 再写下一章。 | 作者未确认不进入正式正文与结算。 |
| 托管写完本链 | 作者一次确认后，主笔与审校连续完成本链余下章节。 | 每章仍先有正文与审校，再定稿/结算；任务可停止；结果不明会停住，不能盲目重发。 |

#### 定稿后的自动维护

作者确认一章正文后，系统同事务保存不可变正文版本和“需要结算”的事件；后台 Worker 再异步维护人物状态、故事状态、伏笔/开放问题与未来规划建议。维护失败不回滚已确认正文，页面显示“正文已安全保存，正在更新故事进度”，并可“继续更新并写下一章”。

这意味着：作者无需逐项点击“更新人物”“更新伏笔”，但也不会因为一个后台维护失败丢掉已确认正文。

### 4.4 资料库

资料库按“卷 → 链 → 章节”显示已经生成的正式资料：

- 已确认章纲的目标、开篇钩子、推进、阻力、转折和回报；
- 已存在的正文版本；
- 正文是否已定稿、当前版本号；
- 本卷/本链创作状态。

作者可展开并查看正文。单篇正文打开失败时仅该篇显示错误和“重新打开正文”；资料库列表仍保留。资料库为空时会清楚显示“还没有正式创作资料”，不把未来规划伪装成已写内容。

### 4.5 任务页

任务页是所有“离开页面后仍在运行”的统一入口，包含：开书、书名/封面、设定、全书路线/框架、卷链正文等任务。

| 功能 | 作用 |
| --- | --- |
| 进行中与待确认 | 自动刷新真实进度；点击可回到对应书和页面。 |
| 失败任务 | 显示可读失败信息，跳转到可以恢复的原页面。 |
| 停止运行 | 对可停止的规划或创作任务发出停止请求；已完成成果保留。 |
| 清理未完成开书任务 | 仅归档“尚未建成书籍”的未完成开书任务；有页内确认。 |
| 历史记录 | 保留完成、取消或失败记录，方便追溯。 |

任务列表部分接口临时不可读时，页面会显示“部分工作记录暂时没有加载出来，编辑部会自动重试”，并保持已成功加载的部分，而不是整个页面失效。

### 4.6 团队页

团队页显示当前书可用的开书、规划、创作成员及其公开职责与可用状态。它用于让作者了解“本轮是谁在做事”，不展示 API Key、原始提示词或模型思维过程。

成员没有固定的“历史文专家”“游戏文专家”人设。当前原则是：成员在执行某本书的某项任务时，依据题材融合档案临时拿到合适的工作身份、写作重点、真实性检查与创意空间；岗位本身保持通用。

## 5. 失败兜底总表

| 失败类型 | 作者端正确表现 | 后台正确处理 | 数据保护 |
| --- | --- | --- | --- |
| 登录或会话失效 | 请求重新登录或重新连接。 | 撤销/更新会话，不暴露认证细节。 | 不读取其他作者书籍。 |
| 页面首次加载失败 | 可读错误 + 重新读取/重新连接。 | 记录请求 ID 与可诊断信息。 | 不清空页面已有成功结果。 |
| 模型明确失败 | 真诚说明“对不起，这次没有完成”，显示原任务的继续/重试/重做路径。 | 只在可判定安全时重试；保留已成功候选。 | 不重复扣费、不覆盖历史。 |
| 模型结果未知或 Worker 中断 | 停在安全状态，等待恢复或人工继续。 | 不自动盲目重发同一调用。 | 防重复生成、重复扣费和多版本覆盖。 |
| 上游资料更新冲突 | 引导回需要确认的上游页面。 | 校验版本和来源指纹。 | 旧页面不能覆盖新确认版本。 |
| 正文已定稿但后续维护失败 | 明确“正文已安全保存”，提供继续维护入口。 | outbox 幂等追赶维护任务。 | 正文不可变，不随维护失败回滚。 |
| 用户主动停止 | 提示已完成内容保留。 | 停止未开始的后续动作。 | 不删除已确认资料、正文和历史版本。 |
| 用户反馈 Bug | 个人中心可提交反馈。 | 后台问题记录把反馈与失败任务集中处理。 | 只管理员可见，按书籍归属校验。 |

## 6. 独立后台：现在能看什么、能改什么

后台地址是 `admin.wenmixiezuo.com/v7/`，只允许管理员会话访问。当前左侧导航共 15 个页面，已经比“没有功能总览”更接近运营工具，但它仍是分区后台，并非一个总配置中心。

### 6.1 创作资产

| 页面 | 可以做什么 | 是否直接改作者正文 |
| --- | --- | --- |
| 资产总览 | 看到叙事方法、剧情模式、剧情配方、分层规划的整体说明。 | 否。 |
| 叙事方法 | 查看方法适用位置、风险、任务责任和创意使用建议。 | 否。 |
| 剧情模式 | 查看不同剧情职责、适用条件、不可逆结果与风险。 | 否。 |
| 剧情配方 | 查看配方阶段、关联方法和组合风险。 | 否。 |
| 分层规划 | 查看五层规划的职责、资料来源、任务包和审计示范。 | 否。 |

这些页当前以阅读/审计为主。方法资产用于帮助 Agent 选择少量相关方法，不等于后台点一次就批量改作者正在写的书。

### 6.2 创作团队与上下文

### 6.3 平台运营

| 页面 | 当前能力 | 操作边界 |
| --- | --- | --- |
| 功能台账 | 查看当前 V7 能力、旧功能去向、疑似遗漏和代码证据。 | **只读**；它是内部台账，不替代本文的产品使用说明。 |
| 运营总览 | 今日失败任务、待处理问题、算力、图片、API 成本、会员、收入、趋势与高用量用户。 | 读取生产账本，不保存统计副本。 |
| 用户与书籍 | 搜索用户/书名、看书籍进度、任务/失败数；暂停或恢复账号。 | 暂停会立即撤销该账号旧会话；管理员不能暂停自己。 |
| 算力与成本 | 按模型、按用户看调用、算力、图片和成本。 | 仅统计，不修改用户余额。 |
| 问题记录 | 汇总作者反馈和失败任务，标记严重度、处理状态和处理备注。 | 不直接修改原反馈或作者正文。 |
| 会员与收入 | 给普通用户办理、续费、撤销会员；看套餐分布与不可变流水。 | 办理有幂等键；撤销权益但不删除历史流水。 |

### 6.4 会员办理：当前实际操作位置

1. 登录独立后台。
2. 打开 **平台运营 → 会员与收入**。
3. 在“用户会员”搜索用户，点该行的 **办理**。
4. 在当前页展开的办理面板选择套餐、实收金额和备注。
5. 点击“开通并记录收入”或“续费并记录收入”。

套餐当前为：青铜 20 万、白银 2000 万、黄金 5000 万、钻石 2 亿算力。普通作者前台不能自行支付或选套餐，前台只显示当前会员状态并引导联系客服办理。

**这解释了“我点击办理，没有选择套餐”的现象**：套餐下拉框并不在表格行里，而是在点“办理”后展开的同页编辑区。若展开后仍没有套餐选择，属于页面/数据加载故障，应在“问题记录”建单并检查后台控制台请求。

## 8. 当前最值得优先验收的清单

这不是立即启动的新开发合同，而是你查看本文后应优先决定是否补齐的验收顺序。

1. **P0：一条真实作者端到端回归**
   隔离测试账号从注册开始，跑团队开书、修改一项可选资料、确认建书、设定推荐与设计、全书方向、第一卷、第一链、章纲、单章写作、定稿、时光机和资料库。每一步保存截图、任务 ID、请求结果和恢复结果。

2. **P0：三类失败演练**
   分别验证模型明确失败、Worker 短暂不可用、页面刷新/网络中断。验收目标是：已确认资料和正文不丢；作者不白屏；恢复按钮回到正确原任务；没有重复调用。

3. **P1：后台运营驾驶舱**
   在现有“功能台账、问题记录、创作运行、用户与书籍”之上，增加一页面向产品负责人的总览：当前版本、健康、活跃失败、最常见恢复动作、关键开关、未验证功能和待办。它不应暴露密钥或作者正文。

4. **P1：会员办理现场验收**
   用非管理员测试账号验证：后台办理 → 作者个人中心刷新 → 可恢复原开书任务 → 会员流水正确。重点检查“办理面板没有展开”这一类 UI 误解或加载故障。

5. **P2：商业化容量方案**
   在产品稳定前，补模型限流、队列、重试预算、数据库备份恢复、监控告警、容量压测和扩容预案。没有这些证据前，不以“一万人同时使用”作为对外承诺。
