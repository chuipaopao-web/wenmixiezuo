# 长篇创作质量规格

## 1. 目标与边界

文秘写作的目标不是用一次提示词自动生成整本小说，而是通过可审计的创作控制系统，降低长篇创作中可识别的系统性失败：正史污染、人物和时间状态矛盾、检索遗漏、计划漂移、上下文过载、文风同质、节奏失控、自审同质化和作者迎合。

最终产品目标明确为单书300至500万字、1000章以上；工程容量按500万规范化中文字符、1500章留出余量。该目标不改变证据规则：容量通过不等于文学质量通过，200章结果也不能直接外推到1000章。

系统必须同时保护创造性、人物生命力和最终输出质量。正史正确、检索命中或规则遵循提高，不代表小说写得更好；任何治理机制都不得把软倾向变成机械硬规则、把写手变成大纲填空器或把11名成员压成同一种安全意见。逐字校对、格式转换、事实修订等非创意编辑可以严格受限，但该例外不得外推到章节创作。

产品可以提高长篇创作的可控性、连续性和缺陷发现率，不能替代基础模型能力、作者审美和最终文学判断。任何质量结论必须说明题材、模型、章节规模、基线、创造性非劣效结果和剩余风险。“不影响创造性”作为发布门禁验证，不伪装为数学上的零影响保证。

## 2. 质量层级

质量必须分层报告，不得互相替代：

1. 局部文字：句子、对白、动作、感官、意象和重复。
2. 单章结构：目标、冲突、转折、代价、情绪、信息和钩子。
3. 跨章连续性：事实、人物状态、因果、知情边界、伏笔和承诺兑现。
4. 全书叙事：主题、主线、人物弧、节奏、信息控制和结构变化。
5. 作者满意度：作者的个人选择，不能自动作为前四项正确性的替代指标。
6. 创作自由与多样性：原创性、合理惊喜、人物可辨识度、情绪力度、语言生命力、检索锚定和方案多样性。

## 3. 数据权威

平台使用逻辑隔离的数据层：

- 正式源：已确认正文、设定、规划、决定和正史事实；不可变、可追溯。
- 临时源：聊天、讨论、初稿、重写稿和中间推演；仅在当前任务有界使用。
- 候选源：待确认事实、研究结论和规划提案；不自动进入正史。
- 派生Wiki：从正式源编译的人物、地点、组织、规则、事件和伏笔页面。
- 检索索引：FTS/BM25、向量、关系和时间投影；可重建，不决定事实。
- 上下文包：某次Agent调用实际采用的不可变资料快照。

聊天本身不默认进入正式长期知识。聊天中形成的决定、设定或偏好，必须经过识别、结构化和相应门禁后进入对应正式层。

小文秘书只拥有短期会话状态、可重建书籍服务缓存、老板明确操作偏好和经验证的工具/路由经验，不另建与正史竞争的私人知识。它保留老板原话并帮助准备最小资料；剧情、规划、正文和文学判断仍由相应创作岗位完成。

## 4. 混合RAG目标架构

检索必须组合以下通道：

1. 结构化查询：人物生死、位置、关系、知情、数量、物品、规则和故事时间。
2. FTS/BM25：姓名、专名、原句、口头禅和明确关键词。
3. 向量召回：无关键词重合的语义改写、主题、行为和风格候选。
4. Wiki/关系链接：实体之间的多跳因果和关联扩展。
5. 时间与版本过滤：只返回当前任务故事时间和正史版本下有效的信息。
6. 融合重排：根据岗位、任务、来源权威、时间、关系和相似度排序。
7. 原文回查：重要结论必须能定位正式事实或正文证据。

检索以“最小充分”为目标，不以召回数量为目标。主笔上下文分成短小的硬约束胶囊和明确可选的灵感调色板；大量历史正文、相似场景和岗位意见会锚定生成，只有能说明当前作用的资料才进入上下文。

已闭合旧阶段默认使用版本化卷/故事弧结算，不注入全部旧正文。实体或别名重现、开放承诺/伏笔进入窗口、规则/知情/关系/人物声音需要证据、历史因果被引用、摘要冲突/缺项或老板明确回顾时，按卷→故事弧→章节/场景→正式事实/原文逐级下钻。全局硬事实和开放线程不能按章节距离衰减；摘要只负责路由，不能裁决正史。

按DEC-012采用SQLite权威源、SQLite FTS5、LanceDB OSS TypeScript本地嵌入式向量投影、SQLite时间关系/Wiki投影和应用层融合重排。LanceDB不开放端口、只保存按书可重建投影；不引入云数据库或需要独立运维的向量/图服务。切片按DEC-017使用不可变原文、结构节点、父子检索块、原子事实和版本化快照；完整合同见 `docs/HYBRID_RAG_DESIGN.md` 与 `docs/CHUNKING_DESIGN.md`。

按DEC-019，四路不直接加分：结构化事实承担硬状态，FTS定位原词原句，向量只产生语义/声音/主题候选，关系/Wiki有界扩展已消歧实体。结果分为H硬约束、E证据、I灵感；H不参加RRF，E/I分车道融合，派生副本按来源血缘去重，确定性结论闭环到正式事实或原文。完整编排见 `docs/HYBRID_RETRIEVAL_ORCHESTRATION.md`。

## 5. 岗位专用上下文与创作模式

- 主编/副编：老板最新要求、活动决定、岗位意见、任务、交接状态和必要正史；不读取整本正文，同一时刻只有活动主编签发工单。
- 两名编剧：在相同权威边界下各自读取活动规划、人物欲望、已发生事件、开放伏笔和阶段目标；初始输出互不可见，必须形成结构不同且因果成立的备选。
- 设定/GLM点评：写作前读取类型化事实、时间线、人物状态、规则、冲突和来源；点评时增加完整当前稿，只阻断有证据的硬连续性。
- 主笔/副笔：写作工单、约束胶囊、前章状态、人物声音、自由创作区和少量灵感调色板；同一正式版本只激活一人，禁止整书和全部聊天。
- Kimi点评：完整当前稿、写作契约、少量人物声音和重复证据；检查文学、语言和可解释AI腔风险，不接收写手自我解释。
- 豆包点评：完整当前稿、目标读者、内容尺度、趋势和策略版本；检查体验、政治与情色风险，不以固定爽点模板强制每章同构。
- 研究：研究问题、时间地区和可信来源；资料提供事实边界与可能性，不直接决定剧情。
- 版权：授权、隔离来源和相似风险；阻断实质性相似，同时允许类型惯例和独立表达。

小文秘书不属于上述11个创作岗位。它默认只读取原始消息、当前书/会话、实体/别名候选、资料水位和路由政策，不接收I灵感车道，不生成剧情结论；本地候选经正式上下文编译器重新校验后才可进入岗位包。

每个上下文包记录模式、来源、采用原因、版本、排序、Token、压缩、约束层级和排除理由。11名成员不能为了“公平”共享同一个资料包；独立意见完成前不读取其他岗位结论。唯一例外是每轮事实/文学/体验三点评共同读取同一完整当前稿，各席附加的旧史和策略资料仍不同且有界。硬来源超预算时暂停，不得静默截断。

创作分为四种模式：

1. 开放讨论：发散和质疑，不写正史。
2. 创意推演：保留多个相互冲突候选，不提前压成共识。
3. 暂存试写：试对白、场景、开头或文风，只进入临时区。
4. 正式生产：准备进入正式正文，执行完整准备、审校和结算链。

系统默认使用足以满足意图的最轻模式。前三种不因缺章纲而阻断，也不能因文本看起来完整就自动升级正式层。

## 6. 动态分层规划

规划层级为：

```text
创作方案
→ 故事圣经
→ 双编剧独立阶段总纲（连续章节范围、主线闭环、阶段级起承转合、结算、待回收项与后续方向）
→ 卷纲
→ 近期章纲
→ 场景级写作契约
```

远期保持粗粒度，近期逐步细化。章节结算、作者决定或正史变化可以触发受控修订，但必须计算影响范围，使依赖旧版本的章纲、上下文和任务失效或待复核。计划不是已发生正史。

滚动视野固定为：全书终局、主题和重大承诺保持稳定；卷和20至30章故事弧保持中程因果；未来30至50章保持可执行轮廓；未来5至10章细化；当前1至3章形成精确场景契约。远期不一次写死1000章，近期也不能只看前一章即兴续写。

规划成果区分硬结果、任务目标、软倾向、自由创作区和重大候选。章纲约束因果与必要结果，不预写每个动作、句子和情绪节拍；合理的局部偏离只记录理由和影响，不默认判错。

全书表达基线与场景技法分层：作者确认版本化的叙事视角、语言气质、文字密度、目标读者、内容尺度和总体声音；编剧与主编确定场景叙事功能和目标读者效果；主笔按场景动态选择一种核心技法及必要辅助技法。系统不限制全书只能使用一至三种手法，也不允许按剧情标签机械套用固定模板。

章节字数使用“目标＋硬容差”而不是为几十个字符整章重写：正式主笔仍以2500至3500有效字符为目标；硬检查只在低于2350、高于3650、存在占位或正文不完整时触发长度修复。目标外但容差内必须记录告警并交给三席按内容裁决，不能把字数接近目标冒充文学质量，也不能用容差接受片段、摘要或截断稿。规则版本与回滚条件见DEC-044。

内部技法库是可检索、可版本化、可回滚的抽象工具箱。单次上下文只包含当前场景必要的少量技法卡，卡片是软建议并必须保留主笔提出库外做法或合理偏离的空间。

## 7. 正式生产闭环

```text
作者讨论
→ 两名异模型编剧检索并独立给出意见
→ 设定检查硬矛盾
→ 主编保留异议并形成推荐
→ 作者确认方向
→ 写作工单、场景契约与动态技法选择
→ 主笔或副笔单人生成暂存正文
→ 硬检查与事实/文学/体验三异模型全文点评
→ 主编合并单一定点修改单
→ 定点重写或上游返工
→ 正文确认
→ 正史结算、Wiki和索引更新
→ 纵向质量检查
```

该闭环只适用于正式生产。自然“开始写/继续写”和直接 `writing-runs` API必须共用准备门禁并只启动下一章；上一章未结算时下一章不能开始。主笔/副笔不得直接修改正式正文或正史。

生成前只做正史、依赖、版权、安全、隔离和费用硬预检；活动写手先连续形成完整草稿，再做确定性硬检查和三异模型整体点评。语言、节奏、审美和人物表现不得在逐句生成中被实时纠正。软修改降低整体效果时保留原稿并撤销对应建议。

三席固定职责但不做简单多数投票：事实席默认GLM，GLM活动写手时改用DeepSeek，检查正史/时间/状态/知情/规则/伏笔；Kimi检查文学/人物/语言/节奏和AI腔风险；豆包检查体验/情绪/钩子及政治/情色风险。证据明确的正史、安全与合规阻断项必须处理；相互冲突的文学软建议保留差异。每轮三份报告必须绑定同一不可变稿件，最多两轮自动改写；两轮后只剩一个主观席反对而另两席通过且无硬风险时，将少数异议交给老板确认，不追逐移动风格目标。具体边界见DEC-045与 `docs/REVIEW_CONVERGENCE_AUDIT.md`。

`ai_style_risk_score` 只是套话、模板化、解释过度、节奏均质等可观察文本特征的0至100风险指数，`flagged_paragraph_ratio` 是有证据标记段落数占比；均不代表AI作者概率。政治/情色结果是带位置和策略版本的风险筛查，不代表法律意见或目标平台最终结论。不能为降低AI腔风险机械加入错误、碎句、口语或随机变化。

## 8. 人物与叙事质量

人物分析视图必须由正式事实和行为证据构成，包括故事时间下的状态、关系、欲望、知情边界、价值观、说话风格和允许变化。人物标签不能替代正文证据。

纵向质量投影至少维护：

- 场景功能和冲突类型；
- 情绪曲线和承诺—兑现；
- 伏笔创建、推进、误导和回收；
- 人物声音与行为证据；
- 重复情节、表达和钩子；
- 章纲偏离及其理由。
- 检索锚定、创作自由区使用、岗位意见差异和软规则累积。
- 全书表达基线漂移、场景技法与目标效果的匹配、同类场景套路重复和技法库锚定。

## 9. 作者治理与反迎合

作者偏好必须区分：硬边界、稳定风格倾向、当前任务选择、临时情绪和可质疑观点。建议采纳率不是正确性指标。

当作者方案与正史、因果或既定目标冲突时，Agent应提供证据、最强反对理由、可行替代和影响，同时保留作者对创作方向的最终裁决权。不得为了“反迎合”而无意义唱反调。

聊天可读性使用“有效输出”而不是固定字数截断：直接回答、关键依据、结构不同的备选、风险/未知和需确认项默认可见，补充证据与完整岗位意见按需展开。结构化失败时保留完整实质内容；少数意见、事实冲突和风险不能作为废话删除。正式正文和暂存试写不适用聊天有效输出层。改变岗位输出合同必须以旧完整回复为基线，分别验证信息保留、成员辨识度、创意覆盖、Token/延迟和整体质量非劣效。

Agent持续进化不等于永久记忆全部聊天和采纳。经验必须经过“候选—适用范围/反例—跨样本验证—确认—版本化启用—效果观察—到期复核/撤销”；一次成功改写、老板一次采纳和模型自评分不能成为永久规则。

## 10. 证据等级

| 等级 | 证据 | 允许结论 |
|---|---|---|
| E0 | 文档、想法、提示词 | 计划解决 |
| E1 | 代码、接口、Schema存在 | 机制已实现 |
| E2 | 构造单元/集成测试 | 构造场景通过 |
| E3 | 独立金标、对抗集、消融、故障注入、长规模回放 | 系统风险在评测范围内降低 |
| E4 | 真实模型连续创作、跨章盲评、作者验收 | 指定范围内改善长篇质量 |

对外声称改善长篇质量至少需要E3＋E4。确定性模型只能证明流程、状态、版本、隔离和恢复，不能证明文学质量。

E4必须包含创造性和输出质量非劣效：相同任务、相同模型族与相近预算下，多次采样、匿名打乱、成对盲评。评测强度按影响范围分级：局部可逆修改做针对性对照，岗位默认做跨任务盲评，全书或流水线改变做纵向评测。正史和检索改善不能以综合平均分抵消原创性、惊喜、人物、情绪或整体阅读质量下降。

原创性、惊喜和岗位差异是退化检测维度，不是写作配额；不得要求每章强行反转、每个岗位必须反对或用随机怪异换取指标。因果、人物和作品目标必须同时成立。

## 11. 最低验收

### 系统与检索

- 使用至少500万规范化中文字符、1500章的满规模测试书，硬锚点分散在不同卷、故事弧、章节、位置、来源和故事时间；独立查询金标从全书分层抽样，不用单行百万字符或集中前缀代替。
- 硬状态正确率100%，跨书污染为0。
- 查询集与实现代码独立，覆盖别名、语义改写、多跳、时间、否定、冲突和无答案。
- 分通道报告Recall@K、Precision@K、MRR、nDCG、延迟和Token。
- 做混合方案相对单一FTS、单一向量和整书上下文的消融。
- 验证正式源变化后派生Wiki、向量、关系投影和上下文正确失效或重建。
- 验证LanceDB在目标Windows/Node版本安装、冷启动、离线查询、任务级临时隔离、模型切换和整库损坏重建；正式生产不会使用落后水位。
- 验证第500/1000/1500章对早期卷关键信息的触发下钻、摘要失败原文兜底、无关旧资料不注入和全局硬事实/开放线程不衰减；初始检索加一次补充周期保持有界，计数统一为活动集0、卷1、故事弧2、章节/场景及结构化事实3，原文证据解引用单独记预算。

### 上下文

- 分别评测11名成员的上下文合同以及三点评席共享正文/分离附加资料的合同。
- 比较全量上下文、岗位最小上下文、只有硬约束和旧流程基线的约束遵循、遗漏、幻觉、重复、成本、检索锚定和创作质量。
- 比较阶段摘要＋触发下钻、摘要永不回查、任何命中都回查和整书上下文，分别报告连续性、原文证据率、误触发、漏触发、Token、延迟、旧文模仿和创作非劣效。
- 测试关键证据位于上下文开头、中部和末尾。
- 测试独立意见与提前共享结论的创意覆盖、少数方案保留和缺陷检出率。

### 纵向创作

- 真实订阅模型按20章早期趋势、50章中期稳定、100至200章长篇能力分层评测；每层保留跨章匿名盲评和旧流程基线。只有实际覆盖1000章以上和目标字数范围，才能形成相应范围的长期陪伴与文学质量声明。
- 统计每万字正史矛盾、无依据事实、人物声音漂移、重复、伏笔债务、章纲偏离和重写率。
- 独立报告原创性、合理惊喜、人物声音、情绪力度、语言/画面/节奏、整体阅读质量和作者意图，不允许相互抵消。
- 保留全部blocker和major样本，不用平均分掩盖失败。

## 12. 停止条件

- 证据不足却要求形成确定正史结论。
- 检索为空、冲突或版本不明，继续会凭空补事实。
- 硬来源超上下文预算。
- 双编剧模型不独立、豆包进入剧情席，或事实/文学/体验三点评席彼此/与活动写手不独立。
- 指标改善但人工盲评下降。
- 一致性或召回提高，但创造性、人物可辨识度、情绪力度或整体阅读质量低于预设非劣效门槛。
- 主笔自由创作区为空、软规则持续累积、岗位过早共识或探索模式被完整生产链误阻断。
- 只有E0—E2证据却要求宣布长篇质量有效。

## 13. Agent连续性质量

长期陪伴的质量不以聊天数量或在线时长衡量，而以跨间隔接续正确率衡量：同一成员在跨Worker重启、跨卷、跨100章以上间隔和正史升级后，必须正确识别当前状态、相关旧承诺、自己的未决关注和最新权威证据。

测试必须同时包含反例：旧岗位日志已失效、作者临时情绪与长期决定冲突、同模型多岗位意见相关、历史偏好诱导迎合、全量聊天造成注意力分散、未激活专家被错误显示工作中。连续性提高但独立意见、创造性或整体质量下降时，回滚岗位日志提取/召回规则，不把更多历史强塞给模型。

阶段性遗忘测试还必须包含两种相反失败：摘要遗漏关键旧事实而系统拒绝回查；任何旧实体出现都触发大量原文并锚定新剧情。通过触发准确率、原文证据率、无关旧块注入率、每章Token上界和盲评共同裁决，不能只优化召回。

## 14. Skill前置设计治理

任何会改变本规格十个质量回路的重要方案，在推荐结论形成前建立 `design_review_id` 并选择适用Skill，保存Skill版本/哈希、权威基线、事实/推断/老板偏好/未知项、推荐/替代/现状、两轮审查、创造性代价、E0—E4证据和回滚条件。Skill不能在方案定完后只作格式检查，也不能默认整篇注入产品团队上下文。

Skill更新、模型上下文变化或新故障证据只触发相关决定的定向影响复核，不静默改写已经生效的实施合同。完整流程和DEC-009至DEC-017复核修正见 `docs/DESIGN_GOVERNANCE_AUDIT.md`。

## 15. DEC-020独立评测冻结

容量、检索正确性、运行可靠性、创造性非劣效和纵向文学质量必须分别报告。阻断项包括跨书、权威覆盖、H被软证据覆盖、晚到提交、秘密泄漏、路径越界和无确认D级提升，容忍值均为0。

检索E3使用与生产规则分离的至少500个冻结查询和对抗集；主笔上下文通过最小RAG、无RAG、过量上下文、无偏好、无旧文声音和无摘要消融。最小RAG相对无RAG在创造性、自然度、人物声音和非套路的95%置信区间下界不得低于 `-0.25/5`，同时硬事实/因果不得退化。

完整固定指标、数据集治理、20/50/100—200/1000章闸门和失败处置见 `docs/EVALUATION_PROTOCOL.md`。阈值不得在看到结果后静默放宽；确定性假模型不能证明文学质量。

## 16. DEC-049稿件最佳版本保护

每个通过结构校验的三席点评面板形成一份分维度质量快照。事实、文学、体验和AI腔自然度保留命名空间，不折叠成一个总分；政治、情色、版权、事实重大冲突等硬问题独立判断，不能被文学高分平均掉。

新稿相对上一最佳稿在至少两个可比软维度下降8分及以上、没有任何维度提升5分及以上，且没有修复硬问题时，判定为条件性多维退化：新稿保留为被拒绝版本，取消其活动修订单，章节与流水线指针恢复上一最佳稿，并停止自动改写等待上游调整。该规则只防止明显越改越差，不把评分变成写作目标，也不能证明文学质量。

试写不进入三席质量快照或最佳稿竞争；只有显式升级到正式生产后才参与。确定性测试最多证明版本、门禁、回退和恢复达到E2；真实长篇创造性、人物生命力与整体阅读质量仍需E3/E4盲评。
