# 文秘写作 · 创作台重设计讨论稿

> 状态：讨论稿，未拍板，未开发。2026-08-16 晚，基于 DeepSeek《前端故事化界面优化方案》与当前代码现状。
> 本文不进当前文档中心白名单，仅作讨论载体；拍板后结论写入 `docs/DECISIONS.md` 并同步正式规格。

---

## 一、先说结论

DeepSeek 方案的核心内容（事件预告卡、"因为…所以…"因果链）**在代码里已经实现了**——
`apps/web/src/features/planning/StoryEventCard.tsx` 已有"上一幕 / 眼前的麻烦 / 不得不作出的选择 /
这一幕会走到哪里"四段式预告卡和 `StoryCausalLink` 因果连接件。也就是说上一轮已经做过
**文案级故事化**，老板仍然不满意，说明真正的病不在卡片文案，而在**信息架构**：

> 现在的前端是"流水线工序管理系统"，作者需要的是"故事创作台"。

---

## 二、现状诊断（代码事实）

### 2.1 页签即工序

主导航 8 个页签就是流水线的工序名（`apps/contracts/src/workflow.ts`）：

```
信息  设定  分卷  规划  章纲  正文  资料库  取名
```

加上工具区：团队 / 任务 / 灵感 / 设置。

- 打开一本书，**默认落在"信息"页**（`App.tsx` 第 125 行 `useState<PlanningTab>('framework')`）——
  作者打开自己的书，第一眼看到的是开书信息表单，不是"我的故事写到哪了"。
- 作者必须理解系统的阶段模型（事件链→事件大纲→章纲的分层），才知道此刻该点哪个页签。
  而作者脑子里的模型是：**故事 → 写到哪了 → 接下来发生什么 → 哪里不对劲要改**。

### 2.2 "等你确认"散落在各工序

每个阶段都是同一套动作：AI 出候选稿 → 作者确认 → 下一阶段解锁。但确认入口分散在
五个页签里，作者要轮流巡检。系统知道作者此刻有几个待办（`resolveConfirmation` 链路），
界面上却没有一个汇总的"等你拍板"收件箱。

### 2.3 AI 团队存在感与卖点不匹配

11 人创作团队是产品核心卖点，但前端主要呈现为任务列表（任务页）和成员面板（团队页）。
作者想要的心智是"**我交代想法 → 团队去干活 → 干完拿给我审**"，当前 UI 没有围绕这个
循环组织。

### 2.4 回头改没有一等地位

真实创作是迭代的：写了三章发现设定要调。后端支持（上游变更下游候选失效重确认），
但 UI 上"回到上游改"感觉像出错回退，不像正常创作动作。

### 2.5 DeepSeek 方案四个主张的对照

| DeepSeek 主张 | 现状 | 我的判断 |
|---|---|---|
| 2.1 事件卡片改故事预告片 | **已实现**（StoryEventPreview 四段式） | 已解决，不必重做 |
| 2.2 爽点勾选改情绪氛围引导 | 未实现 | **可取**，收进故事地图的事件编辑，不单独成模块 |
| 2.3 事件链改心电图（含因为所以连接） | 因果连接**已实现**；张力曲线未实现 | 张力曲线**降级为可选叠加层**，不做独立视图（过度工程） |
| 2.4 大白话门禁注入叙事润色 | 部分（术语过滤已有） | **可取**，属生成层提示词策略，顺手做 |
| 全局"故事模式/大纲模式"双模式 | 无 | **不建议**：两套 UI 双倍维护；改为默认故事化、字段收进"展开详情" |

结论：DeepSeek 方案治的是"卡片不像故事"，没治"作者要在工序之间跳"。我们要改的是后者，
顺手吸收它 2.2 / 2.4 两个可取点。

## 三、目标形态：一本书 = 一个创作台

### 3.1 导航从 8 页签收敛为 4 区

```
写作 ｜ 故事 ｜ 团队 ｜ 资料
```

| 区 | 吸收现有页签 | 定位 |
|---|---|---|
| **写作**（默认落点） | 正文、章纲 | 码字主场：当前章正文 + 本章章纲 + 结算流转 |
| **故事** | 信息、设定、分卷、规划 | 全书地图：卷→事件→章一屏看完，点哪改哪 |
| **团队** | 团队、任务 | AI 团队在干什么 + 等你拍板收件箱 |
| **资料** | 资料库、取名、灵感 | 工具与素材 |

老页签名（信息/设定/分卷/规划/章纲）不消失，降级为"故事"区内的锚点/筛选，
老作者的肌肉记忆有处安放。

### 3.2 写作区（默认主页）

作者打开一本书，直接落到写作区：

- **顶部进度条**：当前卷 → 当前事件 → 当前章，一眼定位"写到哪了"。
- **左栏正文**：当前章不可变版本链 + AI 续写稿。
- **右栏本章上下文**：本章章纲、出场人物、上章结算留的钩子、AI 写手备注。
- **底部动作**：确认本章 / 说想法退改 / 继续下一章。
- 章节结算、事件结算在流程到达时**就地弹出**，不跳页签。

### 3.3 故事区 = 全书地图

把五个工序页签合并成一屏"故事地图"：

- **主线**：卷 → 事件 → 章 的可缩放地图。默认卷级总览（每卷一张卡：卷名、一句话使命、
  进度、张力标记）；点开卷进事件链（复用现有预告卡 + 因果连接件）；再点进章纲。
- **地基抽屉**：开书信息、设定从独立页签变为地图左侧抽屉——它们是"地基"，
  偶尔改，不需要天天占一个页签。
- **改哪层看哪层**：点事件改事件，点章改章；上游一改，下游受影响节点在地图上
  直接标"需重新确认"徽标——**把"回头改"做成正常的地图操作，而不是错误回退**。
- 事件编辑里吸收 DeepSeek 2.2：用"这段剧情最想让读者感到什么"（扬眉吐气/细思极恐/
  心碎/反转/智斗/自定义）替代爽点勾选项，映射回底层软约束。
- 张力曲线：可选叠加层（地图上一个开关），由 AI 估算、作者拖拽微调；**初期可不做**，
  先把地图本身做对。

### 3.4 团队区 = 实况 + 收件箱

- **等你拍板（收件箱）**：全书所有待确认候选汇成一条队列——每条一张卡：
  什么内容（章纲/事件/设定）、AI 给的方案、作者动作（用 / 改 / 说想法退给 AI）。
  作者每天打开先清收件箱，**不需要懂自己在哪个工序**。
- **团队实况**：11 名成员当前在忙什么、刚交了什么稿，交的稿一键点开就是收件箱条目。
  任务列表降级为实况页里的"运行明细"折叠区。

### 3.5 "说想法"全局悬浮入口

任何页面右下角固定一个"说想法"按钮：大白话输入（必须/强偏好/灵感/问题四档已有），
AI 转述为附着到当前业务对象的正式输入。把现有 `AuthorIdeaComposer` 从页签内嵌
提升为全局入口——**让"用大白话驱动 AI"成为贯穿全程的操作方式**。

## 四、分期建议

| 期 | 内容 | 改动面 | 预期收益 |
|---|---|---|---|
| **P1** | 默认落写作区 + "等你拍板"收件箱 | 前端 App 路由 + 新收件箱面板；API 加一个全书待确认聚合查询 | 最大：立刻解决"打开书不知道干嘛" |
| **P2** | 故事地图（卷→事件→章合并视图，吸收 2.2 情绪引导） | 规划页签重构，复用 StoryEventCard | 解决"在工序间跳" |
| **P3** | 全局说想法入口 + 团队实况化 | 前端为主 | 强化"交代-干活-审"循环 |
| **P4** | 打磨：张力曲线叠加层、生成层叙事润色提示词（DeepSeek 2.4）、键盘流 | 前端 + 提示词 | 锦上添花 |

P1+P2 是骨架，P3 是体验放大器，P4 可放验收之后。全程不改数据库 schema、
不动工作流领域逻辑，纯表现层 + 一个聚合查询。

## 五、需要老板拍板的决策点

1. **导航收敛**：8 页签收 4 区，是否接受？（老页签名降级为故事区内锚点，不丢功能）
2. **默认落点**：打开书直接落"写作区"？还是给作者一个可记忆的偏好（上次停在哪儿开在哪儿）？
3. **分期**：同意 P1 先行、P2 紧随的切法？
4. **张力曲线**：同意降级为 P4 可选项，不做 DeepSeek 原案的独立心电图视图？
5. 收件箱的"退改"是否要带一句必填的大白话理由（帮助 AI 学偏好），还是允许空退？

---

## 六、不做什么（明确划界）

- 不改 11 人团队编制、不改工作流阶段模型、不改版本/结算/失效机制。
- 不做独立的"心电图"页面、不做故事/大纲双模式开关。
- 不动资料库、取名、管理后台的信息架构（P1-P3 之外）。
- 不趁这次重做视觉风格（配色字体保持不变，只改结构与呈现）。
