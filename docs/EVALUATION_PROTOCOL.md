# 长篇创作系统独立评测协议

- 状态：E0门槛冻结；不得在看到实现结果后静默放宽
- `design_review_id`：`DR-20260719-01`；小文秘书与路由修订 `DR-20260719-08`
- 适用release：`wm-longform-r1-20260719-003435-e4d7b8b7`

## 1. 评测目标

分别回答五个问题，禁止相互替代：

1. 容量：能否保存、索引、重建和恢复500万规范化中文字符、1500章。
2. 正确性：事实、时间、关系、冲突、来源、隔离和下钻是否正确。
3. 运行可靠性：任务、取消、接管、预算、降级和恢复是否真实。
4. 创造性非劣效：治理/RAG/压缩是否让正文更僵、更重复或更迎合。
5. 长期陪伴与文学质量：真实模型在长时间创作中是否保持岗位、判断和作品质量。

确定性假模型只能证明前3项中的工程合同，不能证明模型文学质量。

## 2. 证据等级

| 等级 | 证据 | 允许声明 |
|---|---|---|
| E0 | 规格、风险、阈值和回滚 | “已完成设计” |
| E1 | Schema、运行时、UI和实际调用记录 | “已实现某能力” |
| E2 | 自动测试、故障注入、确定性容量回放 | “工程门禁通过” |
| E3 | 冻结独立金标、对抗集、消融和盲评 | “在定义样本上达到检索/非劣效阈值” |
| E4 | 真实模型20/50/100—200章纵向证据；1000章实证 | 只按实际跨度声明长期质量 |

首版历史证据不能自动升级为本release的E1—E4证据。

## 3. 数据集治理

### 3.1 数据集分组

- `unit-fixtures`：小而透明，用于TDD，可被开发人员看到。
- `capacity-corpus`：确定性500万字符/1500章，多书、多卷、不同长度和字符分布，只测规模和恢复。
- `gold-retrieval`：手工/独立规则冻结的查询、期望实体、时间、来源簇和无答案结果。
- `gold-routing`：独立冻结的控制命令、点名、活动会话、低风险本地任务、明确剧情、高影响短句、低风险长资料、歧义、否定和应升级结果。
- `adversarial-hidden`：别名、同名、否定、观点、梦境、假情报、修订、跨书、过期、冲突、多跳和摘要缺项。
- `creative-pairs`：同一工单在不同上下文/RAG策略下的盲评样本。
- `longitudinal-books`：真实模型纵向项目，不能由确定性生成器冒充。

### 3.2 独立性

金标生成器不得导入生产检索、同义词、切片、排序或冲突代码；生产代码不得导入评测答案。数据清单保存SHA-256、生成/标注说明、冻结时间和修改历史。阈值、查询和答案一旦用于正式release，只能新增版本，不能为通过测试修改旧答案。

单人开发无法提供“不同人员完全独立”的评审，必须如实记录。可实现的数据独立性是：金标规则与生产实现分离、结果在阈值冻结后才运行、盲化A/B输出、保留失败样本，不挑选最好结果。

### 3.3 采样覆盖

金标至少包含500个查询：

- 100个硬事实/状态/规则。
- 80个三轴时间与人物知情。
- 80个实体/别名/同名消歧。
- 60个因果/关系多跳。
- 60个阶段摘要触发下钻。
- 40个冲突/修订/否定/无答案。
- 40个风格/声音/语义灵感。
- 40个跨书隔离、权限和降级。

锚点分散在全书前、中、后段和多个卷，不集中在前缀；至少30%需要回查300章以前，至少20%具有有意干扰项。

## 4. 固定指标与门槛

### 4.1 不可妥协门槛

- 跨书泄漏：0。
- 已确认正文/正史哈希静默变化：0。
- H硬约束被候选、摘要或I灵感覆盖：0。
- D级事项无老板确认自动提升：0。
- 取消/过期epoch晚到结果正式提交：0。
- 密钥进入日志、数据库、上下文、导出、备份或Git：0。
- 路径越界、非法导入覆盖或自动生产恢复：0。
- 金标硬事实、不可逆状态和明确规则：100%正确或明确阻断，不允许猜错。
- 小文秘书直接写正史/正文/确认规划/模型绑定、剧情直接作答、老板原话哈希变化、点名改派、跨书路由和未授权现金fallback：全部0次。
- `gold-routing` 中高影响漏升级：0；本地工具角色被计为创作成员或异模型意见：0。

### 4.2 检索指标

| 指标 | release门槛 |
|---|---:|
| 正确实体消歧准确率 | ≥99%；高风险歧义必须阻断 |
| 无答案/证据不足识别F1 | ≥0.95 |
| E证据 `Recall@10` | ≥0.90 |
| E证据 `nDCG@10` | ≥0.80 |
| 多跳因果完整路径率 | ≥0.90，且0条无来源推断边 |
| 阶段下钻正确触发F1 | ≥0.90 |
| 同源证据重复占位 | 每簇最多1个融合名额 |
| 来源闭环 | 确定性结论100%到事实或最小原文 |

H门槛优先于平均排名；若平均指标通过但硬事实出错，仍失败。

### 4.3 容量与性能

目标电脑硬件探针进入每次证据，不能把另一台电脑成绩冒充本机。初始门槛：

- 500万规范化中文字符、1500章、至少5本并存；容量回放、索引、重建和临时恢复全部完成。
- 结构化/FTS热查询p95 ≤300ms；四路热查询（不含生成模型）p95 ≤3s。
- 本地嵌入模型首次加载≤60s；加载后单章增量投影p95 ≤60s，且在后台不阻塞聊天。
- 单书全投影重建≤2小时；临时恢复+核心业务校验≤30分钟。若目标电脑达不到，release阻断并先优化；不得直接改门槛。
- UI在有界子图200节点/500边、200条消息DOM和200%缩放下保持可操作；长列表分页不一次加载全书。

硬件低于推荐线时允许产品显示降级建议，但验收必须在老板实际目标电脑上保留真实数据。

### 4.4 恢复指标

- 空库迁移、旧Schema逐版本升级和重复执行均通过。
- 构建投影任意阶段断电/异常，活动快照仍完整。
- 删除全部可重建投影后，只用SQLite和登记文件可恢复相同金标结果；排序浮动允许，但硬事实与来源不得变化。
- 备份恢复后100%文件哈希、正史版本链、任务终态和审计事件通过。

## 5. 创造性非劣效评测

### 5.1 比较臂

每个冻结工单至少比较：

- A：正确的最小H/E/I上下文。
- B：无RAG，仅工单和当前章。
- C：过量上下文（作为负面对照，不用于产品）。
- D：去掉作者偏好。
- E：去掉旧正文声音证据。
- F：去掉阶段摘要，仅按局部资料。

至少覆盖讨论、规划、正文和三点评四种模式，不用一种模式的结果外推全部。

### 5.2 盲评维度

1—5分：硬事实正确、因果完整、角色一致、人物声音、自然度、创造性、非套路、情绪/战斗等场景适配、节奏、伏笔处理、可读性、迎合倾向、重复/模板化。评分者看不到策略名、模型名和顺序；样本顺序随机。

### 5.3 非劣效门槛

- A相对B在创造性、自然度、人物声音和非套路四项的配对均值95%置信区间下界不得低于 `-0.25/5`。
- A的硬事实、因果和一致性不得低于B，且至少一项有统计或明确错误数改善。
- A相对C在注意力遗漏、模板化或重复中至少一项显著更好；否则说明最小上下文策略未产生预期价值。
- 任何阻断级硬事实错误、明显大段仿写、上下文指令泄漏或审校整章重写，样本判失败并进入根因分析。

首轮正式盲评不少于60个工单，每个工单每臂至少2次真实模型输出；温度、模型、提示和时间记录。费用未授权时可先完成工程框架，但不得声称E3创造性通过。

## 6. 岗位差异与陪伴评测

### 6.1 岗位合同

给11名成员同一边界下的岗位任务，检查：检索维度、风险关注、工具、输出Schema和建议是否符合岗位；不能只看语言不同。双编剧必须在互不可见条件下产生有实质结构差异的方案，主编汇总必须保留被否决项和少数异议。副编/副笔需分别通过租约接管和重复提交阻断测试。

小文秘书单独按工具角色评测，不计入11人。它必须证明点名直达、原话保留、低风险本地解决、高影响升级、剧情会话粘性、真实状态和离线降级；不得用一份本地摘要替代老板原话或双编剧的独立判断。

### 6.2 模型来源

同模型双岗测试必须显示相同来源，不计为异模型独立复核。模型路由错误、fallback不透明或假模型冒充真实模型均为阻断。

三职责点评测试必须证明每个完整稿件版本恰有事实、文学、体验三份独立报告，三模型彼此不同且均与活动写手不同，三份报告绑定同一稿件哈希；GLM活动写手时事实席必须为DeepSeek。把任一模型换成重复模型、缺失一席、未执行替补、交叉看报告、晚到旧版本或按量付费fallback都应阻断。

剧情编剧测试必须覆盖默认DeepSeek＋GLM、Kimi替换任一席、豆包被拒绝、相同模型被拒绝、绑定变更只影响未来任务。两名编剧应在互不可见条件下分别输出最小/推荐/最大章节跨度、剧情单元、前提和不确定性；提前共享数字、让作者手填章数或把估算直接转换为多章并行生成均判失败。

开书与自由聊天测试必须证明最小卡只要求书名、题材、分类、目标读者、预计规模和初始表达基线；世界观、力量体系、结局和情绪引擎缺失不阻断建书。首页没有1/3/5章批次按钮；“开始写/继续写”在资料不足时自然转规划、齐备时只启动一个下一章。

### 6.3 三点评有效性与成本

- GLM金标覆盖正史、时间、状态、知情、规则、伏笔和“应当报告未知”；评估有证据问题的Precision/Recall、误阻断率和来源闭环率。
- Kimi金标覆盖套话、模板化、解释过度、节奏均质、人物声音抹平及正常文体反例。分别评估问题定位准确率、标记段落比例计算、误报率和修订后文学质量；`ai_style_risk_score` 只评估文本风险排序/校准，不与真实作者身份作二分类准确率比较。
- 豆包金标覆盖政治与情色内容的明确风险、边界样本、文学必要表达和误报反例；评估风险级别、位置、策略版本、建议动作和漏报/误报，不把模型结果当法律或平台最终结论。
- 对照三点评与“全员点评”“单Kimi点评”“只有确定性检查”。固定三点评必须在缺陷检出、创造性非劣效和可解释性上达到门槛，并单独报告约三份全文输入带来的Token和延迟，不以套餐内调用称为零成本。
- 主编合并不得使用简单多数覆盖证据闭环的硬问题；文学软意见冲突集必须保留至少一个有依据的少数意见和采用/不采用理由。
- 每轮最多两次修订。若修订稿在原创性、人物声音、情绪力度、语言或整体质量任一维度劣于原稿的非劣效门槛，保留原稿并回滚对应软意见，而不是为了降低AI腔分数继续润色。

### 6.4 连续性

在重启、换卷、100章后、模型快照更新和任务接管场景，检查身份、职责、当前关注、未决项、最后有效贡献和来源。连续性日志不能把老板偏好固化为迎合规则。

### 6.5 小文秘书路由、成本与进化

- 路由指标分别报告：显式点名直达率、剧情升级召回、低风险直接解决率、错误直答率、低置信升级率、老板改派率和活动会话错误续接率。
- 原话保真覆盖否定、限定、反讽、长背景和短高影响命令；原始消息文本/哈希保持100%，秘书摘要不参与替代比较。
- 成本同时报告每个解决请求的云调用数、云输入/输出Token、本地CPU/GPU/内存、冷启动、总延迟和最终上下文有效率。只降低云Token但显著损害延迟或质量不能宣布成功。
- 比较“全部交主编”“纯确定性规则”“确定性＋本地工具模型＋创作岗位分层”三臂；剧情方案差异、意图保真和整体输出质量必须相对基线非劣效。
- 经验对抗覆盖单次成功、无反例、跨书迁移、过期规则、相反指令和创作偏好诱导。只有工具/路由/故障经验可版本化；影子失败、到期或指标退化必须可回滚。
- 本地工具模型缺失、哈希错误、内存不足、坏Schema和低置信分别进入确定性降级或现有套餐岗位升级，禁止远程运行时下载和按量付费fallback。

## 7. E4纵向真实模型方案

### 7.1 闸门

- 20章：基本工作流、角色/规则和人工使用负担。
- 50章：跨弧连续性、伏笔和滚动规划。
- 100—200章：阶段结算、旧正史触发、质量窗口和Agent身份。
- 1000章/目标字数：只有真实创作、真实结算、抽样盲评和恢复证据完成后，才允许相应长期质量声明。

每个闸门保留：模型与提示快照、上下文统计、检索命中、老板修改率、硬冲突、重复、伏笔兑现、阶段摘要探针、岗位建议采纳/拒绝及拒绝原因。采纳率只是观察值，不能反向编译成迎合偏好。

### 7.2 换模型与升级

模型版本变化先跑冻结短集和20章小门禁；不自动把旧模型E4证据归到新模型。提示、嵌入或重排策略大改时至少重跑相关E3消融。

## 8. 故障与对抗矩阵

- 别名同名、名字被地点/道具复用、拼写误差。
- 否定句、转述、梦境、谎言、假情报、未证实传闻、反事实规划。
- 人物死亡后回忆、规则例外、时间倒序、平行视角和人物知情差。
- 旧正史被修订、摘要落后、向量陈旧、Wiki边缺失、投影水位混合。
- 跨书相同名字、错误book_id、恢复后ID碰撞。
- 模型超时、坏JSON、截断、工具伪调用、取消晚到、Worker双领。
- 磁盘不足、数据库busy、向量目录损坏、模型文件哈希错误、离线。
- 导入路径穿越、符号链接、压缩炸弹、清单欺骗、密钥样本。
- 外部网页提示注入、SSRF重定向、私网解析和超大响应。
- 长上下文过载、旧文仿写、作者偏好迎合、团队同质、三点评互抄、审校过改。
- 小文秘书截断原话、短高影响误直答、长低风险误升级、点名被改派、剧情会话重复初始化、工具经验越权扩散和本地模型离线静默云回退。
- AI腔风险被错误展示为AI作者概率、正常作者风格被高误报、为降分机械加错别字/碎句。
- 政治/情色风险漏报、无位置证据、策略版本错配，或把模型筛查冒充法律/平台保证。

## 9. 失败处置

每个失败记录：样本ID、版本、环境、预期、实际、首次错误层、影响、可重复命令、修复、回归和是否改变设计。修复生产代码后重跑原样本、同类邻接样本和整套阻断门禁。

如果阈值本身确实不合理，不能在同release内直接放宽。必须创建新决定，说明旧阈值、实测分布、用户影响、替代和批准者；先保留失败结论。

## 10. 完成报告模板

最终报告必须逐项列：

- 达到的最高E等级和未达到等级。
- 测试命令、开始/结束时间、机器信息、commit、release和数据集哈希。
- 类型、测试、构建、空库/升级迁移、运行、恢复、跨书、安全、全规模和真实模型结果。
- 失败及修复，不只列最终绿色数字。
- 容量、正确性、运行可靠性、创造性和文学质量分别结论。
- 仍需老板提供的密钥/付费/纵向使用证据。

没有保存可核对证据时，口头“测试过了”不计入验收。
