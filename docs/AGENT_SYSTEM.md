# AI团队与介入规则

## 1. 团队组成

每本书保持14名创作成员；岗位、Agent实例和模型绑定相互独立。同一个模型可以承担多个岗位，但界面必须如实显示，不能冒充异模型意见。

1. 主编 貂蝉：决定全局优先级，组织卷纲、事件和融合；负责事件与卷的节奏体检。
2. 副编 西施：资料员、摘要员和主编备份。代表确定性 `ContextCompiler` 的资料准备职责，负责编译、压缩、去重、标注来源和排除项；不做事实判断，也不垄断数据库或检索。只有真实调用副编模型时，团队页才显示副编正在工作。
3. 编剧A 婉儿：偏强冲突、爽点节拍和快速推进。
4. 编剧B 红玉：偏递进、人物关系、铺垫和因果。
5. 编剧C 幼薇：偏脑洞、反套路和题材化新鲜感。
6. 设定 文姬：检查世界、规则、能力、资源和命名体系。
7. 主笔 秋香：当前活动正文写手。
8. 副笔 湘君：候补写手或局部润色，不默认串行重写整章。
9. 事实审查 班昭：设定、正史与因果事实核对，固定承担正文审查事实席。
10. 文学审查 妲己：语言、节奏、场景、重复和人物声音。
11. 体验审查 昭君：目标读者视角的代入、期待、爽点、困惑和弃读风险。
12. 体验·挑剔读者 妙玉：老白读者视角的毒点、吐槽点和弃读风险找茬。
13. 研究 道韫：只为明确事实研究任务提供有来源资料，不决定剧情。
14. 来源与版权 弄玉：执行来源、授权、原创性和风险检查，不设置独立页面。

小文秘书是本地确定性工具角色，不属于14名创作成员，不给剧情结论、不冒充模型、不保存聊天记忆。

## 2. 介入时机

| 阶段 | 主持/执行 | 其他成员 | 输出 |
|---|---|---|---|
| 开书 | 系统确定性校验 | 无 | 书籍、定位版本、团队、预算、设定任务 |
| 设定项 | 主编＋两位编剧独立提案 | 设定按需要检查 | 三份候选、作者选择、主编整理稿 |
| 分卷 | 主编主持 | 两位异模型编剧独立设计，设定/研究按需 | 卷候选、差异、融合稿 |
| 事件链 | 主编 | 两位编剧 | 事件序列、因果衔接、卷任务覆盖 |
| 事件大纲 | 主编融合 | 两位编剧独立方案，设定按需 | 当前事件完整大纲 |
| 章纲 | 指定编剧生成主方案 | 作者可选红玉或幼薇中任一位只挑战关键转折、冲突或钩子；设定/事实按需预检 | 完整事件章链、单章章纲；至多3条不自动采纳的挑战建议 |
| 正文 | 单一活动写手 | 设定/研究只提供证据 | 单章正文候选 |
| 审查 | 四席并行 | 事实席由班昭固定承担，文学、体验、挑剔读者（妙玉）按异模型规则选座；四席互不读取；无挑剔读者岗位的旧书保持三席 | 各席独立报告 |
| 结算 | 确定性结算＋必要抽取 | 主编查看事件/卷偏差 | 事实、状态、伏笔、摘要、下一层承接 |

## 3. 独立性

两位编剧独立阶段互不可见，不交叉投票；主编只有在独立结果全部保存后才读取并融合。审查席使用与活动写手不同的模型，彼此不读取报告；事实席由班昭固定承担，妙玉作为挑剔读者固定第四席；没有挑剔读者岗位的11人旧书保持三席运行。幼薇参与灵感讨论并可在章纲阶段由作者指定挑战候选；三编剧提案管线由后续批次接入。模型不可用或实际来源重复时必须明确降级或阻断，不能伪装独立；没有真实创作模型时，设定、分卷、事件、章纲、正文、审查、灵感和续写分析都不能用本地确定性夹具冒充成员工作。

## 4. 创造性边界

上层规划提供目标、边界、因果和必须项，不规定每句写法。AI可以提出有代价的偏离方案；局部合理发挥可以直接执行，影响卷目标、事件结果、人物核心选择或正史规则的偏离必须先给作者看影响。

模板只是软参考。岗位提示词不得把质量规范、评分表或固定叙事结构全文注入模型，也不得要求每章同时满足所有爽点和审查指标。

章纲挑战者不是第二套正式方案，也不参与自动融合。它只能针对作者指定的章链候选或单章章纲版本，提出少量替代思路及收益、代价和后续影响；作者可以忽略，只有作者主动修改或重新生成后，内容才会进入正式对象。

副编与文姬的职责必须分开：副编/`ContextCompiler`只准备可追溯资料；文姬是使用该资料进行设定判断的模型；正文事实核对由班昭承担。正文的占位符、格式、字数、内部治理口吻和最近章节大段复用等硬检查由确定性代码执行，不属于任何AI成员。质量规则只进入检查与审查，不进入主笔小说正文。
主笔调用只接收自然语言的资料角色、是否必须遵守和内容正文；来源ID、版本、哈希、优先级、检索理由与Token统计保存在后台ContextPack和调用审计，不进入主笔创作提示。状态面板只有在真实任务和真实模型调用发生时才显示工作中；模型未连接时统一显示“创作模型尚未连接”，不展示夹具名称或内部模型ID。

## 5. 真实状态

状态由任务、上下文编译、模型调用、心跳和保存事件驱动：等待、准备中、工作中、完成、失败、超时、已取消、等待作者。界面不得用计时器或文案伪造工作。

## 6. 失败与恢复

- 确定性失败可在幂等键和检查点保护下重试。
- 远程结果未知不自动重试，先调和。
- 正文主笔一次调用失败后只允许同一模型再试1次；供应商结果未知时不盲重试。两次明确技术失败、超时或不可用后，副笔才可按同一冻结资料包接管且最多1次。作者不满意风格不属于技术失败。
- 已完成成员意见复用，未完成成员单独重做。
- 主编租约变化后旧结果必须通过epoch门禁。
- 作者退回时保留满意部分，修订只读取明确反馈和当前候选。

## 7. 追溯

每个结果能追溯到任务、Agent、岗位、模型快照、上下文包、作者输入、上游版本、预算和输出哈希。不保存模型内部思维链。
