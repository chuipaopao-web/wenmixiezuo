# AI团队与介入规则

## 1. 团队组成

每本书保持14名创作成员；岗位、Agent实例和模型绑定相互独立。同一个模型可以承担多个岗位，但界面必须如实显示，不能冒充异模型意见。

1. 主编 貂蝉：决定全局优先级，组织卷纲、事件和融合；负责事件与卷的节奏体检。
2. 副编 西施：资料员、摘要员和主编备份。代表确定性 `ContextCompiler` 的资料准备职责，负责编译、压缩、去重、标注来源和排除项；不做事实判断，也不垄断数据库或检索。只有真实调用副编模型时，团队页才显示副编正在工作。
3. 编剧A 婉儿：偏强冲突、爽点节拍和快速推进。
4. 编剧B 红玉：偏递进、人物关系、铺垫和因果。
5. 编剧C 幼薇：偏脑洞、反套路和题材化新鲜感。
6. 设定 文姬：检查世界、规则、能力、资源和命名体系。
7. 主笔 秋香：当前活动正文写手。
8. 副笔 湘君：候补写手或局部润色，不默认串行重写整章。
9. 事实审查 班昭：设定、正史与因果事实核对，固定承担正文审查事实席。
10. 文学审查 妲己：语言、节奏、场景、重复和人物声音。
11. 体验审查 昭君：目标读者视角的代入、期待、爽点、困惑和弃读风险。
12. 体验·挑剔读者 妙玉：老白读者视角的毒点、吐槽点和弃读风险找茬。
13. 研究 道韫：只为明确事实研究任务提供有来源资料，不决定剧情。
14. 来源与版权 弄玉：执行来源、授权、原创性和风险检查，不设置独立页面。

小文秘书是本地确定性工具角色，不属于14名创作成员，不给剧情结论、不冒充模型、不保存聊天记忆。

## 2. 介入时机

| 阶段 | 主持/执行 | 其他成员 | 输出 |
|---|---|---|---|
| 开书 | 系统确定性校验 | 无 | 书籍、定位版本、团队、预算、设定任务 |
| 设定项 | 主编＋两位编剧独立提案 | 设定按需要检查 | 三份候选、作者选择、主编整理稿 |
| 分卷 | 主编主持 | 两位异模型编剧独立设计，设定/研究按需 | 卷候选、差异、融合稿 |
| 事件链 | 主编 | 两位编剧 | 事件序列、因果衔接、卷任务覆盖 |
| 事件大纲 | 主编融合 | 两位编剧独立方案，设定按需 | 当前事件完整大纲 |
| 章纲 | 指定编剧生成主方案 | 作者可选红玉或幼薇中任一位只挑战关键转折、冲突或钩子；设定/事实按需预检 | 完整事件章链、单章章纲；至多3条不自动采纳的挑战建议 |
| 正文 | 单一活动写手 | 设定/研究只提供证据 | 单章正文候选 |
| 审查 | 三席并行 | 事实席由班昭固定承担，文学、体验两席按异模型规则选座；三席互不读取，写手与三审合计四个不同模型来源；挑剔读者（妙玉）不进固定席，作者在正文页按需点"请挑剔读者找茬"单独跑，结果只供参考不卡定稿 | 各席独立报告 |
| 结算 | 确定性结算＋必要抽取 | 主编查看事件/卷偏差，并在结算完成后出节奏体检报告；副编写大白话摘要 | 事实、状态、伏笔、摘要、下一层承接、节奏体检报告 |

各阶段提示词统一注入"本书题材简报"（频道、分类、融合题材、标签、基调、节奏策略、目标读者），简报只取自作者已确认的开书信息；岗位身份不随题材更换。

## 3. 独立性

两位编剧独立阶段互不可见，不交叉投票；主编只有在独立结果全部保存后才读取并融合。审查席使用与活动写手不同的模型，彼此不读取报告；每章固定三席（事实由班昭固定承担，文学、体验按异模型规则选座），写手与三审合计四个不同模型来源；妙玉作为挑剔读者不进固定席，正文页按需找茬、结果只供参考（DEC-CURRENT-067）。幼薇参与灵感讨论并可在章纲阶段由作者指定挑战候选；三编剧提案管线由后续批次接入。模型不可用或实际来源重复时必须明确降级或阻断，不能伪装独立；没有真实创作模型时，设定、分卷、事件、章纲、正文、审查、灵感和续写分析都不能用本地确定性夹具冒充成员工作。

## 4. 创造性边界

上层规划提供目标、边界、因果和必须项，不规定每句写法。AI可以提出有代价的偏离方案；局部合理发挥可以直接执行，影响卷目标、事件结果、人物核心选择或正史规则的偏离必须先给作者看影响。

模板只是软参考。岗位提示词不得把质量规范、评分表或固定叙事结构全文注入模型，也不得要求每章同时满足所有爽点和审查指标。

章纲挑战者不是第二套正式方案，也不参与自动融合。它只能针对作者指定的章链候选或单章章纲版本，提出少量替代思路及收益、代价和后续影响；作者可以忽略，只有作者主动修改或重新生成后，内容才会进入正式对象。

副编与文姬的职责必须分开：副编/`ContextCompiler`只准备可追溯资料；文姬是使用该资料进行设定判断的模型；正文事实核对由班昭承担。正文的占位符、格式、字数、内部治理口吻和最近章节大段复用等硬检查由确定性代码执行，不属于任何AI成员。质量规则只进入检查与审查，不进入主笔小说正文。
主笔调用只接收自然语言的资料角色、是否必须遵守和内容正文；来源ID、版本、哈希、优先级、检索理由与Token统计保存在后台ContextPack和调用审计，不进入主笔创作提示。状态面板只有在真实任务和真实模型调用发生时才显示工作中；模型未连接时统一显示“创作模型尚未连接”，不展示夹具名称或内部模型ID。

## 5. 真实状态

状态由任务、上下文编译、模型调用、心跳和保存事件驱动：等待、准备中、工作中、完成、失败、超时、已取消、等待作者。界面不得用计时器或文案伪造工作。

## 6. 失败与恢复

- 确定性失败可在幂等键和检查点保护下重试。
- 远程结果未知不自动重试，先调和。
- 正文主笔一次调用失败后只允许同一模型再试1次；供应商结果未知时不盲重试。两次明确技术失败、超时或不可用后，副笔才可按同一冻结资料包接管且最多1次。作者不满意风格不属于技术失败。
- 已完成成员意见复用，未完成成员单独重做。
- 主编租约变化后旧结果必须通过epoch门禁。
- 作者退回时保留满意部分，修订只读取明确反馈和当前候选。

## 7. 追溯

每个结果能追溯到任务、Agent、岗位、模型快照、上下文包、作者输入、上游版本、预算和输出哈希。不保存模型内部思维链。
## 8. 思考与输出预算（2026-08-18 评估定稿，当晚复核翻倍）

**设计结论：注意力保护放在输入侧，输出侧保持宽松上限。**

- 输入侧（资料包）有界：讨论主编 7.2k Token（设定成组 16k）、成员 8k、章管线按上下文包预算编译。资料过多会分散注意力，这一侧不放宽。
- 输出侧（max_tokens 与思考预算）是上限而非目标：模型写够即停（end_turn），宽松上限不会拉长输出、不影响注意力；上限过紧才会截断 → 结构校验失败 → 重试 → 双倍计费并中断任务（2026-08-18 生产多次实测）。
- 思考预算是"必然要花"的额度（模型基本用满预算），可见输出是"用多少算多少"的封顶。

**当前取值**：

| 项目 | 值 | 依据 |
| --- | --- | --- |
| 思考预算（全部套餐模型、全部用途统一） | 16,000 Token | 方舟六个在役模型实测接受 enabled+budget 且预算生效；disabled 反被 glm-5.3/kimi 拒绝；老板复核后从 8,000 翻倍——预算是上限，用多少算多少，只保证复杂任务不被思考额度截断 |
| 讨论可见输出：阶段抽卡/交叉质疑/普通成员地板 | 6,000 | 上限是天花板不是目标；宽松不拉长输出，过紧才会截断重试 |
| 讨论可见输出：编剧独立方案 | 4,000 | 完整方案的实测尺寸 |
| 讨论可见输出：主编通用 / 设定成组融合 / 剧情总纲 / 滚动章纲 | 3,600 / 8,000 / 6,000 / 6,500 | 均为真实截断事故后调出的最小安全值 |
| 章管线：正文 draft/rewrite / 审查 / 主编汇总 / 其他 | 8,000 / 6,000 / 6,000 / 4,000 | 正文合同 2700-3200 有效字符 ≈ 3-4k Token，重写须返全章 |
| 卷纲 / 事件章纲（章链/细化） | 12,000 / 12,000、9,000 | 十事件卷纲与多章章纲的实测尺寸 |
| 结算后续 / 主编设计 / 续写分析 | 4,000、6,000 / 4,000 / 8,192 | 结构化报告的实测尺寸 |

**调用侧不变量**：max_tokens = 可见输出上限 + 16,000 思考预算；八处预算冻结必须追加同一份思考预算（thinkingTokenAllowance），否则结算端以"实际用量超过冻结上限"拒绝。调整任何一侧时两侧必须同时改。

**额度考量**：两个方舟套餐是包月额度。思考预算提到 16k 后，一轮四人讨论最坏多耗约 6 万 Token，占 3,000 万套餐的 0.2%，可忽略；截断重试一次的浪费远大于思考预算本身。预算是上限不是定量，只有模型真实使用才计费。

## 分层设计中的AI介入

- 设定三席只在作者点击召集后工作，输出可整份选择或按片段组合；主编只整理作者选中的内容。
- 分卷两位编剧接收系统冻结的不同内部骨架，各自写成大白话具体路线；主编比较和融合，但专业方法名不得进入作者界面。
- 事件编剧只在活动卷路线与事件链边界内设计当前小故事；阅读感受是不选或单选的软参考。
- 章纲编剧把卷与事件职责拆成连续章链；第一卷前三章和首章前500字职责必须继续向下传递。
- 写手接收当前章完整任务、最近1—3章、线程账本和按需资料，在对白、动作、意象和场景细节上保留自由；三席审查仍互不读取报告。
