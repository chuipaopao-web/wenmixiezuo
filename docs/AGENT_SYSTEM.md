# Agent系统规格

## 1. Agent的定义

真正Agent不是“带名字的模型API”。它必须具备稳定身份、岗位、权限、书籍范围、持久任务、检查点、记忆、模型和工具能力、预算、纠错、询问、失败升级和停止条件。

系统分开管理：

- 模型：提供推理和生成能力；
- 岗位模板：定义职责、规则、可用工具和质量标准；
- Agent实例：承担一本书中的具体身份、记忆、权限和任务责任；
- 模型配置快照：记录实例当时使用的供应商、模型、参数和能力。

## 3. 激活策略

- 日常交流：活动主编单独响应，必要时点名1名核心岗位。
- 剧情讨论：主编、编剧、设定师；需要情绪评估时增加体验官。
- 章纲：编剧、设定师、体验官，主编汇总。
- 正文：主笔执行；审校与设定师复核；出现语言问题时增加文编。
- 历史或当前资料：研究员参与，研究结果仍需主编判断。
- 拆书或借鉴：版权顾问必须参与，未通过版权门禁不能进入写作。
- 正式会审：按问题选择3至7个岗位，只有明确理由才扩大。

按需专家不参与与自己无关的闲聊、普通确认和每章固定流程。

### 3.1 创造性分工

- 主编保护目标、边界、少数高潜意见和结构不同的备选，不把所有观点压成安全折中。
- 编剧在重大推演中至少保留一条主推荐和一条结构不同的替代路径，并为近期场景说明叙事功能、目标读者效果、冲突、信息和情绪变化；设定师只阻断硬矛盾，不替编剧决定剧情。
- 主笔在写作工单的自由创作区拥有表达权，根据场景目标动态选择核心与辅助技法，可以提出库外做法、更好的场景实现和有理由的软偏离；不得把全书表达基线误当固定技法模板。
- 审校、体验官和文编在完整草稿后工作；软问题必须有正文证据，不规定唯一改法，不统一角色和作者声音。
- 研究员提供事实边界与可能性，不堆资料；版权顾问阻断实质性相似，同时允许类型惯例和独立表达。
- 本次被激活岗位先独立工作再综合；共享同一模型或同一资料造成的相关性必须记录，意见数量不等于证据强度，按需专家不得为了凑齐九岗位而空转。

## 4. Agent实例最低字段

每个实例至少包含：

- `agent_id`、`owner_id`、`book_id`；
- `role_template_id`、姓名、头像和岗位显示名；
- `model_provider`、`model_id`、配置快照版本和能力快照；
- 启用状态、权限、工具、联网范围和知识范围；
- 当前任务、阶段、检查点、心跳和健康状态；
- Token、费用、时间、步骤和重试上限；
- 岗位记忆指针与最近有效上下文包；
- 需要主编或老板确认的操作清单。

新书的9个实例和配置快照必须原子创建。

## 5. 统一运行循环

```text
接收任务或事件
→ 路由开放讨论/创意推演/暂存试写/正式生产
→ 读取权威事实和任务书
→ 验证能力、范围、依赖、权限和预算
→ 形成有限步骤
→ 形成岗位专用检索意图并检索记忆和知识
→ 构建岗位专用最小上下文包，分离约束胶囊与灵感调色板
→ 执行一次模型或工具动作
→ 确定性校验
→ 必要的模型质量复核
→ 有限纠错或重新规划
→ 保存结果、依据、事件和检查点
→ 继续、询问、等待、升级或结束
```

每一步是持久状态转换，不允许实现成只存在内存中的无限循环。暂停、继续、取消和回到版本等明确命令由控制层直接处理。

开放讨论、创意推演和暂存试写不因缺少正式章纲而失败，只能写对话、候选或临时区；正式生产才执行完整准备、审校和结算。任何模式仍遵守版权、安全、费用、隔离和不可逆操作边界。

## 6. 状态机与真实性

对外状态采用有限集合：

- 待命；
- 读取资料；
- 思考方案；
- 调用工具；
- 写作；
- 审校；
- 等待确认；
- 暂停；
- 受阻；
- 离线。

状态必须来自真实任务阶段、心跳、模型调用和工具事件。任务结束或心跳过期后必须收口，前端不得猜测“工作中”，也不得展示模型内部思维链。

## 7. 任务书

Agent执行前必须获得：

- 目标和不做什么；
- `owner_id`、`book_id`、章节和版本；
- 权威资料和允许引用的知识；
- 允许的模型和工具；
- 验收标准；
- 默认处理规则；
- 预算与停止条件；
- 确认门禁；
- 幂等键和预期产物。
- 创作模式，以及“必须实现、不得违反、可自由决定、需要候选确认”四栏；非创作任务可标记不适用。
- 正式正文任务还必须携带当前表达基线版本、场景叙事功能、目标读者效果和技法选择理由；技法只作为软建议，不能占满自由创作区。

Agent可以在范围内拆步骤，但不能静默改变老板目标、扩大范围或绕过依赖。

## 8. 能力验证

每次执行前检查：

- 模型是否真正支持所需模态、上下文、文件或工具；
- 岗位是否匹配任务；
- 工具和联网是否可用；
- 权限和书籍范围是否合法；
- 必要记忆和检查点是否完整；
- 预算是否足够；
- 执行者和复核者是否满足真实模型独立性。

静态配置与运行时能力不一致时，以运行时结果为准，并进入暂停、降级、转派或升级。

## 9. 主动询问

以下情况必须暂停并给出决策单：

- 缺少不可安全推断的必要信息；
- 选择会明显改变主线、人物命运或成果方向；
- 新要求与正史、老板决定或任务书冲突；
- 涉及重大正史、高费用、版权或不可逆操作；
- 无法确定书籍、章节、版本或对象；
- 继续可能重复生成或重复计费。

同一决策点只问一次。同一Agent在同一任务连续主动询问最多3次，之后升级给活动主编。低风险默认值必须在任务书中预先允许，并进入自动假设清单。

## 10. 反思与纠错

优先进行零Token确定性检查：正史冲突、人物生死、时间线、道具属性、版本、格式、必填字段、重复度和验收条件。文风、情绪、节奏和人物表现才使用模型评审。

正式写作只在生成前运行会使结果无效的硬检查。文风、情绪、节奏、人物表现和语言问题在完整草稿后审校，禁止将软评审插入逐句生成。软建议两次仍降低整体质量时，应撤销建议、保留原稿或返回上游，而不是继续统一润色。

纠错受次数和预算限制。质量问题进入定点重写或上游调整，不能当成技术故障重复调用。重大成果不能只由原执行Agent自审通过。

### 10.1 反迎合与独立判断

- 岗位先依据正史、任务目标和可核验证据形成独立判断，再考虑老板偏好和表达方式。
- 老板偏好区分硬边界、稳定风格倾向、当前任务选择、临时情绪和可质疑观点；不得把全部历史选择累积成必须迎合的规则。
- 主编汇总必须保留有依据的异议和最强反对理由，不以建议采纳率、同意率或语气积极作为正确性指标。
- 老板保留创作方向最终裁决权；事实、版本、安全、费用和正史门禁不能因老板使用肯定语气而跳过。
- 同模型多岗位或相同上下文造成的意见相关性必须如实记录，不得以人数包装独立共识。

### 10.2 经验进化与防固化

- 经验先作为候选，记录来源失败、适用题材/岗位/阶段、反例、禁止外推、证据、版本、到期和撤销条件。
- 只有跨样本验证并经相应确认后才进入岗位默认建议；启用后持续与基线比较，退化即降级或撤销。
- 原始聊天、一次成功改写、老板一次采纳、模型自评分和没有反例的技巧不能成为永久规则。
- 经验不能跨书默认共享，也不能把九岗位统一成同一种安全写法。建议采纳率和老板满意语气不作为经验正确性奖励。

## 11. 双主编

- 每本书同时只有一个活动主编。
- 活动主编租约绑定 `active_editor_agent_id` 和 `editor_epoch`。
- 接管优先级：老板指定、正式交接、满足故障条件后的候任接管。
- 接管包包含任务、章节、正史版本、待决事项、预算、模型调用状态和下一步。
- 接管后旧 `editor_epoch` 指令全部拒绝。
- 接管不能造成重复生成、重复计费或重复确认。

## 12. 工具边界

所有工具调用绑定 `task_id` 和 `book_id`，具有权限、预算、参数哈希、幂等键、超时和真实取消能力。结果先写暂存区，校验后由应用服务登记。Agent不能直接修改正式正文、正史或其他书籍数据。
