# 章纲 V2 与主笔最小资料包设计审计

## 明确结论与置信度

结论：章纲升级为 `chapter_outline_v2`。它必须把本章的因果闭环、人物当下目标、知识边界、冲突代价、三至五个推进节点、结尾状态和与下一章的接口说清楚；情绪、爽虐、描写重点、信息控制与伏笔动作只作为按需软提示。正式主笔只接收编译后的中文最小资料包，不接收原始 JSON、重复人物传记或整套世界设定。

本设计对结构正确性与工程可验证性的置信度为高，对真实模型提高正文质量的置信度为中。当前实现最多形成 E1/E2 工程证据；没有真实纵向盲评前，不宣称达到 E3/E4 文学质量改善。

## 最强替代方案与取舍

1. 保持 V1，只依赖主笔检索补齐。优点是改动小，缺点是主笔无法区分“必须实现”和“可自由发挥”，继续存在补造因果的风险，拒绝。
2. 建立超详细逐场景分镜。优点是确定性强，缺点是把小说压成机械执行，信息量也会超出最小上下文，拒绝。
3. 采用 V2 分层章纲。它比 V1 增加本章必要因果，比逐场景分镜保留更大的行动、对白、场面和意象自由，采纳。

## 预先验尸与反例

- 若模型为了填满模板，给普通过渡章虚构爽点、虐点或伏笔，则软字段必须允许为空，解析器不得要求填满。
- 若人物列表复制全书传记，工单会重复并挤压当前任务；因此只允许“当前目标、知识边界、本章作用、状态变化”。
- 若硬信息本身超过预算，不能静默截断；必须拒绝进入正式主笔并让主编收缩章纲。
- 若旧 V1 被自动补全为 V2，来源会被伪造；因此旧版本只读，不做数据迁移。
- 若现有书籍由确定性假数据“升级”，会冒充真实成员工作；运行升级必须有真实模型调用与版本来源，缺凭证时只报告阻塞。

## 修正后的最终设计

- Schema：`chapter_outline_v2`。
- 硬层：引用的剧情总纲阶段、本章功能、开场状态、必须结束状态、出场人物当下信息、核心冲突及失败代价、三至五个推进节点、章末结果与下一章接口、必须实现、不得违反、自由创作区。
- 软层：主情绪和三至五段情绪变化、零至两个爽点、零至两个压力/虐点、期望读者感受、主次描写、信息揭示/隐藏/信息差、零至两个伏笔动作。
- 存储保留完整结构；主笔输入由确定性编译器转换为中文，章纲目标一千至一千二百字，硬上限一千三百五十字；连同写作契约不超过一千五百字。
- 全主笔资料包继续遵守四千二百字上限，其余空间留给相关阶段、人物当前状态、必须遵守、前章结尾和少量定向检索。
- 章纲只细化未来一至三章。每章独立版本化并引用活动 `stage_master_v2` 的对应阶段。

## 创造性与输出质量保护

- 明确保留“自由创作区”，行动细节、对白、场面调度、意象和微转折默认由主笔决定。
- 情绪、爽虐、描写重点和信息控制是软提示，不是每章必须填满的硬清单。
- 创造性非劣效基线是当前 V1 章纲流程；至少比较原创性、合理惊喜、人物可辨识度、情绪力度、检索锚定和整体阅读质量。
- E3/E4 前使用构造样本和同任务配对检查，不把单人自评写成盲评。真实盲评必须隐藏版本、跨不同题材并保留自由度退化的停止条件。

- E2：完整讨论落库、主笔预检、跨书隔离、界面无技术字段、迁移与恢复构造验证。

## 剩余风险与未知项

- 模型可能在单次输出中超过 JSON 长度或漏字段，需要一次定向结构修复，但不得代填内容。
- 一千三百五十字对群像章可能偏紧；若真实样本反复因硬信息超限阻断，应按数据调整预算，而不是截断。
- 现有书的历史章纲升级会产生新的规划版本，但不能改写生成正文时冻结的旧版本引用。
- 当前单人开发只能证明工程证据，不能证明跨模型文学质量。

## 停止、回滚和升级条件

- 需要新密钥、实际付费、生产数据恢复、永久删除、重大岗位/模型合同变化或必须修改 `D:\AI智囊团` 时停止并升级老板。
- 任一历史章纲或正文版本被覆盖、跨书来源错配、硬信息被静默截断、软字段成为正式写作门禁、技术字段重新暴露到前端时立即停止。
- 回滚只撤销新生成提示、V2解析/编译和专用界面；V1继续可读。已创建的V2版本不物理删除，活动指针通过新的正常版本选择恢复。
