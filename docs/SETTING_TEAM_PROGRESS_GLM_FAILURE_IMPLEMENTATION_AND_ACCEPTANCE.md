# 设定团队进度与 GLM 空输出修复清单

> 建立时间：2026-08-22  
> 当前状态：开发、自动验收与生产发布完成

## 1. 用户目标

- AI 成员开始设计后，页面始终显示醒目的团队总体进度，不因单席失败而消失。
- 每位成员显示真实的工作中、已完成或已失败状态；失败席可单独重试，成功结果不重跑。
- 红玉使用 GLM-5.3 设计短设定方案时，不再把整份输出额度耗在内部思考而没有可见方案。
- 普通作者只看到可理解的失败说明与恢复动作，不展示模型协议、Token、思考字符或内部错误码。

## 2. 页面与交互验收

- 通过：没有成员运行记录时不显示虚假进度。
- 通过：`pending`、`queued`、`working` 状态显示“团队正在设计”和真实进度。
- 通过：部分完成、单席失败或总任务结束时进度条仍保留，并显示已完成数、已失败数。
- 通过：全部成员完成后显示 100% 和“团队方案已完成”，方案继续保持折叠查看。
- 通过：失败席显示“已失败”和“只重试这位”；重试后其他成功方案不清空。
- 未验证：360、390、430px 登录态真实浏览器视觉走查；新版已部署，自动测试与现有 640px 断点已通过，但不冒充真机证据。

## 3. AI 调用与失败恢复验收

- 通过：生产最近三次 GLM-5.3 失败均为 `max_tokens`，每次 11,000 输出 Token、约四分钟、只有 thinking 与空 text；前一次成功也耗时 256 秒。
- 通过：不含作者资料的生产端点探针证明 `thinking: disabled` 返回 400；省略 thinking 字段后 17 秒正常结束，799 输出 Token、133 字可见方案。
- 通过：仅 `GLM-5.3 + discussion + 可见输出不超过3000` 省略 thinking 字段，并把推理余量从 8000 降为 1000；复杂讨论、规划、审校和正文仍保留 16000。
- 通过：空正文仍作为单席可恢复失败，不写入候选或正史。
- 通过：重试只补失败席，复用同书、同设定项和最新临时资料包，成功席不重复运行。
- 通过：作者视图只返回“这位成员本次没有形成可用方案，请只重试这位”；完整供应商诊断仍保留在后台审计表。

## 4. 数据、接口与安全

- 通过：没有新增或改写数据库迁移，没有覆盖作者输入、已确认设定或成功方案。
- 通过：总体进度只由后端成员 `completed / failed / unavailable` 状态计算，没有前端计时伪造。
- 通过：现有 `owner_id`、`book_id`、活动设定项、模型快照和幂等边界未改变。
- 通过：API Key 未进入代码、日志、测试夹具、文档或前端错误。

## 5. 清理与文档

- 通过：删除短 GLM 强制 8000 思考预算的旧常量、注释和测试断言。
