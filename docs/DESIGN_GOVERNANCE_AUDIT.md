# 当前设计治理与审计规范

## 1. 适用范围

架构、数据、上下文、检索、Agent、生成、审查、结算或长篇质量的重要变更使用本规范。纯文案、低风险样式和明确机械修复不启动完整审查。

## 2. 权威顺序

作者最新决定 → 项目章程与开发规则 → 当前生效决定 → 当前规格 → 代码和证据。Git只提供追溯，不能覆盖当前规格。

## 3. 设计记录

每项重大设计创建唯一 `design_review_id`，记录：

- 问题、可观察症状和真实根因；
- 已确认事实、推断、作者偏好和未知；
- 适用Skill名称与文件哈希；
- 至少一个最强替代方案及取舍；
- 机制、反例、指标、证据等级和停止条件；
- 影响文件、迁移、回滚和复核人。

设计记录写在当次提交信息与 `docs/DECISIONS.md` 对应决定中；本文档不再累积历史审计记录，历史 DR 一律通过 Git 历史追溯。

## 4. 两轮审查

第一轮检查正确性、安全、恢复、跨书隔离、版本和来源。第二轮检查创造性、人物生命力、合理惊喜、情绪力度、整体阅读质量和作者控制权。第一轮提升不能抵消第二轮下降。

## 5. 上下文和RAG变更

必须验证任务矩阵、其他书排除、活动版本、作者原话、硬约束位置、来源回查、预算、降级和投影可重建。不能用“增加向量、多Agent或更大上下文”代替根因证据。

## 6. 创作机制变更

相对现行流程或弱治理基线做非劣效对照。局部修改使用多样本对照；全链路修改使用跨题材、跨阶段和纵向盲评。评分表不得直接成为正文提示词。

## 7. 证据等级

E0规格，E1机制存在，E2确定性工程，E3独立金标/真实模型盲评，E4真实长篇纵向效果。不得用短流程或固定同义词测试声明E3/E4。

## 8. 精简审计

精简前检查启动入口、动态引用、路由、Worker任务、迁移、恢复、测试和作者数据。只有当前产品不需要且运行时零引用的代码或资料才能移出工作树。已合并迁移、作者原件和不可变正文不参与普通精简。

## 9. 规则折旧

每次事故新增的规则必须写明触发来源（什么书、什么误判、哪一天），补丁措辞保持通用，不得把单本书的实体、事件或数值写进通用提示词与通用规范；复查时通用化或删除仍能覆盖根因的过时条款，防止规则只增不减反向稀释注意力。

## 10. 当前审计基线

当前工作流为开书—设定—卷—事件链—事件大纲—章纲—正文—三级结算；统一创作台和独立灵感只围绕这些对象运行。开发结算必须通过运行时可达性、类型、全量测试、四端构建、真实本地服务和文档同步，并以双事件20章确定性纵向流程作为E2基线。真实套餐模型长篇文学质量仍需独立E3证据，不能由自动测试冒充。

## 11. DR-20260820-LAYERED-NARRATIVE-RHYTHM-V1

- 已知事实：长篇工作流已有开书、设定、卷、事件、章纲、正文和结算对象，但旧交互让作者先理解模板，且可选设定过多时会争夺模型注意力。
- 产品偏好：手机端优先、少填少选、逐层推进；作者看具体路线，不看专业术语。
- 采用方案：四项核心设定；后台22种方法白盒审计、前台白话路线；第一卷开篇职责；事件软参考单选；ContextPack来源分级与硬资料无损。
- 被否决方案：把全部设定全文塞入每次调用；让作者多选整套宏观结构；把前500字、黄金三章和爽点密度做成每章固定频率。
- 两轮审查：规格轮检查层级、真值与兼容；实现轮检查作者投影、资料包、移动端和旧版本读取。
- 停止条件：硬资料需要静默截断、两条路线无实质差异、普通页面泄露专业方法或内部ID、移动端横向溢出时不得验收。

## 12. DR-20260820-layered-design-contract-v1

- 已知事实：系统已有开书、设定、卷、事件、章纲、正文和结算对象，但卷计划仍混有事件序列，设定正文仍可能整包注入下游，作者原话尚未统一分级绑定。
- 推断：按“换卷后是否仍成立”划分设定与卷责任，并让事件、章节只接收上层责任，可以减少上下文噪声和职责越界；该效果仍需真实长篇证据。
- 产品偏好：小白作者逐层完成，不一次填写整书；越远越开放、越近越具体；硬事实、当前任务、软参考和留白明确区分。
- 未知：不同题材的最优事件数量和细纲滚动窗口；长期20/50/100/200章中线程账本的实际维护成本。
- 采用方案：独立 `BookStorySpineVersion`、`VolumeDirectionVersion`、`EventChainVersion`、`StoryThreadRecord` 和八类稳定资料包；规划向下传、结算事实向上回。
- 最强替代方案：保留单一卷计划JSON并在调用时临时裁剪。否决原因是职责继续混合、版本失效难追踪且容易把计划冒充实际。
- 第一轮规格审查：核对对象边界、约束强度、真实性、作者原话、依赖失效、按需补设定、兼容读取和逐层确认粒度；结论为进入实施。
- 第二轮实现审查（E2）：已完成数据、领域、API、前端、ContextCompiler、迁移与恢复复核；卷方向/事件链、故事总线、线程计划/实际、八类资料包、按需补设定和管理员隔离链路均有确定性证据。创造性非劣效仍须E3/E4，不能把本结论扩张为文学质量完成。
- 所需证据：A02～A13、E01～E14、F01～F12及I13～I17；真实正文结算必须能驱动线程状态。
- 停止条件：分层使作者操作显著增加、软约束变硬、计划污染实际、必要硬资料被截断、人物生命力或衔接质量下降。
- 回滚：只停用新写入和新编译策略；保留作者原话、候选、各层版本、正文、结算和调用证据；旧卷计划继续兼容读取。

## 13. DR-20260820-first-volume-launch-v1

- 已知事实：老板明确要求首卷前500字产生兴趣、黄金三章建立追读、10万有效正文字符前完成一次大高潮；现有字段尚未贯穿事件、章纲、审查和实际结算。
- 推断：把效果责任放进首卷合同，再由事件和章承载，比把打脸、战斗或反转写成固定公式更能跨题材工作；仍需五类题材盲读验证。
- 产品偏好：首卷按爆款强启动设计，同时保护言情、悬疑、日常等题材的不同抓力方式和AI自由发挥。
- 未知：不同平台和题材的最佳回报间隔；“兴趣”不能由确定性算法充分判断。
- 采用方案：`FirstVolumeLaunchPlan`、黄金三章整体启动包、第一章专属合同、前500有效字符切分、三审证据、10万字运行预测和高潮实际结算。
- 最强替代方案：固定每章必须冲突、反转、打脸和钩子。否决原因是高度模板化、情绪疲劳且不适合全部题材。
- 第一轮规格审查：核对硬效果与可选手段、事件覆盖、章纲继承、有效字符口径、防疲劳和不可逆高潮；结论为进入实施。
- 第二轮实现审查（E2）：事件七类职责、黄金三章整体包、第一章专属合同、体验席前500证据源、滚动章纲读取真实结算、85k预警/101k逾期和高潮实际结算均已通过工程复核。真实模型前500字、三章连读和高潮文学效果仍为E3/E4未完成。
- 所需证据：D01～D20、I09～I12及J08～J09；必须实际阅读前500字、黄金三章和高潮后果。
- 停止条件：所有题材生成同类开局、连续重复同一冲突、高潮只有计划没有正文证据、强启动压倒人物合理性。
- 回滚：停用首卷新合同写入和预警策略，不改写已确认路线、正文或结算；保留失败样本用于重新设计。

## 14. DR-20260820-internal-structure-routes-v1

- 已知事实：作者不希望学习或选择专业理论；内部已有部分模板能力，但缺少方法版本审计、五类分工、候选差异门禁和作者选后融合闭环。
- 推断：每条路线只给一名编剧一套精简方法软参考，能减少多模板混杂；真实多样性必须用异模型和盲审验证。
- 产品偏好：作者只看“这卷具体怎么走”的两套白话方案，可整选、片选、融合、编辑、手写或重做。
- 未知：不同题材和后续卷的最佳方法选择；方法增加后是否会反而降低人物生命力。
- 采用方案：五类版本化方法库、单主骨架组合规则、两名独立编剧、语义差异门禁、作者选择后主编融合、普通接口术语隔离。
- 最强替代方案：把三幕式、五幕式、猫咪节拍等作为前端多选模板。否决原因是增加小白负担并诱发节拍表平铺。
- 第一轮规格审查：核对方法目录、适用边界、冲突节点、双路线差异维度、后续卷重诊断和术语隔离；结论为进入实施。
- 第二轮实现审查（E2）：22种方法五类持久化、版本指纹、候选调用关联、普通分层规划API裁剪、作者整选/片选/选后融合及九维差异门禁已通过；过度相似时只废止并重做B。跨题材真实模型盲审与人物生命力非劣效仍为E3未完成。
- 所需证据：C01～C14、H04～H08及I07～I08、I18；候选必须在选择、因果、关系、代价、高潮和卷末状态上有实质差异。
- 停止条件：候选只换措辞、泄漏方法名、同一方案平铺多套节拍、作者操作增加或真实盲审显示多样性下降。
- 回滚：切回上一活动方法注册表和候选装配器，旧方法快照保持可审计，作者已选内容和卷方向版本不删除。
## 15. DR-20260820-LAYERED-AUTHOR-SAFETY-CLOSEOUT-V1

- 已知事实：旧Web仍有页面直接回退`Error.message`，普通任务详情可返回阶段、模型调用和原始失败字段，固定`100dvh`不能可靠反映手机输入法弹起后的可视高度；总表的停止条件也缺少可执行只读回滚门禁。
- 推断：网络洁净投影、统一组件错误门禁、`visualViewport`桥接与只关闭新分层写入的只读开关，可以分别降低内部信息泄漏、手机主操作被遮挡和回滚误伤作者数据的风险；真实手机生产体验仍需实机确认。
- 产品偏好：普通作者只看业务对象、自然语言进度和恢复动作；管理员保留完整审计；旧缓存前端可继续使用；回滚不覆盖任何作者输入、定稿、结算、版本或调用证据。
- 未知：不同手机浏览器、第三方输入法和浏览器工具栏组合下的像素级滚动体验，仍需生产真机走查，自动DOM测试只能提供E2证据。
- 采用方案：`clean-v1`普通作者JSON/SSE投影、独立管理员任务审计路由、全页面错误门禁静态扫描、`visualViewport.height`动态CSS变量与焦点滚入、十类停止条件识别器及分层写入只读模式。
- 最强替代方案：仅在各React页面隐藏字段并继续让API返回原始任务和错误。否决原因是新页面、SSE、缓存和遗漏组件仍可泄漏，且无法建立统一兼容与恢复合同。
- 第一轮规格审查：确认作者/管理员边界、旧缓存兼容、错误恢复动作、手机降级、停止条件范围与不可变证据保留；结论为进入实现。
- 第二轮实现审查（E2）：普通响应和失败响应投影、管理员物理路由、全部TSX静态泄漏扫描、动态视口单元测试、只读集成快照以及管理员19步HTTP全链均形成确定性证据。E3真实模型与生产手机实机不由本结论替代。
- 停止条件：任何普通网络响应出现模型/方法/路径/堆栈/原始错误，旧缓存不可恢复，键盘弹起后输入或主操作不可达，或只读回滚改变作者与审计证据时不得发布。
- 回滚：新Web可停止发送`clean-v1`而继续读旧兼容响应；API投影与动态视口桥均可独立停用；分层写入切到只读只阻断新设计写入，不删除数据、不修改迁移，恢复后重新执行隔离和全链验证。
