# 设计治理与审计

## 何时使用

只有以下高风险变化建立 `design_review_id`：账号/权限隔离、作者数据不可变性、数据库语义与迁移、跨服务恢复、模型计费与现金、ContextCompiler权威来源、不可逆架构或会大范围改变创作质量的机制。

纯文案、普通UI、组件重排、低风险样式、明确机械修复、局部兼容字段和可逆实验不启动完整设计审计。

## 最小记录

高风险设计在 `docs/DECISIONS.md` 或专项文档记录：

- 问题与可观察证据；
- 已知事实、推断、用户偏好和未知；
- 采用方案与一个有价值的替代方案；
- 数据/权限/兼容/回滚影响；
- 对应测试和停止条件。

不要求复制Skill全文、重复所有规格或生成固定长度报告。

## 审查深度

- 安全、数据、权限、恢复：检查隔离、版本、来源、幂等和回滚。
- 上下文/检索：检查活动版本、正式来源、其他书排除、预算和可重建投影。
- 创作机制：再检查作者控制权、人物生命力、合理惊喜、情绪力度与题材差异，不能只提升一致性。
- 普通产品/UI变化：一次实现审查即可，重点看任务是否更易完成、状态是否更清楚、手机是否可达。

两轮独立审查只用于不可逆或影响广泛的高风险设计，不是所有开发的默认流程。

## 证据口径

E0规格、E1机制、E2确定性工程、E3真实模型/独立阅读、E4真实长篇。只按实际证据等级陈述，不用自动测试承诺市场效果。

## 精简与折旧

规则只保留能防止当前真实风险的通用条款。事故细节、单书实体、旧测试数量、旧模型名单和一次性发布过程只留在 Git 历史，不继续污染默认提示。新增规则要能说明它防止什么；若现有基础安全或测试已经覆盖，就不再添加第二条门禁。

删除源码或正式数据前仍需确认入口、动态引用、任务、迁移、恢复和作者数据边界；文档与Skill精简优先归档，确认无当前引用后再移出默认目录。
