- 不做什么：不调用未授权真实模型；不让Worker直接修改正式正文或正史；不把半章、失败稿或审校意见当正式正文。
- 唯一写负责人：当前Codex。
- 允许文件：Schema 6迁移、创作应用服务、确定性创作适配器、Worker受限执行器、REST路由、创作测试和发布文档。

- 实现约束：主笔与审校模型真实不同；每次模型调用先冻结预算并绑定不可变上下文包；每次重写生成完整新版本；后章依赖前章任务和正史结算。
- 验收标准：单章全部阶段通过；5章每章2500至3500字；第2章后中断从第3章继续；章内检查点不重生初稿；独立Worker通过API应用服务执行；结构化审校完整；重写不超过2次。
- 测试命令：`npm run verify`、两次迁移、创作/Worker/升级测试、生产启动探测。
- 失败停止条件：同模型伪装独立复核、半章提升、正文静默覆盖、后章越过前章、预算未冻结、调用无上下文或已完成章重复生成。
- 回滚方法：代码向前修复；Schema只新增；正文保留完整历史版本；流水线从持久检查点继续或明确失败。
- 独立复核人：当前Codex以5章中断、章内暂停、独立Worker、不可变版本链和模型/预算调用账本复核。

## 实现摘要

- 新增主笔选择、章节批次、章节流水线、硬检查、审校轮次/问题和质量趋势数据。
- 标准模式保存两个匿名样章的同资料哈希、700字样章、样章哈希、同等一次修改机会和盲测评分；快速/老板指定模式保留同一审计结构。
- 缺少真实凭证时使用三个明确标注的0现金确定性配置：主笔A、候选B、审校；界面和调用账本不会冒充Codex、GLM或其他真实供应商。
- 主笔与审校Agent分别绑定不同的不可变模型配置快照；独立复核前再次核验provider/model组合。
- 单章状态机依次执行预检、章纲/契约、上下文、完整初稿、硬检查、异模型审校、定点重写、事实提取、正史结算和质量记录。
- 初稿故意包含一个可定位的重复转折词，审校生成位置、类型、严重度、证据和修改要求；一次定点重写生成父子相连的完整新版本，复审通过。
- 所有四次确定性模型调用均先冻结预算、结束后结算实际Token/0现金费用，并绑定各自不可变上下文包。
- 批次只允许1章或连续3至5章；任务依赖和预检同时阻止前章未结算时启动后章。
- 批次在第2章后保存 `next_index=2`；继续时只生成第3至5章，已完成正文哈希保持不变。
- 章内可在审校后安全暂停；继续时从定点重写阶段恢复，不重复生成初稿，任务尝试次数和检查点真实记录。
- 独立Worker只负责领取、心跳并调用本机内部API；正式正文、事实与正史仍由API应用服务门禁处理。
- 章节正文提供带范围上限的读取接口，默认返回当前正史版本并携带哈希和总长度。
