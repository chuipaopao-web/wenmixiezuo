# 阶段5：记忆与正史核心验收记录

- `release_id`：`wm-v1-20260716-220959-d5dd704d`
- 目标：完成事实分级、正史原子结算、八层记忆、FTS检索、不可变上下文包和可重建投影。
- 不做什么：不引入独立向量库或图数据库；不让候选事实绕过门禁；不静默截断硬来源。
- 唯一写负责人：当前Codex。
- 允许文件：Schema 5迁移、章节/知识/记忆服务、REST路由、知识与记忆测试、发布文档。
- 禁止文件：来源快照、真实API Key、项目外目录、外部向量库和项目外服务。
- 依赖：阶段4提交 `d38db84`、Schema 4、不可变正文提升和持久任务底座。
- 实现约束：全部查询携带书籍隔离键；D级确认绑定正史版本；正文文件先提升再短事务结算；派生状态可重建。
- 验收标准：A/B/C/D门禁、D级阻断、正文/事实/章末状态/正史全成全退、百万字符硬锚点100%、Recall@10不低于95%、FTS重建、旧上下文失效、跨书零串线。
- 测试命令：`npm run verify`、两次迁移、知识/记忆/故障注入/升级测试、生产启动探测。
- 失败停止条件：半结算、过期确认生效、跨书检索、硬来源截断、旧正史继续驱动或投影不可重建。
- 回滚方法：代码向前修复；Schema只新增；正史通过新修订更正，不修改历史绑定与正文版本。
- 独立复核人：当前Codex以故障注入、跨书检索、FTS删除重建和确定性投影重建复核。

## 实现摘要

- 新增卷章、完整正文版本、实体、事实断言、正史修订/绑定/变更、确认、冲突、八层记忆、FTS、检索记录、上下文包、章末状态及三类投影。
- A级保留候选；B级有证据且无冲突时自动批准；冲突B级与C级进入主编复核；D级进入老板确认并绑定预期 `canon_revision`。
- 章节结算要求正文已选定且B/C/D事实全部解决；正文转正史、事实激活/替代、正史修订、章末状态、失效传播和投影重建处于同一短事务。
- 两个结算故障点均验证整体回滚，不留下正文已定稿但事实只写一半的状态。
- 正史改变会失效旧上下文及依赖旧正史的派生记忆，并从FTS删除旧派生内容；系统规则和故事圣经不会被机械失效。
- 上下文包保存完整来源内容、版本、采用原因、原始长度、压缩方式、顺序、Token占用、排除理由和内容哈希。
- 硬规则、当前正文、前章状态和老板决定合计超预算时明确暂停；可选低优先级资料才会按预算排除。
- FTS始终先按 `owner_id/book_id` 过滤；删除索引后能从活动记忆按书重建。
- 人物状态、时间线和关系投影只由当前正史绑定重建，人工删除投影后可确定性恢复。
- REST补齐卷章、实体、事实、复核、确认、结算、记忆、检索、上下文包和正史查询主路径。
