## 原始故障与根因

实机已归档书在输入旧完整确认词后仍返回“内部错误”。隔离测试使用真实开书流程复现后，SQLite在旧实现的 `DELETE FROM books` 处返回 `FOREIGN KEY constraint failed`。根因是旧服务只删除四张表，真实书籍的配置、团队、预算、对话等关联记录仍引用 `books`。旧测试只创建几乎空的草稿书，因此未暴露该错误。

## 修复内容

- 归档书的确认词统一为 `YES`；前后端都忽略首尾空白且不区分大小写，非YES仍拒绝。
- 删除弹窗去掉书名、短ID和“填入完整确认词”按钮；用户输入YES后仍必须再点一次“彻底删除”。
- 新增 `BookPurgeRepository`，在一个 `BEGIN IMMEDIATE` 事务内写删除墓碑，清理导入隔离记录、可移植操作从表、开书草稿与全部 `owner_id + book_id` 作用域表，最后删除书籍。
- 事务启用延迟外键检查；任何未处理引用会让提交失败并整体回滚。文件只在数据库提交成功后删除。
- 活动书仍返回409，普通删除仍为可恢复归档，删除墓碑仍阻止旧书ID复活。

## 红绿与恢复测试

1. 真实开书失败测试在旧实现上稳定复现 `FOREIGN KEY constraint failed`。
2. UI新合同在旧界面上因仍存在完整口令按钮而失败。
3. 修复后删除专项、备份恢复、REST和UI四组测试通过。
4. 测试枚举当前Schema全部同时含 `owner_id` 和 `book_id` 的表，删除后同书记录均为0，另一本书的配置保留，可移植从表与隔离记录为0，`PRAGMA foreign_key_check` 为空。
5. 故障注入额外创建一张未被清理的引用表；永久删除被SQLite拒绝后，书籍、配置全部保留且墓碑0条，证明整单回滚。
