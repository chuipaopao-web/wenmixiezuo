# 当前开发路线

## P0 UI/UX整体重设计

状态：重新打开，当前最高优先级。

- 应用壳和手机导航：重新组织书籍、创作阶段、资料与辅助功能，不沿用两排入口或固定卡片布局。
- 开书：只收基础方向，表单分组、推荐和AI介入更简洁。
- 设定：四项核心清楚，扩展项按需；AI方案、片选、融合、质检和前置阻断在同页可理解、可恢复。
- 分卷：双路线比较围绕具体故事差异，首卷强启动自然融入，不显示内部结构术语。
- 事件/章纲：从卷方向到事件链、事件大纲、完整章链和近期细纲逐层可见，上一实际结果清楚。
- 正文：全屏写作优先，本章任务、相关事实、审查和结算按需打开。
- 资料/辅助：资料库、团队、任务、灵感、取名和设置不与主创作阶段争抢首层导航。

每页先确定状态和交互原型，再统一视觉。手机检查360/390/430px，桌面检查比较、长内容与键盘操作。

## P0 核心流程稳定

- 设定整理、整份质检和第一卷规划的失败恢复保持可达。
- 活动版本、上游前置和作者确认不因UI重构失真。
- 普通作者响应保持白话洁净；管理员审计保留完整证据。
- 老旧数据、旧URL和已确认内容继续可读，不批量覆盖作者数据。

## P1 分层创作质量

- 四项核心设定、按需补设定、内部双路线、首卷500字/黄金三章/重大高潮、事件链、章链、ContextCompiler继续按真实使用反馈优化。
- 重点防止候选同质、软参考变硬、计划污染实际、重复情节、人物工具化和上下文噪声。
- 真实文学质量按题材样本阅读；工程字段和自动测试不承诺爆款效果。

## P2 运营与可靠性

- 账号、会员、预算、后台模型管理、任务恢复和备份按真实运营问题迭代。
- Web-only发布与后端发布分开；API/Worker/迁移继续使用静默窗口和回滚。
- 邮箱验证、找回密码、协议/隐私、导出/注销等在公开运营前完成。

## 暂停项

- 单书20章验收已按老板要求停止；只有重新明确要求才继续。
- 50/100/200章不作为当前开发任务，也不阻塞UI和功能调整。
- 历史事故、旧双书和旧测试数字只在Git历史追溯。
