# 剧情总纲分阶段规划审查

- `design_review_id`：`DR-20260730-03`
- `release_id`：`wm-longform-r1-20260719-003435-e4d7b8b7`
- 日期：2026-07-30
- 适用 Skill：`wenmi-longform-quality`
- Skill 快照：`.agents/skills/wenmi-longform-quality/SKILL.md`（沿用当前 release 已记录哈希）

## 1. 已确认事实、老板决定与未知项

### 已确认事实

- 当前 `master_outline` 只强制核心前提、核心冲突、主角成长线、阶段标题/目标/转折和结局方向。
- 当前阶段没有章节范围、主线问题如何解决及结果、起承转合、阶段结束状态、待回收信息与伏笔或后续方向。
- 当前两名编剧只提交自然语言全书方案，只有活动主编被要求输出可落库结构。
- 当前前端使用通用递归字段展示，不能形成作者可快速核读的阶段总纲。
- 当前叙事主线投影仍读取旧 `goal/turningPoint/result/chapterStart/chapterEnd` 字段。

### 老板最新决定

- 剧情总纲由两名编剧直接按阶段规划，活动主编基于真实编剧产物核对和整理。
- 每阶段至少包含：阶段编号/名称、预计章节范围、剧情主线（遭遇、解决、结果）、起承转合摘要、阶段总结、待回收信息与伏笔、后续方向。
- 例如第一阶段可以规划为第1—50章；它是全书阶段，不是卷纲或50份章纲的拼接。

### 推断

- “阶段总结”应描述阶段结束后的角色、关系、资源和局势变化，避免与剧情主线重复。
- “后续方向”描述下一阶段入口和仍可变化的空间，不预写下一阶段全部事件。
- 章节范围是预计值，可通过新版本调整；不能被当作已发生正史。

### 未知项

- 一本书最终需要多少阶段由编剧依据题材和全书主线决定，不写死固定阶段数。
- 待回收项允许为空；为空必须如实显示，不得为填满模板虚构伏笔。

## 2. 痛点—根因—机制追踪

| 痛点 | 症状 | 根因 | 修复机制 | 反例 | 指标 | 停止条件 |
|---|---|---|---|---|---|---|
| 总纲与章纲相似 | 只有目标和转折，无法判断全书阶段闭环 | 总纲 Schema 过浅 | `stage_master_v2` 强制阶段闭环字段，章纲只引用相关阶段 | 不把逐章事件塞进总纲 | 每阶段字段完整且不与章纲重复 | 新结构反而生成逐章流水账 |
| 编剧没有直接规划 | 主编可能凭通用提示补出结构 | 仅校验主编产物 | 两名编剧独立产物先逐份校验，再允许交叉质疑和主编整合 | 同模型岗位不得冒充两份异模型方案 | 两份独立结构及来源都可追溯 | 缺任一份真实编剧结构 |
| 作者难以核读 | 前端展示嵌套键值或 JSON | 使用通用结构渲染 | 专用阶段卡片及中文标签 | 不隐藏开放问题和待回收项 | 页面无英文键/机器协议 | 作者界面泄漏 JSON |
| 图谱主线过长或缺范围 | 不能按1—50章查看阶段 | 投影仍读旧字段 | 从阶段范围和主线闭环生成一阶段一条简洁投影 | 不复制整段起承转合 | 每阶段至多一条主线 | 投影反写规划或正史 |

## 3. 合同

新确认的剧情总纲使用：

```json
{
  "outlineSchema": "stage_master_v2",
  "premise": "全书核心前提",
  "coreConflict": "贯穿全书的核心冲突",
  "protagonistArc": "主角从起点到终局的变化",
  "majorStages": [
    {
      "stageNumber": 1,
      "title": "第一阶段名称",
      "chapterRange": { "start": 1, "end": 50 },
      "mainline": {
        "encounter": "主角遇到什么核心问题",
        "resolution": "主角最终如何解决",
        "result": "阶段结束得到什么结果"
      },
      "structure": {
        "setup": "起",
        "development": "承",
        "turn": "转",
        "conclusion": "合"
      },
      "stageSummary": "阶段结束后的关键状态变化",
      "pendingThreads": ["待回收信息或伏笔"],
      "followUpDirection": "下一阶段从哪里继续"
    }
  ],
  "endingDirection": "全书终局方向",
  "storyPromises": ["需要兑现的作品承诺"],
  "openQuestions": ["仍需作者确认的问题"]
}
```

规则：

- 至少两个阶段；编号从1连续递增。
- 第一阶段从第1章开始；相邻阶段章节范围连续、不重叠、不跳章。
- 主线必须明确“遇到什么—如何解决—结果是什么”。
- 起承转合是阶段级总结视角，不限定每章必须对应四段，也不要求等分章节。
- 阶段总结只写结束状态差异；待回收项允许为空；后续方向必须保留创作余地。
- 旧 `majorStages[{title,goal,turningPoint}]` 只读兼容，不能作为新确认总纲写入。

## 4. 替代方案

1. 只改前端：拒绝。数据和提示词仍错误，属于遮盖症状。
2. 让主编单独生成：拒绝。会绕过双异模型编剧的真实独立规划。
3. 为每阶段直接生成50份章纲：拒绝。过早定型、上下文膨胀并压缩创造空间。
4. 采用阶段总纲合同：选择。层级清晰、可版本化、可检索，且不把远期规划写死。

## 5. 两轮审查

### 第一轮：正确性与治理

- 总纲阶段与滚动章纲 Schema 保持分离；当前故事弧保存为持续会话和确认决定，不再建立独立卷纲。
- 编剧独立产物、交叉质疑、主编整合和作者确认均保留来源。
- 缺少任一关键字段、范围重叠/跳章或只有普通摘要时拒绝落库。
- 不修改历史正式规划、正文或正史；旧版本继续可读。

### 第二轮：创造性与输出质量

- 起承转合只作为阶段复盘维度，不变成逐章公式。
- 预计章节范围允许通过版本调整，不作为强制忘记或剧情填充指标。
- 待回收项可以为空，禁止为了模板完整虚构伏笔。
- 下游主笔只检索当前阶段和相关最小资料，不把整部总纲每次全量注入。
- 若真实模型盲评出现模板化上升、人物选择空间下降或整体阅读质量下降，回滚提示词和强制校验，不删除新结构数据。
