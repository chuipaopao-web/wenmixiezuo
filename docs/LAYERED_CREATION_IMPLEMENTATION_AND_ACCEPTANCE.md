# 分层创作系统：当前方案与验收

> 本文是分层创作的当前功能合同和状态表，不再承担每次开发的148项全量门禁。旧总表完整保留在 Git 基线 `e8517d9` 的同名文件中。

## 1. 目标

让小白作者不需要一次填完整本书，而是在需要时完成当前层：开书定方向，设定定非剧情骨架，卷定大故事，事件定因果小故事，章纲定近期表达，正文执行，结算把真实结果带回下一层。

硬参考只约束不能违反的事实和当前任务；软参考允许AI调整；开放区明确留给创作发挥。任何层都不能把未确认计划冒充已发生事实。

## 2. 对象与职责

| 层级 | 负责 | 不负责 |
|---|---|---|
| 开书信息 | 题材、目标读者、基调、基础承诺、作者已有想法 | 世界百科、整书剧情 |
| 非剧情设定 | 世界舞台、主角底板、规则与代价、边界与留白；扩展设定按需补 | 卷剧情、事件顺序、章场景 |
| 全书故事总线 | 长期核心矛盾、主角长期欲望、最终方向和可开放线程 | 固定每卷细节 |
| 卷方向 | 本卷开场局面、推动、升级、关键选择、高潮、代价、卷末新局面、重点表达 | 逐事件排期和逐章场景 |
| 事件链 | 卷内事件顺序、因果、承诺/铺垫/兑现责任 | 事件内部全部场景 |
| 事件大纲 | 当前小故事的目标、对立、转折、高潮、后果和下一事件接口 | 逐章正文表达 |
| 完整章链 | 当前事件全部章节的责任与顺序 | 远期章节细节冻结 |
| 近期详细章纲 | 最近1—3章的场景、人物行动、情绪、信息、回报与章末接口 | 代写完整正文 |
| 正文与结算 | 正文自由表达；结算记录实际变化、事实、线程和后续影响 | 用计划替代实际 |

作者原话绑定具体对象，区分必须遵守、强烈偏好、灵感参考和需要先问。AI未采用作者原话时要说明原因；作者可以修改、留空、重做或回到上层。

## 3. 设定体验

默认只显示四项核心设定：

1. 世界舞台；
2. 主角底板；
3. 规则与代价；
4. 边界与留白。

系统可按题材推荐扩展设定，但不能让作者多选一大串后才允许写作。写到需要时再补设定：立即补、带着明确空白继续、或把它作为本层开放问题。扩展项没有确认时不注入下游硬上下文。

每项可由多名编剧独立提出方案，作者可整选、摘片、补自己的话、融合、编辑和重新设计；选择必须刷新不漂移，确认后收起旧候选，只保留定稿和重做入口。整份设定质检只处理会阻断下游的真实矛盾，不替作者自动确认。

## 4. 内部结构方法与卷路线

三幕式、五幕式、英雄之旅、故事圈、七点式、八序列、黄金三章、爽点/悬念/单元剧/多线等保存在后台版本化方法库。每项记录适用问题、长度/题材、可移动节点、套路风险、版本和指纹。

作者不看方法名、幕、节拍或内部键。卷设计读取开书、活动设定、故事总线、上一卷真实结算和作者本卷想法，判断当前卷最需要解决的任务，再选择两条不同的内部路线交给独立编剧。每名编剧只收到自己的精简软参考。

普通页面展示至少两条代入本书的具体路线，包括：开场局面、推动事件、主角行动、阻力升级、关键选择、关系变化、高潮、代价、解决结果、卷末状态、好看点和风险。两条路线至少在主动/被动、对立力量、因果路径、关键选择、关系变化、代价、高潮触发、卷末状态或读者体验中的多个维度有真实区别，不能只换措辞。

作者可整份选择、跨方案摘片、让主编融合、自己编辑或全部重做。事件链只接收确认后的故事责任，不接收内部方法名。后续卷根据上一卷实际重新选择结构，不继承固定模板。

## 5. 首卷强启动

首卷强启动属于第一卷设计，不属于设定。效果必须达到，写法由AI针对题材设计。

- 主要追读动力：爽感、冲突、情绪、秘密、新奇、人物、关系或混合。
- 前500有效正文字符：明确读者为什么继续看，包括即时处境、情绪抓力、读者问题和马上会发生的变化。
- 黄金三章：第一章进入处境并启动；第二章主动行动、阻力升级并展示独特看点；第三章给第一次明确回报，同时打开更大期待。
- 持续追读：处境、关系、身份、信息、能力/资源、目标、冲突和阶段回报持续发生有效变化。
- 重大高潮：不晚于累计约10万有效正文字符；短卷在卷末完成。必须兑现重要承诺，包含重大选择、代价、主要冲突变化、不可逆新局面和下一阶段入口。
- 防疲劳：冲突类型、爽感/压迫、情绪/回报和快慢节奏要换味，不能连续复制同一种打脸、误会、追杀或反转。

事件链必须标明谁承载开篇、黄金三章、早期回报、升级、高潮铺垫、高潮和后果。第一事件先形成三章整体启动包，只冻结第一章；每章结算后保留总体承诺并校准后续细节。系统按定稿正文累计有效字符，提前预警高潮可能逾期，不等到最后一刻突然切高潮。

## 6. 事件、章纲与衔接

事件链遵循：承诺提出 → 人物行动 → 阻力升级 → 阶段回报 → 新局面 → 再升级 → 高潮兑现 → 后果。数量由卷任务决定，不用固定十事件。

当前事件大纲要说明它从上一实际结果如何开始、人物要什么、谁/什么阻止、关键选择、转折与代价、如何结束、留下什么事实和下一事件问题。事件阅读感受是可留空的单选软参考，不允许一次多选整套节拍。

完整章链保证当前事件有完整顺序；详细章纲只滚动细化最近1—3章。第一章额外包含前500字兴趣锚点、主角即时处境、第一处有效变化、独特看点首次露出、小回报和章末期待。第一章明显全是说明或无抓力时定点重写，不直接继续第二章。

## 7. ContextCompiler与资料包

每次调用只编译当前任务需要的包：

- 身份与对象：owner、book、当前层和活动版本；
- 硬事实：确认开书、相关设定、正式正文/结算和明确禁止项；
- 当前任务：上层确认责任、目标、输出合同和停止条件；
- 连续性：最近正文、上一实际结果、活动线程、相关人物/关系/资源/时间因果；
- 软参考：作者偏好、卷重点表达、内部结构软工具；
- 开放区：AI可以自由决定的场景、对白、意象、节奏和合理惊喜；
- 来源与预算：每项来源、版本、选择理由、排除理由和预算。

明确排除其他书、未摘录灵感、未确认候选、过期版本、整库全文堆叠、AI猜测和无关审查报告。硬事实/当前任务若放不下应诚实阻断或回查正式源，不能静默截断。摘要只导航，争议回查原文。

## 8. 前端交互

整体信息架构和视觉允许继续重设计。必须保持：当前书清楚、当前层清楚、任务状态清楚、下一步清楚、旧内容可找回。

页面按状态而不是按数据库表堆内容：

1. 说明当前要完成什么；
2. 作者可选补充（默认收起或简短）；
3. AI开始工作的明确按钮；
4. 工作中进度与参与者；
5. 方案差异和作者选择；
6. 确认后的简洁结果与继续下一层；
7. 失败原因和就地恢复。

手机优先，360/390/430px无横向溢出，主操作可单手触达，触控目标约44px，输入法弹起后仍能编辑和提交。不要用重复大卡、长说明、专业术语和过多同时可见按钮制造负担。

## 9. 作者API与运行边界

普通作者响应只返回业务对象、白话状态、结果和恢复动作；不返回供应商/模型内部ID、任务/讨论/ContextPack/方法键、路径、堆栈、SQL、JSON合同或原始枚举。管理员审计走独立路由。

任务需要幂等、检查点、失败恢复和预算结算；重复恢复不重复扣量。Worker不直接改核心业务表或正式正文。作者确认后才进入正式版本，下游任务绑定当时的精确活动版本。
