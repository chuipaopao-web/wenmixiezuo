# 设定协作流程继续优化：开发与验收清单

> 老板最新需求建立于 2026-08-22。本清单是本次实现与验收合同；旧页面、旧文案和旧测试与本清单冲突时，以本清单为准。

## 一、用户可见目标

- [x] 完整设定库不再自动勾选题材推荐项；核心必选项仍按产品约束处理，推荐项由作者主动判断和勾选。
- [x] AI 成员选择区和任务状态区同时显示头像、成员名与职位；高级编剧额外显示“高消耗”，不向普通作者暴露模型名。
- [x] 成员状态来自真实席位任务：未开始、工作中、已完成、已失败；单席失败不抹掉其他成功方案，并可就地重试。
- [x] 恢复设定页原有的高辨识度整页任务进度条，不再使用卡片右侧的小型装饰进度条。
- [x] 编剧方案默认折叠；作者点“查看方案”后阅读、片选、整选或重新设计，桌面和手机都不被长方案撑满。
- [x] 恢复完整决策链：编剧独立方案 → 作者勾选片段/整份方案 → 交由主编融合 → 形成可编辑稿 → 作者修改 → 可“按此整理”交主编专业化整理 → 作者确认本项设定。
- [x] 作者确认前，编剧候选、主编融合稿和作者修改稿只属于当前设定条目的临时候选；确认后才写入该条目的已确认结果与临时资料包。

## 二、页面与交互状态

| 状态 | 页面行为 | 验收状态 |
| --- | --- | --- |
| 初始选择 | 推荐设定不自动选；核心约束与作者主动选择清楚区分 | 通过 |
| 等待开始 | 成员卡显示职位；高级编剧显示“高消耗”；只有一个显著开始按钮 | 通过 |
| 工作中 | 对应席位显示“工作中”；整页显眼进度条显示已完成席位比例 | 通过 |
| 部分失败 | 成功方案保留；失败席位显示“已失败”和可恢复动作 | 通过 |
| 全部失败 | 不产生空编辑稿；说明失败并允许重试 | 通过 |
| 待选择 | 方案默认折叠；展开后可片选、整选、重新设计 | 通过 |
| 主编融合中 | 明确显示主编正在融合作者所选内容，防止重复提交 | 通过 |
| 编辑稿 | 显示主编融合后的可编辑稿；作者可直接修改 | 通过 |
| 按此整理 | 主编只基于当前作者修改稿专业化整理，不偷换已选事实 | 通过 |
| 确认完成 | 确认后更新当前条目和临时资料包，收起过程并进入下一条 | 通过 |
| 刷新恢复 | 已完成席位、失败席位、已选片段和活动编辑稿可恢复 | 通过 |

## 三、AI、任务与性能

- [x] 查明 GLM-5.3 慢发生在排队、ContextPack、提示长度、输出上限、网络重试还是模型生成阶段，不以“换模型”代替根因检查。
- [x] 在不降低设定方案完整性、不泄漏模型内部信息的前提下，缩短无关上下文和冗长输出要求，控制单席输出预算。
- [x] 多席并行保持独立；状态由席位运行记录、任务状态和结果事实共同决定，不用页面本地猜测。
- [x] 主编融合与“按此整理”使用独立幂等动作；重复点击、刷新和失败重试不重复创建确认版本或重复扣量。

## 四、数据与接口

- [x] 明确并复用或补充“主编融合所选片段”和“按作者修改稿整理”接口，输入绑定 `owner_id`、`book_id`、设定条目与活动轮次。
- [x] 主编只接收作者选中的编剧内容；未选方案不得混入融合稿。
- [x] 作者修改稿与主编整理稿可追溯，确认操作不覆盖历史候选和作者原话。
- [x] 旧轮次数据采用最小兼容读取；不修改已合并迁移，不清空作者正式数据。
