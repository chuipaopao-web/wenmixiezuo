# 验收标准

## 1. 完成定义

只有本文件全部通过、没有未解决的 `blocker` 或 `major`、证据与当前提交一致时，才能宣布首版完成。执行成员不能自行宣布整个产品完成。

## 2. 基础工程

- 第1至24条共识和后续老板决定全部映射到实现、测试和文档。
- 类型检查、全量测试、构建和本地运行验证通过。
- Web、API和Worker统一启动，只监听 `127.0.0.1`。
- AI智囊团关闭后，小说平台仍可独立运行；反向也成立。
- 运行时、依赖、Schema、API、文档和发布版本锁定并可追溯。
- 未配置远程Git时明确标记“仅本地版本”。

## 3. 数据与迁移

- 所有迁移可以在空库执行，并能安全升级已有数据。
- 已合并迁移不可修改；重复运行安全；失败事务正确回滚。
- 所有核心Repository自动携带 `owner_id` 和 `book_id`。
- 建书时9个Agent实例和配置快照原子创建。
- 两本测试书的消息、正文、知识、任务、记忆、FTS、缓存、预算、租约和界面状态零串线。
- 正文文件、数据库指针和哈希双向一致。
- 索引和图谱损坏后可按书重建，不影响正文和正史。
- LanceDB只作为本地嵌入式可重建向量投影运行，不开放新端口、不要求独立服务、API Key或现金费用；SQLite和不可变正文仍是唯一权威源。
- 标签定义、别名、标签赋值和人类可读语义标注保存在SQLite并按书隔离；原始向量不通过普通资料API暴露，也不成为作者可编辑的正史。

## 4. Agent与任务

- 9个岗位具备稳定身份、真实模型来源、书籍范围、权限、记忆和状态。
- 九名成员在同一本书跨Worker重启、跨卷、跨100章以上间隔和正史升级后仍能从岗位连续性包取得正确当前关注、相关旧承诺、最后有效贡献和权威证据；未激活成员保持零调用、零伪状态。
- 按需专家只在任务相关时激活。
- 同模型分身不被标记为异模型独立复核。
- Agent状态、任务、预算、模型和工具调用来自真实事件。
- 状态心跳过期、任务结束、取消或失败后正确收口。
- 任务暂停、继续、取消和接管可以恢复，不依赖旧聊天。
- 结果不明的调用保持 `interrupted`，不自动重试。
- 底层HTTP和子进程取消是真实取消，不只是修改数据库状态。
- 主编和主笔如实显示同一 Codex GPT-5.6 Sol 来源，不被当成两个独立模型。
- 编剧使用 Coding Plan DeepSeek V4 Pro，设定师使用 Agent Plan GLM 5.2，审校使用与主笔不同的 Agent Plan Kimi K2.6。
- 方舟真实调用只能命中 `/api/coding` 或 `/api/plan`；Codex只使用ChatGPT登录态；任何通道都不能回退到按量付费API。
- 老板指定主笔时记录 `owner_specified`，不生成虚假盲选样稿或评分；模型切换新增快照并使旧选择失效。

## 5. 双主编

- 每书同时只有一个活动主编租约。
- 第3章开始前完成一次双主编接管演练。
- 接管包包含任务、章节、正史、待决、预算和调用状态。
- 接管后旧 `editor_epoch` 指令全部拒绝。
- 接管不造成重复生成、重复计费或丢失决定。

## 6. 记忆与正史

- 使用至少500万规范化中文字符、1500章的满规模测试书；硬锚点分散在不同卷、故事弧、章节、位置、来源和故事时间，硬状态正确率100%。不得用单行百万字符、集中前缀或同源规则夹具代替。
- 查询金标与实现规则独立，覆盖精确词、别名、语义改写、多跳关系、时间切片、否定、冲突和无答案；固定同义词同源测试不能证明语义RAG。
- 结构化、BM25、向量、关系、融合和重排分别报告Recall@K、Precision@K、MRR、nDCG、无答案准确率、延迟和Token，并完成消融。
- 混合方案在独立评测中优于单一FTS、单一向量和整书长上下文；重要命中均可回查正式事实或原文。
- LanceDB在锁定的Windows/Node版本完成安装、冷启动、本地离线嵌入/查询、索引中断恢复、整库删除重建和跨书/正式临时隔离；向量模型、维度与查询指令形成快照且不混用。
- 正文、设定、规划、事实、Wiki、人物声音和任务临时资料分别遵守切片合同；场景父子块、偏移、父级、来源版本、故事时间、实体和哈希均可追溯。
- FTS、向量、关系和Wiki投影具有投影任务与正史水位；落后、失败、错误模型或版本不明的投影不能静默驱动正式生产。
- 每次模型调用具有可追溯的不可变上下文包。
- 场景、章节、故事弧、卷和全书主脊五级连续性节点均携带正史版本、来源范围、哈希和原文指针；新增章节只增量更新受影响节点，正史修订可以精确失效与按范围重建。
- 主支线承诺、伏笔、人物目标、知情差和未决决定具有独立状态、预计窗口、最后推进章节和关闭依据，不依赖摘要碰巧记住。
- 长聊天压缩保留来源消息范围、决定、事实、未决、异议、承诺和下一步；事实探针失败时不覆盖上一个有效快照，原始聊天不进入正式向量索引。
- 硬规则、当前正文、前章结算和老板决定不会静默截断。
- 主编、编剧、设定师、主笔和审校分别通过岗位专用上下文合同；全量上下文与最小上下文完成注意力、遗漏、幻觉、Token和延迟对照。
- 体验官、文编、研究员和版权顾问也分别通过岗位专用上下文合同；九岗位独立意见不能被共享资料和提前共识压平。
- 主笔的约束胶囊＋灵感调色板、全量资料包、只有硬约束和旧流程基线完成对照；最小包在事实遵循达标时，原创性、人物声音、情绪力度和整体质量不劣于基线。
- 全书表达基线与场景技法分开版本化；建书不要求固定选择一至三种手法，感情、战斗、悬疑等不同场景可按叙事目标动态选择技法且保持可辨识的作品身份。
- 主笔只收到当前场景必要的少量技法卡，并能提出库外做法或合理偏离；整个技法库、固定模板和具体作品仿写材料不会进入上下文。
- 人物生死、时间线、位置、道具、属性、技能、知情和伏笔状态可以确定性检查。
- A、B、C、D四级事实门禁正确。
- D级事实未确认时，章节和依赖任务不能继续。
- 正史版本变化会使相关上下文、摘要、图谱和章纲失效。
- 正史版本变化会使相关向量、Wiki和关系投影失效或进入可追溯重建。
- 无关任务不会因正史变化机械重做。
- 人物档案、时间线和图谱能够从正式事实重建。
- 作者可在资料库查看角色、势力、地点/地图、道具/资源/技能、事件/时间线、规则、伏笔/钩子、关系图谱、情绪图谱、标签、证据和版本状态；每项均能区分正史、老板确认、候选和派生信息。
- 关系图谱支持方向、同一实体对的多重关系、故事时间、观点主体和证据；情绪图谱区分明确与推断情绪；地图画布位置不会反向成为地点正史。
- 标签定义和赋值分离，支持命名空间、别名、适用对象、版本、归档与可撤销变更；AI建议只能进入候选，老板明确对象化指令才能确认相应标注。
- 新增普通标签只更新结构化/投影元数据，不要求重写正文或全量重新嵌入；嵌入模型、维度或嵌入文本策略变化时建立新索引并完成可回滚重建。
- 资料缺口只报告与当前任务或叙事目标相关的硬缺口、建议和可选灵感；有意未知、悬念和自由创作区不会被统一完成率误判为缺陷。
- 不安装Neo4j、Qdrant、Milvus、Chroma、GBrain、LLMWiki、Graphiti或Cognee作为运行时权威服务；引入任何独立数据库服务必须重新提交重大架构决定。

## 7. 创作闭环

- 主测试书连续生成5章，每章2500至3500字。
- 上述5章只验收短流程、状态和恢复；20章只观察真实模型早期趋势，50章验证中期人物/节奏/伏笔，100至200章进入长篇能力判断。每层均与旧流程或弱治理基线做匿名成对盲评；只有真实运行实际覆盖1000章以上和目标字数，才能声明相应范围的Agent长期陪伴或500万字文学质量。
- 滚动规划同时维护全书终局/重大承诺、卷、20至30章故事弧、未来30至50章轮廓、未来5至10章细化和当前1至3章场景契约；不会一次写死1000章，也不会只凭前一章即兴续写。
- 每章更新正史、状态、承诺和投影；每10章、每个故事弧、每卷及20/50/100/200章滚动窗口均产生可追溯检查结果，软趋势不自动改写正文。
- 纵向评测记录每万字正史矛盾、无依据新增事实、人物声音漂移、重复情节/表达、伏笔债务、章纲偏离和重写率。
- 局部文字、单章结构、跨章连续性、全书叙事、创作自由/多样性和作者满意度分别报告，任一blocker不能被平均分掩盖。
- 原创性、合理惊喜、人物可辨识度、情绪力度、语言/画面/节奏和整体阅读质量分别设置预先定义的非劣效门槛；正史一致性提升不能通过综合平均分抵消任一核心创作维度下降。
- 开放讨论、创意推演和暂存试写在缺少正式章纲时仍可使用且不写正史；正式生产才强制完整准备、审校和结算。模式升级必须显式，试写不得自动转正。
- 每章完成预检、上下文、初稿、硬检查、异模型审校、定点重写、事实提取和正史结算。
- 第2章完成后模拟中断，系统从正确检查点继续。
- 前章未结算时后章不能启动。
- 已完成章节不会重复生成。
- 半章和失败暂存结果不会进入正式正文。
- 每次修改形成新的完整不可变版本。
- 审校意见具有位置、类型、严重度、依据和修改要求。
- 生成前只运行硬预检，软审校在完整草稿后执行；审校建议不规定唯一表达，修改稿整体质量低于原稿时保留原稿并撤销对应软规则。
- 动态技法路由相对无路由和固定模板基线完成多样本匿名盲评；若原创性、人物声音、情绪力度、场景效果或整体质量下降，不得升级为默认规则。
- Kimi审校输出只有通过严格JSON字段、枚举和0至100评分校验后才能写入审校记录。
- 同类重大文风问题反复失败时触发上游调整，而不是无限润色。

## 8. 讨论与老板体验

- 老板可用自然语言完成建书、切书、讨论、选方案、生成、暂停、继续、接管和查看历史。
- 明确控制命令零Token处理；模糊创作意图才调用模型。
- 普通消息必须产生可追溯的活动主编回复；自然创作意图无需 `讨论` 前缀即可激活相关岗位。
- 老板可用自然语言要求主编新增标签定义、别名或给明确对象赋标签；单书、明确、可撤销的命令直接执行并返回审计回执与撤销入口，歧义命令只问一个必要问题。
- 最近聊天只进入有界任务上下文，不自动污染长期记忆或正史。
- 未形成并确认创作方案、活动故事圣经、总纲和对应章纲时，`写N章` 与直接批次API都不能创建章节或启动主笔。
- 章前资料和章末事实不得包含与当前书籍无来源关系的固定测试人物、地点、情节或钩子。
- 讨论只激活相关岗位，未回复成员不被伪造也不阻塞。
- 主编汇总推荐、理由、分歧和影响，老板不需要阅读原始模型长输出。
- 老板强势提出与证据或正史冲突的方案时，主编能给出有依据的反对意见、替代方案和影响；建议采纳率不作为正确性奖励。
- 相关岗位在主编综合前使用差异化资料独立给出意见；主编保留少数高潜创意、未解决分歧和结构不同的备选，不以快速一致为目标。
- 岗位经验只有在记录适用范围、反例、版本、到期和撤销条件并跨样本验证后才能启用；单次采纳、聊天和模型自评分不得永久固化。
- 重大确认单展示对象、版本、范围、后果和费用。
- 模糊回复不能触发重大操作。

## 9. 版权与研究

- 原文、详细逐章摘要、人物映射和拆书FTS不能进入主笔上下文。
- 结构卡去除专有名词、独特场景、角色映射和原事件顺序。
- 生成前进行结构检查，生成后进行文本和结构分维度检查。
- 换名仿写、近似改写、翻译规避、多来源拼接和标志性事件链照搬被阻断。
- 高风险只能通过适用授权或重新设计解除，普通“继续”无效。
- 联网资料保存来源、时间、地区、语言、哈希和证据关系。
- 联网结果只形成候选，不自动修改正史或书籍定位。

## 10. 预算与稳定性

- 每次模型调用前持久冻结预算，结束后按实际Token、费用和耗时结算。
- 并发申请不能超卖预算。
- 使用70%时重新预测，达到100%后不启动新调用。
- 费用未知且可能产生现金支出时正确暂停或降级。
- 技术故障最多自动重试一次，备用模型最多接管一次。
- 使用确定性适配器完成24小时Worker测试，无僵尸任务、未解释暂存残留或持续失控资源增长。

## 11. 备份、恢复和删除

- 备份包含数据库、正文、历史版本、正史、任务、预算、调用、墓碑和必要暂存成果。
- 每个备份具有完整文件清单和哈希。
- 在干净临时目录真实恢复，数据库完整性、外键、正文和正史哈希完全一致。
- 有数据变化时，滚动24小时内至少有一次真实恢复演练。
- 归档、导入和恢复不会污染其他书籍。
- 普通删除只归档。
- 永久删除要求包含 `YES`、对象名称和短ID的严格确认，并写墓碑阻止旧备份复活。
- 第二物理位置未配置时，不声称可以防硬盘损坏。

## 12. 多端体验

- 桌面、平板和手机核心流程无横向溢出和布局跳动。
- 桌面三栏可折叠，正文阅读模式完整。
- 两侧栏保持紧凑，中间创作与正文区获得主要横向空间；默认浅绿底色，并可持久切换米白、雾蓝、夜间底色和四档字体。
- 九个岗位直接显示女性姓名、简短职业名称和原型头像；完整职责不冒充岗位名称，真实模型来源仍可追溯，头像不参与状态推断。
- 成员状态位于身份下方，空闲、排队中、后台工作中、需要处理和离线的语义与配色明确；只有任务、成员和Worker心跳吻合时显示后台工作中。
- 当前任务位于左栏并显示章节、阶段和状态；详情可查看任务书、检查点和任务ID，可取消状态调用真实取消接口。
- 左栏任务入口可打开中间任务二级页面；进行中的任务、最近任务、预算和待确认事项均在该页面使用真实数据展示。
- 资料库使用中间全屏二级页面，提供实体卡、时间线、关系/情绪图谱、地图、标签中心、证据和任务相关缺口；右侧成员栏不承载资料内容。
- 右侧栏只显示团队成员，不出现预算或待确认；重大确认从任务中心调用真实接受或拒绝接口。
- 手机输入框不被软键盘遮挡，长文可全屏阅读。
- PWA可安装；已加载内容可离线查看；草稿刷新和断线后不丢失。
- 正史更新后旧缓存失效。
- 亮色、暗色、键盘、焦点、对比度和减少动画通过无障碍验证。
- 长对话和长正文保持流畅，状态刷新不会造成页面闪跳。
- 超长篇状态页显示总字数/章节、当前卷与故事弧、正史/索引水位、开放承诺、伏笔债务和滚动质量窗口；成员详情显示当前关注、最后有效贡献和证据，不显示思维链或伪造在线状态。

## 13. 最终交付证据

- 主分支提交、任务账本、文档指针、迁移和运行版本一致。
- 每阶段具有不可变验收包。
- 24条覆盖矩阵没有未说明的跳过项。
- 老板收到成果演示、风险和使用说明，不需要检查代码或执行技术命令。
- 最终由项目经理基于完整证据签署通过。
