# 文秘写作使用说明

## 启动与停止

1. 双击项目根目录的 `文秘写作-启动.cmd`。
2. 启动器会检查数据库、完成生产构建并打开浏览器工作台。
3. 工作台地址固定为 `http://127.0.0.1:43110`，只允许本机访问。
4. 使用结束后双击 `文秘写作-停止.cmd`。停止器只处理本项目启动器登记的进程。

第一次启动前需要安装项目锁定的 Node.js 24稳定版，并在项目目录执行一次 `npm install`。当前交付目录已经装好依赖，可以直接启动。

## 创建第一本书

打开工作台后，选择“创建新书”，只需填写书名并选择男频、女频、不限或待确定。题材、故事特点和额外作品边界都可以不选；已选标签只是主要方向，其他元素仍可随剧情自由发挥。世界观、力量体系、人物、主线与结局在开书后的自由聊天里共同确定，不要求一次填完。确认后，系统会原子创建书籍工作区、11名创作成员、小文秘书会话、预算和空规划入口。

如果不填写书名，系统会给出确定性的建议名称。建书失败时不会留下半本书或残缺岗位。

## 日常创作

### 续写自己已经写好的小说

1. 先在书架创建一本空书，只填写这本旧稿对应的基本开书资料；不要先手工创建章节。
2. 打开该书的“正文”页，在空正文工作台点击“续写已有作品”。可以直接粘贴全文，也可以选择本机 TXT 文件；单次最多接收500万规范化中文字符。
3. 点击“识别章节”后逐章检查预览。系统会显示识别标题、字符数和异常提示；作者可以修改标题、排除误识别的前言或附录。没有清晰章标题的文本只会作为一章候选，不会假装识别成多章。
4. 勾选“我已核对章节与顺序”，再点击“确认导入为前文正史”。确认前不会创建章节、正文或正史；确认后旧稿按原文建立不可变版本，不补造历史三席点评。
5. 导入完成后系统会自动把精简的“续写诊断资料包”交给主编并打开对话。主编只接收书名、导入章数、总字符数、末章信息和下一步目标，不会把整本全文一次塞进模型。
6. 在对话中先与主编、双编剧讨论未来剧情方向，需要时再锁定剧情总纲；随后只细化未来1—3章章纲。旧人物、规则、伏笔或地点被提及时，成员通过混合检索按需回查前文正史。
7. 后续新写章节仍执行正常的主笔生成、硬检查、三异模型点评、修订与老板定稿流程。旧稿导入不等于允许未来章节跳过审校。

导入中断后重新打开“正文”页，会恢复最近一次预览或导入检查点；不要重新粘贴同一份全文。若这本书已经有章节，专用整书导入会拒绝执行，以免把无关正文混进现有作品。

- 直接像聊天一样输入想法即可，例如“我想写一本玩家进入历史战役副本的游戏文”。貂蝉（主编）会回复；涉及剧情、人物、设定、题材、节奏或章纲时，会自动邀请最相关的一名成员，不必先输入命令。
- `讨论 具体问题` 仍可用作显式讨论快捷方式。相关成员先给出真实意见，主编读取意见后汇总并给出方案ID；输入完整的 `确认方案 <ID>` 才会把创作规划版本化。
- 自然说“开始写”或“继续写”即可。如果创作方案、故事圣经、总纲或下一章章纲未齐备，系统不会启动主笔，而会在当前对话继续讨论和补齐规划；资料齐备后只启动唯一下一章。编剧估算的章节跨度用于规划，不是批量盲写参数。
- 最近聊天只按需带入一次回复或讨论的有界上下文，不会自动写进长期记忆或正史。
- 点击输入框左下角的“+”可以添加图片或文件。单个文件最多20 MiB，一条消息最多6个；图片提供预览，TXT/Markdown/JSON/CSV/LOG、可提取文字PDF和DOCX会显示真实解析状态。扫描PDF和图片文字当前不会自动识别。附件只作为本次对话的临时资料，不会因为上传或成员引用就自动进入正史。
- 输入 `暂停`、`继续` 或 `取消`，会作用于当前书籍中符合条件的任务。
- 输入 `准备接管` 会创建包含章节、正史、待决、预算和调用状态的接管包；只有再输入带完整接管ID的 `确认接管 <ID>` 才会完成接管。
- 输入 `切书 书名` 或 `切换到《书名》` 可以在本地零Token切换书籍。
- 开放式消息会保存到当前书籍并创建可追溯的主编回复或岗位讨论任务。真实通道不可用时任务会如实失败；开发测试模式会明确显示确定性假模型来源。
- 主编使用真实Codex套餐通道时，回复可能需要约1至3分钟。发送后看到“主编已收到”，可以先“返回书架”，再打开首页左侧“任务”查看真实处理状态；返回书架不会停止后台工作。可以继续进入任意书补充信息，系统会按书和消息顺序分别处理，不会用固定话术假装成员已回复。
- 书架首页左侧提供“书架、任务、团队、设置”。点击“任务”会打开多书任务中心，按书显示进行中的任务、最近任务、预算和待确认事项；任务行写明所属书、章节、当前阶段和状态，详情可查看执行岗位、任务目标、检查点和任务ID，并通过真实任务状态机取消或重试。
- 打开一本书后，左侧只提供“对话、规划、正文、图谱、资料库、版权”六个书内入口，不再显示任务。点击“正文”后，内容区固定为左侧卷章目录、右侧正文，目录支持按卷展开、分页和搜索。
- 待确认事项只在首页“任务中心”显示；查看所属书、范围和影响后，可使用“拒绝”或“明确接受”调用该书真实确认接口。
- 右侧只显示11名女性创作成员，例如“貂蝉（主编）”“西施（副编）”“文姬（设定）”“湘君（副笔）”。小文秘书已经与系统身份合并，只在聊天、附件、任务和导航回执中出现，不再在团队栏重复一张卡。成员姓名下方显示真实状态：空闲、排队中、后台工作中、需要处理或离线。只有任务、分配成员和Worker心跳同时吻合时才显示“后台工作中”；点击成员可查看职责、边界、交付物、模型来源和工作证据。
- 顶栏齿轮按钮是“界面设置”。可以在浅绿、米白、雾蓝、夜间四种底色间切换，并选择小、标准、大、特大四档字体；设置只保存在本机浏览器中，点击“恢复默认”会回到浅绿和标准字号。
- 桌面顶栏中间显示当前书名、创作状态、卷数、章数和正史修订号；它只用于确认当前书籍和进度，不是第二套功能导航。

## 阅读与资料

- “正文”页会自动打开当前可见的第一章并优先读取当前版本。章节尚无正文时，可以直接输入或粘贴内容并保存第一份草稿；每次保存都创建新的完整版本，旧稿不会被覆盖。保存出真实版本后才能使用“重写”和“定稿”；“重写”交给真实主笔任务，“定稿”先经过硬检查、三异模型点评和老板确认，确认后才进入正史。已定稿正文只读。
- 中间内容区不再重复显示功能标题或第二条书籍摘要，打开功能后直接占满主区。桌面工作台固定为一屏，浏览器页面不会随正文或聊天不断向下延长；需要回看时在中间内容区或左右栏内部滚动。
- 顶栏的展开按钮进入沉浸阅读，左右区域会完全收起。
- “规划”显示本书资料、设定大纲、剧情总纲和章纲，不再重复显示章节目录，也不再提供独立卷纲。题材、角色和作者确认的开书信息归入本书资料；设定大纲维护世界观、力量/资源体系、装备等级、经济规则、属性字段和安全属性公式；剧情总纲按连续章节阶段规划全书；章纲只细化未来1—3章并引用相关总纲阶段。
- “图谱”只集中展示人物关系、情绪、钩子/伏笔和信息差；主线请在“规划→剧情总纲”的阶段卡中查看，支线请在当前创作会话、章纲和开放线程中查看。“资料库”保存实体、事实、标签和缺口，并提供“来源与证据”：按人物或资料对象查看已去重的中文事实、来源章、证据等级、权威状态和简短依据，不会显示内部代码或原始JSON。资料库的“主角”页不使用固定模板，只按这本书实际出现的身份、能力、资源或任何自定义资料动态分组；带结构化正史证据的变化会在章节结算后自动建档/更新，无法归类的项目会显示“待归类”并请您确认。
- 手机和平板使用左、右抽屉，不会把桌面三栏强行压缩到小屏幕。
- 桌面左右栏约为176像素和190像素，中间对话、创作和正文区会优先占用剩余空间。

## 离线与安装

浏览器支持把文秘写作安装为PWA。已经打开过的正文和知识快照可以离线查看，输入框草稿保存在本机IndexedDB中。离线时不会生成模型结果，也不会声称已经完成联网研究。正史修订变化后，旧快照会自动失效。

## 模型与费用

运行时可以使用Codex登录态与火山方舟Coding Plan/Agent Plan套餐模型，现金按量付费回退关闭；缺少套餐凭证时使用明确标注的确定性假模型。可在设置的模型配置页先预览独立性与能力，再激活只影响未来任务的新修订。真实API Key只允许从环境变量读取；代码、数据库、日志、上下文、备份和Git都不会保存密钥。

## 数据与恢复边界

所有运行数据保存在 `D:\wenmixiezuo\data`。备份包含数据库、正文历史、正史、任务、预算、调用和墓碑，并通过清单与哈希验证。当前没有配置第二物理备份位置，因此能够验证本机恢复，但不能防止整块本机硬盘损坏。

普通删除只归档。需要彻底删除时，先展开左侧“已归档”，点击目标书旁的垃圾桶，在影响提示下输入 `YES`，再点击“彻底删除”。小写 `yes` 和首尾空格也会被规范化接受；其他文字和活动书仍不能删除。彻底删除会清理本书全部数据并留下防复活墓碑，不可恢复。

## 常见问题

- 显示“服务不可用”：先双击停止入口，再重新启动；仍失败时查看 `data\logs` 中最新的 `desktop-*.err.log`。
- 提示端口占用：`43110` 或 `43111` 已被其他程序使用。启动器会停止而不会结束占用端口的其他程序。
- Worker显示离线：停止后重新启动。系统不会把过期心跳伪装成工作中。
- 发送消息后暂未看到主编文字：返回书架并点击首页左侧“任务”，在对应书籍分组查看任务是否仍为“后台工作中”。真实GPT-5.6 Sol实机回复可能需要约1至3分钟；若任务明确失败，可在任务详情重试，不会自动切到按量付费模型。
- 未看到近期热门结论：这是正常的离线诚实边界。只有明确授权联网研究并保存来源证据后，结果才会作为候选出现。
