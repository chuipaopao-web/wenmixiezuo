## 1. 目标与非目标

目标是解决两个同时存在的问题：普通团队页需要让作者快速理解岗位，老板又需要核对后端真实使用的完整稳定岗位提示词；后续商用时不能把完整提示词直接暴露给普通访问者。

本次不修改任何岗位提示词、模型绑定、动态任务指令、检索资料包、工具权限、模型调用、正史或正文，也不建立互联网账号体系。它只增加只读可见性门禁。

## 2. 事实、偏好、推断与未知

- 已确认事实：此前前端展示的是由岗位合同拼装的公开说明，不是运行时提示构建器的完整结果；完整提示若放进普通团队接口，任何访问页面的人都能读取。
- 老板偏好：默认只看简短岗位表达；完整内容需密码查看，避免上线后被直接复制。
- 工程推断：密码若只由前端比较等同于没有保护；必须由API服务端验证并让普通接口根本不返回完整内容。
- 未知：未来商用部署的用户、租户和管理员模型尚未冻结，因此本地共享密码只能是当前门禁，不能冒充最终互联网鉴权。

## 3. 方案比较

| 方案 | 优点 | 缺陷 | 结论 |
|---|---|---|---|
| 前端折叠或遮罩完整提示 | 实现最少 | 浏览器已经拿到明文，任何人都能从网络响应读取 | 拒绝 |
| 把提示加密后随页面下发 | 看似隐藏 | 解密逻辑和密钥仍需到浏览器，不能形成真实边界 | 拒绝 |
| 服务端环境变量密码门禁 | 本地部署简单，普通响应无明文，可测试限流与缓存 | 不具备多用户权限和审计 | 当前采用 |
| 完整账号、管理员权限和密钥托管 | 适合互联网商用 | 当前本地单用户版改动过大，属于后续重大架构 | 商用前必须追加 |

## 4. 数据流与安全边界

普通团队端点只返回 `roleStatement`。受保护端点接收密码和岗位标识，服务端先校验环境变量密码，再校验岗位以及可选的书籍—成员—岗位绑定，最后直接调用运行时提示构建器生成稳定提示变体。响应使用 `no-store`，密码不写数据库、日志、URL、浏览器存储、导出或备份。

可查看内容只包含稳定岗位系统提示；明确排除本书补充要求、任务指令、检索结果、附件摘录、工具参数、密钥、登录态、模型响应和思维链。查看行为不改变模型实际输入。

失败限流采用单进程内存窗口，避免产生新的密码或个人信息持久记录。API重启会清空失败计数，这是本地门禁的有意取舍；未来商用需由认证与审计基础设施替代。

## 5. 两轮审查

第一轮从泄漏路径反查：普通端点不得含完整提示；错误密码、未配置密码和连续错误必须拒绝；查看响应不得缓存；本书详情请求必须验证书籍、成员和岗位一致；启动器不得把密码传给Web或Worker。

第二轮从过度暴露和产品质量反查：不能因为老板可查看就返回动态资料包、工具隐藏规则或思维链；不能把公开岗位表达删到作者无法理解；不能修改运行时提示或把查看文本再注入模型。本功能不改变创作上下文，因此不要求文学盲评，但必须证明模型调用路径和提示构建结果没有被改写。

## 6. 指标、停止条件与回滚

- 普通团队端点完整提示泄漏数必须为0。
- 正确密码可以读取所有11个岗位的实际稳定提示变体；错误、未配置、限流和身份错配路径全部有自动测试。
- 密码在数据库、日志、导出、备份、URL和Git中的出现数必须为0；环境变量名称和测试专用假值不计。
- 一旦出现公开泄漏、跨书读取、密码落盘、动态上下文泄漏或查看行为改变模型输入，立即停止发布。
- 回滚只移除受保护端点和前端查看器，保留简短岗位表达；无数据库迁移和业务数据回滚。

## 7. 商用上线前置条件

对外开放前必须增加真实登录、管理员角色、会话过期、HTTPS、服务端审计、秘密托管和更强的暴力破解防护。未满足这些条件时，该入口只适用于老板控制的本机部署。
