# 文秘写作长篇创作质量当前审计

## 1. 明确结论与置信度

结论：文秘写作已经具备长篇创作控制系统的部分正确基础，但当前不能证明混合RAG有效，也不能证明几十章后的叙事质量稳定。当前系统工程基础总体为E2；真实长篇质量证据处于E0—E1，尚未达到E3或E4。

置信度：高。判断来自当前规格、真实检索代码、上下文包代码、集成测试和发布验收声明的交叉核对。

## 2. 当前事实基线

已确认事实：

- 存在正史事实、不可变正文版本、八层记忆、章节结算、上下文包、任务恢复和跨书隔离机制。
- 存在自然讨论、写作准备门禁、分层规划、异模型审校和定点重写流程。
- 当前 `RetrievalService` 使用SQLite FTS/BM25和20组固定同义词扩展，没有真实向量召回、实体链接、关系遍历、融合重排或语义嵌入。
- 当前所谓语义Recall测试直接使用检索器同一组固定同义词作为测试对，属于同源构造测试。
- 当前百万字符测试把100个硬锚点集中放在同一个前缀和同一条记录中，只证明精确词可以命中该记录。
- 当前发布验收要求连续生成5章，只能证明短流程和状态机运行，不足以外推长期人物、节奏、伏笔和文风稳定。
- 确定性适配器可以验证流程，不代表真实模型文学质量。

未知项：真实订阅模型在20章连续创作下的缺陷密度、上下文位置敏感性、不同检索通道消融收益和人工盲评结果。

## 4. 最强替代方案与取舍

推荐方案：保留现有SQLite正式源、正史和任务基础，在 `RetrievalProvider` 后增加本地嵌入式混合RAG投影，组合结构化事实、FTS/BM25、向量、Wiki关系、时间过滤、融合重排和原文回查；同时建立岗位专用上下文和纵向质量评测。

替代方案一：只扩大模型上下文。实现简单，但注意力稀释、位置敏感、Token和证据追溯问题仍存在，不推荐。

替代方案二：只增加向量库。可改善语义召回，但不能可靠处理精确状态、时间、否定、多跳和正史权威，不足以单独承担长篇记忆。

维持现状：可以继续作为流程演示和确定性测试基础，但必须停止使用“语义RAG已达标”和“长篇质量已完成”的表述。

取舍：混合RAG和纵向评测增加实现复杂度、索引重建、Token、延迟和测试成本，因此必须分子系统实施并通过消融证明收益。

## 5. 预先验尸与反例

假设推荐方案失败，最可能路径是：

1. 向量命中高相似但时间错误的片段，重排没有把正史有效期置于相似度之前。
2. Wiki编译遗漏人物谎言或有限视角，主笔把派生结论当客观事实。
3. 关系扩展返回过多邻居，真正证据被长上下文淹没。
4. 所有岗位使用同一个融合结果，岗位差异只剩提示词角色扮演。
5. 指标针对固定金标优化，真实章节盲评没有改善。
6. 作者长期选择同一套路，系统把采纳率误当质量并逐渐迎合。

最强反例：即使混合RAG完全召回了正确资料，基础模型仍可能写出平庸、机械或缺乏审美价值的正文。因此检索正确只能减少事实和上下文问题，不能单独证明小说写得好。

## 6. 修正后的最终设计

1. 保留正式源、临时源、候选源、派生Wiki和索引的权威分层。
2. 建立查询理解、硬过滤、多路召回、冲突检测、融合重排和原文回查流水线。
3. 为主编、编剧、设定师、主笔和审校分别定义上下文合同和Token预算。
4. 将总纲、卷纲、章纲和场景契约做成动态分层计划，并在正史变化后传播失效。
5. 增加人物声音、承诺—兑现、节奏、重复、伏笔债务和章纲偏离投影。
6. 保持异模型审校与确定性硬检查，连续失败时返回上游规划而非无限润色。
7. 将作者偏好分级，保留有证据异议，禁止以采纳率训练迎合。
8. 用E0—E4证据等级控制验收用词，不修改历史发布证据，只登记当前能力纠正。

## 7. 测试与证据等级

- E0：长篇质量目标、混合RAG和纵向评测规格。
- E1：当前正史、任务、上下文、规划和审校代码存在。
- E2：现有集成、隔离、恢复、结算和固定同义词构造测试通过。
- E3：尚缺独立200章/百万字金标、混合检索消融、位置敏感、故障注入和长规模回放。
- E4：尚缺真实订阅模型20章连续创作、跨章盲评和老板验收。

安装Skill后先拆分四个业务计划：混合RAG、岗位上下文、动态规划与纵向质量评测。每个计划单独完成类型、测试、构建、迁移、运行、恢复和隔离验证。

## 8. 剩余风险与未知项

- 混合检索可能增加延迟和噪声，融合权重需要按题材和岗位校准。
- 本地向量实现的模型、维度、更新策略和本机资源尚未选型。
- 关系图与Wiki编译可能丢失含蓄、讽刺、谎言和不可靠叙述。
- 二十章仍不能代表百万字，只能提高指定范围内的置信度。
- 人工盲评受题材和评审偏好影响，需要记录分歧和评审目标。
- 基础模型能力仍是上限，系统只能减少可控制的失败。

## 9. 停止、回滚和升级条件

- 停止：证据不足会污染正史；硬上下文超预算；索引结果冲突无法裁决；真实模型通道结果不明。
- 回滚：所有向量、Wiki和关系索引必须可删除并从正式源重建，不能影响正文和正史。
- 升级：选择需要独立服务、现金费用或不可逆数据迁移的实现前，提交重大架构和费用决定。
- 完成门槛：只有E3系统证据与E4创作证据同时满足，才允许在明确评测范围内报告长篇质量改善。
