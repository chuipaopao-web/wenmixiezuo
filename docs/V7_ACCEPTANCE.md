## 4. 第一条完整纵向闭环

### 4.1 开书

- [ ] 4.1.1 只选择题材即可请求 3 个实质不同的开书方向。
- [ ] 4.1.2 一句话方向、已有片段和作者补充均为可选，不形成填表门槛。
- [ ] 4.1.3 作者可以选择、编辑、补充、换一批和确认。
- [ ] 4.1.4 确认生成版本化开书简报；候选不进入正式下游。

### 4.2 第一卷方向

- [ ] 4.2.1 AI 基于开书简报和正式设定生成少量白话卷方向。
- [ ] 4.2.2 方案在冲突、人物选择、代价、卷末状态或阅读感受上有实质差异。
- [ ] 4.2.3 作者可以整选、片选、融合、编辑、重做和确认。
- [ ] 4.2.4 卷方向只冻结宏观责任，不提前冻结全部事件和章节。

### 4.3 当前事件

- [ ] 4.3.1 后台建立轻量事件骨架，前端默认收起显示事件名和因果。
- [ ] 4.3.2 作者无需逐项确认未来事件即可进入当前事件。
- [ ] 4.3.3 当前事件从上一实际结算开始，形成目标、阻力、代价、新状态和下一问题。
- [ ] 4.3.4 事件角色和节奏以白话决定呈现，不暴露内部模板名。

### 4.4 当前章纲与正文

- [ ] 4.4.1 生成轻量完整章链，只含每章一句责任和因果。
- [ ] 4.4.2 详细章纲只生成当前章和未来最多 2 章。
- [ ] 4.4.3 作者确认或编辑当前章纲后才能生成正文。
- [ ] 4.4.4 默认一名主笔；追加主笔后独立出稿，不自动拼接。
- [ ] 4.4.5 作者可以选择正文底稿、直接编辑或要求定向修改。

### 4.5 审查、定稿和结算

- [ ] 4.5.1 事实、文学、体验三席独立输出，默认每席一名，可追加。
- [ ] 4.5.2 事实硬冲突必须解决；文学和体验建议可采纳或忽略。
- [ ] 4.5.3 默认不自动二次审查，作者主动点击才再次检查。
- [ ] 4.5.4 作者确认形成不可变正文新版本。
- [ ] 4.5.5 章节结算只读取作者定稿正文，写入实际事实、关系、资源、伏笔和开放问题变化。
- [ ] 4.5.6 下一章重新编译资料包并校准未来章链，不覆盖历史章纲和正文。

## 5. 故事雷达

- [ ] 5.1 开书时故事雷达不成为门槛。
- [ ] 5.2 章节结算后后台可以记录候选线路，但候选不冒充正式事实。
- [ ] 5.3 第一个事件完成后首次主动展示故事雷达摘要。
- [ ] 5.4 事件/卷结算提示确认、继续观察或忽略；作者可以直接继续写。
- [ ] 5.5 作者可查看和手动添加线路、关系、伏笔与开放问题。
- [ ] 5.6 故事雷达能区分正文实际、作者规划、开放问题和 AI 候选。
- [ ] 5.7 切换书籍后雷达内容完全隔离。

## 6. ContextPack 与长期连续性

- [ ] 6.1 定义 V7 每个节点允许读取的正式对象、版本、字段和预算。
- [ ] 6.2 当前任务只使用当前用户、书籍、活动版本、上一实际结果和必要上游责任。
- [ ] 6.3 作者硬要求、正式事实、规划、开放问题和候选分区明确。
- [ ] 6.4 其他书、过期候选、独立灵感、密钥、思维链和无关全文不得进入资料包。

- [ ] 6.7 章节、事件、卷结算能够逐层写回真实变化并被后续任务读取。
