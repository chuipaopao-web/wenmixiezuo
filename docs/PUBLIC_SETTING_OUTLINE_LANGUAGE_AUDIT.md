## 痛点—根因—机制

| 项目 | 结论 |
|---|---|
| 痛点 | 前端已经使用“设定大纲”，副编仍讨论“故事圣经”，并显示英文键、来源编号和空决定字段。 |
| 症状 | 模型把可修订规划说成正史冲突；作者可展开消息暴露内部追溯脚手架。 |
| 已确认根因 | 开放回复资料包直接传入原始Artifact JSON、内部来源类型/编号、空决定数组和上下文哈希；输出层没有当前产品术语投影。 |
| 机制 | 内部ContextPack继续保留完整审计来源；模型只接收中文资料名、用途和自然摘要；输出与历史读取统一做确定性作者投影。 |
| 反例 | 只在前端替换“故事圣经”会保留模型的错误正史判断；直接删除全部依据会损害可解释性和创作判断。 |
| 指标 | 模型提示不含内部类型、字段、编号或校验值；回复保留结论、依据、风险、问题和下一步；历史消息刷新后同样生效。 |
| 证据等级 | E2工程证据；不外推真实模型推理或文学质量。 |
| 停止条件 | 清洗误删创作内容、上下文审计断链、规划被写成正史或迁移发生同名冲突。 |

## 事实、推断、偏好与未知项

- 事实：当前书真实消息中出现了 `故事圣经`、内部字段名、来源编号和空决定字段；对应模型资料包确实包含这些内容。
- 推断：模型的旧术语和错误正史判断主要由资料包诱导，而不是副编岗位自主产生。
- 老板偏好：作者界面不存在“故事圣经”，成员应使用当前产品名称，回复只保留有效信息。
- 未知项：不同远程模型是否会自行发明新的技术表达；通过输出合同与作者投影兜底，但不能据一次修复声称彻底消除所有模型措辞问题。

## 替代方案

1. 只在React显示层替词：拒绝。模型仍会基于错误权威理解继续推理。
2. 物理重命名全部数据库类型和字段：拒绝。会扩大兼容、迁移和恢复风险，且没有业务收益。
3. 保留内部稳定类型和存储标题，隔离模型/作者表示：采用。审计完整、可回滚，且直接修复根因。

## 两轮审查

### 第一轮：正确性与安全

- 内部来源、版本、消息和模型结果不删除、不覆盖。
- 空决定不注入；规划参考不冒充正史；模型提示不暴露内部字段。
- 历史消息按读取投影转换，原始记录保持不变，跨书查询仍显式携带隔离键。

### 第二轮：创造性与输出质量

- 不增加剧情硬规则，不改变双编剧、主笔、三点评或检索召回。
- 不删除成员的结论、依据、风险、未知项、问题或替代方案，只处理技术脚手架和过期产品术语。
- 设定大纲被明确为可修订规划参考，降低旧规划错误锚定，保留老板新说明和创作偏离空间。

## 回滚

- Git恢复资料包和作者投影代码。
- 内部Artifact类型与存储标题没有迁移，不需要数据回滚。
- 原始上下文包、消息、模型调用、Artifact版本和正史数据始终保留，不需要生产数据恢复。
