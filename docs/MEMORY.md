# 上下文、记忆与任务资料规范

## 1. 原则

上下文由确定性 ContextCompiler 按任务编译，不由拟人成员自由访问全库。越往下游越压缩上层信息，但上层硬约束必须完整保留；当前任务对象使用完整版本。其他书、旧聊天、过期版本、无关候选、全文堆叠和无依据猜测始终排除。

## 2. 权威层

1. 作者原始输入与不可变导入原件。
2. 作者确认的开书、设定和活动规划版本。
3. 定稿正文与章节/事件/卷结算形成的正史事实。
4. 摘要、Wiki、图谱、全文和向量投影。

低层不能推翻高层。摘要只导航，事实争议回查正式源。

## 3. 任务上下文矩阵

| 任务 | 必须接收 | 必须排除 |
|---|---|---|
| 开书 | 作者填写的全部开书信息、附件和明确约束 | 其他书、聊天、AI猜测 |
| 设定方案 | 完整开书信息、当前设定项、核心人物/读者承诺/作者禁区、与本项存在直接依赖的已确认设定、作者本项原话；融合额外接收作者选中方案的规则骨架并保留原方案ID回查 | 无关已确认设定、方案的重复解释与未选备选、无关正文、其他书、未确认候选 |
| 分卷 | 无损压缩后的完整开书与设定、上一卷正式结算、当前角色状态、节奏选择、作者卷想法 | 旧卷候选、无关细节、聊天历史 |
| 事件链 | 压缩开书/设定、完整活动卷纲、模板与作者想法 | 其他卷未来猜测、过期卷纲 |
| 事件大纲 | 压缩开书/设定/卷纲、完整事件链和当前事件卡、上一事件结果、作者本事件想法、触发伏笔 | 其他事件草案、无关人物全集 |
| 章纲 | 压缩上层信息、完整事件链、完整当前事件大纲、上一章链状态、作者章纲想法 | 越过当前事件的自由扩写 |
| 章纲挑战 | 与主方案相同的冻结上游、精确目标候选版本和作者本次关注点 | 其他候选、其他事件全文、聊天、审查报告、未摘录灵感；挑战意见不自动进入后续资料包 |
| 正文 | 压缩卷纲、事件链和事件大纲、完整当前章纲、最近正式正文/结算、触发实体与声音证据、作者本章意见 | 全书全文、其他候选、其他书 |
| 事实审查 | 当前正文、冻结上游版本、命中设定/事实/时间/伏笔原文 | 文学和体验报告 |
| 文学审查 | 当前完整正文、章纲、表达基线、必要相邻正文 | 事实席或体验席报告 |
| 体验审查 | 当前完整正文、目标读者、章纲目标、必要前章 | 其他审查报告 |
| 结算 | 定稿正文、冻结章纲、已有正史、当前事件/卷目标 | 草稿和未确认建议 |

## 4. 压缩规则

压缩不是删掉上层规则。必须保留：身份、目标、因果、时间、能力上限、关系、禁区、未回收伏笔、卷目标、当前事件结果和作者必须项。可压缩：重复解释、已回收低优先细节、无关场景描写和未采用候选。

每份压缩物保存来源列表、版本、内容哈希、生成策略和可回查位置。长度由任务预算和证据密度决定，不使用固定“最近5章后遗忘”规则。

资料包去重分两层执行。完全相同的内容只保留一份；某个活动章纲、前章正文或其他权威对象已经以完整版本进入硬来源时，同一对象、同一版本的尾段、摘要和检索切片不再重复注入。只有切片包含完整来源没有覆盖的独立内容，或完整来源根本未进入资料包时，才保留该切片。所有排除项继续记录来源、版本和排除理由，去重不能变成静默丢证据。

## 5. 检索触发

实体、别名、规则、物品、地点、时间、因果、伏笔、人物声音或冲突信号出现时，先结构化直达，再结合FTS、向量、关系和时间过滤。高风险事实至少回查一段正式原文。低相关结果不因相似度分数高就自动注入。

## 6. 写入与结算

模型输出默认是候选。只有作者确认资料和定稿正文结算可以更新正式状态。章节结算按正文实际内容检查人物、势力、地点、道具/资源、规则、事件、人物变化、关系、时间、伏笔和摘要；存在且对后续有价值时追加，不存在时保持空结果，不为分类覆盖编造。事件/卷结算聚合实际结果并记录计划偏差。投影异步重建，失败不能污染正式源。

## 7. 续写

导入全文保存在不可变原件和章节版本中。反向拆解结果带来源，仅作为待确认派生资料。续写任务按实体和当前目标回查旧文，不把整本全文塞入每次模型调用。

## 8. 验收

上下文测试至少覆盖跨书隔离、版本失效、硬约束位置、长输入预算、对抗检索、来源回查、摘要消融、同源全文覆盖切片、只有切片时不误删独立证据、人物声音和连续多章漂移。召回提高不能以原创性、人物可辨识度或整体阅读质量下降为代价。
## 9. 题材无关的资料沉淀

事实审查和章节结算不得依赖某一本样稿的人名、道具或题材关键词。每个题材都按当前正文实际出现的实体、行动、关系、时间、状态和规则生成候选；没有持久事实时返回空候选并说明原因，不能补造。

进入正式资料的候选必须同时满足：

1. 绑定当前书、来源章节和不可变定稿正文版本；
2. 证据原句能在该正文中逐字回查，不能使用模型摘要代替；
3. 实体、关系目标、时间和知情状态在当前书内可解析；
4. 章节结算或带来源的作者修订明确激活，未确认候选不进入正史；
5. 图谱、时间线、人物状态和检索投影能删除重建，不能反向修改正文。

历史章节需要补建结构化资料时，不修改原正文、旧结算或旧正史修订；先在数据库副本验证来源和幂等，再创建可追溯的纠错修订，重建投影并完成跨书检查。

验收不能只数全文切片、实体总数或情绪投影；还要分别检查主角状态与历史、配角、势力、地点、世界路线图、道具/资源、生效规则、聚合事件时间线、正式事实、人物关系、来源回查和作者界面的自然语言显示。设定来源不得重复冒充分类正式资料；人物每章出现不得冒充事件。类型档案要验证字段与来源的语义匹配：配角年龄/性格/门派/装备、势力规模/实力/驻地、道具属性/归属、地图节点/路线和时间线的时间/章节都只能来自本书权威源。某分类确有证据却显示空白，或没有证据却被猜测填充，均视为资料沉淀或展示适配失败。
