# 设定候选不满意分流审查

- `design_review_id`：`DR-20260803-setting-dissatisfaction-routing-v1`
- 适用Skill：`wenmi-longform-quality`（2026-08-03读取）
- 目标：避免主编把“不满意”继续变成问题清单，同时保留作者否决和改向权。

## 事实与根因

- 旧实现只有 `ask/collect/revise`，任何候选后的作者消息都进入同一个 `revise`。
- 任务资料包没有旧候选、反馈类型或连续不满意轮次，主编只能临场猜测“改一点”还是“全部推翻”。
- 这会导致反问原因、重复改写、重开方向树或误删作者认可部分。

## 机制与反例

- 调用模型前分类为局部修订、泛化不满意、完全换向，并注入上一候选。
- 泛化不满意第1轮直接改善，第2轮换结构，第3轮起才允许一个关键问题；任何轮次都先给推荐。
- “悬疑太重，救赎感加强”不能被当成泛化不满意；“完全推翻这个方向”不能只做同义改写；“不满意”不能立刻变成问卷。
- 轮次只读取同书同设定项的历史任务，不跨书、不跨设定项。

## 两轮审查

1. 防漏审：检查旧候选进入资料包、三类反馈互斥、轮次按同项任务计算、候选确认门禁不变。
2. 防过度约束：系统只规定收敛方式，不规定小说结论；局部反馈保留有效内容，明确换向仍允许真正不同的创意，连续失败后保留一个诊断问题出口。

## 指标、证据和停止条件

- E2目标：任务资料包反馈类型正确；前两次泛化不满意不出现原因盘问；明确修改不被错误重开；跨书/跨项轮次隔离。
- 当前不声称真实模型文学质量已达到E3/E4。若真实多样本显示新候选趋同、作者控制权下降或具体修改被忽略，停止推广并回滚反馈提示，保留全部历史数据。
