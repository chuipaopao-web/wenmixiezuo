# 归档书删除与同名书限制开发验收清单

## 变更合同

- 任务类型：生产 BUG 修复 + 局部创建规则调整。
- 当前问题：同一作者的两本归档书永久删除均失败；当前允许同一作者创建同名书。
- 复现步骤：归档目标书，完成影响预览、输入 `YES` 并二次确认；服务端在提交删除事务时返回失败。再用同一账号创建相同书名，当前可成功。
- 期望结果：两本归档书均能走完原有安全确认后原子删除；同一作者不能再创建同名书，不同作者仍可使用相同书名。
- 允许修改：书籍生命周期、书籍仓储、永久删除仓储、直接相关测试，以及 API/数据模型说明。
- 明确不改：归档/恢复入口和布局、永久删除影响预览与两次确认、开书表单布局、创作主流程、正文/结算/历史版本、AI 岗位/模型/提示词/资料包、其他页面与全局样式。
- 必须保留：`owner_id + book_id` 隔离；永久删除仅允许归档书；`YES` 与二次确认；失败事务全量回滚；墓碑；不同作者可同名；现有同名书不改名、不合并、不自动删除。
- 新功能验收：同一作者的活动书或归档书与新书标准化书名相同时返回明确冲突；不同作者同名成功；永久删除全部同名旧书后允许再次使用该名称。
- 原功能回归：开书原子性、改名版本控制、归档、恢复、墓碑、跨书隔离、永久删除失败回滚和已有作者数据读取均通过。
- 测试范围：直接集成测试、API 类型检查/构建、生产数据库内存副本删除模拟、线上登录与目标交互。未触发数据库迁移、权限、跨服务恢复或核心创作工作流结构变化，因此不运行 `verify:full`。
- 部署要求：API 变更按生产发布门禁执行；不得替作者实际删除书籍；发布后只验证闭环可用性和错误提示。
