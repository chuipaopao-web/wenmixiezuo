# 章纲阶段闭环边界审查

- `design_review_id`：`DR-20260802-chapter-stage-boundary-v1`
- `release_id`：`wm-longform-r1-20260719-003435-e4d7b8b7`
- 适用决定：DEC-086、DEC-087
- 适用Skill：`wenmi-longform-quality`（本次施工前完整读取；文件快照沿用当前工作区版本）

## 痛点与故障基线

真实十章流程中，已确认剧情总纲要求第1—10章完成阶段主事件并形成明确结果，但旧章纲流水线只校验章号、长度和结构。模型可以在第10章继续写“证据未闭合、身份不得恢复”，技术流水线仍判定成功，导致总纲、章纲和正文边界互相冲突。

## 根因

- 总纲阶段结构只作为自然语言上下文，没有成为章纲保存前的结构化权威。
- 章纲只携带可自由生成的 `sourceStage`，没有阶段终章闭环字段。
- 主笔资料包不知道当前章是否必须结算阶段，容易把悬念保留误写成主事件未解决。

## 采用机制

1. 从当前已确认 `stage_master_v2` 提取阶段边界合同，不读取未确认候选。
2. 所有章纲校验所属阶段编号、名称和章节范围。
3. 阶段结束章必须带 `stageBoundary`，精确承接解决方式、结果和允许保留的未决线索。
4. 确定性代码拒绝错误引用、结果偏移、额外未决线索和明显反闭环措辞。
5. 主笔编译包明确阶段终章硬要求；局部写法继续属于创造性自由区。

## 未采用方案

- 仅依赖提示词：模型仍可能生成结构正确但语义相反的章纲，不能形成工程门禁。
- 在正文完成后才检查：会浪费主笔和三席调用，并把上游规划错误扩散到正文。
- 要求每章闭环阶段：会破坏连续剧情、过度约束悬念与人物发展。
- 模糊相似度判断结果：阶段结果是已确认结构化规划，应使用精确来源与集合校验，不需要向量猜测。

## 两轮审查

第一轮针对一致性与恢复：错误阶段、错误章节范围、错误结果、缺失闭环、额外未决线索和反闭环措辞必须被拒绝；旧章纲缺少可选字段仍可读取，非终章不被误拦。

第二轮针对创造性非劣效：门禁只固定阶段必须完成的主事件与结果，不固定句式、对白、意象、场景调度、情绪细节或局部惊喜；允许总纲明确保留的伏笔继续存在，避免为了形式闭环清空未来张力。

## 指标、证据与停止条件

- 单元/集成：阶段终章反例被拒绝，合格闭环通过；章纲解析、讨论恢复和规划Artifact回归通过。
- 真实流程：同一测试书完成开书、类型自适应设定、当前阶段总纲、10份章纲、10章正式正文、定稿与阶段结算；第10章章纲和正文必须与总纲结果一致。
- 停止条件：非终章被误判、总纲允许的伏笔被清空、阶段结果仍可漂移、修复器代填创作内容，或正文多样性/人物生命力相对旧合同明显下降。
- 证据等级：当前最多E2。一次十章流程只能证明工程链与短流程语义边界，不能证明500万字长篇质量。
