# 剧情总纲逐阶段规划审查

- `design_review_id`：`DR-20260801-incremental-stage-master-v1`
- release：`wm-longform-r1-20260719-003435-e4d7b8b7`
- 适用Skill：`wenmi-longform-quality`、`writing-plans`、`systematic-debugging`
- 证据上限：E2工程证据

## 问题与根因

旧解析器和模型提示强制首次总纲至少包含两个阶段，导致团队在当前事件尚未写完时提前规划远期细节。症状是规划负荷过大、后续阶段容易建立在未验证前提上，并与老板确认的“完成一段再规划下一段”流程冲突。根因不是模型能力不足，而是结构校验和提示合同把多阶段当成最低合法输出。

## 机制与替代方案

采用单阶段递增：第一次只生成一个有起承转合和明确结算点的阶段，最多50章；阶段正文完成并结算后，才创建新总纲版本追加下一阶段。保留全书前提、核心冲突、成长和结局方向作为软锚点，避免完全失去远期方向。

未采用一次规划全书，因为远期细节会放大注意力和错误锚定；也未删除总纲层，因为只靠章纲会失去事件级因果与结算边界。

## 两轮审查

第一轮检查结构完整性：单阶段可解析；空阶段、超过50章、编号不连续、范围重叠或留空仍拒绝；既有多阶段历史版本继续可读。

第二轮检查创造性与注意力：章节范围只是预计，不要求填满；起承转合约束阶段因果，不把每章压成公式；远期锚点不自动展开成后续剧情；章纲仍只滚动准备未来1—3章。

## 指标、停止与回滚

- 指标：首次总纲恰有一个完整阶段；单阶段不超过50章；第1—10章测试阶段可在一个事件内闭环；主笔上下文不增加远期阶段全文。
- 停止条件：单阶段造成全书承诺丢失、追加阶段覆盖既有阶段、章节范围断裂，或模型仍提前生成后续阶段。
- 回滚：只回滚解析下限和提示合同；不可删除已生成的总纲、章纲、正文、来源或调用证据。
