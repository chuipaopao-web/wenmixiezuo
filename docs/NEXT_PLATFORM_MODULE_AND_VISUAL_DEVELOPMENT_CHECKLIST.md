## 1. 交付规则和逐项状态协议

### 1.1 每项完成定义

每一个编号只能按以下顺序变更，不能把“写了代码”直接勾成完成：

1. 实现：代码、数据、文案和设计稿已经落地；

3. 测试：自动化、浏览器、视觉或真实模型验证按风险完成；
4. 清理：被替代入口、代码、样式、测试和文档已清除；
5. 勾选：证据链接登记后才把 `[ ]` 改为 `[x]`。

## 2. 全站视觉合同：只能持平或提升

### 2.1 双基准制度

新版同时接受两套基准约束：

- **旧版质量基线**：字体质感、阅读舒适度、色彩克制、排版密度、留白、按钮完成度和整体高级感不得低于旧版；
- **新功能内容基准**：新增语义、状态和交互必须与登记内容参考一致，但必须嵌入原功能板块；参考图不具有改变页面布局的权力。

- [x] 2.1.1 未改造的稳定区域与旧版基线进行像素比对，稳定区域相似度达到 `95%`。
- [x] 2.1.2 已改造区域的外部几何、板块位置和内容顺序相对旧版达到 `95%`；新增内容只在原板块内部比对状态参考，有意差异单独遮罩并写明原因。
- [x] 2.1.3 每页同时出旧版、内容参考图、新版三联图；几何以旧版为准，新增状态以参考图为准，不用单张新版截图自证美观。
- [x] 2.1.4 功能自动化全部通过但视觉合同不通过时，本页仍判定失败。
- [x] 2.1.5 老板反馈“比原来难看、空、挤、薄或廉价”时，直接回到设计/样式修正，不用功能完成度抵扣。

### 2.2 字体与可读性

- [x] 2.2.1 恢复并统一旧版正文、控件、导航的无衬线中文字体栈；品牌字和少量大标题才允许使用衬线字体。
- [x] 2.2.2 桌面正文和主要控件为 `14–16px`，辅助文字不得小于 `12px`，禁止 `8–11px` 承载功能信息。

- [x] 2.3.1 原版内容区宽度、左右呼吸感、对齐线和段落节奏作为最低基准；新版只为真实功能需要调整。

## 5. 滚动生长的故事线

### 5.1 产品规则

- [x] 5.1.1 全书故事线和全书结局永远不是开书前置必填项，作者可以零故事线直接设计第一卷。
- [x] 5.1.2 作者可以只确认目前想到的阶段，例如“第十卷完成宗门复仇”，而全书结局和其他故事线继续留空。
- [x] 5.1.3 系统允许第一卷、第二卷甚至更久只有半条故事线；“不知道”是合法状态，不显示为缺陷或待办警告。
- [x] 5.1.4 故事线随正文和卷结算增长，正文事实优先；规划描述未来，结算只记录实际发生，两者永远分开。
- [x] 5.1.5 主编只推荐下一段看得见的范围，默认下一卷至未来两卷；证据不足时允许建议“继续观察”。
- [x] 5.1.6 已经有完整想法的作者可以直接录入一条或多条全书故事线，由 AI 补全表达和检查衔接，但仍由作者逐项确认。
- [x] 5.1.7 只有开局灵感的作者可以跳过故事线；系统不得在第一卷或第二卷结束时设置“必须形成全书故事线”的硬触发点。
- [x] 5.1.8 作者可在任意事件或卷后主动提炼、延长或新建故事线；系统提醒只作为非阻塞建议，作者可以延后处理并继续写作。

### 5.2 五区故事线地图

- [x] 5.2.1 “已经发生”只读展示正文和结算确认事实，可追溯到卷/事件/章节证据。
- [x] 5.2.2 “正在推进”展示活跃故事线的真实现状、最近推进、当前压力和最后证据。
- [x] 5.2.3 “我目前想到这里”只保存作者明确确认的最远节点，不要求结局。
- [x] 5.2.4 “主编推荐下一段”展示 2–3 个真正不同的候选方向或“继续观察”，不自动生效。
- [x] 5.2.5 “还没决定”保存开放问题、未知结局和待观察矛盾，不被系统擅自补齐。
- [x] 5.2.6 五区使用不同来源标签和视觉层级，作者确认、正文事实与 AI 猜测不得混淆。

### 5.3 卷结算后的提炼

- [x] 5.3.1 卷结算确定性更新与事件/章节显式关联的现有故事线实际进度。
- [x] 5.3.2 系统从正文发现跨事件持续推进的矛盾、关系或目标时，只生成“潜在线路候选”。
- [x] 5.3.3 候选必须列出正文证据、连续性理由、可能类型、未知点和误判风险。
- [x] 5.3.4 作者确认后才创建正式故事线；拒绝只记录决策，不污染事实库。
- [x] 5.3.5 重试保持幂等，同一卷同一证据不重复推进、不重复建线、不重复扣费。
- [x] 5.3.6 卷结算变化时，受影响候选失效并按新结算重编译；已确认事实通过新版本修订，不原地篡改。

### 5.4 主编推荐下一段

- [x] 5.4.1 每个推荐说明从哪些正文事实自然延伸、主角为什么继续卷入、下一段核心问题和可能推动的已有线。
- [x] 5.4.2 明确哪些是推断、哪些尚未发生、是否可能长出新故事线。
- [x] 5.4.3 方向之间在目标、冲突或代价上真正不同，不做同义改写假装多方案。
- [x] 5.4.4 作者可以选一个、编辑后确认、全部拒绝或选择“继续边写边看”。
- [x] 5.4.5 选择推荐只形成作者规划版本，不冒充正文已经发生，也不自动锁死更远卷。

### 5.5 故事线页面验收

- [x] 5.5.1 零故事线、单条半线、多条活跃线、有阶段终点无全书结局、完全规划型作者五类场景均可继续创作。
- [x] 5.5.2 桌面五区不做五张等权大卡，采用阅读优先的主次布局；相似度和视觉评分通过。
- [x] 5.5.3 手机按当前决策顺序纵向组织，顶部仍只有两排导航，候选证据可展开但不淹没主操作。
- [x] 5.5.4 页面没有固定拓扑选择器、固定四阶段故事线板、全书完整度进度条或强迫补结局的文案。

## 6. 分卷—事件—章节—结算自然衔接

### 6.1 下一卷因果桥

- [x] 6.1.1 每次创建下一卷都明确展示“上卷实际结果 → 新状态 → 未解决压力 → 主角选择 → 本卷目标 → 受影响故事线”。
- [x] 6.1.2 因果桥只读取已确认结算和作者确认规划，不把 AI 候选当作事实。
- [x] 6.1.3 作者可以修改本卷方向而不需要先补全全书路线；修改形成新版本并让依赖候选失效。
- [x] 6.1.4 第一卷没有上卷结算时使用开书蓝图、主角当前处境和已确认设定作为起点。

### 6.2 事件链

- [x] 6.2.1 事件明确服务本卷目标、角色选择和一个或多个故事线，但允许存在只承担节奏/关系功能的事件。
- [x] 6.2.2 当前事件显示前置状态、冲突、人物动机、预期变化和不可越过的已确认事实。
- [x] 6.2.3 事件完成只结算实际写出的结果；未写出的计划自动保留为未发生或失效，不混入事实。
- [x] 6.2.4 事件修改、删除、归档和重新排序不破坏已定稿正文的历史引用。

### 6.3 章链、正文与三席审查

- [x] 6.3.1 章节页同时维持完整章链、近期详细章纲、当前正文、事实/文学/体验三席审查和章节结算的清晰主次。
- [x] 6.3.2 每章只向当前任务提供最小充分 ContextPack，不把全书资料无差别塞入上下文。
- [x] 6.3.3 正文采用不可变完整版本；修改产生新版本，审查和结算固定引用具体版本。
- [x] 6.3.4 单席失败可单独重试或换人，其他成功结果保留；融合时来源可追溯。
- [x] 6.3.5 章节、事件和卷结算依次汇总真实发生，并为滚动故事线提炼提供结构化证据。
