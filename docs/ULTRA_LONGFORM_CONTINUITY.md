# 300—500万字超长篇与Agent长期陪伴设计

## 1. 结论

文秘写作的最终目标按单书500万中文字符、1500章设计，覆盖300至500万字和1000章以上。这个数据量对本地SQLite、不可变正文文件和嵌入式LanceDB并不大，真正困难的是让第1200章仍然使用正确的故事时间、人物状态、承诺、伏笔和作品声音，同时让11名成员在跨月、跨重启和跨卷后仍能接上工作。

推荐方案不是扩大模型上下文，也不是让11个Agent全天运行，而是建立五条相互制约的长期链路：

```text
不可变正史链
＋ 层级知识与原文证据链
＋ 滚动规划与承诺链
＋ 每岗位连续性链
＋ 跨章质量与恢复链
```

系统能工程化降低遗忘、矛盾、检索遗漏、计划漂移和上下文过载，但不能仅靠数据库保证500万字一定好看。技术容量、连续性正确和文学质量必须分别验收。

## 2. 规模口径与容量预算

- 单书技术目标：至少500万中文字符、1500章、11个稳定Agent实例。
- 正文口径：规范化后的中文字符和有效文字字符；不把提示词、标签、向量、Wiki、日志和元数据算作正文。
- 初始切片估算：正文子块约350—700字符，500万字约形成7000—15000个子块；加父场景、设定、规划、Wiki和人物声音后，预计仍是数万块量级。
- 该规模不需要分布式数据库或独立向量服务。SQLite按书索引、不可变文件分层目录和LanceDB按书投影足以承载；最终磁盘、内存、冷启动、重建和P95查询必须在目标电脑实测。
- 设计余量：测试按1500章而不是刚好1000章，避免平均章长、番外和拆章差异让“1000章通过”无法覆盖500万字。

## 3. 五级长期知识

### 3.1 权威原始层

老板确认的正文、故事圣经、总纲、卷纲、章纲、表达基线、设定和正史事实保持不可变版本。它们是唯一可裁决来源，向量、Wiki、摘要和Agent日志都不能推翻它们。

### 3.2 当前状态层

保存人物在指定故事时间的生死、地点、关系、知情、能力、资源、伤势、目标，势力状态，世界规则以及物品归属。状态至少分开世界有效时间、人物/群体知情时间和系统记录/正史修订时间，不用“最新一条”覆盖所有历史时间，也不把客观发生与某人物已经知道合并。

### 3.3 承诺与开放线程层

单独追踪：

- 主线与支线当前阶段；
- 已提出但未兑现的叙事承诺；
- 伏笔的创建、推进、误导、回收和失效；
- 人物未完成目标、关系张力和知情差；
- 老板已决定但尚未落地的方向；
- 少数有依据、尚未裁决的异议。

每项都必须有来源、创建章节、预计窗口、最后推进章节、当前状态和关闭依据，不能只藏在摘要中。

### 3.4 层级派生层

使用场景→章节→故事弧→卷→全书主脊五层派生知识。每层只概括自己的范围并保留来源指针：

- 场景：发生了什么、状态变化、信息变化和读者效果；
- 章节：章目标、关键因果、结算差量和新承诺；
- 故事弧：约20—30章的目标、升级、转折、兑现和未结项；
- 卷：约50—150章的阶段命题、人物变化、主线推进和卷末状态；
- 全书主脊：主题、终局、重大因果、核心关系和全局承诺。

不得每次把整本书重新总结。新章节结算后只合并新增范围，旧层级摘要按正史版本保留；发生正史修订时精确标记受影响节点重建。

### 3.5 检索投影层

SQLite结构化查询处理硬状态和故事时间，FTS5处理姓名、专名和原文，LanceDB处理语义候选，SQLite关系/Wiki处理多跳扩展。所有命中最终回查权威事实或正文；投影可以删除重建。

## 4. Agent长期陪伴的真实含义

11名成员是一本书生命周期内稳定的“岗位身份”，不是永久占用模型的进程。长期陪伴由四类持久记录组成：

1. 身份锚点：姓名、岗位、职责、权限、书籍范围和模型快照历史。
2. 岗位连续性日志：该岗位已经确认的观察、正在追踪的问题、最后有效贡献、来源和适用范围。
3. 当前关注快照：当前卷、故事弧、章节、任务、未决事项和下一步；任务结束或切卷时显式更新。
4. 工作证据：任务、意见、上下文包、调用、稿件、审校和老板决定的可追溯引用。

每次Agent被唤醒时，系统构建岗位专用“连续性包”：

```text
稳定身份与职责
＋ 当前正史/卷/故事弧/章节
＋ 本岗位当前关注与未决项
＋ 与老板当前问题相关的结构化事实和原文
＋ 少量必要的近期消息
＋ 本次任务目标、边界和输出合同
```

不注入全部聊天、全部岗位日志或其他成员的全部结论。不同岗位共享同一本正史，但以不同问题和检索范围独立判断；主编最后综合。这样成员会“接得上”，又不会因为长期历史越来越多而注意力崩溃或集体迎合。

## 5. 十一名成员的长期关注

| 成员 | 长期跟踪重点 | 默认不长期固化 |
|---|---|---|
| 貂蝉（主编） | 老板确认决定、分歧、当前创作阶段、未决事项、交付与风险 | 老板一句随口评价、历史采纳率 |
| 西施（副编） | 交接完整性、租约、检查点、待决事项和主编遗漏 | 主编个人表达习惯、未验证猜测 |
| 婉儿（编剧） | 主线/支线、因果、承诺、转折、故事弧和替代路线 | 每次脑暴的全部废案 |
| 红玉（编剧） | 结构不同的路线、反例、代价和长期叙事债务 | 为不同而不同的猎奇方案 |
| 文姬（设定） | 时间、人物状态、规则、关系、知情、物品与冲突 | 没有证据的性格推测 |
| 秋香（主笔） | 表达基线、人物声音证据、场景实现经验和需要避免的重复 | 大量历史范文、可被模仿的原句 |
| 湘君（副笔） | 接管状态、表达基线、人物声音和候选稿差异 | 主笔内部解释、大量旧范文 |
| 妲己（审校） | 已验证的文学/语言缺陷、AI腔风险证据和修复结果 | 单章风险分、永久禁词表、统一化润色偏好 |
| 昭君（体验） | 情绪曲线、期待、兑现、疲劳、读者信息差和适用内容尺度 | 追求每章强刺激的机械配额、单次合规判断 |
| 道韫（研究） | 已核验资料、主张—证据、时效与适用章节 | 未核验网页、无关资料堆积 |
| 弄玉（版权） | 授权范围、结构风险、隔离材料和已处理风险 | 把类型惯例误判为抄袭的泛化规则 |

岗位经验必须记录来源、反例、范围、版本、到期和撤销条件。它是可质疑的建议，不是为了迎合作者而不断变硬的偏好画像。

## 6. 滚动规划，而不是一次规划1000章

一次把1000章详细写死会制造僵化和大量过期信息；完全不规划又会漂移。采用分辨率随距离递减的滚动规划：

- 全书层：主题、终局方向、核心关系、重大承诺和不可破坏边界；
- 卷层：每卷阶段目标、对抗结构、人物变化和卷末不可逆结果；
- 故事弧层：未来20—30章的因果链、转折、兑现和备选路径；
- 近期层：未来30—50章保持可执行轮廓，未来5—10章细化章目标；
- 当前层：当前1—3章形成精确场景契约和写作工单。

每章结算只推动受影响的近期计划和故事弧状态；每个故事弧结束重新评估下一弧；每卷结束重审全书主脊但不静默改写老板确认的终局与重大承诺。

## 7. 长篇检索与上下文控制

正式调用按以下顺序工作：

```text
识别任务、岗位、实体、别名、故事时间和问题类型
→ owner/book/canon/权限硬过滤
→ 当前状态与承诺直接查询
→ FTS、向量、关系/Wiki多路候选
→ 时间、冲突、否定与无答案检查
→ H硬约束固定，E证据/I灵感分别RRF融合和岗位/权威加权
→ 原始事实或正文回查
→ 最小约束胶囊＋可选灵感调色板
→ 必要时一次定向二次检索
```

上下文预算与全书长度解耦。500万字时模型仍只看到完成当前工作所需的有限资料。硬事实不能因预算静默丢失；软资料先去重、限量和说明采用原因。主笔默认只取得少量人物声音和相邻场景证据，避免旧正文把新场景锚定成仿写。

同一来源的场景父块、子块、阶段摘要和Wiki不能在融合时重复投票；它们先聚成一个证据簇。关系扩展只接受已消歧实体种子，并有边类型、深度、扇出和总节点预算。完整查询意图、11名成员配方、E0起始限额和证据闭环见 `docs/HYBRID_RETRIEVAL_ORCHESTRATION.md`。

### 7.1 阶段摘要优先与关键触发下钻

新阶段不应默认携带全部旧章节，也不能把旧阶段彻底忘掉。系统在故事弧或卷叙事闭合时生成“阶段结算”，并据此建立当前活动工作集。以第500章为例，默认连续性包只包含：

- 全书主脊和全局不可破坏边界；
- 当前卷目标、当前故事弧和当前1—3章场景契约；
- 上一卷结算以及与当前问题直接相关的更早卷结算；
- 当前人物、势力、地点、关系、知情、资源和规则状态；
- 所有仍开放的承诺、伏笔、秘密、债务和人物目标；
- 最近3—5章结算、必要相邻原文和当前岗位关注。

更早阶段的原始正文默认不注入模型，但仍保存在正史、FTS、向量和来源图中。资料按检索活跃度形成可重建投影：

| 活跃度 | 典型内容 | 默认处理 |
|---|---|---|
| 始终活动 | 世界硬规则、不可逆生死/身份、核心能力限制、当前有效状态 | 直接结构化查询，不按距离衰减 |
| 开放线程 | 未兑现承诺、伏笔、秘密、债务、目标、知情差 | 持续进入相关岗位候选 |
| 当前阶段 | 当前卷、故事弧和近期章节 | 默认活动工作集 |
| 休眠待触发 | 已结束阶段中的旧人物、地点、道具、事件和局部关系 | 摘要优先，触发后下钻 |
| 已闭合局部 | 已解决且不影响当前状态的局部事件 | 默认只保留阶段摘要 |
| 已被替代 | 旧规划、旧设定版本和已否决候选 | 仅审计/历史用途，不驱动生成 |

活跃度不改变正史地位，也不能用“300章以前”等固定章数直接把硬事实或开放线程移出检索。时间距离只降低普通局部材料的软相关性。

关键信息触发器至少包括：

1. 当前问题或工单出现旧实体、别名、地点、道具、势力、规则或事件；
2. 承诺、伏笔、秘密、债务或人物目标进入预计推进/兑现窗口；
3. 人物的知情边界、关系、声音、动机或历史经历需要证据；
4. 当前说法与阶段摘要、当前状态或结构化事实发生冲突；
5. 存在因果缺口，例如需要回答“为什么能这样做”或“此前发生过什么”；
6. 阶段摘要没有覆盖当前问题、探针置信不足或来源水位落后；
7. 老板明确要求回顾、呼应、重启旧线或比较前后变化。

触发后按以下路径逐级下钻：

```text
活动工作集
→ 相关卷结算
→ 相关故事弧结算
→ 章节/场景结算＋结构化事实/承诺
→ 最小正史原文证据
```

若摘要已足以回答低风险问题，可以停止；涉及硬事实、重大回收、冲突裁决或摘要缺项时必须回到正式事实或正文原文。三级使用唯一计数：活动工作集为0级、相关卷为1级、故事弧为2级、章节/场景及结构化事实为3级；从已选来源指针取得最小原文属于证据解引用，不增加语义深度但仍计预算，精确ID允许跳级。一次初始检索后只允许一次有界补充检索周期；仍无依据时报告未知或阻断正式生产。每次检索记录触发原因、路径、语义深度、证据解引用、候选量、注入量、Token、采用与排除理由。

不同岗位使用同一权威链但有不同下钻倾向：主编/副编与活动写手默认摘要优先；两名编剧优先补开放线程和历史因果但先独立推演；设定遇到时间、规则、状态或同名风险时更早查结构化事实与原文；事实点评席发现疑似矛盾时必须查证，不论该席当前由GLM还是GLM写手场景下的DeepSeek承担。Kimi只补少量声音/重复证据，豆包只补体验趋势和策略版本。活动写手只取得完成当前场景所需的短原文证据，旧相似场景和人物声音片段限量且标为可选，避免“连续性更好、创造性更差”。

## 8. 长会话压缩

聊天为审计和恢复可以保存，但不是默认长期记忆。压缩由逻辑任务/阶段边界、模型输入预算和新增消息范围共同触发；原始聊天继续归档，老板早期约束、确认决定、精确ID/路径、未决承诺和不可逆边界另存硬锚，不能只依赖自由摘要。长讨论采用带锚点的增量压缩，固定保留：

- 来源消息范围和内容哈希；
- 已确认决定及确认人；
- 已确认事实与正史版本；
- 开放问题和下一步；
- 有依据的异议与反例；
- 与承诺、伏笔、规划和任务的引用；
- 明确排除和失效的内容。

每个快照还保存上一有效快照、结构Schema、压缩模型/适配器/提示词/Tokenizer快照和逐段来源哈希。压缩只合并新消息，不反复总结全部历史。

探针覆盖事实回忆、决定理由、继续工作、来源证据、冲突/否定和未决承诺，并使用轮换隐藏样本，避免固定探针造成假通过。失败则保留旧快照并重做当前增量，不能用错误摘要覆盖历史；同时记录压缩后重新读取旧消息的频率，回读率持续上升时扩大近期窗口或降低压缩强度。

## 9. 章节、故事弧和卷级结算

每章结算更新：正文版本、原子事实、人物/势力/地点状态、关系与知情、资源变化、承诺与伏笔、章末状态、故事弧进度、投影任务和受影响计划。

故事弧或卷叙事闭合时还要生成版本化阶段结算，至少包含：不可逆结果、实体当前状态、已经关闭和仍开放的线程、承诺/伏笔、关系/知情/资源变化、规则与关键物品、被排除的候选以及逐项来源。阶段边界由叙事闭合确定；超长未闭合阶段可以建立技术检查点，但不得标成正式阶段完成。

阶段结算采用锚定式增量编译，不做“摘要再摘要”式无源漂移。生成后执行事实、状态、承诺、因果和来源探针；失败节点不替换上一有效版本，也不向卷或全书主脊继续合并，而是从对应正史范围重建。

治理频率：

- 每章：硬事实与章末状态结算；
- 每10章：轻量连续性、重复和承诺老化检查；
- 每20—30章：故事弧目标、因果、人物变化和兑现检查；
- 每50—150章：卷级主线、主题、节奏、关系和资源膨胀检查；
- 持续维护20/50/100/200章滚动窗口，观察人物声音、情绪单调、场景功能重复、伏笔债务、力量膨胀和章纲偏离。

硬冲突可以阻断。趋势是给主编和老板看的证据，不自动把小说修成统一模板；软趋势与人工判断冲突时暂停自动结论。

## 10. 前端陪伴体验

每书应显示：总章节/总字数、当前卷与故事弧、正史版本、索引水位、待兑现承诺、伏笔债务、资料缺口和最近质量窗口。

团队成员区显示11名成员和真实状态，保持190px窄栏并使用滚动，不挤压中间创作区；点击成员可以查看稳定岗位、当前关注、最后有效贡献、相关证据和待处理事项。不得展示模型内部思维链，也不得因为成员有长期档案就伪造“在线”或“后台工作中”。

作者可以从资料库查看全书主脊、卷/故事弧摘要、阶段结算、实体、关系、情绪、时间线和证据；摘要可点开来源章节和正史原文。检索预览显示当前活动工作集、触发原因、下钻路径以及最终注入资料；从任务中心查看当前章节、Agent任务和可取消状态。长期复杂性必须被系统整理，不能转嫁给作者阅读全部日志。

## 11. 验收分层

### E2：确定性满规模回放

- 至少500万规范化中文字符、1500章、两本以上测试书；
- 锚点分散到全书不同卷、章节、段落、资料类型和故事时间；
- 覆盖别名、否定、冲突、多跳、旧正史、无答案、跨书隔离；
- 完成增量索引、全量重建、中断继续、备份恢复和索引删除重建；
- 报告数据库/索引体积、构建时间、P50/P95查询、内存和上下文Token。
- 在第500、1000和1500章设置回查第30、120、280章等旧正史锚点；相关触发必须逐级找到原文，无关旧正文不得进入模型上下文。
- 验证开放线程和全局硬事实不会随章节距离衰减，已闭合局部信息默认保持休眠，错误摘要不能覆盖正史且能从来源范围重建。
- 验证每章上下文Token在全书增长时保持有界，并分别报告本地查询候选量与实际注入Token。

### E3：独立长规模金标

金标与实现代码、同义词表和测试夹具分离。分别评测结构化、FTS、向量、关系、融合和重排，报告Recall@K、Precision@K、MRR、nDCG、无答案准确率、时间正确率、证据回查率和跨书污染。

### E4：真实模型纵向创作

20章只观察早期趋势，50章观察中期稳定，100—200章观察长篇能力。要对“1000章以上一路陪伴”和“500万字文学质量”做完整产品声明，还必须有覆盖相应范围的真实长期运行、关键区间盲评、作者验收和故障记录；不能由200章外推。

## 12. 失败条件与回滚

- 投影落后、来源缺失、故事时间冲突或无答案时，暂停相关正式生成或明确降级，不能用相似文本猜答案。
- 岗位连续性包超过预算时，优先裁掉旧软资料和重复日志，不裁掉任务硬事实和来源。
- Agent建议越来越迎合、同质或套路化时，撤销对应岗位经验版本，保留正史和工作证据。
- 层级摘要出现事实探针失败时，只回滚受影响摘要节点并从原文重建。
- 触发器过宽、反复下钻或旧原文注入增加而没有改善正确率时，收紧触发规则、深度和岗位预算；不把整书检索作为兜底。
- 混合RAG提高召回但降低创造性或整体质量时，回滚软资料、融合权重、切片或重排，不回滚正史、安全和隔离。
- 只有目标电脑上的E2/E3证明现有嵌入式架构无法满足500万字容量、P95延迟或恢复时间，才讨论独立数据库或分布式架构。
