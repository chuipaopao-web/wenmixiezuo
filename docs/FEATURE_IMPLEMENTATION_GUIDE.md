# 文秘写作功能实现、交互、AI检索与上下文说明

本文件说明当前版本每个作者功能“怎么用、页面如何反馈、后台如何实现、AI成员何时介入、检索什么以及明确排除什么”。它描述当前生效版本，不包含旧聊天工作流、旧页面名称或已经退出的功能。

## 1. 全局界面与共同规则

应用打开后直接进入创作台。左侧是单列竖版书籍封面栏，点击封面只切换当前书；顶部是信息、设定、分卷、规划、章纲、正文、资料库、取名、团队、任务、灵感和设置，点击只切换中心页面。书名不在顶部重复，页面已经能从入口和当前内容理解的介绍不再常驻显示。

所有作者可见动态文字先经过大白话展示门禁。页面不显示任务ID、数据库键、原始模型ID、JSON、内部阶段名、哈希、Worker或上下文包名称。技术原件继续写入后台审计，错误、取消、重试和恢复入口不能因为隐藏技术细节而消失。

共同数据规则：

- 每次请求都携带当前`owner_id`和`book_id`，其他书籍不能进入结果；
- 正式对象保存活动版本，修改上游后先做影响判断，下游候选失效或要求重新确认；
- 正文每次修改创建新的不可变完整版本，不覆盖旧正文；
- 规划表示未来，章节/事件/卷结算表示正文实际发生，二者分开；
- 作者确认设定、正式正文和结算是权威源，摘要、图谱、资料卡和向量是可重建投影；
- 作者未写明、正文未发生或来源不足的内容显示未知，不由AI补造。

## 2. 十二个顶部功能

### 2.1 信息

**作者交互：** 查看和修改书名、频道、分类、题材、初始角色、必须遵守和其他开书资料，并查看当前书籍简介；页面不再展示故事方向、标签和作者意见入口。书名最多15字。书名和书籍简介旁的“主编设计”在第一卷方案确认后，由主编依据第一卷已确认方案、设定基线和开书信息一次产出多套候选，作者选一套直接采用；第一卷未确认时提示先完成第一卷设计。修改时显示会影响哪些后续对象，保存后回到干净的资料阅读态。

**后台实现：** 开书字段保存在逐书定位与开书蓝图的活动版本中。修改创建新版本并更新活动指针，不重写旧版本、正文或来源记录。

**AI与上下文：** 开书本身只接收作者填写的全部开书信息，不使用RAG猜缺失字段。定位分析可整理作者原话，但不能引入其他书、灵感讨论、后续规划或AI猜测。

### 2.2 设定

**作者交互：** 初始页面只显示模块、真实进度和“召集成员”操作；未启动前不预放方案卡。启动后显示参与成员的自然语言状态，三份独立候选产生后才展示卡片。作者可比较、选取、融合、重写、直接编辑并逐项确认；作者补充输入默认折叠。

**后台实现：** 每个设定模块有候选、决定、活动版本和来源。只有作者确认的内容进入设定基线和“设定来源”，讨论中内容不进入正史。

**AI与上下文：** 主编组织当前模块，独立策划成员各自产生方案，融合角色只读取已经保存的候选。上下文包含完整开书信息、当前设定模块、作者对此模块的原话/附件和必要已确认依赖设定；排除卷纲、事件、正文、其他书、未摘录灵感和旧候选。

### 2.3 分卷

**作者交互：** 选择当前卷，填写本卷想法，查看2—3个适合本书的节奏建议，也可展开更多、不选、混合、重排或自定义。候选出现后比较差异并确认卷目标、主要冲突、人物变化、高潮、代价和卷末入口。

**后台实现：** 卷纲有活动版本、候选、决定、上游设定版本和影响链。确认卷纲后才能确认该卷事件链。

**AI与上下文：** 主编统筹卷级方案；上下文包含覆盖全部开书字段的核心包、活动设定、长期承诺、作者卷意见和卷级软模板。后续卷另加上一卷真实结算、当前人物/势力/资源状态和开放线索。排除未实现规划冒充历史、其他卷全文和全库堆叠。

### 2.4 规划

**作者交互：** 先查看当前卷的故事动脉，再点入一个事件设计完整事件大纲。节点卡显示事件标题、为什么现在发生，并区分本卷开场、上一幕已发生和预计承接；节点之间以“因为……所以……”解释因果。选中后默认显示上一幕、眼前麻烦、人物选择和这一幕终点的故事预告，可切换细节视图核对目标、阻力、选择与代价、结果、人物变化、下一事件接口、章节范围和卷任务。阅读感受方向只用大白话呈现，专业模板来源不在普通界面出现；作者可不选、混合、自定义、加入灵感、比较两份独立方案并按段融合。上层变化时显示具体影响和重建入口，而不是只显示模糊警告。

**后台实现：** 事件链、事件、事件大纲分别版本化；卷纲约束事件链，事件链约束当前事件大纲。事件有计划状态和结算状态，已发生结果来自正文结算。

**AI与上下文：** 事件链接收开书核心、活动设定、完整卷约束和作者事件链意见。事件大纲额外接收完整事件链、当前事件卡、上一事件真实结算或卷首状态、当前事件作者原话和按需检索的相关人物、势力、地点、道具、规则、线索与前因。其他事件完整大纲、未来结算和未摘录灵感不进入。

### 2.5 章纲

**作者交互：** 系统先评估当前事件需要多少章和字数，再生成完整章链。每章显示章节任务、场景、关键行动、信息揭示、情绪变化、开头/结尾钩子和结束状态。作者可逐章修改、重写、调整顺序或确认。对关键转折拿不准时，可点击“请另一位编剧看看”；页面只显示最多3条自然语言替代建议，并明确收益、代价和后续影响，作者可以完全忽略。

**后台实现：** 章纲绑定当前事件大纲版本和章节位置；批量生成仍逐章保存并校验连续性。挑战任务冻结精确章链候选或单章章纲版本，只把结果保存到任务检查点，不写入正式章纲、不自动融合。目标换版后旧建议不再作为当前建议。事件大纲变化后，未确认章纲失效或要求重建。

**AI与上下文：** 指定编剧生成主方案；另一位异模型编剧仅在作者触发时挑战关键节点。主方案上下文包含压缩但覆盖完整的开书、设定、卷纲和事件链，完整当前事件大纲、上一真实结算和作者章链/单章意见。挑战者再读取精确主方案版本，但不读取其他候选、聊天或审查报告。系统不只给一个摘要，也不加载其他事件全文。

### 2.6 正文

**作者交互：** 一次聚焦一章。主笔生成初稿后进入事实、文学和体验三份独立审查；页面显示正文和可定位的自然语言建议。作者可直接编辑、定点重写、保留满意部分或定稿。定稿前不会结算，下一章不能绕过活动章纲直接生成。

**后台实现：** 正文是不可变完整版本；活动写手只有一个结果进入审查。三席绑定同一正文和章纲但互不读取报告。作者定稿后执行章节结算，更新正式事实、人物状态、来源、检索投影和当前进度。

**AI与上下文：** 主笔接收开书核心、活动设定、卷约束、事件链、完整事件大纲、完整本章章纲、必要前章、当前正史、作者意见和明确自由区。事实席检索规则、时间、能力、知情、人物状态、道具和来源；文学席检索人物声音、情绪与必要近期原文；体验席读取卖点、目标读者、事件位置和期待兑现。三席报告隔离。

### 2.7 资料库

**作者交互：** 在13个页签查看设定来源、主角实时状态、配角档案、势力档案、地点、世界路线图、道具资源、事件时间线、生效规则、标签、待补内容和内容来源。右上角“关系与轨迹”切换到关系图。资料详情可展开，来源可回查。

**后台实现：** 实体、正式事实、关系、人物状态史、结算事件和来源存在SQLite权威表；资料档案与世界路线是可重建查询视图。资料库不写剧情，不把规划直接升级为正史。

**AI与上下文：** 事实席在章节结算时只提取正文明确、会影响后续的持久事实。类型字段是可选语义，不要求每章或每本凑齐。资料库本身用于结构化直达和检索导航；ContextCompiler只为当前任务选择必要字段，不把整个资料库塞入每次模型调用。

资料库各页签详见第3节。

### 2.8 取名

**作者交互：** 选择人物、势力、地点、物品等目标，填写语义、风格、禁用字和数量，生成候选后挑选或复制。候选不会自动创建正式人物或改写正文。

**后台实现：** 保存命名请求、候选、来源和采用状态；采用后仍要绑定到明确业务对象或由作者写入正式内容。

**AI与上下文：** 只读取当前书题材、语言风格、目标对象、相关已确认设定和作者禁用条件。排除其他书名字、未确认候选和无关全文，避免串名。

### 2.9 团队

**作者交互：** 显示11名创作成员的真实状态卡：等待什么、正在处理什么、使用的上下文摘要和已完成输出摘要。点击卡片查看经过整理的信息，不显示思维链。

**后台实现：** 状态来自任务、心跳、模型调用和工具事件，不使用定时动画伪造。岗位、成员实例和模型绑定分离；同一模型来源如实显示。

**AI与上下文：** 团队页不额外触发创作。每次成员调用使用与具体业务任务绑定的冻结ContextPack；上下文详情只显示可公开摘要，原始包留在审计层。

### 2.10 任务

**作者交互：** 按书查看等待、运行、完成、失败、暂停和需要处理的任务。可取消、继续、重试或查看影响；状态使用“正在整理设定”“正在写第3章”等大白话。

**后台实现：** 任务使用幂等键、租约、检查点、取消栅栏和晚到结果隔离。失败恢复不重复提交已完成正式对象；结果未知需要调和后才能重试。

**AI与上下文：** 任务页不改变成员上下文。重试沿用冻结输入或明确创建新任务版本；如果上游版本已经变化，旧结果拒绝落库。

### 2.11 灵感

**作者交互：** 作者与独立灵感分身讨论人物、情节或选择。讨论只给启发，不生成或修改设定、卷纲、事件、章纲、正文和正史。作者必须主动“摘录并绑定”到具体业务对象，内容才成为该对象的作者输入。

**后台实现：** 灵感消息与正式对象、任务和正史分库存储；未摘录讨论不会进入正式检索，也不形成持续聊天记忆。

**AI与上下文：** 灵感成员可读取当前书作者允许的资料帮助讨论，但输出是建议。正式创作成员排除未摘录聊天；摘录后只读取绑定目标、原文和作者强度。

### 2.12 设置

**作者交互：** 管理未来任务的成员模型绑定、预算、显示和本地运行配置；查看连接是否可用。密钥由环境配置，不在页面回显。修改模型只影响未来任务和新快照。

**后台实现：** 绑定有版本和生效时间，已完成调用保留当时真实模型。没有套餐凭证时保持确定性验收模式，不冒充真实模型创作。

**AI与上下文：** 设置页不触发内容生成，也不修改已有上下文包。Kimi K3当前暂停，未来任务按当前有效绑定选择模型。

## 3. 资料库十三个页签

| 页签 | 作者看到什么 | 数据来源与实现 | 空缺处理 |
|---|---|---|---|
| 总览 | 当前书的实体、事实、关系、事件、标签、待补数量和开书摘要 | 按当前书聚合权威表和开书活动版本 | 只显示真实计数 |
| 设定来源 | 作者逐项确认的设定原文、板块和确认来源 | 活动设定基线 | 未确认候选不显示 |
| 主角 | 当前境界/等级、属性、技能、装备、资源、伤势、身份及完整变化史 | 主角状态追加账本；获得、更新、消耗、失去均保留章节/时间 | 不可归类项进入待确认，不猜分类 |
| 配角 | 折叠态只显示姓名和首次出场；展开身份、年龄、性格、门派、境界、实力、属性、装备、关系和出场记录 | `character`实体中排除主角，按正式事实语义聚合 | 每个未写明字段显示“尚未写明” |
| 势力 | 负责人、人数规模、整体实力、等级、驻地、地位和成员 | `organization`实体及本书事实；可从明确人物所属关系反向得到成员 | 不用世界观说明填空 |
| 地点 | 地点类型、所属区域、方位、特点和出场记录 | `location`实体和正式事实 | 没有方位就保持未知 |
| 地图 | 从出生地或首个正式场景出发，按章节连接实际到达的大地点 | 地点首次正式出现、明确出生地和作者初始地图说明；仅大范围节点进入路线 | 不生成坐标；无方向证据不显示东南西北 |
| 道具资源 | 类型、等级品质、属性、效果、数量、当前归属、状态和获得/转移/消耗/失去记录 | `item/resource/skill/stat_panel`实体、事实和明确持有关系 | 不从名字猜属性和主人 |
| 事件时间线 | 每行只显示故事时间或章节范围＋事件名 | 已结算事件、章节覆盖和事件结算；详细摘要留后台 | 无年月日时直接显示章节范围 |
| 生效规则 | 真正约束后文的确认规则和规则事实 | 明确规则设定及`world_rule`实体 | 策划理念不重复显示 |
| 标签 | 标签名称、说明、适用对象和使用数量 | 标签定义与分配关系 | 新标签不自动改正文 |
| 待补内容 | 已发现且需要以后补充或确认的信息缺口 | 资料缺口记录，带目标、严重性和状态 | 不以AI猜测自动关闭 |
| 内容来源 | 按对象列出事实、来源章节和正文短依据 | 正式事实与不可变稿件来源 | 技术ID和内部证据级别不直接展示 |

关系与轨迹视图从正式关系投影读取人物、势力和其他对象之间的有向关系。没有可靠关系时显示空状态，不能用共现代替关系。

## 4. AI成员介入与任务包

当前创作团队保持11名。具体姓名和模型可在团队/设置查看，业务职责按节点划分：主编统筹全局与融合，策划/编剧提供独立方案，数据准备角色编译上下文，活动主笔写正文，事实/文学/体验三席独立审查，维护角色负责结算与长期连续性。小文秘书是本地工具，不是第12名创作成员，不给剧情结论。

每次模型调用都保存：目标对象、冻结上游版本、作者原话、纳入与排除来源、预算、调用快照和结果。系统不保存或展示思维链。

上下文按任务动态编译：

1. 直接放入当前活动上游对象和作者原话，不与相似度结果竞争；
2. 生成结构化查询计划，确定人物、势力、地点、道具、规则、时间、因果和原文需求；
3. 按需组合结构化直达、全文、向量、关系、时间/因果和正式原文回查；
4. 过滤其他书、失效版本、无来源候选、未摘录灵感和错误时间；
5. 按权威、任务相关、时间与因果必要性重排，预算内裁剪；
6. 保存来源指纹，提交结果前再次核对上游版本和正史水位。

不存在一份固定“岗位永远读取这些内容”的永久包。相同成员在设定、事件、正文或审查任务中读取的资料随当前对象变化。类型化资料档案帮助精准定位，但不会自动全部进入上下文。

## 5. 版本、失效、结算与恢复

- 设定变化：提示受影响的卷、事件、章纲和未定稿正文候选；作者查看影响后重建或保留；
- 卷纲变化：当前卷事件链和下游候选需要重新校验；
- 事件链变化：受影响的事件大纲和章纲失效；
- 事件大纲变化：当前事件章纲和未定稿正文候选失效；
- 章纲变化：对应未定稿正文候选失效，已定稿正文不自动改写；
- 章节结算：只读取作者确认正文，写入实际事实、状态、来源和检索投影；
- 事件结算：汇总该事件已结算章节的实际结果、代价、人物状态和下一触发；
- 卷结算：汇总本卷全部事件实际结果、开放线索和下一卷真实入口。

任务失败时从检查点恢复；模型超时、格式错误或取消都有明确状态。晚到结果、过期上游结果和跨书结果拒绝落库。普通删除是归档；正文、已合并迁移和作者原件不随代码清理删除。

## 6. 验收时作者应看到的结果

- 每个入口可点击，切换页面不乱跳、不白屏；
- 页面没有重复标题、重复说明、机器键、英文协议或乱码；
- 配角、势力、地点、地图和道具各自显示正确语义，不再共享一套通用卡；
- 未知字段诚实显示“尚未写明”，不会看起来像已经设定；
- 时间线每行只有时间/章节和事件名，详细证据仍可从来源回查；
- 地图路线来自实际章节，不制造方向和坐标；
- 其他书籍内容不会出现在当前书；
- 上游变化会说明具体影响并提供恢复入口；
- AI成员状态来自真实任务，候选、融合、正文和三席审查可追溯；
- 文档、代码、测试和桌面文档中心在每次开发结算后同步到同一当前版本。

## 14. 统一账号与管理员后台

**前端交互：** 未登录时只显示登录/注册页。注册填写昵称、邮箱、至少10位密码和确认密码；登录只填邮箱密码。登录后左栏底部显示当前昵称和身份，并提供退出；管理员额外显示“管理”入口。管理页显示用户总数、启用/暂停数、已注册账号名下的“用户书籍”总数、搜索和状态筛选；每个用户显示昵称、邮箱、角色、状态和注册/最近登录时间，可暂停或恢复。

**后端逻辑：** 注册以事务创建账号归属。首个账号原子授予admin；如果账号体系启用前已有未认领的本机老板所有者和书籍，则直接复用该owner，使原书籍、正文、资料库、任务和上下文完整归入管理员账号，不复制任何创作表。第二个及以后账号创建全新owner。密码用scrypt，登录令牌只以摘要落库。请求策略先验证Host/Origin/跨站写入，再从Cookie解析账号；领域路由统一使用会话owner。管理员状态变更写审计，暂停同时撤销全部会话。

**上下文与检索：** 账号、邮箱、密码、会话和管理员审计不属于创作资料，ContextCompiler始终排除。登录owner只作为硬隔离范围，不能成为故事内容或AI提示。AI成员只能检索当前owner下当前书的已允许来源。

**当前边界：** 邮箱密码和管理员核心已实现；桌面启动不会自动签发会话，未登录访问受保护接口返回401，真实流程验收脚本必须通过 `WENMI_E2E_EMAIL` 与 `WENMI_E2E_PASSWORD` 登录。公开运营前仍需邮箱验证/找回、持久限流、HTTPS、协议隐私、账号导出/注销和生产备份。手机号、微信以后绑定到现有用户。
