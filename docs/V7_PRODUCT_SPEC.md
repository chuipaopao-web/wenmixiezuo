# 文秘写作 V7 产品规格

> 状态：V7 讨论交接稿，尚未最终定稿，不能视为开发授权。
> 建立日期：2026-08-23。
> 用途：让新任务理解当前已讨论方向、继续与老板商议；老板后续决定可以直接修改本文件。

## 1. 版本边界

- V7 讨论形成之前的工作流、页面结构、UI 图、卡片数量、步骤名称和前置门槛全部失效，不得作为 V7 开发依据。
- V6 当前生产行为只用于识别可复用资产、读取历史数据和确定删除范围，不能反向约束 V7 产品设计。
- V7 不是复制一套旧项目，也不是继续给旧页面打补丁。它是在当前仓库内重建作者工作流和前端表现层，复用经过审计的后台能力。
- 旧开发清单、旧视觉图和 Git 历史仅供追溯；新任务默认不读取，只有定位某项成熟实现时按需查阅。

## 2. 产品目标

把长篇小说创作变成轻量的人机共创循环：

```text
AI 根据当前真实状态给出少量下一步方向
→ 作者选择、补充或要求重做
→ AI 扩展为可编辑内容
→ 作者确认
→ 正文定稿后结算实际发生
→ 系统更新连续性资料
→ 进入下一步
```

作者负责判断、取舍和最终确认；AI 负责提出方案、专业化扩展、写作和检查；系统负责版本、资料包、事实与长期连续性。

## 3. 不再采用的产品思路

- 不让作者在开书前填写大量专业字段。
- 不把故事线、事件链、角色表、节奏模板或版本管理变成必须依次完成的前端门槛。
- 不要求作者理解 ContextPack、RAG、内部模板、模型 ID、任务 ID 或结算表。
- 不在一个页面同时铺开未来卷、未来事件、完整角色库和大量 AI 成员状态。
- 不把全部后台质量控制转化为作者必须操作的步骤。
- 不依赖聊天记忆维持全书一致性，不用无限增大上下文代替正式状态管理。
- 不让多席审查默认形成无限“审查—改稿—再审查”循环。

## 4. V7 核心体验

### 4.1 最小开书

作者可以只选择题材，例如“玄幻修仙”。一句话想法、已有片段和更完整方向均为可选输入。

AI 默认给出 3 个实质不同的开书方向，每个方向只回答作者真正需要判断的内容：

- 主角与开局局面；
- 核心吸引力；
- 第一阶段可能怎样发展；
- 明显优势与风险。

作者可以整选、补充自己的想法、要求换一批或进入更详细编辑。确认后形成版本化开书简报。

### 4.2 当前卷

AI 基于开书简报、已确认宏观设定和上一卷实际结算，给出少量本卷方向。普通作者只看白话差异：本卷主要变化、冲突、代价、卷末状态与阅读感受。

作者可以选择、局部组合、直接编辑、补充意见或重做。确认的是本卷方向责任，不提前冻结所有事件和章节。

### 4.3 当前事件

后台保留当前卷轻量事件骨架，用于保证因果和全局方向。前端默认收起，只显示事件名和因果箭头；作者可以不展开，直接处理当前事件。

AI 只详细设计当前事件。未来事件保持方向性骨架，完成当前事件结算后再校准下一事件。角色需求、节奏结构和伏笔安排由 AI 在后台专业处理，只有需要作者决定时才展示白话选项。

### 4.4 当前章节

系统保留当前事件的轻量完整章链：只包含章数、每章一句责任和前后因果。详细章纲只生成当前章和未来最多 2 章。

章节循环：

```text
AI 给出本章章纲
→ 作者确认或微调
→ 主笔生成正文候选
→ 作者选择、编辑或要求修改
→ 三席独立检查
→ 作者决定是否采纳
→ 作者定稿
→ 章节结算
→ 重新编译下一章资料包
```

事实席发现正文与正式事实的硬冲突时必须解决，但由作者选择修改正文、修改计划或明确建立新的正式修订；文学席和体验席为建议。默认最多一轮修改，只有作者主动点击才再次审查。

### 4.5 故事雷达

故事线不是开书门槛，而是系统根据正文实际逐步识别的长期记忆与观察工具。

- 章节结算后后台持续更新潜在线路、关系、伏笔与开放问题。
- 完成第一个事件后，前端首次主动展示故事雷达摘要。
- 事件和卷结算时集中提示值得确认、继续观察或忽略的线路。
- 作者可以随时查看或手动添加，但故事雷达不阻断继续写作。
- AI 候选线路不是正式事实；作者确认或正文结算后才能进入相应正式区域。

## 5. 共创深度

V7 数据和版本只有一套，界面可以提供不同暴露程度，不得复制三套流程：

- 托管：只看 AI 推荐、当前决定和正文。
- 标准：可查看轻量事件骨架、章链和必要资料。
- 深度：开放更细的方案比较、线路、角色、伏笔和版本信息。

作者可随时切换，已确认内容和草稿不丢失。具体名称、入口位置和默认档位必须在 V7 原型评审时由老板确认，未确认前不得写死。

## 6. AI 编辑部

- 岗位为 7 类：主编、副编、编剧、主笔、事实审查席、文学审查席、体验审查席。
- 初始 25 名成员：3、3、5、5、3、3、3；数量由后台配置，不写死上限。
- 每个 AI 节点默认自动分配一名可用成员；作者可以更换或追加同岗位成员。
- 作者只选择成员，不直接选择模型。
- 作者端只显示头像、姓名、岗位、供应公司、消耗等级和真实工作状态；不显示模型名、擅长、速度、成功率或内部 ID。
- 每个 AI 介入节点都提供可留空的“补充我的想法”输入框。AI 必须同时读取该节点的作者输入版本和正式资料包。
- 同岗位同批次多人比较必须获得完全相同的 ContextPack、作者输入、节点规则和模板版本；成员输出在作者选择前相互隔离。
- 单成员失败不清空其他成功结果；允许只重试失败成员或更换成员，页面不得形成死胡同。
- 闲置、未选和未开始的成员不调用模型、不产生模型消耗。

## 7. 后台仍然保留的正式对象

V7 前端轻量化不等于删除后台分层。后台继续区分：

- 开书简报；
- 换卷后仍成立的非剧情设定；
- 卷方向；
- 事件骨架和当前事件；
- 轻量完整章链与近期详细章纲；
- 正文不可变版本；
- 章节、事件、卷结算；
- 角色、关系、资源、伏笔、开放问题和故事线投影；
- 作者输入、AI 候选、确认稿和历史版本。

硬规则：规划描述未来，结算只记录正文实际；候选、摘要和 AI 推断不能覆盖作者确认内容、正文或结算。

## 8. 资料包与长篇连续性

- ContextCompiler 继续是唯一资料包编译权威，不是可见 AI 成员。
- 每次任务只读取当前 `owner_id`、`book_id`、活动版本、上一实际结果和当前任务需要的上游责任。
- 上层只向下层传递必要责任，不把全书资料和内部检查表全部塞进模型上下文。
- 作者硬要求、正式设定、不可变正文和结算属于硬事实区；作者规划、开放问题和 AI 候选必须分区。
- 章节结算后重新编译下一章资料包；未来章链是可校准导航，不是不可修改的正文预言。
- 上游正式版本改变时，下游候选失效或重新编译，不覆盖已定稿正文和历史版本。

## 9. 前端外壳与交互原则

已锁定：

- 继续保留桌面左侧书籍栏，负责切换书籍。
- 桌面顶部保留页面导航，页面主体直接切换。
- 手机继续使用当前顶部两排导航习惯，不增加第三排。
- 页面宽度和信息密度保持当前产品的阅读习惯，但工作区内部重新设计。
- 一个状态只有一个显著主操作；次要工具降级或收起。
- 每页分为导航层、当前工作层和按需上下文层，不做通用 AI 仪表盘式卡片海。
- 空、可编辑、AI 工作中、待决定、完成、失败、恢复和过期状态都必须有真实交互。
- 360、390、430px 是强制手机验收宽度。

尚未锁定，必须先出信息架构和逐页原型供老板确认：

- V7 顶部导航的最终页面名称和数量；
- 故事雷达是独立页面还是按需视图；
- 共创深度入口位置与最终名称；
- 各页面具体排版、控件、颜色、圆角和动效；
- 首屏方案卡数量、比较方式和移动端切换方式。

旧 V6 设计图不再是 V7 的 95% 视觉基准。

## 10. 工程实现边界

V7 在当前仓库和当前应用内建立独立模块，不建立第二套数据库、登录、部署或完整复制项目：

```text
apps/web/src/features/coauthoring-v7/
apps/api/src/application/coauthoring-v7/
apps/contracts/src/coauthoring-v7.ts
```

新 V7 前端调用新的薄工作流接口；薄接口通过适配层复用现有身份、书籍、AI资源、ContextPack、任务、版本、正文和结算能力。

不得把整个旧 V6 页面或旧总编排服务复制到新目录。只有证据证明一段能力独立、稳定且符合 V7 合同时，才直接复用或提取为共享服务。

## 11. 未来开发开始条件

只有老板明确发出“开始开发”指令后，才激活 `docs/V7_ACCEPTANCE.md`。进入 V7 功能编码前必须完成：

1. 按 `docs/V7_ASSET_INVENTORY.md` 核对保留、适配、重做和待删除资产。
2. 确认在独立分支 `codex/light-coauthoring-v7` 开发，并保护当前未跟踪和未提交内容。
3. 给出 V7 信息架构、关键状态流和桌面/手机逐页原型。
4. 老板确认原型；未确认区域不得由开发者自行发挥。
5. 建立第一条纵向闭环的变更合同和逐项验收清单。

## 12. 当前建议的第一条纵向闭环

这一顺序仍可在讨论中调整。将来首批开发不追求铺满所有页面，当前建议先打通：

```text
题材/可选想法
→ AI 开书方向
→ 作者确认开书简报
→ AI 第一卷方向
→ 作者确认
→ 当前事件轻量骨架
→ 当前章纲
→ 正文候选
→ 作者定稿
→ 章节结算
→ 下一章资料包
```

该闭环真实可用后，再扩展故事雷达、深度视图、多成员比较和旧流程清理。
