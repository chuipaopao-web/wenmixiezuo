# 老板使用说明

## 这个平台最终是什么

它不是一个只会轮流回答的群聊，而是一套本地小说创作工作台。老板负责说想法、选方向和判断成果；系统负责记忆、讨论、写作、检查、保存和恢复。

## 为什么有9个岗位

5个核心岗位负责每天都需要的工作：管理、剧情、设定、写作和审校。另有4个专家负责情绪、文风、资料和版权。专家平时待命，只有任务相关才加入，所以不会出现9个人每句话都抢着回答。

一个模型可以兼任两个岗位，但页面会如实显示。相同模型的两个分身不能假装成两个独立专家。

## 为什么Agent不会一次读取整本小说

几百万字不能每次全部塞给模型。平台会把整本书完整保存在本地，然后根据当前任务查出真正相关的资料：当前章纲、前章状态、有关人物、道具、伏笔和少量正文片段。每次使用了什么资料都会留下清单，可以检查和重现。

## 如何避免人物写死后又出现

每章定稿前，系统提取人物生死、位置、道具、属性、关系和事件，并与已有正史比较。硬冲突会阻止章节结算。重大变化必须经过老板确认，不能由模型自己改掉。

## 日常创作怎么进行

老板可以直接说：

> 我想写一本游戏加历史小说，主角进入北宋副本，从朱仙镇开始。

主编会整理定位、指出需要决定的方向、召集相关岗位讨论并给出推荐。确认后生成故事圣经和大纲，再逐章写作。一次可以安排3至5章，但系统仍然一章一章完成审校和结算，避免后面章节建立在错误事实上。

## 什么事情会找老板确认

- 主线和结局方向；
- 人物死亡、复活、重大身份或核心关系；
- 世界规则和能力体系变化；
- 高费用模型调用；
- 拆书版权风险；
- 恢复正式数据；
- 永久删除。

普通、可逆和低风险事项尽量由团队自动完成。

## 文档怎么修改

老板不用手动编辑文件。直接在Codex的 `wenmixiezuo` 项目里说：

> 修改开发方案：把……改成……

系统会记录新决定、说明影响并同步相关文档。历史原文不会被篡改，旧规则会标记为被新决定替代。
