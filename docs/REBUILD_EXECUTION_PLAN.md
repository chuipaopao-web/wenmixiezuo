## 1. 本次确定的工作方式

### 1.1 全部重构的范围

覆盖访客入口、注册/登录/找回、账号安全、作者端全部能力、AI与长期记忆、会员与账务、独立管理后台、运行维护、数据迁移、上线与旧实现退出。既有功能必须登记去向，不能只重做写作页。新增建议也列入讨论，但没有确认前不冒充既有能力或已批准需求。

“全部功能重构”表示每项都重新审查设计与实现。需要重写的业务代码重写；成熟依赖、安全基础和已验证组件可以复用，由开发者记录理由。不能以重构为名重复手写密码算法、支付验签等成熟基础能力，也不能以复用为由保留已证实的缺陷。

前端按用户看见的页面讨论，后端按身份、书籍、正文、任务、记忆、费用等责任实现。一个页面可能调用多个后端功能，同一后端能力只实现一次；不是“一页一个数据库、一页一套任务系统”。

### 1.2 逐页推进，前后端形成闭环

默认一次聚焦一个页面或一个明确的子视图：先查现状并提出专业方案→与用户讨论→记录本页已定结论和范围→获得该范围实施授权后开发→联调、验收与展示→进入下一页讨论。用户可以明确授权一组已讨论页面连续实施；无需重复确认已定事项。

这里的“先讨论”是用户本次明确要求，适用于本次全产品重构，优先于通用流程中“授权内自主推进”的默认节奏。不得拿此前64章草稿当所有页面已经讨论完，也不能拿一次“开发这个页面”授权连续开发尚未讨论的全站页面。页面内必要、可逆工程决定仍由开发者处理，不逐按钮/逐字段向用户请示。

**先做本页需要的最小后端，再完成本页前端和联调。** 不先做完整前端壳再最后补后台，不先花很长时间搭完所有基础设施再看第一张页面。公共基础第一次需要时做成受测模块，后续页面复用；大模块拆为可验证子项。

### 1.3 关于“没有BUG”

不承诺零BUG。可执行的标准是：需求有明确预期，关键路径和真实失败场景有证据，没有已知安全/数据/主流程阻断缺陷，剩余问题透明记录，故障能定位与恢复。构建通过、测试数量多、AI自称正确都不能替代用户结果。

未通过的独立页面可以不阻塞另一独立页面的讨论，但不能让依赖它的功能假装已经联调通过；不能靠不断往后开发逃避前一页的阻断缺陷。不能通过删测试、放宽标准或隐藏错误结项。

### 3.2 接管步骤

1. 读根规则、HANDOFF和本节；检查当前分支、Git差异、其他任务改动，不能覆盖他人文件。
2. 看总表找到“讨论中/开发中/验收中/阻塞”的单元，打开其合同/证据。若没有，按第3.1节开始。
3. 只读本单元相关页面、路由/服务、必要数据语义和规格章节；文档存在不能代替代码/运行查证。
4. 核对用户最新决定、实施授权、前端/后端实际完成度、未解决问题、最后一条验证证据；无法证明的状态降为未验证。
5. 简短告诉用户当前页面目标和下一步；已授权的剩余实施继续做，尚未讨论的下一页先讨论。
6. 结束或中断前，把当前子项、未提交文件、已跑验证及结果、下一条动作写入当前合同；把总表状态和证据链接同步到真实进度。HANDOFF只指向本文，不复制62行状态。

建议恢复记录字段：单元ID、当前子页面/后端子项、最近用户决定、授权范围、分支/提交、未提交改动归属、验证命令/环境/结果、未解决问题、下一步。记录不能包含密码、密钥、会话、作者隐私正文或模型思维链。

## 4. 状态和进入下一步的条件

### 4.1 分列记录，不能混称完成

| 列 | 允许状态 | 含义 |
| --- | --- | --- |
| 设计 | 待讨论 / 讨论中 / 已定 / 待调整 / 暂缓 / 取消 | “已定”需对应用户结论；内部工程单元记录由开发者确定的方案 |
| 前端 | 未开始 / 开发中 / 已实现 / 不适用 | “已实现”不代表真实交互通过 |
| 后端 | 未开始 / 开发中 / 已实现 / 不适用 | “已实现”必须有真实接口/持久化，不是模拟返回 |
| 验收 | 未验证 / 验收中 / 通过 / 未通过 / 阻塞 / 不适用 | 当前合同要求的证据缺失就不记通过 |
| 上线 | 未发布 / 试用中 / 已发布 / 已回退 / 不适用 | 单独记录发布范围、版本与线上证据 |

本表不是要求做完前端才做后端；后端合同与实现通常先于最终联调，两个实现列用于揭示剩余工作。公共内部能力的前端暂标不适用，若讨论后需要独立页面，应拆子项并补前端状态。暂缓/取消需要用户范围决定，不能为赶进度自行把缺失功能划掉。

### 4.2 一个单元的出口

- 页面/功能决定和具体范围已清楚，代码实现与合同一致；前后端都不是假数据或占位。
- 本单元适用的工程检查、真实交互、失败恢复和保留能力回归有证据；AI功能另有相称真实模型/阅读证据。
- 未解决问题列严重性、影响、恢复方式和去向；安全/数据/主流程阻断不得作为“以后优化”放行。
- 检查完整差异，提交只含本单元及必要依赖。文档、接口/数据说明与当前行为一致。
- 未部署可进入下一独立开发单元，但只能称“本地验收通过”。上线按明确发布方案集中或分批进行。

### 4.3 依赖和拆分规则

总表按推荐处理顺序排列；依赖列给直接关键依赖，未重复列出全部传递依赖。默认逐项推进，依赖满足只表示技术上可开始，**不表示已获授权或已讨论**。

大单元第一次讨论时按子页面/后端功能拆成RB-xx.1、RB-xx.2等，在当前合同维护子项。父行只有所有本批子项满足出口才能通过。后台资产、支付、账号安全等不可用一个“页面完成”笼统掩盖多个未讨论视图。

公共前置不能后补：例如RB-01涉及的必要协议/核验合同应在注册页讨论时一并明确，RB-03/RB-05完成的是独立页面和完整流程；若选择必须邮件核验才能注册，RB-01对公众可用的验收依赖RB-03真实邮件闭环，不能标注注册整体已可商用。不要因编号靠后推迟当前需要的权限、事务或安全功能。

## 6. 每个单元具体讨论什么、开发什么、怎样验收

以下内容均为待逐页细化的建议边界，不是62项都已定稿。前端列是用户结果，后端列是对应实现责任；具体验收值、接口Schema和用户选择进入当前单元合同。现有视觉满意不代表所有布局/按钮必须照抄。

<a id="rb-00"></a>

### RB-00 基线与最小工程准备

- **讨论**：确认现有视觉样本、全部功能去向、隔离开发环境及新旧身份/数据边界；不在此定死所有页面。
- **前端交付**：记录手机/桌面视觉基准和入口清单；建立最小新页面外壳及隔离运行方式，授权实施前只做只读核对。
- **后端逐项实现**：审查身份和版本保护；明确模块、配置、测试账号/数据、迁移与错误合同的最小骨架。暂不建设整套任务平台。
- **重点验收**：隔离环境不连生产写库；旧入口仍可用；记录可重复的启动/验证命令和当前已知失败。
- **依赖与详细设计**：—；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第42—46、52章。

<a id="rb-01"></a>

### RB-01 注册页

- **讨论**：注册标识、必要资料、核验方式、协议呈现、已有账号去向、注册成功落点；默认推荐沿用邮箱，具体交互待讨论。
- **前端交付**：独立讨论注册视图；字段说明、密码可见性、错误就近反馈、提交状态、协议入口；手机键盘下按钮可达。
- **后端逐项实现**：注册合同、唯一身份约束、密码安全存储、滥用限制、注册/核验状态及幂等；新旧用户沿用稳定owner映射。
- **重点验收**：重复邮箱并发只创建一个身份；响应丢失再次提交不重复建号；非法输入/协议未满足/网络失败准确反馈；不记录密码。
- **依赖与详细设计**：RB-00；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第47、46章。

<a id="rb-02"></a>

### RB-02 登录页与退出

- **讨论**：登录方式、自动填充、会话时长和多设备策略、账号异常提示、登录后的安全返回位置。
- **前端交付**：登录视图、输入保留范围、禁用/恢复、退出及会话失效后的重新登录；不丢失受保护的书稿草稿。
- **后端逐项实现**：认证、会话签发/撤销、Cookie与请求防护、限流、服务端角色检查；安全校验回跳目标。
- **重点验收**：错误凭据、暂停账号、过期会话、重复退出、恶意外站回跳、作者访问后台；退出后旧会话不可继续写。
- **依赖与详细设计**：RB-01；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第47、46章。

<a id="rb-03"></a>

### RB-03 账号核验与找回密码

- **讨论**：核验/找回入口、邮件到达体验、重发与过期、找回后的登录方式；短信或第三方登录不默认新增。
- **前端交付**：依次讨论申请找回、核验结果、重置密码三个视图；不把可枚举邮箱的内部情况暴露给访客。
- **后端逐项实现**：一次性凭证的安全存储、有效期/用途绑定、发送限额、消费防重、新密码与会话撤销事务；邮件适配器和发送回执。
- **重点验收**：过期/已使用/错用途链接无效；并发消费仅一次；发送失败不伪装成功；无真实邮件通道只能标未验证，不可宣称已可找回。
- **依赖与详细设计**：RB-02；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第47、46章。

<a id="rb-04"></a>

### RB-04 个人资料与账号安全

- **讨论**：昵称、联系资料修改、改密、设备会话、账号注销入口与保留政策；不将永久删除混作退出。
- **前端交付**：先资料页，再安全页逐个讨论；变更需当前身份证明、重认证和明确结果；设备可辨认。
- **后端逐项实现**：资料版本、身份变更核验、会话管理与安全审计；删除申请/冷静期等只按确认政策实施。
- **重点验收**：撞邮箱、旧核验迟到、并发改密、撤销其他设备、未授权修改、注销取消；永久删除仍走专门授权流程。
- **依赖与详细设计**：RB-03；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第47、46章。

<a id="rb-05"></a>

### RB-05 公共说明、协议与帮助入口

- **讨论**：访客看到什么、产品承诺、服务/隐私/AI说明、客服方式；不制造与实际能力不符的宣传页。
- **前端交付**：逐个讨论必要公共视图与协议阅读；未登录可访问必要帮助，注册返回不清空非敏感输入。
- **后端逐项实现**：协议版本与必要接受记录、内容发布来源；公开/登录权限分离、联系渠道配置。
- **重点验收**：失效链接、离线或加载失败、旧协议留证、无障碍阅读；法务内容需适用性核实，不能用模板冒充审定。
- **依赖与详细设计**：RB-02；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第6、49、51章。

<a id="rb-06"></a>

### RB-06 全局外壳、导航与系统状态

- **讨论**：保留现有视觉风格；登录后起点、移动导航、返回路径和书籍上下文；具体菜单逐页定稿。
- **前端交付**：共享布局、焦点/键盘、加载/空/错误/404/无权限/维护视图、缓存更新提示；不是额外制造几十个页面。
- **后端逐项实现**：错误合同、会话状态查询、请求关联、版本兼容与路由保护；隐藏内部堆栈。
- **重点验收**：深链接、刷新、前进后退、换账号、手机旋转和键盘；旧静态缓存与新API兼容；共享修改回归所有实际受影响页。
- **依赖与详细设计**：RB-02；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第16—18章。

<a id="rb-07"></a>

### RB-07 书架页

- **讨论**：书籍卡片信息、排序/搜索、继续创作、归档与恢复、旧书入口；不默认物理删除。
- **前端交付**：空书架、加载、长书名、多书、归档区和恢复；每个入口明确当前书和可继续的位置。
- **后端逐项实现**：书籍列表/检索/分页、owner隔离、归档恢复、进度投影及新旧引擎路由。
- **重点验收**：跨账号书籍不可读；重复归档/恢复安全；过期搜索响应不覆盖新结果；旧书不能误走新写入引擎。
- **依赖与详细设计**：RB-06；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第8、16、58章。

<a id="rb-08"></a>

### RB-08 手动新建小说页

- **讨论**：最少必填、题材可选范围、暂定书名、是否跳过AI、草稿保存和成功去向。
- **前端交付**：可直接创建空作品并进入手写；失败保留非敏感输入；已有草稿与新建意图区分。
- **后端逐项实现**：幂等建书、作者原始意图版本、初始化书籍/章节目录、草稿归属和清理策略。
- **重点验收**：连点/刷新/网络中断不重复建书；切账号不串草稿；无AI额度仍按已确认政策可手写；未确认计划不冒充正式设定。
- **依赖与详细设计**：RB-07；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第9、22章。

<a id="rb-09"></a>

### RB-09 章节目录、手写编辑与版本

- **讨论**：目录与编辑区关系、保存反馈、章节排序、手动保存/自动保存、冲突处理、正文历史；不先强迫完成全书AI设计。
- **前端交付**：先目录，再编辑和版本比较视图；能新建章节、连续输入、保存、刷新读取和定位历史版本。
- **后端逐项实现**：正文完整版本、草稿修订号/乐观并发、幂等保存、接受身份、删除归档和目录稳定ID；预留正式化事件但未就绪不开放依赖生成。
- **重点验收**：中文输入法、网络断连、两设备编辑、保存响应丢失、旧请求晚到、切书；作者文字不被旧草稿或AI覆盖。
- **依赖与详细设计**：RB-08；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第14、18、23、29章。

<a id="rb-10"></a>

### RB-10 阅读与基础正文导出

- **讨论**：阅读布局、章节顺序、下载范围、是否含草稿；首批格式按用户需要确定，不提前承诺所有格式。
- **前端交付**：阅读视图与明确版本的导出入口；长文可读、空书/部分章节/失败下载有说明。
- **后端逐项实现**：固定正文版本快照、权限下载、编码与文件名、大小限制；导出结果不随着后台更新混入不同版本。
- **重点验收**：导出章节与所选版本逐项一致；跨书下载被拒；长文不截断；下载中断可恢复或安全重试。
- **依赖与详细设计**：RB-09；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第20、22章。

<a id="rb-11"></a>

### RB-11 会员与用量页（现有权益）

- **讨论**：当前套餐、有效期、已用/预留/可用、到期后哪些功能仍可用、费用不足后如何回原任务。
- **前端交付**：清楚显示权益与任务用量，避免把额度不足写成模型故障；保留现有开书返回与恢复体验。
- **后端逐项实现**：唯一会员/账务来源、稳定owner映射、有效期与额度查询；历史已售权益和流水兼容。
- **重点验收**：临界到期、用量刷新、并发预留投影、管理员测试权益；读书/导出是否受限必须按讨论结果验证。
- **依赖与详细设计**：RB-04；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第35、41、47章。

<a id="rb-12"></a>

### RB-12 后台登录、权限和基础用户操作

- **讨论**：后台入口、管理员身份、可见范围、必要操作确认；独立后台视觉逐页讨论。
- **前端交付**：后台登录/退出与外壳；最小用户查找、账号状态查询/修改页面供后续内部验证。
- **后端逐项实现**：服务端管理权限、会话撤销、操作审计、最小数据投影；不存在前端隐藏就等于授权的捷径。
- **重点验收**：普通作者访问每个管理接口都受保护；自锁管理员风险有政策；暂停账号立即按合同限制访问；不输出凭据。
- **依赖与详细设计**：RB-02；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第46、50章。

<a id="rb-13"></a>

### RB-13 后台会员办理与账务基础

- **讨论**：保留已有办理/续费/撤销能力、人工实收与测试权益区别、可纠错方式。
- **前端交付**：最小会员办理和流水视图逐一讨论；显示变更前后、实际收入与办理结果。
- **后端逐项实现**：幂等办理、不可变权益流水、预留/消耗/释放接口、事务与审计；若跨库存储，验证回执和补偿。
- **重点验收**：并发续费/重复点击不重复加量；0元测试不伪装收入；已用权益撤销有规则；对账总额一致。
- **依赖与详细设计**：RB-11、RB-12；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第41、47、48、50章。

<a id="rb-14"></a>

### RB-14 持久化任务执行基础

- **讨论**：内部能力，解释它如何避免刷新、重启后丢任务；无需老板选择锁或队列字段。
- **前端交付**：不另造后台大屏；为下一任务页提供真实状态和恢复合同。
- **后端逐项实现**：逐项实现任务登记→原子领取/租约→检查点→终态/恢复关联→outbox；数据库选择、队列持久化及新旧执行器边界在本批冻结。
- **重点验收**：进程崩溃、租约过期、重复领取、迟到写入、取消竞争、未知远端结果；同一业务副作用至多提交一次。
- **依赖与详细设计**：RB-00、RB-09；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第36—40章。

<a id="rb-15"></a>

### RB-15 任务预算与计费闭环

- **讨论**：作者可理解的预计/上限/已用，哪些失败收费；只采用已确认商业政策。
- **前端交付**：供会员页、任务页和调用前提示复用，不新增重复余额。
- **后端逐项实现**：逐项实现预留→消费授权→供应商usage→内部入账→释放/核对；总任务尝试与成本边界、并发账户限额。
- **重点验收**：重启任一步、迟到usage、重复回执、预留失效、远端未知；供应商可能收费不等于内部可以重复扣用户额度。
- **依赖与详细设计**：RB-13、RB-14；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第35、41章。

<a id="rb-16"></a>

### RB-16 模型网关与最小Agent配置

- **讨论**：任务需要哪些能力，配置与模型选择由开发者提出；不把固定成员数当质量保证。
- **前端交付**：调用状态和简短错误反馈；先具备受保护的最小配置/诊断能力，完整后台在RB-48。
- **后端逐项实现**：调用适配、能力校验、冻结参数与配置版本、流式/结构化输出校验、全局重试上限、限流熔断、调用审计。
- **重点验收**：超时/截断/错误格式/不兼容参数/供应商限流/结果未知；必要真实探针，不能把模拟调用当真实完成。
- **依赖与详细设计**：RB-14、RB-15；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第30、31、34章。

<a id="rb-17"></a>

### RB-17 上下文、来源与检索基础

- **讨论**：什么资料可用于哪种任务、作者隐私与候选边界；技术裁剪方案由开发者负责。
- **前端交付**：提供可读的资料不足/资料更新提示；不向作者展示内部来源键。
- **后端逐项实现**：最小可信资料编译、owner/book/version范围、来源ID合同、token预算、召回后语义判断、历史/候选用途标记。
- **重点验收**：跨书资料、缺来源编号、过期版本、伪指令资料、预算截断、名字歧义；完整原文与派生摘要不可互换权威。
- **依赖与详细设计**：RB-09、RB-16；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第23—25、30—33章。

<a id="rb-18"></a>

### RB-18 任务中心与任务详情

- **讨论**：列表显示什么、查看已有成果、取消/继续/重新尝试区别、失败后的原位恢复。
- **前端交付**：先列表再详情；刷新和切页保持状态，部分成功可查看，未知结果有可执行去向。
- **后端逐项实现**：统一任务投影、事件游标/轮询恢复、分页和权限、取消命令、检查点恢复及关联新任务。
- **重点验收**：无任务/排队/运行/部分成功/待确认/失败/未知/取消；状态与后端一致；多标签页连点不重复收费。
- **依赖与详细设计**：RB-06、RB-14、RB-15；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第21、36—40章。

### RB-19 AI开书页与结果采用

- **后端逐项实现**：冻结原始意图、资料策划与开书任务、候选版本、采用事务、失败检查点；按当前确认范围生成必要资料。
- **重点验收**：长输入/空输入/部分成员失败/响应丢失/重复采用/会员不足；保留成功结果，不重跑整段已完成工作。
- **依赖与详细设计**：RB-08、RB-16、RB-17、RB-18；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第7、9、30—35章。

### RB-20 作品信息与开书资料编辑

- **后端逐项实现**：作品资料版本、来源关联、变更事件、依赖失效和冲突检测。
- **重点验收**：并发保存、旧版本覆盖、改变题材后旧任务迟到；只影响相关依赖，不全书无差别重跑。

### RB-21 设定页

- **重点验收**：少量设定可继续的规则明确；重复确认、部分失败、旧审查永久阻断、候选冒充正式内容均验证。

### RB-22 全书蓝图与方向页

- **后端逐项实现**：蓝图版本、规划对象稳定ID、父子归属、采用回执与下层失效；多方案按需生成。
- **重点验收**：上层变更、重复采用、并发设计、过期方案；不把新规划当作已经发生的正文事实。

### RB-23 卷设计页

- **讨论**：卷负责阶段全局：人物/对手、主支线、因果、信息揭示、伏笔、资源/空间和结尾承接；具体内容逐项讨论。
- **前端交付**：本卷全案、候选/编辑/确认、下层导航与卷结算入口；不堆满内部工程字段。
- **后端逐项实现**：卷规划独立责任合同、上层约束、实际前情、方案版本和下层依赖；不复用一份同义表单冒充不同层。
- **重点验收**：跨卷前情、上卷未结关键事实、计划偏离、单候选/多候选/部分成功；卷确实承担全局设计而非只列标题。
- **依赖与详细设计**：RB-22；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第12章。

### RB-24 链/故事单元页

- **讨论**：链是否保留名称与独立页面、如何变轻、与卷/章边界；本项是讨论单元，不预定必须有链页。
- **前端交付**：若保留，展示当前局部故事目标、转折和章节入口；若合并，明确能力和旧链接去向。
- **后端逐项实现**：局部单元规划、活动卷关联、前后承接、完成状态；不得重做全套世界/人物设计。
- **重点验收**：跨单元承接、伸缩章节数、与卷冲突、重复信息；合并页面后能力与恢复入口不丢。
- **依赖与详细设计**：RB-23；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第13章。

<a id="rb-25"></a>

### RB-25 章计划与章节安排

- **讨论**：章纲粒度、近期滚动规划、插章/移章、作者改纲、无章纲手写和AI续写条件。
- **前端交付**：章列表/计划编辑视图逐一讨论，计划与已写状态清楚；支持自由文字而非固定章数菜单。
- **后端逐项实现**：章节稳定ID、排序版本、父单元关联、计划修订、生成就绪条件。
- **重点验收**：插入/调整顺序后版本引用不串；旧计划任务不能覆盖新纲；不把章节编号当不可变身份。
- **依赖与详细设计**：RB-24；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第14章。

<a id="rb-26"></a>

### RB-26 AI正文生成

- **讨论**：生成入口、字数/风格意图、续写/重新生成、是否多主笔、候选呈现；先完成一条真实可用路径。
- **前端交付**：在已验收编辑区接入生成；任务状态、草稿阅读、部分结果、采用前手改；不让流式文字假装已存档。
- **后端逐项实现**：生成合同、上下文冻结、正文候选完整版本、任务检查点、有限修补与费用记录。
- **重点验收**：截断/中断/迟到、多个候选隔离、编辑与生成并发、写错角色知识；本项未到RB-29前不开放自动连续生成。
- **依赖与详细设计**：RB-25；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第14、18、30—35章。

<a id="rb-27"></a>

### RB-27 审查、比较与定向重写

- **讨论**：作者如何理解问题、哪些必须处理、可忽略的文学建议、改写范围与比较方式。
- **前端交付**：审查问题定位原文、选择修订、全文/局部对比、保留原稿；子视图逐个讨论。
- **后端逐项实现**：确定性校验与语义审查分工、版本绑定、审查证据、定向改写合同和过期审查处理。
- **重点验收**：审错版本、误报/漏报样本、局部改写扩散、同模型冒充独立复核；用真实阅读验证可用性。
- **依赖与详细设计**：RB-26；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第18、34章。

<a id="rb-28"></a>

### RB-28 采用正文与结算确认

- **讨论**：作者采用一次应发生什么、正文已保存但整理未完成怎么显示、哪些状态允许继续。
- **前端交付**：采用/采用并继续的区别、正式版本与整理状态、失败时已保存结果说明；不增加无意义后台步骤按钮。
- **后端逐项实现**：采用回执与outbox原子提交、提取/校验/覆盖检查、衍生证据、结算提交和幂等。
- **重点验收**：重复采用、提交后断电、提取遗漏、整理失败；作者正文已安全保存，未核实事实不能当就绪。
- **依赖与详细设计**：RB-27；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第23—27章。

<a id="rb-29"></a>

### RB-29 连续创作与长期记忆

- **讨论**：下一章所需事实、待核问题、人物认知与读者信息；不要求作者手动维护每张账。
- **前端交付**：必要阻断、自动更新结果、原文来源和恢复入口；第二章起就检查连续性。
- **后端逐项实现**：增量事实/人物/故事状态、依赖水位、时间/视角、事件防重、追赶与纠正。
- **重点验收**：借物与所有权、死亡/身份暴露、倒叙、旧计划冲突、改一句事实后的影响；连续几章真实阅读及故障恢复同时验证。
- **依赖与详细设计**：RB-28；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第24—29、33、34章。

<a id="rb-30"></a>

### RB-30 时光机总览与调整

- **讨论**：总览看计划还是实际、时间尺度、点击去向、调整的范围与成本；不另建重复权威数据。
- **前端交付**：全书/卷/单元/章进度，计划与实际区分，定位、折叠和调整预览；手机长图不迫使横向找按钮。
- **后端逐项实现**：只读投影、准确版本/进度/失败来源、调整命令转对应领域；分页/局部加载。
- **重点验收**：历史失败不能盖住正式成果；切卷/旧链接/部分规划缺失可读；大书性能按实际规模测。
- **依赖与详细设计**：RB-29；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第19、28、29章。

<a id="rb-31"></a>

### RB-31 资料库与来源详情

- **讨论**：正文、设定、计划、事实、参考资料的分类与检索；搜索词与AI问资料的区别。
- **前端交付**：目录/搜索、结果、详情/原文跳转逐页讨论；来源、时间、版本清楚，可从正文回到资料。
- **后端逐项实现**：统一权限检索、索引版本、可重建投影、引用定位、精确与语义检索的分工。
- **重点验收**：查无结果、同名实体、过期索引、删除/归档、跨书引用；索引故障不毁源文。
- **依赖与详细设计**：RB-29；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第20、23、33章。

<a id="rb-32"></a>

### RB-32 人物详情与人物维护

- **讨论**：人物档案、别名、关系、当时状态/认知、作者修正；不能以永久标签限制人物变化。
- **前端交付**：人物列表/详情/修改逐个讨论；显示依据正文和推荐更新的区别。
- **后端逐项实现**：实体身份与别名、时间/版本化状态、人工纠正候选、关系来源及历史查询。
- **重点验收**：同名不同人、改名、假身份、组织变化、人物死而复生误提取；修正不擦掉原证据。
- **依赖与详细设计**：RB-31；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第15、24、28章。

<a id="rb-33"></a>

### RB-33 故事线、关系、伏笔与开放问题

- **讨论**：作者真正需要的查看/筛选/修改能力，列表与图谱取舍；不为展示技术堆复杂图。
- **前端交付**：先清楚列表/详情，再讨论是否增加关系图；回收状态和未解问题有依据。
- **后端逐项实现**：关联实体、事件与来源、计划/实际分类、回收责任、增量维护和更正。
- **重点验收**：计划提到不等于已埋下；提及不等于回收；多线冲突/误合并/重复抽取；高级图后置不丢基础功能。
- **依赖与详细设计**：RB-32；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第12、15、24、28章。

### RB-34 命名与封面工作室

- **讨论**：书名、人物/地名命名和封面分别讨论；保留现有满意能力，生成/上传/采用/下载各自清楚。
- **前端交付**：按命名页→封面页顺序拆子项；候选比较、原图查看、采用当前封面与下载。
- **后端逐项实现**：文本/图像任务、文件来源/权限、尺寸与格式校验、采用版本、防重与费用。
- **重点验收**：部分生成失败、图片失效/过大、重复采用、跨书下载；新增图像服务或付费须相应授权。
- **依赖与详细设计**：RB-20、RB-16、RB-18；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第22、30章。

<a id="rb-35"></a>

### RB-35 完整导入与导出

- **讨论**：导入已有正文还是参考材料、格式优先级、拆章预览、冲突处置和导出包含内容。
- **前端交付**：依次讨论导入预览/进度/结果与导出设置；不直接将上传文本当新书已接受正文。
- **后端逐项实现**：安全解析、上传限额、用途和归属、导入批次防重、版本映射、异步大文件与完整性校验。
- **重点验收**：重复文件、乱码/损坏/超限、同名章、半途失败、恶意附件；导出只含所选授权版本；不恢复已废弃旧产品。
- **依赖与详细设计**：RB-10、RB-31；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第22、58章。

<a id="rb-36"></a>

### RB-36 历史修订、分支与影响预览

- **讨论**：已写章节怎么改、是否需要分支、如何保留原故事和选择受影响修订；作者控制范围先确定。
- **前端交付**：版本比较、影响预览、修订方案/采用按子页面讨论；先展示影响再产生高成本修订。
- **后端逐项实现**：依赖图、正文新版本、事实重新提取、分支读写隔离、活动版本切换与审计。
- **重点验收**：小改字数却改变赠予/借用；旧任务迟到；后文不可被静默删除；切回旧线不丢新线正文。
- **依赖与详细设计**：RB-29、RB-33；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第29章。

<a id="rb-37"></a>

### RB-37 有界托管与自动连续写作

- **讨论**：授权写多少/到何时/花多少、哪些可自动采用、何时停、作者随时接管；不默认全程无限托管。
- **前端交付**：托管设置、运行、暂停/接管、完成摘要依次讨论；全部显示实际已完成与未完成。
- **后端逐项实现**：可撤销授权记录、循环状态、检查点、预算总界、关键事实就绪、暂停/取消与迟到结果规则。
- **重点验收**：配额耗尽、质量连续未过、人工编辑、暂停与自动采用竞争、恢复重启；不把沉默伪装人工确认。
- **依赖与详细设计**：RB-29、RB-36；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第7、35—41章。

<a id="rb-38"></a>

### RB-38 创作团队页

- **讨论**：保留成员形象，哪些选择对作者有价值、岗位/模型如何准确表达、失败状态怎么说。
- **前端交付**：团队介绍与可用配置视图；信息简短，实际执行成员/模型与展示一致。
- **后端逐项实现**：能力目录、书/任务级策略、配置版本与权限；不让前端任意指定未授权模型或预算。
- **重点验收**：下线成员、配置更新中任务、同模型多角色表述；切成员不绕过未知结果和总费用上限。
- **依赖与详细设计**：RB-16、RB-18；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第30、31章。

<a id="rb-39"></a>

### RB-39 卷结束与全书完结

- **讨论**：完成条件、未解问题提示、总结/续卷/完结与重新打开；不靠计划章数决定实际结束。
- **前端交付**：卷总结和完结视图逐一讨论，正文可继续阅读导出；未处理问题明确但不机械阻止作者选择。
- **后端逐项实现**：状态转换、实际摘要、托管排程停止、版本留存与安全重开。
- **重点验收**：还有运行任务时完结、重复完结、重开、归档差异；不能因完结清空记忆或删除正文。
- **依赖与详细设计**：RB-29、RB-30；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第12、15、24章。

<a id="rb-40"></a>

### RB-40 通知、反馈与使用帮助

- **讨论**：通知渠道/频率、反馈带哪些诊断、回复入口；先保留反馈，再讨论站内通知等新增能力。
- **前端交付**：依次讨论反馈表单/历史详情、通知列表、帮助内容；不要求作者复制内部ID才能报错。
- **后端逐项实现**：反馈权限、最小诊断关联、通知防重/已读、偏好、投递审计；外部消息仅在授权渠道内。
- **重点验收**：重复反馈、书籍归属错误、通知迟到/重复、失败任务恢复深链接；正文不自动外发。
- **依赖与详细设计**：RB-18；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第21、49章。

<a id="rb-41"></a>

### RB-41 作者购买、订单与售后

- **讨论**：套餐价格/权益、购买续费退款规则、支付渠道和客服；实际商业条款需老板决定，不写虚假默认价格。
- **前端交付**：依次讨论套餐页、确认订单、支付结果、订单详情/历史、售后申请；未接通不展示可付款假按钮。
- **后端逐项实现**：价格快照、订单幂等、验签回调、关单/迟到付款、权益履约与退款/对账；真实通道单独授权。
- **重点验收**：重复/乱序回调、付费成功未到账、关单后付款、重复退款、退款与已消耗权益；禁止只信前端支付成功。
- **依赖与详细设计**：RB-11、RB-13、RB-15；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第47—49章。

<a id="rb-42"></a>

### RB-42 后台运营总览

- **讨论**：真正需要的健康、活跃、任务、成本指标和统计时间口径；不展示没有证据的成功率。
- **前端交付**：总览页、异常下钻、筛选/时间范围；真实值与无数据区分。
- **后端逐项实现**：指标来源、时区/分母、快照/聚合、查询权限及可追溯明细。
- **重点验收**：跨天/跨时区、迟到数据、空数据、重复事件；指标可与来源样本核对，慢查询不拖垮写作。
- **依赖与详细设计**：RB-12、RB-29；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第50、55章。

<a id="rb-43"></a>

### RB-43 后台用户与书籍

- **讨论**：客服可以看哪些数据、暂停/恢复、书籍定位、临时支持授权；不默认所有人员随意读正文。
- **前端交付**：用户列表→详情→书籍详情分别讨论，展示必要权益/任务/状态，危险操作说明影响。
- **后端逐项实现**：搜索分页、最小权限、会话撤销、管理审计和敏感数据访问记录。
- **重点验收**：越权、分页遗漏、并发操作、误封恢复、已注销账号；不得通过管理API绕过正文不可变规则。
- **依赖与详细设计**：RB-12、RB-39；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第46、50章。

<a id="rb-44"></a>

### RB-44 后台会员、订单与退款

- **讨论**：人工办理与线上支付如何核对、退款/纠错权限、实收收入与赠送权益分开。
- **前端交付**：逐页讨论会员详情、订单列表/详情、退款处理和对账异常；操作需可审计。
- **后端逐项实现**：统一账务、支付凭据、履约补偿、退款幂等和审计；不直接编辑历史余额掩盖错误。
- **重点验收**：重复补单、部分退款、回调晚到、账差、不足权限；无真实资金授权时只做隔离验证。
- **依赖与详细设计**：RB-13、RB-41；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第41、48、50章。

<a id="rb-45"></a>

### RB-45 后台算力与成本

- **讨论**：按用户/书/任务/模型看哪些消耗，如何处理未知成本与内部补偿。
- **前端交付**：成本总览和调用明细分别讨论，预估/实际/待核对明显区分。
- **后端逐项实现**：供应商usage归集、内部账务映射、费率版本、异常检测与受控导出。
- **重点验收**：一个调用多回执、费率变化、失败仍有费用、迟到账单；用户收入不等于供应商成本。
- **依赖与详细设计**：RB-15、RB-42；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第35、41、50章。

<a id="rb-46"></a>

### RB-46 后台创作运行与恢复

- **讨论**：客服/运维如何定位卡住任务、能做什么恢复、已完成结果在哪；不提供无界全量重试。
- **前端交付**：任务列表→执行详情→恢复预览逐页讨论，展示真实阶段和审计。
- **后端逐项实现**：任务/attempt/调用/检查点关联、恢复权限、防重和新旧执行器归属。
- **重点验收**：批量误操作、未知结果重发、失效租约、停止与完成竞争；恢复不改作者选择或伪造终态。
- **依赖与详细设计**：RB-18、RB-29；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第36—40、50章。

<a id="rb-47"></a>

### RB-47 后台问题记录与处理

- **讨论**：失败和反馈如何归并、处理/回复/关闭/重新打开的含义；问题关闭不等于任务成功。
- **前端交付**：问题列表、详情与处理记录逐页讨论，能定位原作者入口和已保存成果。
- **后端逐项实现**：故障/反馈关联、状态审计、脱敏诊断、处理权限与通知联动。
- **重点验收**：错误关联、重复问题、已修复但未验证、重新发生；不删除事故证据来美化统计。
- **依赖与详细设计**：RB-40、RB-46；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第49、50章。

<a id="rb-48"></a>

### RB-48 后台成员、模型与任务策略

- **讨论**：谁能改模型/预算/岗位策略、如何试验/发布/撤回；保留实际成员能力而非固定名册。
- **前端交付**：成员列表、配置详情、策略设置按页讨论；敏感值不返回前端。
- **后端逐项实现**：配置schema、版本、适配能力校验、隔离探针、发布/回退和任务快照。
- **重点验收**：参数不兼容、模型不可用、修改进行中任务、超预算策略；新密钥只在安全配置通道处理。
- **依赖与详细设计**：RB-16、RB-38；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第30、31、50章。

<a id="rb-49"></a>

### RB-49 后台提示词与上下文

- **讨论**：提示词草稿、预览、发布、历史、上下文审计如何使用；不展示思维链。
- **前端交付**：资产列表→编辑/预览→版本比较→任务上下文详情逐个讨论。
- **后端逐项实现**：版本发布、防重、用途权限、快照清单、重建校验、回退草稿和脱敏。
- **重点验收**：错版本发布、旧任务重建、跨书资料、敏感值泄漏；回退配置不能改写已执行快照。
- **依赖与详细设计**：RB-17、RB-48；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第32、33、50章。

<a id="rb-50"></a>

### RB-50 后台创作资产总览

- **讨论**：资产有哪些、来源/用途、真实启用数量和缺口；总览不伪装生产质量评分。
- **前端交付**：资产导航/总览页，能进入方法、模式、配方、规划与版本明细。
- **后端逐项实现**：目录聚合、来源/许可证元信息、版本与引用计数。
- **重点验收**：显示统计可追溯；停用资产历史仍可读；不能仅靠登记宣称功能有效。
- **依赖与详细设计**：RB-48；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第15、30、50章。

<a id="rb-51"></a>

### RB-51 后台叙事方法

- **讨论**：方法的查找、适用性、组合与版本维护；它是参考，不是强制创作模板。
- **前端交付**：方法列表/筛选/详情/编辑按子页讨论，是否可编辑据实际需求决定。
- **后端逐项实现**：方法资产版本、来源、校验、检索与发布权限。
- **重点验收**：同名歧义、缺来源、旧版本引用、禁用方法；不能按关键词直接给文学结论。
- **依赖与详细设计**：RB-50；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第15、30、32章。

<a id="rb-52"></a>

### RB-52 后台剧情模式

- **讨论**：剧情模式如何辅助创作、分类/搜索、避免死套桥段；不默认每故事必须选模式。
- **前端交付**：模式列表/详情/维护依次讨论；清楚展示适用条件与局限。
- **后端逐项实现**：模式结构、版本、组合约束和引用记录。
- **重点验收**：分类漏召回、组合冲突、修改已用模式；历史任务可复现原输入。
- **依赖与详细设计**：RB-51；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第15、30章。

<a id="rb-53"></a>

### RB-53 后台剧情配方

- **讨论**：配方与模式/方法如何区别、组合/自定义/停用；不得成为固定章节配额。
- **前端交付**：配方列表/详情/组合编辑分别讨论；重复信息合并。
- **后端逐项实现**：组合引用、版本依赖、合法性检查、发布/停用与回滚。
- **重点验收**：引用失效、循环依赖、缺资产、旧快照；停用不破坏现有书和任务。
- **依赖与详细设计**：RB-52；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第15、30章。

<a id="rb-54"></a>

### RB-54 后台分层规划诊断

- **讨论**：后台如何检查全书/卷/链责任和数据来源；演示与真实书籍必须区分。
- **前端交付**：规划审计与具体执行详情分别讨论，不硬编码某个模型/成员数作为事实。
- **后端逐项实现**：版本树、父子约束、实际资料使用与运行投影、权限及脱敏。
- **重点验收**：示例不冒充线上状态；错层引用、历史任务、已改规划可追溯。
- **依赖与详细设计**：RB-23、RB-24、RB-53；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第11—14、50章。

<a id="rb-55"></a>

### RB-55 后台功能台账与上线能力

- **讨论**：哪些功能是配置、实现、验证或上线状态，管理员需要哪些核查入口。
- **前端交付**：能力列表与证据详情；不可用能力不能显示已完成，不能作为作者功能开关的唯一证据。
- **后端逐项实现**：能力注册/发布版本/证据引用和审计；项目开发进度仍只在本执行表维护，不双向自动伪同步。
- **重点验收**：仅有字段/测试/旧发布记录的状态准确区分；禁用入口不产生孤立任务。
- **依赖与详细设计**：RB-54；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第50、52章。

<a id="rb-56"></a>

### RB-56 运行配置、监控、备份与恢复

- **讨论**：告警通知与处理责任、维护窗口、备份/恢复可用目标；数值先测量再承诺。
- **前端交付**：如需运维页面，先逐页讨论；不能把危险运维命令直接暴露作者端。
- **后端逐项实现**：配置管理、日志/指标/告警、备份校验、恢复演练、容量限制、健康探针、灰度和发布脚本。
- **重点验收**：隔离库恢复、磁盘不足、依赖失效、告警送达、旧资源缓存；恢复生产数据需具体授权。
- **依赖与详细设计**：RB-14、RB-45、RB-46；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第46、50、54—56章。

<a id="rb-57"></a>

### RB-57 旧账号、权益、书籍迁移

- **讨论**：用户迁移提示、旧书能力一致性、只读期与失败退回体验；不把升级等于同意丢历史。
- **前端交付**：如需要迁移状态页逐个讨论；旧链接、书籍入口和受影响能力明确。
- **后端逐项实现**：按账号/账务/书分边界迁移，ID映射、校验、路由权威、在途任务归属；各书依赖必须全数就绪。
- **重点验收**：所有正文版本/回执/权益总额/附件与任务历史核对，重复迁移安全；新写入后的回退方案必须真实可行。
- **依赖与详细设计**：RB-39、RB-44、RB-56；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第58章。

<a id="rb-58"></a>

### RB-58 全产品集成、质量与容量验收

- **讨论**：商用范围、支持设备、实际并发/书长/等待目标；完整范围未过不能叫全部重构完成。
- **前端交付**：逐页巡检及跨页完整用户旅程，真实模型阅读、手机输入、错误/恢复和多设备流程。
- **后端逐项实现**：权限/账务/任务/版本贯通，迁移恢复、负载/长时间运行、限流和可观测性。
- **重点验收**：注册→登录→建书→连续写作→回改→导出；购买→到账→消费→售后；管理员处理故障；按风险门禁补足独立模块测试发现不了的问题。
- **依赖与详细设计**：RB-57；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第52—55章。

<a id="rb-59"></a>

### RB-59 分批试用、上线与线上观察

- **讨论**：先哪些账号/新书、观察多久、扩大条件和回退条件；每次上线有具体授权范围。
- **前端交付**：试用入口与生产入口可辨，必要升级说明和支持通道；保持原视觉风格。
- **后端逐项实现**：不可见构建、备份、迁移预检、任务安全窗口、逐服务切换、线上冒烟与指标观察。
- **重点验收**：没有部署记录/线上检查不能标上线；持续观察错误/费用/恢复/阅读反馈，试用通过不直接证明万人并发。
- **依赖与详细设计**：RB-58；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第55、56、58章。

<a id="rb-60"></a>

### RB-60 旧实现退出与重构结项

- **讨论**：全部能力去向是否兑现、延期/取消项是否明确、旧用户能否完成原任务。
- **前端交付**：清理已替代入口并保留必要跳转，不删除未替代有效功能。
- **后端逐项实现**：检查路由、动态注册、任务、数据读写、脚本与测试引用；保留历史迁移、作者资产和回滚证据。
- **重点验收**：全部范围能力已验收/上线或有明确取消决定；无未处置阻断缺陷，迁移/回滚证据完整，后续维护入口可用。
- **依赖与详细设计**：RB-59；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第58、61章。

<a id="rb-61"></a>

### RB-61 推广、邀请与其他商业扩展

- **讨论**：仅为待决范围：邀请码/推广结算/提现、剧本等是否实际做；现有能力若发现需保护，不因排最后自动删除。
- **前端交付**：只有确认需要的独立页面才拆子项讨论、实现；未决定不生成假入口。
- **后端逐项实现**：确认后定义归因、防刷、账务/提现、权限、凭据和第三方边界。
- **重点验收**：真实资金/监管条件与渠道未满足不得启用；用户明确暂缓/取消后才能从当前交付范围移出。
- **依赖与详细设计**：RB-41、RB-44；[详细规格](REBUILD_DEVELOPMENT_SPEC.md)第49、62章。

## 7. 后端按功能实施的顺序与责任

这张表只说明后端责任和首次交付单元，不另记第二份进度。后端状态始终看第5节对应行。先写合同和数据约束，再实现服务/仓储/API，最后接页面；不能让一个巨型控制器同时承担全部领域。

| 后端责任 | 首次需要 | 分步结果 | 后续消费者 |
| --- | --- | --- | --- |
| 身份/会话/角色 | RB-01—RB-03 | 凭据→账号→会话→核验/恢复→权限 | 全部作者与后台接口 |

## 9. 每一页真正开工时的合同

沿用[开发流程](DEVELOPMENT_WORKFLOW.md)的相称合同；以下为全产品逐页重构需要补齐的内容，不额外建立第二套审批。当前单元首次进入正式讨论/实施时创建一份文件，例如`coauthoring-v7/docs/worklists/RB-01-REGISTRATION.md`（示例路径，尚未创建），随后在总表链接它。该文件同时保存本页定稿和实现证据，不复制另一份“最终版”。

### 9.1 页面定稿内容

1. **用户目标**：谁来、从哪里来、要完成什么、成功后去哪里。
2. **本页范围与去向**：保留/合并/替代的旧能力；明确不在本页处理的内容。
3. **视觉与交互**：已有视觉样本、信息顺序、字段含义、主次操作、移动端键盘/返回/刷新；必要草图或原型。
4. **实际状态**：初始、加载、提交、成功、空数据、业务阻断、失败恢复；只列本页存在的状态。
5. **数据与权限**：谁能读写、保存何种版本、敏感数据、跨账号/跨书边界、并发冲突。
6. **后端功能与接口**：请求/响应、错误码/安全文案、幂等、事务/异步边界、超时/取消、重复和迟到处理。
7. **AI专属字段（适用才填）**：任务角色、可信输入、模型/参数、预算/重试上限、输出/采用合同、真实质量验证。
8. **验收例子**：正常成功、至少相关关键失败/边界、旧能力回归、证据类型；固定预期不能迁就后来的实现。
9. **确认与授权**：哪些结论用户已定、哪些由开发者负责、哪些仍待讨论；实施和发布范围分别记录。

不得每次都把全部64章发给用户。讨论时使用用户能判断的大白话给出推荐及理由，把API/SQL等细节留在合同中。若用户只说“这样可以”，按语境判断是认可设计还是授权实施，不制造固定口令，也不擅自扩大。

### 9.2 后端子功能合同

每个子功能回答：输入和身份是什么→读取哪些真实来源→做何种确定性事务或AI判断→写入什么→返回什么→重复/并发/失败怎样恢复→怎么验证。实现顺序推荐：

合同/用例→数据约束与必要迁移→领域服务→仓储/事务或任务→HTTP/事件→前端联调→真实失败验证。不是先写大量没有调用方的表，也不是为了展示页面让接口暂时无条件返回成功。

对依赖不足的演示必须明确“原型/模拟”；不能据此把后端或验收列改成完成。新表、数据库和架构选择按实际任务证据由开发者确定，不需要让老板选择技术名词。

### 9.3 示例：注册页尚待讨论的问题

推荐先保持邮箱注册作为最小路径，避免同时引入手机号和多个第三方渠道。需要在RB-01讨论中说明：首次需要填哪些资料、是否必须完成邮箱核验、注册后进入空书架还是新建小说、协议如何呈现。这些推荐不是本文件定稿。

工程上应提前覆盖：重复账号、大小写/空白处理策略、恶意重试、请求成功但响应丢失、核验链接重放、键盘挡按钮、注册与登录切换、密码不被日志/浏览器持久草稿记录。若所选核验需要未配置邮件服务，先核实现有通道；只有新费用或凭据确实缺失才请求对应授权，不能编造验证码服务。

## 10. 验收、联动回归和发布

### 10.1 分层证据

- 工程层：合同、权限、数据一致性、幂等和相关测试/类型检查/构建。
- 页面层：真实浏览器走过成功及关键失败；手机输入/键盘/刷新/返回与桌面同样可用。
- AI层：真实调用与实际阅读分别记录成本、时延、输出质量和恢复情况；格式正确不等于小说写得好。
- 业务层：跨页结果一致，任务/正文/记忆/会员/订单相互核对。
- 运行层：迁移、恢复、部署、线上观察和容量有实际证据。

具体测试范围仍以[验收标准](ACCEPTANCE.md)为准。不是每页都全量，也不是“只动一页”就忽略其改变的账号隔离、数据语义或核心工作流风险。没有浏览器、邮件、支付或模型环境，完成其他可执行检查并保留未验证状态；不向用户承诺已经商用可用。

### 10.2 防止逐页正确、整体错误

每个新单元同时回归它依赖或改变的已验收行为。例如：改登录回归草稿与账户切换；改导航回归深链接；改模型网关回归当前已接入的AI任务；改会员回归开书阻断和任务恢复；改正文接受回归事实水位和导出；共享组件变化回归所有实际受影响页面。

在RB-10建立第一条手写闭环，在RB-29建立第一条连续AI创作闭环，在RB-41/RB-44形成商业收费闭环；每条路径使用真实后端和隔离数据验收。未经相应发布授权，不给普通作者切换未完整验证的新路径。

### 10.3 缺陷处理

当前单元合同记录问题、复现条件、实际/期望结果、严重性、影响范围、修复及复验。阻断当前页面的问题优先修复，合同外独立问题映射未来单元；发现数据/权限等紧急风险应暂停相关发布并说明，不擅自生产恢复。

“无法复现”不是“已修复”；“已修改”不是“已验证”；“未看见错误日志”不是“所有用户都不会出错”。未解决问题要能被下一位接管者复现和判断。

### 10.4 迁移与上线纪律

现有产品继续按当前生产事实维护。重构在隔离环境逐功能验收；每项需要明确旧数据读写归属和兼容策略，不允许新旧执行器同时处理同一任务、两套账户余额各自扣费、已迁移书回旧页越界写入。

上线以获准的一组单元和具体版本为单位，不强制每讨论一页就发布一次。采用现有[部署规程](DEPLOY.md)中的相关步骤，验证在途任务安全、备份/兼容/回滚与公网状态。新写入后的回退必须保护这些新数据，不能只切代码版本。

### 10.5 全产品重构完成的定义

全范围入口有去向；逐页决定和实现已验收；现有作者资产/权益保留或经验证迁移；关键真实创作与商业路径通过；没有未处置阻断缺陷；已完成获准发布与线上观察；旧实现按退出条件清理；后续维护者能从本表找到实际代码、合同和证据。

建议能力若暂缓或取消，必须有明确范围决定并从“已完成全部目标”声明中排除。不能把“62行都填了文字”或“旧功能仍在旧系统能用”当新系统全部重构完成。
