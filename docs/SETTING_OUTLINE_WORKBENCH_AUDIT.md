# 动态设定大纲设计审查

- `design_review_id`：`DR-20260727-dynamic-setting-outline-v1`
- `release_id`：`wm-longform-r1-20260719-003435-e4d7b8b7`
- Skill：`wenmi-longform-quality`
- 适用范围：设定模板、上下文包、主编/双编剧协作、候选确认、规划UI与书籍级持久化。

## 事实、推断、偏好与未知

- 已确认事实：开书已保存频道、单一分类、题材和软标签；11人团队已有活动主编与两名异模型编剧；SQLite是唯一权威；讨论候选不能自动进入正史。
- 产品偏好：小白作者能沿明确顺序逐项完善；框架尽量完整；缺少项可自定义；点击后无需再次说明讨论主题。
- 工程推断：动态模板可由开书分类确定性生成，只需持久化状态覆盖和自定义项，避免每书复制整套模板。
- 未知：真实模型对不同题材设定问题的方案质量仍需独立样本验证；当前工程测试不能外推文学质量。

## 替代方案

1. 静态标签墙：实现简单，但缺少依赖顺序、状态和行动入口，否决。
2. 所有模板项全部入库：可查询，但每书重复大量相同记录，升级目录困难，否决。
3. 动态模板＋状态覆盖/自定义项入库：保留版本化目录与书籍状态，采用。
4. 只由主编讨论：成本低，但重大设定缺少异模型反例；不满足老板要求，否决。
5. 所有设定都强制双编剧：会浪费Token并过早定型；只在作者点击专项讨论时启用。

## 第一轮：正确性与安全审查

- 痛点：设定清单没有流程，普通讨论可能只激活一人，浏览器缓存可能丢失。
- 机制：顺序化目录、显式命令、主编＋双编剧代码级选择、SQLite作用域记录、候选门禁。
- 反例：含“设定”的普通闲聊不能自动启动专项讨论；无书ID不能读写；讨论结果不能直接成为正史。
- 指标：参与岗位恰为主编和两名编剧；跨书读取为零；刷新后状态一致；无规划/正文产物。
- 回滚条件：跨书、重复任务、错误进入剧情规划或正史。

## 第二轮：创造性与注意力审查

- 痛点：完整模板可能变成必须填满的表格，压缩未知与创意空间。
- 机制：七种状态、软标签声明、仅当前项和最多八项已确认前置进入资料包、未启用模板不限制创作。
- 反例：刻意留白和不适用不算失败；辅助题材不能覆盖主分类；编剧不得在设定讨论中生成剧情或章纲。
- 指标：资料包不含完整目录；同题材至少保留两个有差异的候选；作者可不采纳或稍后处理。
- 证据等级：当前为E2工程行为；真实创造性、合理惊喜和设定质量须多样本盲评后提升。
- 停止条件：候选趋同、上下文膨胀、设定完备主义或真实输出质量低于旧流程。
