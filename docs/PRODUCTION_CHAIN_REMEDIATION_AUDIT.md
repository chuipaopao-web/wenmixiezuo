## 明确结论与置信度

高置信结论：当前代码不是空壳，但多项已实现基础设施尚未进入正式章节生产链，且任务租约、模型调用结果、预算状态与正史结算存在可由故障或并发触发的真实性缺口。应按既定模块化单体、SQLite权威、独立Worker、十一名创作成员和三异模型审校架构补缺，不应照搬“十一岗减为六岗”或删除epoch/接管机制的建议。

高置信保留项包括十一名创作成员、小文秘书、双异模型编剧、主编/主笔候任、三异模型正式点评、H/E/I证据车道、不可变正文和作者确认后入正史。中等置信优化项包括三席并发、主编基于报告综合、正式生产按岗位检索和投影自动触发；需要专项故障与创造性非劣效测试。实际模型的长期文学收益仍是低置信项。

## 当前事实基线

- 修改前 `npm run verify` 通过103个测试文件、232项测试、三端类型检查和生产构建，但未证明正式章节生产使用混合RAG。
- `ChapterPipelineService.buildDraftContext()`只读取活动规划、前章状态和全局前12条活动记忆，没有按当前任务执行四通道检索。
- `HybridRetrievalService`已被公开检索API装配，但讨论、对话回复、章节写作和三席审校未调用它。
- 切片快照、FTS/vector outbox和Worker执行器存在；章节结算没有创建包含已确认正文和结构资料的新版切片快照并投递投影任务。
- 章节批准只创建一条泛化“已发生事件”和结尾摘录，不能支撑人物、关系、规则、地点、伏笔及时间线精确回查。
- 三席调用串行；`ProductionReviewService.merge()`是确定性并集，不是活动主编读取三份报告后的真实综合。
- 任务租约在长模型调用中不续约；检查点和完成缺lease token、到期时间与主编epoch三重栅栏；过期恢复没有生产调度入口。
- 成功模型输出只保存哈希引用；中断调用无法安全判断是否已完成；晚到结算可能错误处理已释放预算预留。
- `CanonService.settleChapter()`在事务前读书籍修订与正文状态，更新书籍未检查影响行数，存在陈旧并发提交风险。
- 当前证据最高为工程E2和有限检索候选E3，不存在真实纵向E4文学质量证据。

## 最强替代方案与取舍

维持现状只补文档的优点是零代码风险，缺点是继续把“类和测试存在”误当生产能力，不能接受。把十一岗减为六岗并删除epoch能减少表面代码量，却把单Worker误等同于没有晚到响应、进程重启、租约过期和候任接管并发，也违反老板冻结合同，拒绝。把全书资料一次性装入超长上下文实现简单，但让500万字目标失去上下文解耦并扩大注意力稀释，拒绝。

推荐保留四路召回，按岗位只注入最小充分证据；可重建投影允许降级，正史权威不允许降级。

## 预先验尸与反例

失败路径一：新章确认后新快照只包含新章，活动水位切换导致早期章节消失。修复要求新快照覆盖全部现行不可变来源，覆盖探针通过后才切换。

失败路径二：Worker租约过期、另一Worker重领、旧模型响应晚到，两边都写正文并结算。修复要求每次领取产生不可复用lease token，所有续租、检查点、完成和模型结果提交校验token、attempt、未过期和epoch；未知provider结果进入待调和，禁止自动重试。

失败路径三：事实抽取把推测、梦境或反讽当正史。事实候选必须带原文位置、叙事层级和置信带；不可靠叙述、梦境、假设与角色观点不能自动成为硬事实。

十倍规模反例还包括同名人物、跨卷旧伏笔、旧规则失效、向量资产损坏、三席一个超时、主编候任同源故障、迁移文件删除、备份缺新表和真实模型坏Schema。

## 修正后的最终设计

1. Schema只向前增加任务租约审计、模型结果和调和记录、索引请求及事实抽取记录，不改写旧迁移。
2. Worker在外部调用期间续租；状态提交以owner/book/task/worker/lease token/attempt/editor epoch为栅栏。失效执行者只能留下审计，不能提交业务状态。
3. 模型成功结果以不可变文本、哈希、用量和provider引用持久化；成功可复用，明确未发送才可重试，结果未知进入调和。预算只允许`reserved→settled|released`。
4. 作者确认和正史结算在短事务内重读权威状态并执行CAS；正文文件读取和模型调用留在事务外。结算成功同事务写索引请求，投影失败不回滚正史。
5. 索引协调器从权威来源构建覆盖全书的不可变来源清单；既有来源复用已验证切片，只切新增/变更来源，嵌入向量按模型与文本哈希复用。清单验证覆盖、哈希和成员快照后再投递FTS/vector并原子切水位；落后正史修订的投影直接失效。关系/Wiki从SQLite权威事实派生。
6. 讨论、正文和三席按岗位执行HybridRetrieval；RoleContextCompiler分硬事实、证据和灵感。主笔获得章纲、工单、前章接口、人物声音、伏笔和场景相关事实，不输入全库。
7. 章节批准使用带原文证据的事实抽取结果，按A/B/C/D门禁晋升；阶段边界触发卷/故事弧结算、滚动规划和连续性快照。
8. 正式三席保持三异模型并独立生成，可并发；缺任一席、同源冒充或坏Schema即阻塞。活动主编只读三份报告综合，不读全文做第四次点评。
9. 试写/草稿可走明确快速模式，但永不进入正式正文、正史或正式通过状态。
10. 接管前验证候任模型能力和套餐可用状态；不可用则阻塞并如实报告，不切确定性模型冒充真实创作。

## 创造性与输出质量保护

自由创作区包括开放讨论、双编剧独立方案、局部试写，以及主笔在硬事实与任务目标之外的对白、动作、意象、节奏和局部调度。RAG只提供边界与证据，不把检索命中变成必须逐条出现的正文模板。

以当前“章纲+全局活动记忆”作为弱治理基线，与新“岗位检索+最小包”做非劣效对照，比较原创性、合理惊喜、人物可辨识度、情绪力度、事实锚定和整体阅读质量；真实默认上下文变更需要跨任务盲评。若一致性提高但创造性、人物生命力或整体阅读质量下降，回滚注入模板或减少软资料，不能关闭权威事实门禁。

检索坚持召回多、注入少：H车道只放闭环硬事实，E车道给审校证据，I车道是可拒绝的灵感调色板。历史原文按触发逐级回查，阶段摘要不是唯一真相。作者偏好不得自动提升为硬规则或训练岗位迎合作者。

## 测试与证据等级

- E0：本审计、DEC-040、实施计划、任务账本和规格同步。
- E1：新增迁移、Repository、服务装配和状态机通过类型与单元契约测试。
- E2：确定性适配器和故障注入证明租约、崩溃、预算、正史事务、索引重建、RAG接线、跨书、三席并发及阶段结算。
- E3：独立金标的同名、否定、时间冲突、旧伏笔、无答案、消融和创造性盲评通过后才可声明对应范围；当前不预填通过。
- E4：真实模型与真实作品连续20/50/100章及更长纵向评测；本次工程修复不能制造该证据。

## 剩余风险与未知项

- provider是否支持查询幂等请求状态取决于套餐接口；无法查询时必须保守阻塞。
- 真实模型遵循事实Schema和主编综合合同的比例未知；缺凭证时只能完成确定性E2。
- 增量来源清单已避免每章全书重切与全量重嵌入；向量物理表仍按奇偶修订双缓冲重建活动集合，长期写入放大需在真实持续创作中监测，但不得以丢弃旧章换取性能。
- 三席并发降低墙钟时间但不降低正式审校Token；节省主要来自岗位最小资料包与试写分流。
- E4只能随真实创作积累。

## 停止、回滚和升级条件

出现实际付费、新密钥/登录、真实书永久删除、生产恢复、需要推翻模块化单体/十一岗/正史权威的重大变更、跨书泄漏、正史半结算、预算不可调和或无法自行消除的外部阻塞时停止并升级老板。

业务代码按阶段提交并可非破坏性revert；新增迁移不回退，以后续迁移修正。投影可关闭并从SQLite重建，旧水位保留；RAG可降级到结构化+FTS；主编综合可回退为保守阻塞，但不能伪造缺失报告。

## 实施后事实复核

- 采纳项均由生产入口和故障/集成测试证明，不以类名存在作结论：对话、讨论、主笔和三席均执行岗位检索；章节确认登记索引请求并消费；三席并发后由活动主编真实综合；结构化失败只有一次定向修复。
- 接管条件被收紧为同一任务连续两次技术失败、候任岗位/模型匹配且24小时内存在同owner同provider/model成功证据。鉴权、额度、请求错误、取消、坏Schema与未知远程结果不触发自动接管。该证据是保守可用性下限，不冒充provider实时额度查询。
- 非客观断言不再把断言主体自动猜成观点或知情主体；事实候选显式携带认识状态、否定、观点/知情主体与时间，未知保存为null/partial。客观人物状态、时间线和关系投影只接受未否定的objective断言。
- 正式链没有采用单席快审、事实席去全文、删副编/副笔/设定、删epoch或确定性候任冒充。前述改动没有足够证据证明安全，并与当前决定冲突。
- 代码审查额外发现并修复：失败章节的新任务必须重新冻结当前模型绑定并清零旧接管计数；主编真实模式上下文不重复发送三报告；聊天取消按数据库关联活动任务中止调用且保持跨书隔离。
- 长篇规模复核额外发现“每章全书重切/重嵌入”与冻结规格冲突，已改为不可变来源成员清单：相同来源版本复用原切片，事实版本按内容哈希稳定，向量缓存只计算新增文本，LanceDB使用双缓冲表切换；旧修订投影任务不能覆盖当前水位。
- 最终测试、迁移、运行、备份、验收、提交和远程同步结果以release evidence为准；在证据写入前本段不提前标记E3/E4。
