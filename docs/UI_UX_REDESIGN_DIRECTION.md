# UI/UX 重设计方向

## 1. 这次要解决的问题

当前页面主要问题不是颜色，而是同一屏同时出现太多导航、状态、说明、卡片和操作；作者需要理解系统内部流程，才能知道下一步。手机端又把桌面信息压成多排入口和长卡片，导致首屏看不出当前任务。

重设计目标：作者进入任意页面后，几秒内知道当前书、当前阶段、AI在做什么、自己要决定什么、下一步是什么。

## 2. GitHub写作产品给出的启发

- [novelWriter](https://github.com/vkbo/novelWriter)：项目树稳定组织长篇小文档，编辑面保持克制。启发是“层级随时可见，正文始终最重要”。
- [Manuskript](https://github.com/olivierkes/manuskript)：大纲、索引卡、故事线和无干扰写作分成不同工作模式。启发是“结构阶段和写作阶段不应共用一套拥挤页面”。
- [Kindling](https://github.com/smith-and-web/kindling)：写正文时大纲仍可见，但场景节拍可展开，也能切换全页正文。启发是“上层约束靠近正文但默认折叠”。
- [Zettlr](https://github.com/Zettlr/Zettlr)：稳定编辑区、可折叠工作区和临时多窗格。启发是“比较时才多栏，平时回到单工作区”。
- [Manuscript](https://github.com/manuscriptapp/manuscript)：iOS/macOS使用同一数据但不同呈现，含项目树、卡片和分屏。启发是“手机不是桌面缩小版”。

不照抄任何外观，只采用这些成熟的任务结构。

## 3. 新的信息架构

```text
账号
└─ 当前书
   ├─ 创作进度（开书 → 设定 → 卷 → 事件 → 章 → 正文）
   ├─ 当前工作（此刻唯一主任务）
   ├─ 资料（人物、世界、规则、线程和来源）
   └─ 辅助（团队、任务、灵感、取名、设置）
```

创作进度是作者主路径；资料和辅助不应与六个创作阶段在同一层争抢十二个入口。全局任务中心负责跨书汇总，当前对象的AI任务仍在当前页就近显示。

## 4. 页面骨架

每个创作页使用相同状态骨架：

```text
当前对象 + 简短状态
        ↓
活动结果 / 当前要完成的内容
        ↓
作者补充（可选、短、按需展开）
        ↓
唯一主操作
        ↓
AI进行中 / 方案比较 / 失败恢复（按状态替换）
        ↓
确认结果 + 下一层
```

不要同时铺开作者输入、三份原始方案、质疑、融合稿、质检报告、历史版本和下一步。待决定时重点比较；确认后只留活动定稿和“查看过程/重新设计”。

## 5. 桌面与手机

### 桌面

- 左侧或顶部保留一个稳定的书籍/阶段定位区，具体形态在原型后确定。
- 中间是单一主工作区；方案比较时临时双栏，正文写作时单栏。
- 右侧上下文只在写作、核对或审查时按需打开，不常驻。

### 手机

- 顶部只放返回/当前书/更多；阶段切换放进可滑动进度或全页导航，不堆两排十二按钮。
- 当前页以单列卡片或无卡片段落为主，一次只看一个方案；底部固定当前状态的主操作，但尊重安全区和键盘。
- 书籍、资料和辅助工具进入抽屉或独立页；抽屉不能被遮罩盖住。
- 正文编辑全屏优先，“本章任务/相关事实/审查”作为底部抽屉。

## 6. 三种工作模式

1. 设计模式：设定、卷路线、事件和章链，强调比较、选择、重排与确认。
2. 写作模式：正文占中心，最近章纲和事实按需展开。
3. 复核模式：围绕精确版本展示差异、审查证据、作者修改和实际结算。

同一对象可以切换模式，但不把三种模式的全部控件同时摆在一屏。

## 7. 视觉原则

- 安静耐读，中心内容优先；少颜色、少厚边框、少阴影、少装饰渐变。
- 卡片只在“卡片本身可选择/重排”时使用；普通分组优先标题、留白、分隔线和列表。
- 一个强调色同时表达主操作或活动状态，不让多个按钮竞争。
- 页面文案是业务语言：状态、范围、影响、动作；删掉宣传语和重复教学。
- 字号、间距、圆角、颜色、焦点、状态和动效统一成token，不继续逐页补丁。

## 8. 实施顺序

1. 应用壳、导航、手机抽屉和共享页面状态；
2. 开书信息；
3. 四项核心设定与按需补设定；
4. 分卷双路线和首卷强启动；
5. 事件链、事件大纲、完整章链和近期细纲；
6. 正文写作、三审和结算；
7. 资料库、团队、任务、灵感、取名和设置。

每批先出交互原型和状态表，再实现；共享壳稳定后再统一视觉。旧数据和旧URL保持可读，新旧页面不要长期混用两套状态语义。

## 9. 验收

每页覆盖空、编辑、工作中、待决定、完成、失败/恢复；检查360/390/430px和桌面。验证当前书/对象不丢、刷新不漂移、重复点击不重复发任务、键盘不遮操作、长内容不溢出、错误有恢复动作。工程门禁按 `docs/ACCEPTANCE.md` 的风险矩阵执行。
