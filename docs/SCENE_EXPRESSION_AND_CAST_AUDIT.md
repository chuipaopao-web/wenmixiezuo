# 多主角与场景表达策略设计审查

- `design_review_id`：`DR-20260728-scene-expression-and-cast-v1`
- 适用决定：`DEC-066`
- Skill：`wenmi-longform-quality`（2026-07-28读取）

## 痛点与根因

1. 当前Web把后端已支持的1—8位主角压缩成单一主角，导致女主、共同主角和群像角色无法在开书时录入。根因是前端回归，不是数据模型限制。
2. 当前把语言气质、情绪基调和节奏设为开书必填，并称作全书风格。长篇不同剧情需要不同情绪和语言，这会把软倾向误升级为全书硬规则。
3. 当前主笔胶囊把所有风格项平铺注入，容易造成同时执行、机械混合和注意力污染。

## 方案比较

- 删除全部风格信息：界面简单，但会丢失作者稳定的表达偏好、禁用退化和人物声音约束。
- 保留固定全书风格：可追溯，但错误地假设全书情绪恒定，创造性风险高。
- 采用表达调色板与场景编译：保留可选范围和稳定原则，每章只选择当前场景必要项。采用本方案。

## 两轮审查

第一轮防错：多角色逐项校验且姓名不重复；空调色板合法；旧书数据兼容；不删除历史版本。

第二轮反迎合与创造性审查：调色板仅为候选范围，不是每章清单；场景目标、人物声音和因果优先；不得因作者选过“热血”而阻止悲壮、温馨或克制场景；不得把所有标签同时塞入主笔上下文。

## 指标、证据与停止条件

- 契约：1—8位角色可保存、读取、进入本书资料与开场资料包。
- 上下文：主笔只接收一份有界场景表达胶囊，不接收完整调色板目录。
- 非劣效：人物可辨识度、情绪力度、合理惊喜和整体阅读质量不得下降。
- 停止/回滚：出现角色丢失、旧书无法读取、固定情绪残留门禁或场景胶囊同时要求互斥情绪时停止发布。
