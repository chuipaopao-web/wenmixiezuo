## 明确结论与置信度

高置信结论：现状不能继续用“已完成全部数据库和本地智能功能”描述。Schema、适配器和构造测试存在，但当前 release 账本为空，vector outbox 被 Worker 明确拒绝，公开 retrieval API 仍走旧 FTS 服务，本地工具模型没有进入真实秘书链。应沿用已冻结架构补齐运行接线，而不是增加新数据库或生成式本地 LLM。

推荐安装 24M 参数、512 维、MIT 许可的中文 BGE small v1.5 ONNX 量化资产作为本地语义基础。它只做嵌入、语义分类/排序和抽取候选，不给剧情结论；确定性代码继续控制权限、风险、状态和写入。该结论不声称模型能提高文学创造力。

## 当前事实基线

以下事实固定为本次补缺开工前基线；文末“实施闭环”记录完成后的新状态。

- 已确认事实：SQLite 已迁移至 0018；LanceDB、Transformers.js 与 ONNX runtime 可加载；没有登记的本地模型资产；正式库当前没有可投影的确认块。
- 已确认事实：`ProjectionTaskExecutor` 只接受 `fts`；`VectorChunkProvider`、`RetrievalRouter` 仅被测试直接构造；公开 API 使用同步旧 `RetrievalService`。
- 已确认事实：秘书公开路由为确定性正则；Worker 中两个 local utility adapter 未被主程序实例化。
- 已确认事实：当前环境的 subscription-plan 配置已识别，现金 fallback 为 false；这不等于各模型真实调用已验证。
- 可验证推断：接通四通道可提高无关键词重合的资料召回，但错误向量仍可能带来主题相似噪声。
- 老板偏好：小问题尽量本地处理，Agent 长期陪伴 300—500 万字作品；不能为省 Token 损害创作质量。
- 未知项：真实连续 20/50/100 章对文学质量的纵向影响、第二物理备份介质、作者实际语料中的最佳语义阈值。

## 最强替代方案与取舍

最强替代是安装 Qwen 等生成式本地小模型，让秘书自由理解、压缩并回复。优点是表面表达更自然；代价是 CPU/内存和冷启动更高、Schema 与事实可控性更差、容易截断老板原话或越权给剧情结论，也新增一套生成质量评测。当前任务核心是可靠路由、实体和压缩候选，中文嵌入模型更小、更可验证，故不选生成式模型。

维持现状的优点是零资产和最低复杂度；缺点是用户明确需要的语义召回与本地智能没有真实运行，因此不能接受。

## 预先验尸与反例

假设补缺失败，最可能路径是：模型资产不完整却被标记可用→Worker 建出维度错误索引→API 命中旧/错书表→相似文本进入事实车道→主编据此给出错误结论。修正为逐文件哈希、维度探针、owner/book/snapshot 三重过滤、manifest/watermark 同 revision、vector 永远只在 I 车道。

第二条路径是秘书语义分类把“让张三今晚死”当普通短句并直接处理。修正为长度从不决定风险；高影响词、点名、活动会话和保护操作先走确定性门禁，语义候选只能在剩余低风险集合中排序，低置信直接升级主编。

十倍规模反例包括 1500 章重建中断、同名实体、多跳关系、时间冲突、旧快照命中、查询没有答案、关键证据位于长上下文中部、重复父子块和本地模型离线。测试必须覆盖旧水位继续服务、无答案不臆造、同源聚类、一次有界回查和确定性降级。

## 修正后的最终设计

1. 资产只由显式安装命令从固定 revision 下载；注册表逐文件验证，运行期关闭远程模型。
2. Worker 对 FTS 和 vector 使用同一 outbox/执行记录，但 vector 在数据库事务外完成耗时嵌入与 LanceDB 构建，最后以短事务登记 manifest 并切换水位；失败不影响旧水位。
3. API 为每次查询读取当前书的 FTS/vector 水位和 manifest，执行 query plan、四通道、同源聚类、H/E/I 融合和证据闭环；通道状态及降级原因持久化。
4. 召回集合与最终上下文分离。结构化硬事实不参加 RRF；向量只帮助找候选，必须解引用 SQLite 块和来源哈希；无来源不得升级。
5. 小文秘书采用“确定性门禁→本地语义候选→确定性动作/岗位升级”。本地候选只输出枚举意图、置信带、实体候选和来源句指针；不能执行 SQL、工具、正史或正式正文写入。
6. 相同 BGE 资产可以承担 embedding 和 local-utility 两项能力，但注册清楚同一模型来源，不能冒充两个独立 Agent。生成式创作仍由已配置大模型岗位完成。

## 创造性与输出质量保护

自由创作区包括开放讨论、互相冲突的剧情方案和暂存试写；本地语义模型不能提前收敛方案、润色老板原话或把历史偏好固化成规则。正式生产中只把事实/安全/费用/隔离作为硬门禁，章纲、节奏和风格仍是可偏离并需解释的软约束。

新检索相对旧 FTS 基线做非劣效验证：同一查询与资料分别使用 FTS-only 和 hybrid，比较事实锚定、原创性、合理惊喜、人物可辨识度、情绪力度和整体阅读质量。局部路由用多样本对照；默认上下文改变需跨任务盲评。若一致性提高但任一核心创作维度显著下降，不能用综合分抵消，回滚注入策略而保留索引。

检索可以多取候选，但注入必须最小充分；保留约束胶囊与灵感调色板的区分、少数意见、冲突标识和原文回查入口，避免全量资料锚定把正文压平成 Wiki 摘要。

## 测试与证据等级

- E0：本审计、DEC-031、实施计划和当前规格同步。
- E1：资产安装器、异步 vector executor、hybrid service、秘书语义候选与账本代码存在并通过类型检查。
- E2：确定性/冻结夹具证明跨书、重建、降级、路由、恢复和 500 万字符/1500 章容量；不能证明文学改善。
- E3：独立编写的同义改写、无答案、时间冲突、索引破坏、检索消融和成对盲评数据通过；真实套餐连通只证明模型可调用与身份快照。
- E4：只有真实作者作品连续 20/50/100 章的纵向盲评和作者验收才能形成；本次不得用假章节补齐。

## 剩余风险与未知项

- BGE small 的通用中文指标不能替代本项目实体、规则和小说语料阈值；上线阈值需由独立金标校准。
- 首次本地模型加载可能带来数秒延迟和内存峰值；需预热和显示状态，不能伪装即时。
- 真正的第二物理备份需要老板提供独立设备或位置；同盘另一个目录不算。
- E4 必须随真实作品累积，不能在一次开发任务中诚实制造。

## 停止、回滚和升级条件

出现现金请求、新密钥、永久删除、生产恢复、未授权重大架构变化、资产许可/哈希不明、跨书泄漏、保护操作被模型执行、来源闭环失败或创造性非劣效失败时停止对应激活。向量可通过删除可重建目录和关闭能力回滚；秘书可关闭语义候选回到确定性路由；公开检索可回旧 FTS 路径；所有回滚不修改正史与正式正文。

## 实施闭环（2026-07-19）

本审计列出的四个运行缺口已按原架构闭合：当前release机器账本已初始化；固定BGE资产完成逐文件与聚合哈希验证；Worker真实建立LanceDB表并在探针后原子切水位；公开HTTP入口运行四通道混合检索并保存计划、候选、同源簇和闭环；小文秘书在确定性保护/点名门禁后使用本地语义候选。点名成员会直接取得任务并以本人岗位/模型回复，不再由主编代答。

真实连通探针已覆盖Codex GPT-5.6 Sol、DeepSeek V4 Pro、GLM 5.2、Kimi K2.6和豆包Seed 2.0 Pro，严格套餐模式和现金fallback=false；探针不保存回复正文。首轮Kimi因隐藏思考耗尽输出Token而返回空文本，修正为显式关闭隐藏思考后通过。冻结13条检索金标的候选评测达到混合Recall@5=1、MRR=1、语义Recall@5=1、无答案准确率=1、跨书泄漏0；该集合由同一开发者编写，故只标记 `E3-retrieval-candidate`，不冒充独立人员盲评或E4文学质量。
