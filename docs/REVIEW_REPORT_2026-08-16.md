## 二、P1 高优先级问题（4 个）

### 1. 【并发】全局单任务串行 —— 所有用户/书籍同一时刻只能跑一个 AI 任务

- **位置**：`apps/worker/src/scheduler/task-claimer.ts:37-41`、`apps/api/src/application/tasks/task-service.ts:201-207`
- **现象**：两个取任务入口都先查 `SELECT 1 FROM tasks WHERE status='working' AND lease_expires_at > ?`，只要**任意一本书**有一个任务在跑，就返回 null 不取新任务。
- **影响**：目前线上 37 个真实用户。任何用户发起一章续写/设定讨论（耗时 1–5 分钟），**其余所有用户的所有 AI 任务全部排队等待**，无法并行。这是目前对"付费多用户产品"最伤的问题。
- **建议**：改为按 `owner_id`（或 `book_id`）维度判定"该书是否有进行中任务"，并支持 worker 多实例（每个 owner 一个互斥即可）。需要同时改 API 取任务接口与 worker 取任务接口，并确认 `budget` 结算逻辑不受影响。

### 2. 【流程】非会员选"已有正文续写"会被引导到 500 万字粘贴、识别、勾选之后才被 403 拦截

- **位置**：`apps/api/src/application/continuation/existing-manuscript-continuation-service.ts:198-261`（confirm/analyze 经 `TaskService.create` 触发会员门禁）、`apps/web/src/features/manuscript/ManuscriptWorkspace.tsx:236-267`（`confirmImport` 前端无 `guardAi` 前置）
- **现象**：非会员可以成功创建"已有正文续写"的书（建书时 `!isContinuation && !generationBlocked` 才发任务，续写模式被跳过，见 `book-onboarding-service.ts:228`）。但导入面板允许用户粘贴/读取 500 万字 → 识别章节 → 勾选"我已检查" → 点"确认导入 N 章"时才弹会员弹窗。用户导入的是**自己的文本**，弹窗文案却说"召集AI团队需使用算力"，场景错位且损失一次长流程操作。
- **建议**：a) 建书选择"已有正文续写"时或在导入面板顶部，对非会员明确提示"继续导入需要会员"；b) 若希望非会员也能保存正文，则把"文本保存"与"AI 拆解/分析"解耦（文本保存走非 AI 路径，分析再门禁）。这是产品决策，请拍板。

### 3. 【生产】线上管理员 9 本迁移书语义检索不完整（re-index 未完成）

- **位置**：生产库（见运维记录）。8 本中 4 本（灰烬领主/灵契天墟/阵骨问天/零帧登顶）chunk 已建但嵌入 API 返回 `CANON_INDEX_API_500` 失败；4 本（斗罗星轮行/烬脉天衡/界域领主日志/逆帧之上）因随包导入的 `content_snapshot_manifests` 元数据被 `findReadySnapshot` 判"已最新"而**跳过重建、content_chunks 实际为空**。
- **影响**：9 本书章节/书架/实体正常，但资料库**语义检索**不可用。上次结论是"保留现状、不修、不回滚"，请确认是否本轮补齐。
- **建议**：补 re-index + 修 `findReadySnapshot` 的"已最新"误判（应校验 content_chunks 是否真的有数据而不是只看 manifest 元数据）。

### 4. 【性能】SSE 长连接 + 1s 轮询 + 客户端 30s 轮询 + 80ms 防抖全量刷新 叠加

- **位置**：`apps/api/src/http/server.ts:237-262`（每个连接 1s 一次 DB replay + 10s keepalive）、`apps/web/src/lib/api/client.ts:1059-1096`（断线 1s 后重连，游标按 `bookId|'all'` 存 localStorage）、`apps/web/src/app/App.tsx`（30s 全量轮询 + 编辑输入 80ms 防抖触发 workspace 全量刷新）
- **现象**：2C4G 服务器上每个在线用户占一条常驻 SSE（每秒一条 DB 查询），同时 App 还定时全量拉取。多用户同时在线 + 频繁编辑时请求量与 DB 压力偏高，也是响应变慢的隐患之一。
- **建议**：a) 事件推送改为**定向刷新**（任务事件只刷任务区，章节事件只刷章节区），别全量 refetch；b) 30s 轮询退避到更长时间或仅作为 SSE 兜底；c) 80ms 防抖放宽。

## 三、P2 中优先级问题（7 个）

### 5. 【会员】续费/重新开通会重置周期，剩余天数与已用算力清零
- **位置**：`apps/api/src/infrastructure/security/membership-service.ts:183-197`（`ON CONFLICT(user_id)` 直接覆盖 `period_start=now`）
- **现象**：会员还有 20 天时管理员提前续费，剩余 20 天作废，算力计数也归零重算。
- **建议**：续费按剩余天数折算（延长 `period_end` 而非重置），或明确告知管理员"续费会重置周期"。

### 6. 【后台】管理员用户列表 LIMIT 200 无分页
- **位置**：`membership-service.ts:232`
- **现象**：用户超过 200 后，第 201 位以后在管理后台完全不可见、不可开会员/停用。
- **建议**：加分页或"搜索到后单查"。

### 7. 【文档】USER_GUIDE 描述与新版会员行为不一致
- **位置**：`USER_GUIDE.md:79`
- **现象**：仍描述旧版"内测锁屏 + 20 秒自动刷新"；新版已是"可关闭的顶部通知 + AI 触发时弹窗"（`membership-gate.tsx` / `App.tsx`）。`docs:sync` 未跑。
- **建议**：本轮改完代码后统一同步文档。

### 8. 【付费】"算力值"概念对普通用户不直观，且无消耗预期
- **现象**：会员=3 亿/10 亿/百亿算力值（token），但用户在开书、续写、优化表达前**看不到预计消耗多少**，对"还剩多少、够不够"没有概念。
- **建议**：在关键 AI 入口展示当前余额；若能让模型或规则给出单次预计消耗则更佳。这是付费转化与信任的关键一环。

### 9. 【实时性】SSE 游标按 scope 存储，切书会重放历史事件；断网期间错过的事件不补
- **位置**：`client.ts:1059-1096`（游标 key=`wenmi-event-cursor:${bookId|'all'}`）
- **现象**：订阅"全部"后再订阅某本书，该书游标从 0 开始 → 重放该书全部历史事件 → 每次切书一次事件风暴（触发批量 refetch）。反向地，离线/断线期间本地游标只前进不回放，漏掉的事件只能靠 30s 轮询兜底。
- **建议**：统一用单一全局游标（服务端按 seq 去重）；或订阅仅用"全部"一个流，事件按 bookId 过滤。

### 10. 【安全配置】限流仅在 `publicOrigin` 非空时生效
- **位置**：`apps/api/src/infrastructure/security/request-policy.ts`（限流开关）
- **现象**：若部署配置漏配 `publicOrigin`，登录/注册/全局限流会**静默关闭**。
- **建议**：启动时校验：公网部署必须配 `publicOrigin`，缺配则拒绝启动或告警。

### 11. 【会员】非会员完全没有自助开通入口，所有 AI 一律不可用
- **现象**：付费只能"联系管理员微信"（用户既定方案）。但需确认产品预期：**非会员连"AI 点评/优化表达/自然化"都不可用**，只有建书、手动写正文、存稿可用。若希望非会员有"轻量试用"（如每本书限几次 AI），需另开入口。
- **建议**：至少在开书/导入/正文工作台等入口把"哪些能用、哪些要会员"讲清楚，避免用户在长流程末端才被弹窗拦截（与 #2 合并处理）。
