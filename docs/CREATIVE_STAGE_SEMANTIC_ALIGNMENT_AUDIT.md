# 创作阶段语义对齐审查

- `design_review_id`：`DR-20260728-creative-stage-semantic-alignment-v1`
- release：`wm-longform-r1-20260719-003435-e4d7b8b7`
- 目标：保证“本书资料、作品风格、设定大纲、剧情总纲、卷纲、章纲、正文”的名称、输入资料、岗位任务、模型输出和落库结构一致。
- 非目标：不改写既有书籍的历史污染数据；不调用真实付费模型；不缩减开放创作空间。
- Skill：`wenmi-longform-quality`（2026-07-19，当前文件快照）；同时执行系统化调试和完成前验证。

## 故障基线

已确认事实：

1. 旧实现对剧情总纲只取得主编普通讨论摘要，并把同一摘要同时写入核心冲突和故事方向。
2. 旧实现对卷纲再次使用同一类摘要，同时写入卷目标和唯一故事弧目标。
3. 主编提示词只有滚动章纲具备机器可验证合同；剧情总纲和卷纲只有通用“推荐、理由、风险”要求。
4. 讨论上下文包虽然保存了检索来源，但模型提示词只读取检索来源，未强制读取已确认的上一级规划版本。
5. 前端个别兼容名称仍把 `master_outline` 显示为“全书总纲”，与当前“剧情总纲”标签不一致。

根因不是岗位数量不足，而是阶段输出合同、上游资料注入和落库校验同时缺失。增加岗位不会消除重复落库。

## 修复机制

1. 剧情总纲使用独立合同：核心前提、全书核心冲突、主角成长线、至少两个不同推进阶段、结局方向、作品承诺、开放问题。
2. 卷纲使用独立合同：卷名、唯一卷目标、卷首状态、本卷故事弧、转折、兑现、高潮、卷末状态、开放问题。
3. 普通总结、缺字段结构、重复阶段目标一律拒绝落库；确认事务回滚，不生成看似完整的假规划。
4. 剧情总纲讨论硬注入已确认作品风格和设定；卷纲再硬注入已确认剧情总纲；滚动章纲再注入当前卷纲。
5. 双编剧收到与阶段相符的创作任务：总纲讨论全书因果，卷纲讨论当前卷兑现，章纲才细化未来章节。
6. 作者界面隐藏三类内部落库合同，并统一显示“本书资料、设定大纲、剧情总纲、当前卷纲、滚动章纲”。
7. 确定性假模型补齐同样合同，使缺少真实凭证时仍能验证流程，但输出明确只属于零费用测试基线。

## 两轮审查

第一轮（正确性）：

- 反例“把普通总结确认成剧情总纲”被拒绝。
- 反例“两个全书阶段使用相同目标”被拒绝。
- 剧情总纲与卷纲使用不同字段，卷纲不能复用全书结局文本冒充本卷结果。
- 上级规划按书籍隔离键读取，且只接受 `selected` 版本。

第二轮（创造性与输出质量）：

- 合同只约束规划层级和必需因果，不规定唯一情节、固定章数、固定模板措辞或文学表达。
- 作品承诺和开放问题被保留，允许少数高潜方案与刻意未知继续存在。
- 不将阶段规划合同注入正式正文显示，不增加第二次模型调用。
- 停止条件：若跨题材盲评显示新合同显著降低合理惊喜、人物生命力或整体阅读质量，应回滚提示词措辞；不得回滚层级校验和防重复门禁。
