## 1. 目标与非目标

目标是删除作者可见和活动运行时中的独立“卷纲”成果，使剧情总纲的连续章节阶段直接连接滚动章纲，消除重复规划、层级混淆和无效上下文。

非目标：

- 不删除正文目录中的物理分卷；
- 不删除历史卷纲版本、来源、调用记录或审计证据；
- 不把剧情总纲改成逐章清单；
- 不一次规划远期所有章纲；
- 不修改模型绑定、三席审校、正史、混合 RAG 或正文版本链。

## 2. 已确认事实、推断、偏好与未知

已确认事实：

- 活动剧情总纲已经使用 `stage_master_v2`，每个阶段包含连续章节范围、主线闭环、起承转合、阶段总结、待回收项和后续方向。
- 当前卷纲仍作为单独状态、Artifact、讨论模板、写作门禁、前端页签和模型来源存在。
- 总纲阶段与卷纲都表达中长期章节范围、冲突、结果和开放线程，实际职责高度重叠。
- 章纲已经是未来 1—3 章滚动规划，不需要卷纲才能表达当前讨论决定。

老板最新决定：

- 删除卷纲相关功能和信息，不再保留这一设定。

推断：

- 删除独立卷纲可以减少一次讨论、一次确认、一次模型资料注入和一层错误锚定。
- 中期规划能力仍需保留，但应放在剧情总纲的当前阶段和持续创作会话的已确认故事弧中，而不是换名再造一个卷纲页面。

未知：

- 真实模型在没有独立卷纲时对 50 章以上阶段的细节保持能力，需通过后续纵向样本验证。
- 旧书历史卷纲是否仍有作者导出需求；当前按审计保留、作者工作台隐藏处理。

## 3. 痛点链

| 痛点 | 症状 | 根因 | 修正机制 | 反例/停止条件 |
|---|---|---|---|---|
| 规划重复 | 总纲与卷纲内容近似，作者不清楚差别 | 新版总纲已升级为连续阶段结构，旧卷纲门禁未同步退役 | 总纲直接连接滚动章纲 | 总纲被迫膨胀为逐章事件时停止 |
| 流程过长 | 每轮需额外讨论、确认和等待卷纲 | 卷纲被当成正式写作硬前置 | 写作只要求活动设定、总纲和目标章纲 | 缺少近期目标却仍允许写作时停止 |
| 上下文污染 | 主笔同时收到总纲、卷纲、章纲的重复约束 | 层级间复制而非引用 | 章纲只引用相关总纲阶段和确认讨论决定 | 上下文长度、重复率或冲突数上升时回滚 |
| 历史破坏风险 | 直接删表或版本会失去追溯 | 把功能退役误解成数据物理删除 | 向前迁移清活动指针、归档 Artifact、保留版本 | 旧版本、调用或来源丢失立即停止 |

## 4. 方案比较

### 方案 A：保留卷纲，只改名“故事弧”

优点是改动小；缺点是仍保留同一层重复、确认门禁和上下文负担。否决。

### 方案 B：删除卷纲，同时删除所有中期规划

优点是流程最短；缺点是总纲到 1—3 章章纲之间缺少当前剧情段的选择和跨度，长篇容易漂移。否决。

### 方案 C：退役卷纲，保留总纲阶段＋会话故事弧＋滚动章纲

采用。总纲负责全书阶段边界，持续创作会话保存作者锁定的当前故事弧、代价、未知和预计跨度，章纲只细化未来 1—3 章。物理分卷仅用于正文目录组织。

## 5. 两轮审查

第一轮正确性与恢复：

- 公共 API 不再生成或确认卷纲；
- 历史状态只向前映射，不删除版本；
- 已可写书籍不因迁移回退；
- 章纲必须引用同书活动总纲，所有查询继续携带 `owner_id` 与 `book_id`；
- 失败时可 Git 回滚服务/UI，数据库保留兼容列和历史版本，无需恢复生产数据。

第二轮创造性与输出质量：

- 不把总纲阶段扩写成新的硬性“隐形卷纲”；
- 不增加固定章数、每卷模板或强制起承转合等分；
- 章纲仍只覆盖未来 1—3 章，开放讨论与试写不被完整生产门禁阻断；
- 资料包只取相关阶段和当前故事弧，避免因删层反而注入完整总纲；
- 若人物选择空间、合理惊喜、情绪力度或整体阅读质量相对旧流程显著下降，停止推广并恢复可选中期规划策略，但不恢复重复的作者卷纲页。

## 6. 回滚

代码与界面通过 Git revert 回滚。迁移保持向前：如需恢复旧行为，新增迁移重新激活兼容字段，不修改 `0033`，不从备份覆盖生产数据。旧卷纲版本始终保留，故无需进行不可逆数据恢复。
