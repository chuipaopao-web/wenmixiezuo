# 四路混合检索编排最终设计

## 明确结论与置信度

结论：500万字、1500章的文秘写作不能把“向量分、BM25分、事实分、关系分”直接相加。最终方案采用：**先做权威/时间/实体硬门禁，再按查询意图选择四路召回，把结果分成硬约束、证据、灵感三条车道，只在同类软候选内部做RRF融合，最后回查正式事实或原文并按岗位组装最小充分上下文。**

四路职责固定为：结构化事实负责“现在真实是什么”，FTS/BM25负责“原词原句在哪里”，向量负责“换一种说法仍然相关”，Wiki/关系负责“这些对象如何连接”。Wiki、摘要、向量和融合分都不是正史权威。

- `design_review_id`：`DR-20260718-02`
- `release_id`：`wm-v1-20260716-220959-d5dd704d`
- 目标规模：单书500万规范化中文字符、1500章；不把容量外推成文学质量。
- 当前证据：E0设计。运行时Schema、迁移、四路查询、LanceDB索引、融合校准和真实创作评测尚未实现。
- 置信度：架构边界高；查询类型和失败处理高；具体Top-K、权重、阈值和本机延迟只有中等或低置信度，必须在E2/E3冻结前由独立查询集校准。

## 当前事实基线

- 当前运行时只有SQLite结构化查询、FTS5/BM25和固定同义词扩展；没有真实向量、四路编排、关系多跳、RRF、证据闭环或岗位检索配方。
- DEC-012已经确定SQLite和不可变正文为唯一权威，LanceDB只保存可重建向量投影，关系/Wiki从SQLite正式源派生。
- DEC-015已经确定旧阶段摘要优先、关键触发再按活动集0→卷1→故事弧2→章节/场景及结构化事实3下钻，最小原文解引用单独计费。
- DEC-016已经确定临时、候选、正史、派生四层生命周期；DEC-017已经确定不可变原文、结构节点、父子检索块和原子事实。
- 当前高层文档虽然写了“并行召回→RRF→权威/时间/岗位加权→原文回查”，但尚未规定四路谁能决定事实、什么先融合、父子块怎样避免重复投票、关系扩展由什么种子触发、冲突和无答案如何停，以及团队各岗位分别取什么。

因此，“四种技术已经列出”不等于“组合方案已经可实现”。本文件补齐的是组合合同，不替代数据库、切片或超长篇连续性规格。

## 最强替代方案与取舍

| 方案 | 优点 | 致命不足 | 结论 |
|---|---|---|---|
| 只用向量 | 实现直观，能找语义相似 | 无法可靠处理生死、数量、否定、时间、同名和规则版本 | 不采用 |
| FTS＋向量直接加权 | 常见、代码少 | 原始分数不可比，硬事实会被软相似覆盖 | 不采用 |
| 全部交给Wiki/知识图谱 | 多跳关系清楚 | 抽取错误、隐喻、谎言和叙述视角会变成伪事实 | 不采用 |
| 整书长上下文 | 不做复杂检索 | 500万字不可装入；长上下文仍有位置敏感和注意力稀释 | 仅作为小规模对照基线 |
| 四路全部进入统一学习排序 | 可潜在优化综合指标 | 需要高质量训练数据，解释和回滚困难，易把软相关学成事实权威 | 首阶段不采用；E3后仅可试验软候选重排 |
| 硬门禁＋意图路由＋三车道＋证据闭环 | 事实边界清楚、可审计、可降级、保护创造性 | 编排较复杂，需要独立查询集校准 | 采用 |

最强替代方案是“FTS＋向量直接RRF”。它适合普通文档问答，但小说还存在故事时间、人物知情、谎言、候选剧情和正式正史，必须先由结构化事实和关系类型决定合法范围，不能让两个文本排名器包办事实裁决。

## 预先验尸与反例

假设本方案上线后失败，最可能出现以下传播链：

1. 向量把另一名同名角色召回→错误实体成为关系种子→整条历史因果错位。控制：先结构化/别名消歧，向量不能直接授予实体身份。
2. 同一段正文以子块、父块、章节摘要和Wiki页四次出现→RRF误认为多源一致。控制：来源血缘聚类，一个证据簇一票。
3. 旧阶段人物状态语义更相似→压过当前状态。控制：三轴时间和正史版本先过滤，当前状态从硬约束车道固定进入。
4. Wiki把“张三声称自己有十万兵”写成“张三有十万兵”。控制：事实类型区分客观、角色认知、声明、谎言、计划和推断；原文证据闭环。
5. 关系遍历把张三的所有熟人、地点、组织全部展开→真正的宣战规则被淹没。控制：查询类型白名单、目标关系路径、扇出与节点上限。
6. 为防漏检给主笔塞入十几个旧战斗场景→新战斗复用旧措辞和解决方式。控制：旧场景进入灵感车道，默认少量且可不用；正式主笔优先事实、工单和人物声音。
7. 为节省Token过度压缩→“不能宣战”的否定词或来源被丢掉。控制：硬事实不做有损摘要；压缩保存否定、三轴时间、来源和探针。
8. 四路都没答案，但向量仍返回近似战争片段→模型编造确定结论。控制：无答案是成功状态，不用“最像”代替“有证据”。
9. 本地向量投影落后一个正史版本→新死亡状态未入索引。控制：通道水位门禁；可降级任务不用向量，依赖语义证据的正式任务等待或停止。

最强反例：结构化事实、关键词、向量和关系全部检索正确，模型仍可能写出平庸剧情。混合检索只能降低漏事实、错时间、错实体和注意力稀释，不能独自解决文学创造力。

## 修正后的最终设计

### 1. 查询先变成受控计划

每次检索先创建不可变 `retrieval_query_plan`，至少包含：

- `owner_id`、`book_id`、任务、岗位、创作模式和调用目的；
- 当前正史版本、故事时点、观点主体/知情边界、权限域；
- 实体候选ID、别名命中、歧义状态和解析依据；
- 一个主意图和零到三个子意图；禁止无限拆查询；
- 活动工作集、允许下钻层级、四路开关、候选预算、模型注入预算；
- 查询策略、切片快照、嵌入模型、融合和重排版本。

模型只生成受Schema验证的计划AST，业务代码把AST编译成Repository查询；禁止模型直接生成SQL、文件路径或工具命令。高风险正式任务未能消歧实体、故事时点或观点主体时停止；开放讨论可以并列展示多个分支。

### 2. 超长篇先定活动范围

500万字检索不是先搜全书再裁剪，而是先建立活动工作集：全书主脊、当前卷/故事弧、上一阶段结算、当前实体状态、开放承诺与最近章节。已闭合旧阶段保持休眠。

出现实体/别名、开放承诺/伏笔、世界规则、知情/关系/声音证据、历史因果、摘要冲突/缺项或老板明确回顾时，才按0活动集→1卷→2故事弧→3章节/场景及结构化事实下钻。最小正式原文只是证据解引用，不增加语义深度，但单独记录候选数、延迟和Token。

### 3. 四路各司其职

| 通道 | 解决的问题 | 主要输出 | 不能做什么 |
|---|---|---|---|
| 结构化事实 | 生死、位置、数量、归属、知情、关系状态、规则版本、故事时间 | 类型化断言、有效区间、观点主体、来源指针 | 不能凭抽取结果自动升为正史；不能决定文学表达 |
| FTS/BM25 | 姓名、别名、专名、原句、口头禅、明确关键词、精确定位 | 叶子块排名、命中词、正文位置 | BM25原始分不能与向量距离直接相加；命中不等于事实为真 |
| 向量 | 无关键词重合的改写、主题、行为、情绪、人物声音和场景相似 | 语义候选及距离、元数据 | 不能确认实体身份、时间、正史、因果或数量；不能推翻硬事实 |
| Wiki/关系 | 人物—地点—组织—事件—规则—伏笔之间的连接 | 有类型、有方向、有时间、有来源的路径 | Wiki摘要不能独立作证；未消歧种子不能扩展；不能无限遍历 |

Wiki不是第五份正文副本。它是从实体、事实、关系和来源编译出的导航视图；关系边使用SQLite派生投影，仍回链正式事实或正文。

### 4. 查询意图决定通道配方

| 查询意图 | 主通道 | 辅助通道 | 组合规则 |
|---|---|---|---|
| `exact_text` 原句/专名 | FTS | 结构化实体解析 | 按命中位置返回，必要时取相邻块 |
| `hard_fact` 当前状态/数量/规则 | 结构化 | FTS原文证据；关系验证 | 硬事实固定进入约束车道，向量仅补漏 |
| `entity_state` 人物/势力现状 | 结构化＋关系 | FTS证据、向量行为候选 | 按故事时点和观点主体切片 |
| `causal_multihop` 为什么/此前关系 | 关系＋结构化 | FTS/向量发现相关原文 | 路径每一跳都要有来源，不用摘要补缺 |
| `semantic_recall` 主题/改写/相似行为 | 向量 | FTS、结构化过滤 | 只产生证据或灵感候选，不产生硬事实 |
| `voice_style` 角色声音/写作表达 | 向量＋FTS | 人物身份和时间过滤 | 只取少量代表片段，标记可不用且不得仿写原句 |
| `creative_exploration` 讨论新剧情 | 结构化硬边界＋开放线程关系 | 少量向量/FTS灵感 | 先独立构思，必要时一次定向回查；不让旧剧情决定新剧情 |
| `consistency_review` 审校矛盾 | 结构化＋关系＋FTS | 向量找隐含重复/行为漂移 | blocker必须闭合到正式来源，软问题保留不确定性 |
| `decision_support` 老板判断/主编决策 | 结构化＋关系 | FTS/向量收集历史证据 | 输出事实、推断、反方和未知，不按作者喜好改证据 |

一次请求可以有多个子意图，例如“张三今天要向天安城宣战”会拆成实体状态、规则、历史因果和决策支持，但最多四个意图面，避免组合爆炸。

### 5. 硬约束、证据、灵感三条车道

1. **H硬约束车道**：当前有效正史、任务硬目标、安全/版权/费用边界。按权威和三轴时间排序，不参加RRF，不被重排器删除。
2. **E证据车道**：用于回答、判断、解释或审校的正式原文、事实证据和有来源关系路径。允许融合和重排，但不能改变H。
3. **I灵感车道**：主题、情绪、声音、意象、相似场景和可撤销经验。与E分开排名，限量进入灵感调色板，明确“可不用、可变形、不得仿写原句”。

候选进入哪条车道由来源权威、任务意图和用途决定，不由相似分决定。临时/候选资料只有被当前任务显式激活时才能进入重大候选区，不能混入H。

### 6. 去重、融合与证据闭环

四路返回的原始分数不可直接比较。处理顺序固定为：

```text
硬范围过滤
→ 四路各自Top-K召回
→ 按事实ID/实体/来源字节范围/父子血缘/摘要来源聚成证据簇
→ 建立冲突组和否定/失效标记
→ H车道固定；E与I分别用RRF融合
→ 加权调整（权威、时间、实体精确、活动阶段、岗位作用、来源完整）
→ 可选本地重排器只处理E/I
→ 选中证据回查正式事实或最小原文
→ 无答案/冲突/歧义/超预算判定
→ 岗位专用上下文包
```

E/I车道的起始融合公式为：

`rrf(candidate) = Σ channel_weight(intent, role) / (k + rank_channel)`

只使用名次，不把SQLite BM25负分、向量距离和图路径分强行归一成同一物理量。`k`、通道权重和后续调整都是版本化起始参数，E3校准前不能宣称最优。

同一事实的Wiki段、阶段摘要、父块、子块和正文只形成一个证据簇；簇内保留最短可引用证据和来源血缘。独立来源才可形成多源支持，派生副本不能冒充多票。

冲突不做平均：将互斥断言放入同一 `conflict_group`，优先检查正史状态、来源等级、世界有效时间、人物知情时间和系统修订时间；仍无法裁决时，正式生产停止，开放讨论展示分支。

证据闭环要求：所有H和用于确定性结论的E都必须解引用到当前正史事实或正式原文字节范围，并校验来源版本与哈希。无法闭环的候选只能降级为推断、灵感或未知。

### 7. E0起始预算，不是永久常数

下列数值用于首轮实现防止无界爆炸，必须保存为策略版本并由E2/E3调整：

| 项目 | E0起始上限 | 超限处理 |
|---|---:|---|
| 主意图＋子意图 | 4个意图面 | 合并重复问题或拆任务 |
| FTS候选 | 每意图24，通道去重后最多48 | 按实体/时间/范围收紧 |
| 向量候选 | 每意图24，通道去重后最多48 | 收紧元数据和距离范围 |
| 结构化硬记录 | 目标不超过40条，不设静默截断 | 细化时点/实体或拆分任务 |
| 关系种子 | 8个已验证实体 | 未验证种子不扩展 |
| 初始关系遍历 | 深度2、单节点扇出12、总节点64 | 按关系类型/时间收紧 |
| 融合证据簇 | E/I各自最多96个进入融合 | 保留排除理由 |
| 本地重排 | E/I合计最多32个 | 没有兼容重排器时跳过 |
| 原文证据闭环 | 最多12个证据簇 | 硬证据仍超限则拆任务/停止 |
| 模型灵感卡 | 正式主笔默认0—4张 | 先删旧相似场景，不删硬事实 |
| 补充检索 | 最多1个有界周期 | 仍不足则未知或停止 |

“本地候选数量”和“实际注入模型的资料/Token”分开记录。结构化查询和关系遍历本身不消耗模型Token，只有最终被组装进上下文的短事实卡、证据片段和灵感卡才消耗；本地嵌入/重排仍消耗CPU、内存和延迟，不能叫零成本。

上下文先按目标模型Tokenizer预留最大输出、工具结果、结构化格式和安全余量，再分配输入。硬来源超预算时不得截断，应缩小查询、按场景拆任务或停止。

### 8. 十一人团队检索剖面

| 成员/岗位 | 主要检索维度 | 默认资料 | 重点限制 |
|---|---|---|---|
| 貂蝉/西施（主编/副编） | 决定、影响、分歧、任务与交接状态 | 当前决定、关键正史、岗位结论、证据缺口、租约/检查点 | 不载入整书或把多数意见当真理；副编只在检查/接管范围读取 |
| 婉儿/红玉（编剧） | 因果、承诺、人物欲望、历史冲突 | 相同权威边界下的独立包：开放线程、阶段结算、关系路径、必要旧史 | 初始阶段互不看答案；各自保留结构不同方案与失败条件 |
| 文姬（设定/GLM点评） | 时间、规则、状态、同名、知情、世界边界 | 写作前读取结构化事实/关系；点评时再加完整当前稿和最小正式原文 | 最早触发证据闭环；不替编剧决定剧情；不把摘要当硬证据 |
| 秋香/湘君（主笔/副笔） | 工单、当前状态、人物声音、伏笔、表达基线 | H约束胶囊、前章状态、少量E、0—4张I | 同一正式版本只激活一人；不看整书/全部讨论/废稿 |
| 妲己（Kimi点评） | 当前稿文学、人物、语言、节奏、重复和AI腔特征 | 完整当前稿、写作契约、前章结尾、少量人物声音/重复定位 | 不做无界旧史检索；AI腔风险必须定位证据且不是作者概率 |
| 昭君（豆包点评） | 当前稿体验、情绪、钩子、政治/情色风险 | 完整当前稿、目标读者、表达尺度、策略版本、少量趋势投影 | 不使用固定爽点模板；合规筛查不冒充法律/平台保证 |
| 道韫（研究） | 现实事实边界、时间地区、来源可信度 | 研究任务、外部资料、少量故事事实 | 外部知识与小说正史隔离，研究建议先候选 |
| 弄玉（版权） | 授权、来源、表达相似风险 | 隔离参考、待审稿件、结构卡 | 参考原文不得进入主笔灵感包 |

11名成员共用同一权威源，但查询意图、通道权重、粒度和预算不同。没有被激活的岗位不检索，也不为“公平”给所有岗位同一资料包。唯一固定全文共享是每轮事实/文学/体验三席读取同一不可变当前稿；其附加旧史仍按各自维度最小化，并分别记录三份全文输入Token。事实席默认GLM，GLM活动写手时使用DeepSeek；模型替补不改变检索职责。

小文秘书不属于11人检索剖面。它只能执行“受理检索”：当前书内实体/别名消歧候选、活动会话/任务状态、查询意图、资料水位和岗位包候选。它默认不接收I灵感车道，不生成剧情结论，不读取无关岗位日志，也不能用本地摘要替换老板原话。需要剧情讨论时，它为两名编剧分别生成同一权威边界、互不含对方结论的最小候选包，随后由正式上下文编译器重新校验并冻结。

### 9. 张三宣战示例

老板输入“张三今天要对天安城宣战”时：

1. 结构化通道解析张三、天安城、`今天`对应的故事时点、张三所在阵营、位置、兵力、权限和人物知情边界。
2. 关系通道从已确认实体ID扩展“张三—阵营—天安城—控制者—盟友—历史冲突—承诺”，只走与宣战相关的边类型。
3. 结构化规则查询取当前有效的宣战、战争、外交、距离、补给和权限规则。
4. FTS定位双方曾经的明确宣言、条约、威胁和正文证据；向量补找没有出现“宣战”二字但语义等价的敌意升级、背叛、战争准备和人物行为。
5. 按来源血缘去重，建立“双方实力”“是否具备宣战权”“盟友反应”“历史因果”证据簇，冲突资料不平均。
6. 回查最小正式原文，区分客观实力、张三自认为的实力和对方掌握的情报。
7. 两名异模型编剧分别收到同边界的因果和风险资料并独立提出路线；设定收到规则与硬冲突；主编收到推荐、最强反对理由、未知项和需要老板裁决的方向。主笔/副笔在没有写作工单前都不会直接写正文。

### 10. 更新、降级与恢复

- 正史事务写入事实/正文和 `projection_jobs`；FTS可同事务更新，向量、关系、Wiki由Worker幂等构建。
- 每次查询记录四路投影水位。向量落后但任务只需精确事实时，可显式降级为结构化＋FTS；关系落后时不得给出确定性多跳结论；正式任务依赖缺失通道时等待或停止。
- 缓存键至少包含查询计划哈希、岗位、模式、正史版本、故事时点、观点主体、活动阶段和全部策略/索引版本。任何依赖变化使缓存失效。
- FTS、LanceDB、关系或Wiki损坏时从SQLite和不可变正式文件按书重建；索引不是备份，也不是恢复权威。
- 不生成假向量、随机向量或虚构Agent状态来冒充降级成功。

### 11. 两轮设计审查结果

第一轮按失败传播链检查，修复了：硬事实同池排序、未验证关系种子、重复证据多票、冲突平均、无答案填空、关系爆炸和投影落后。

第二轮按创造性、岗位和超长篇反向检查，修复了：主笔旧文锚定、岗位同包、阶段摘要冒充证据、本地候选与模型Token混算、参数冒充最优，以及容量证据外推文学质量。

## 创造性与输出质量保护

本方案从创作者手中拿走的自由只有：不能违反已确认硬事实，不能把候选/谎言/旧版本当正史，不能让无证据的重大新增自动结算。它不决定对白、动作、意象、局部调度、节奏实现和新剧情的唯一走向。

- 主笔上下文必须同时标出硬事实、任务目标、软倾向、自由创作区和重大候选；自由创作区为空则不启动正式生成。
- 相似场景、人物声音和技法只进入灵感调色板；可不用、可变形、不得仿写原句，也不因检索命中要求逐项消费。
- 创意推演可以先在硬边界内形成独立方案，再针对已暴露的事实缺口做一次回查，避免检索材料提前收窄方案空间。
- 硬事实错误必须修复；软审美差异不能借“知识库命中”获得阻断权。
- 以旧流程作为基线，并与只有硬约束、全量资料包、FTS单路和整书上下文做同模型族、相近预算、多次采样的成对盲评。
- 原创性、合理惊喜、人物声音、情绪力度、语言、节奏和整体质量分别设置非劣效门槛，不能用正史正确率提升抵消任一核心维度下降。
- 出现旧文复用、套路化、角色同质或整体质量退化时，只回滚软候选权重、灵感预算、切片、重排或上下文模板；不回滚正史、安全、版权和隔离门禁。

## 测试与证据等级

| 等级 | 必须取得的证据 | 允许表述 |
|---|---|---|
| E0 | 本设计、决定、Schema合同、预算起始值、失败和回滚 | 已确定实现方案 |
| E1 | QueryPlan、Repository、四路适配器、融合记录、证据闭环和迁移存在 | 已实现机制，不称有效 |
| E2 | 构造书上的类型、集成、隔离、时间、冲突、重建、降级和恢复测试 | 构造场景通过 |
| E3 | 独立金标、隐藏对抗集、通道消融、故障注入和500万字/1500章回放 | 在评测范围降低系统风险 |
| E4 | 真实模型20/50/100—200章分层创作、盲评和作者验收；实际1000章以上后才能报告相应长期范围 | 仅在明确题材/模型/规模内报告改善 |

E3查询集至少覆盖：精确专名、别名/指代、语义改写、多跳、当前/过去/计划/失效、人物有限视角、否定、冲突、反事实、无答案、高相似错误实体/错误时间，以及第500/1000/1500章触发早期事实、规则、伏笔和因果。

分别报告结构化、FTS、向量、关系和整体的Recall@K、Precision@K、MRR、nDCG、无答案准确率、证据闭合率、错误实体率、错误时间率、P50/P95延迟、CPU、内存、索引磁盘和注入Token。做以下消融：单结构化、单FTS、单向量、单关系、结构化＋FTS、完整方案逐路移除、无证据闭环、无三车道、整书上下文。

对上下文位置做开头/中部/末尾测试；对父子块/摘要重复、冲突源、多本书、索引落后、向量损坏、关系爆炸和中断恢复做故障注入。阈值、样本、盲评维度和通过条件必须在看结果前冻结，失败样本不得隐藏。

## 剩余风险与未知项

- 中文小说最佳嵌入模型、维度、量化、向量距离门槛、RRF常数、岗位通道权重和Top-K仍未知。
- 本地Windows电脑的CPU、内存、索引时间和P95延迟未实测；E0预算可能需要下调。
- 自动实体链接仍可能误判代称、伪装、同名、不可靠叙述、隐喻和讽刺。
- 关系路径正确不等于因果解释正确；模型仍可能把共现关系说成因果。
- 原文回查能证明文本存在，不能自动证明角色陈述为客观事实。
- 摘要和Wiki可从权威源重建，但错误抽取在重建后仍可能重复，必须用独立探针而不是只验哈希。
- 少量风格片段仍可能锚定表达；创造性退化只能通过真实盲评发现，不能靠检索指标推断。
- E3系统正确性不能替代E4文学质量；即使达到E4，也不能外推所有题材、模型和500万字全过程。

## 停止、回滚和升级条件

- 实体、故事时点、观点主体、正史版本或来源无法确定：正式生产停止；开放讨论显示分支和未知。
- 硬事实冲突无法按权威和三轴时间裁决：停止，不让RRF或重排器决定真相。
- 硬资料超过上下文预算：拆分任务或缩小场景；不得静默截断。
- 向量/关系/Wiki水位落后：按任务显式降级；依赖该通道的正式结论停止。
- 关系遍历达到深度/扇出/节点上限仍未闭合：只允许一次定向补充，之后返回未知。
- 创造性、人物、情绪或整体质量低于基线：回滚软检索策略、灵感预算、重排和上下文模板。
- 需要新增独立图数据库/向量服务、云Embedding、付费API或新端口：属于重大架构/付费变化，暂停并提交老板决定。
- 每个策略、模型和索引使用不可变版本；回滚切回上一已验证快照，保留原始正史、失败样本和审计记录。

官方技术边界依据：SQLite FTS5的BM25结果是独立排名值且数值越小匹配越好，支持短语、前缀、NEAR和列过滤；LanceDB官方混合检索将FTS与向量结合并默认使用RRF，支持元数据预过滤和显式Top-K。产品采用这些底层能力，但事实门禁、三车道、关系路径、证据闭环和岗位路由由文秘写作业务层实现，不能把数据库自带混合搜索直接当最终小说检索系统。
