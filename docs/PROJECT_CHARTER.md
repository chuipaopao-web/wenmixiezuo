# 项目总章程

## 产品使命

把老板的创意、剧情梗概和方向要求，转化为可追溯、可修改、可持续300至500万字、1000章以上的小说创作成果。平台负责主动提问、组织讨论、形成方案、生成大纲和正文、三异模型点评、修订、结算正史、维护长期记忆，并让每书十一名稳定成员从开书到完结保持有依据的工作连续性；需要老板决定时提供清楚的选择单。

## 产品边界

- 小说平台是独立产品，不是AI智囊团的功能页面。
- 当前仅供老板个人、本机使用。
- 首版不实现登录、多用户、租户、收费、商用后台、云部署、高并发、分布式系统或原生手机App。
- 当前不实现无限无人监督运行，也不执行未经确认的外部发布。
- 核心领域从第一天预留未来商用需要的归属、版本、审计和导入导出边界。

## 设计原则

1. 老板只负责表达想法、选择方向和体验成果，不要求老板读代码或处理技术问题。
2. 自然语言是主要入口，平台负责把模糊想法变成结构化创作流程。
3. 正文和正史是不可静默覆盖的资产；聊天不是长期事实源。
4. 所有Agent使用本地长期记忆和可追溯上下文包，不依赖单次模型上下文记住全书。
5. 讨论要有主持、范围、预算、共识和退出条件，不能无限调用模型。
6. 模型、岗位和Agent实例分离；真实能力和真实状态优先于人设描述。
7. 先保证数据隔离、版本、恢复和正史安全，再接入长任务和正文生成。
8. 低风险可逆工作尽量自动完成；重大正史、高费用、版权风险和永久删除必须严格确认。
9. 所有阶段以可验证结果为终点，不以“模型说完成了”为完成。
10. 模型上下文大小与全书总字数解耦；长期陪伴依赖正史、层级知识、滚动规划和岗位连续性记录，不依赖加载全部聊天或让所有模型全天运行。
11. 已结束阶段默认以阶段结算进入活动工作集；关键信息出现时逐级回查前文正史，既不按固定章数遗忘硬事实，也不把全部旧正文重新注入模型。

## 不可突破的门禁

- AI智囊团停止后，小说平台仍能独立工作；反之亦然。
- Worker不能直接写正式正文和核心业务表。
- 前一章未结算，后一章不能进入正文生成。
- 重大正史变化必须由老板确认。
- 结果不明的模型调用不得自动重试。
- 跨书数据不得进入另一书的上下文、检索、任务或预算。
- 换名仿写、近似改写、翻译规避和标志性事件链照搬必须阻断。
- 永久删除必须输入包含 `YES`、对象名称和短ID的完整确认词。

## 首版成功定义

在本机完成两本测试书的严格隔离，并让主测试书连续生成5章、每章2500至3500字。历史首版每章经过异模型审校；下一release每个完整稿固定经过GLM/Kimi/豆包三异模型点评、主编合并、最多两轮定点重写、事实提取和正史结算。中断恢复、主编/副编与主笔/副笔接管、预算冻结、版权门禁、备份恢复和PWA核心体验全部通过。

上述首版成功定义只证明短流程发布，不代表最终超长篇目标完成。最终规模目标另按500万规范化中文字符、1500章的容量与连续性评测，以及真实模型纵向创作证据分级验收；不得从5章、200章或100万字符直接外推。

## 长篇终局增量边界

DEC-020以新release开发长篇终局能力，DEC-021在同一release补充十一人团队和固定GLM/Kimi/豆包三异模型全文点评；历史首版证据保持不可变。新能力必须采用单一SQLite权威、向前迁移、可重建投影、逐书影子验证和可回滚策略指针；不得为500万字符目标直接引入微服务、独立向量/图数据库、云运行依赖或未授权费用。

容量、检索正确性、运行可靠性、创造性非劣效和真实纵向文学质量分别按E0至E4验收。完整设计和开工入口见 `docs/PRE_DEVELOPMENT_DESIGN_FREEZE.md` 与 `docs/superpowers/plans/2026-07-19-final-longform-platform-implementation.md`；当前只授权E0文档冻结，下一条明确开工指令前不创建源码、迁移、依赖或运行任务。
