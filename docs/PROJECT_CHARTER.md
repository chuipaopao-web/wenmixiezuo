# 项目总章程

## 产品使命

帮助作者逐层完成长篇小说：系统准备资料、提出可选方案、辅助规划和写作、核对事实并结算实际状态；作者始终保有选择、修改、留白和最终确认权。质量提升不能把作品压成固定公式。

## 主流程

```text
开书信息 → 非剧情设定 → 分卷方向 → 当前卷事件链 → 当前事件大纲
→ 完整章链与近期详细章纲 → 单章正文 → 章节/事件/卷结算 → 下一卷
```

已有正文导入和反向拆解是兼容入口，原文不可覆盖；分析结果带来源，并回到同一对象链继续创作。

## 分层职责

- 开书信息：题材、读者、风格等基础方向。
- 设定：世界舞台、主角底板、规则与代价、边界与留白等非剧情骨架；扩展项按需补。
- 卷方向：本卷大故事方向、主要变化、重点表达和卷末新局面。
- 事件链/事件大纲：卷内因果结构和可独立成立的小故事。
- 章链/详细章纲：完整章序列与最近章节的场景、情绪、信息、动作和接口。
- 正文：在当前章任务内自由表达。
- 结算：只记录正文真实发生的结果，并向后续规划反馈。

规划描述未来，结算记录实际；上游确认版本改变时，下游候选必须失效、重编译或重新确认。

## 创作合同

- 作者可见内容全部用大白话，软参考可不用、混合、重排或自定义。
- 专业叙事方法只在后台帮助生成有实质差异的具体路线，不在普通作者页面泄漏方法名。
- 首卷负责前500字兴趣、黄金三章追读和约10万有效正文字符内（或短卷卷末）重大高潮的故事职责；效果是硬目标，打法保持开放。
- ContextCompiler区分硬事实、当前任务、软参考和创作空白；计划不能冒充事实，摘要和检索投影不能覆盖正式源。
- 创作团队的当前人数、岗位与模型绑定由产品规格和运行配置决定，规则文件不冻结界面呈现。

## 产品与界面

产品仍在快速完善。左侧书籍切换、顶部功能导航和现有视觉语言只是当前实现，不是不可修改的章程。UI/UX 可以持续重构，只需保持书籍归属清楚、当前任务明确、作者数据不丢、旧内容可读，并优先保证手机端可操作。

每个页面优先回答三件事：我现在在哪里、系统正在做什么、下一步能做什么。表单按需展开，不要求作者一次填完未来层级；AI在作者需要选择或生成下一层时介入，不提前替作者锁死剧情。

## 权威与版本

作者确认的开书资料、设定、规划版本、原话和不可变正文是正式来源。SQLite正式对象与不可变原文是权威源；全文、向量、图谱、Wiki和摘要是可重建投影，事实争议必须回查正式源。

## 基础安全

- 每个业务请求从已验证会话取得 `owner_id`，核心对象同时携带 `book_id`，禁止跨用户、跨书污染。
- 正文使用不可变完整版本；修改产生新版本。
- API Key 只从环境变量读取，不进入数据库、日志、上下文、备份、导出或 Git。
- 普通删除为归档；永久删除作者数据需影响预览、`YES` 和二次确认。
- 不保存或展示思维链；只保存任务、来源、结论、预算和调用证据。
- 同模型不得冒充异模型独立意见，任务状态必须来自真实任务/心跳/调用事件。

## 成功定义

作者能在手机或桌面上从开书连续推进到卷、事件、章纲和正文；每一步负担可控、状态可理解、失败可恢复。系统能长期衔接事实和规划，跨书隔离，可追溯，并保持原创性、人物生命力、情绪力度和整体阅读质量。
