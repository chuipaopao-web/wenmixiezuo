## 1. 痛点、症状与根因

痛点是已配置的团队成员在空闲或任务异常后显示掉线。真实根因不是Agent身份丢失，而是Presence派生逻辑把“活动任务15秒没有心跳”直接映射成“成员离线”，混淆了持久身份、模型路线可用性和当前任务活动三种状态。

## 2. 采用机制与非目标

成员身份继续由数据库持久化；模型路线可用性依据成员启用状态和运行时凭证配置派生；任务活动仍由任务、Worker、心跳、模型调用和工具调用派生。空闲显示在线，过期任务显示待恢复，真实缺凭证或停用显示不可用。

本次不创建常驻模型会话、不做定时付费探活、不伪造工作中、不改变接管、模型选择、预算、正文或正史。供应商网络的瞬时健康仍以实际调用结果为准，配置存在不等于承诺外部API永不故障。

## 3. 两轮审查

第一轮验证旧故障：同一工作任务心跳超过15秒后，成员保持 `available` 且活动状态转为 `受阻`；没有任务的启用成员显示在线空闲/待命；缺凭证或停用成员显示模型不可用。

第二轮防止反向造假：工作中仍必须有当前Worker与任务匹配证据；阻塞、中断和陈旧心跳不能显示工作中；在线标志不得触发模型调用、Token消耗或把失败任务自动重试。

## 4. 指标、停止条件与回滚

- 空闲或陈旧任务导致的错误离线数为0。
- 没有真实任务证据却显示工作中的数量为0。
- 在线状态导致的额外模型调用和Token消耗为0。
- 若出现缺凭证仍显示可用、任务异常被隐藏或在线标志触发调用，立即停止发布。
- 回滚只恢复状态投影与前端标签；不回滚或删除Agent、任务、调用、连续性和业务数据。
