## 2. 必须保留

- 当前作者工作流和生产正在使用的路由、服务、Worker、迁移与前端入口。
- `owner_id`/`book_id` 隔离、会话与密钥安全、正文不可变、备份恢复和迁移幂等测试。
- 开书、设定、分卷、事件、章纲、正文、结算的核心成功路径和失败恢复。
- 仍有生产数据读取需求的历史数据兼容；只保留读取适配，不保留已废弃功能的新写入口。
- 当前产品、开发、安全、部署和验收所需的最小文档。

## 4. 测试策略

- `verify`：日常快速门禁，只跑类型检查、18个核心测试文件和完整构建，不再默认运行全量。
- `verify:full`：发布、迁移、权限、恢复、核心工作流大改和大范围删除时运行全部测试。
- 长篇20/50/100/200章只在老板明确要求专项验收时运行，不属于工程默认门禁。
- 删除测试前必须确认它验证的风险已由保留测试覆盖，不能只因为运行慢而删除数据安全测试。

## 6. 结算结果（2026-08-21）

本次审计快照由680个文件、126,056行降为614个文件、110,643行。应用核心源码没有为了追求数字被强删。Git跟踪的删除可恢复，生成型临时构建目录可重新生成；部署回滚压缩包继续保留且由 `.gitignore` 排除。

验证证据：

- `npm run verify`：类型检查、18个测试文件/88项测试、完整构建通过；
- `npm run verify:full`：182个测试文件/773项测试、完整构建通过；
- `git diff --check`：通过；
- 被删文件名称引用扫描：0命中；
- 未安装新Skill；当前官方Skill目录没有代码瘦身专用Skill，临时审计工具也未写入依赖。

保留例外：`app.css`、`domain-routes.ts`、Web API客户端仍是运行入口。它们应在以后修改对应业务时按领域拆分，不能在删除批里做大范围机械重构。

## 7. 长期规则

每批先检查引用和替代，再删除，再跑与风险相称的测试。发现仍被当前功能使用就退出清理名单，不为达到行数目标强删。普通改动只跑快速门禁；高风险改动和发布再跑全量门禁。详细历史交给Git，不再生成重复文档中心。
