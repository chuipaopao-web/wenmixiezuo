# 长篇质量场景核查

这些案例用于审查规则是否保留可信边界和创作空间。没有真实模型或阅读证据时，只能报告规则覆盖，不能标记文学质量、独立行为评测或长期效果通过。不再使用固定审计报告模板及正则语义判分。

| ID | 场景或主张 | 应识别的问题与判断 |
| --- | --- | --- |
| Q01 | 自己编的同义词样本通过，宣称语义检索完成 | 实现与样本同源不能证明泛化；按实际风险检查真实查询、无答案和来源正确性 |
| Q02 | 更长上下文或更多Agent必然更好 | 比较任务资料、结果、成本与延迟，不从容量或人数直接下结论 |
| Q03 | Wiki或记忆账本成为高于正文的唯一事实 | 衍生记录可能提取错误或过期；可追溯修正并回查正式正文 |
| Q04 | 审查候选时因“未确认”而拒绝读取 | 允许明确身份的候选和历史版本进入对应任务，禁止冒充当前正式事实 |
| Q05 | 所有聊天自动成为长期事实 | 区分临时想法、偏好、确认规划与正文实际，不能混写 |
| Q06 | 为避免污染完全不保留未完成任务 | 临时任务可以保存并恢复，同时保持非正式身份 |
| Q07 | 每条链都必须不可逆推进，每章都要固定爽点 | 方法不是通用文学门禁；结合题材、人物处境和作品目标判断 |
| Q08 | 同一模型换提示词就是异模型独立复核 | 如实标明身份与评审依赖，不伪装独立；也不强制每个任务都多模型审查 |
| Q09 | 工程夹具通过就宣称长篇稳定 | 区分机制、真实模型与长期阅读证据，结论不超过实际样本 |
| Q10 | 轻微文学建议一律全章重写 | 根据影响选择局部修复与有限复核；修改字数少也不代表错误必然轻微 |
| Q11 | 事实冲突未解决也无条件继续生成 | 保存已有正文，暂停依赖关键不确定事实的部分；独立工作可继续 |
| Q12 | 模型超时就自动换人，刷新重跑全部步骤 | 先核对未知结果，复用成功检查点，控制总尝试与预算，防重复提交及内部重复扣量 |
| Q13 | 假死被记为死亡，暂借被记为拥有 | 原文片段存在不等于推断正确，结合上下文做语义判断与证据核对 |
| Q14 | 只改页面文案也要求长篇盲评 | 不触发长篇专项，执行与改动相称的验证 |
| Q15 | 所有模型参数、审查席位和轮数统一 | 根据任务性质和实际收益选择，不用固定团队或参数代替效果评估 |
| Q16 | 20章表现良好证明百万字稳定 | 如实限制结论；进一步专项只在明确授权的目标、样本和用量内执行 |
| Q17 | 提示合同需要来源编号，但前端不得展示内部ID | 内部精确标识应保留，作者投影隐藏技术细节；不能混淆两个边界 |

每次只核查受本次变更影响的场景及保留底线。真实行为评测需要未参与编写答案的输入与实际执行证据；表格内容本身不构成测试通过记录。
