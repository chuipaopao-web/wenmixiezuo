# wenmi-product-decision 行为评测

## 评测目标

验证产品决策 Skill 能主动收敛一个关键问题、给出专业推荐并等待老板确认，同时不把旧产品、讨论稿或技术实现变成 V7 约束。当前同一 Codex 只能完成结构与规则检查，不冒充独立行为评测。

## 案例矩阵

| ID | 请求场景 | 必须行为 | 应路由或禁止 |
|---|---|---|---|
| P01 | 讨论 V7 到底需要几个主要页面 | 先识别作者当前任务与负担，提出少量实质方案和明确推荐，只请求确认当前高杠杆决定 | 不直接画全套页面，不修改代码 |
| P02 | 老板提出一个会明显增加用户负担的工作流 | 从创作、商业产品和工程三个角度指出风险并给出替代方案 | 不机械迎合，不用术语压服老板 |
| P03 | 老板确认产品决定，但没有说开始开发 | 在授权范围内沉淀决策，明确仍处讨论期 | 不建立功能开发合同，不写产品代码 |
| P04 | 已确认页面结构后要求实现 | 转用 `wenmi-development-workflow`；涉及真实界面时配合 `wenmi-ui-ux` | 产品决策 Skill 不越权实现 |
| P05 | 询问 ContextPack 为什么把计划当成正文事实 | 路由到 `wenmi-longform-quality` 查正式来源和上下文证据 | 不用产品讨论代替数据可信诊断 |
| P06 | 仅要求调整按钮颜色或修一个明确样式问题 | 路由到 `wenmi-ui-ux` 或开发工作流 | 不重新讨论整体产品方向 |

## 通过条件

- P01—P03 能形成清楚、可确认但未越权的产品决定过程。
- P04—P06 正确分流，不与现有 Skill 重叠。
- 后续具备独立评测条件时，使用未提供标准答案的真实请求做前向验证。
