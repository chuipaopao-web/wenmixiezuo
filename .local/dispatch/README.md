## 通道结构

- `inbox\`    任务投放区（GPT写任务书存这里，task-编号.md）
- `outbox\`   结果回收区（执行报告：改动清单/差异摘要/测试证据）
- `archive\`  已处理任务归档（含失败任务）
- `worktrees\`：隔离工作副本统一建在 **`D:\wenmixiezuo\.local\dispatch\worktrees\<task>`**，遵守只在项目内工作的规则；不得加入主分支提交。

## 执行隔离（重要）

- 每个改动型任务在独立git工作树中执行；具体基准提交和分支由任务书指定。已有同名副本先核对，禁止覆盖或重置。
- 主工作区 D:\wenmixiezuo 在合入前**零改动**；"不提交"期间改动只存在于隔离副本
- 合入按当前任务的技术验收与授权处理，可用merge或cherry-pick，保护主区未提交修改。
- 废弃任务先保留副本和差异供审计；清理另行处理，禁止自动强制删除。
- 依赖复用须确认测试解析的是隔离副本源码，不能因共享 node_modules 的工作区链接指回主目录而假通过；不得修改共享依赖或锁文件。

## 失败处理

- 构建或测试失败：如实写入outbox报告（失败命令+输出摘要），工作树保留供检查，标记失败
- 同一问题修正后仍失败先复核原因和方案，不机械重试；由技术负责人处理，继续独立工作，不让老板决定代码。
- 执行中崩溃（进程/会话中断）：工作树与分支保留，报告"结果未知"，重新执行前先核对遗留状态

## 禁止事项（硬规则）

- 提交/集成/推送/部署遵守当前任务有效授权和生产门禁；未授权不执行，不重复申请已有授权。只读批次不改产品代码。
- 禁止越界：任务书范围外的文件只记录不顺手改
- 计费：执行消耗ZCode Plan套餐额度，以实际账单为准

## 执行流程

1. GPT把任务书存为 `inbox\task-001.md`（格式见 `任务模板.md`）
2. 触发执行：老板在ZCode明确指定任务文件；当前采用手动触发，不开启监听、定时任务或自动领取下一批。
3. ZCode按任务书在隔离副本执行，写 `outbox\task-001.result.md`
4. GPT做技术验收：读结果报告、读隔离副本代码差异、必要时复跑测试
5. 按当前有效授权处理集成/发布。未通过则在同一任务中记录具体返修意见，不要求老板判断代码。
